Fastino exposes one route family for training:

```text
/v1/training/jobs
```

Every job has a `type`:

<CardGroup cols={2}>
  <Card title="Config jobs" icon="sliders">
    Send a prepared dataset and training configuration. Fastino runs the
    training loop. Start with the [GLiNER fine-tuning guide](/guides/fine-tune-gliner).
  </Card>
  <Card title="Interactive jobs" icon="code">
    Run the training loop one step at a time from your application. Start with
    the [RL API overview](/rl-api) and [RL API quickstart](/rl-api/quickstart).
  </Card>
</CardGroup>

Use a `config` job for managed fine-tuning. Use an `interactive` job when your
application must control forward passes, backward passes, optimizer steps, and
checkpoint timing.

## Set up your API key

1. **Create a [Fastino](https://agent.fastino.ai/) account**
2. **Get your API key** from [Settings](https://agent.fastino.ai/api-keys)

Set your key as an environment variable so the examples below work as-is:

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="your_api_key_here"
```

```powershell Windows
$env:FASTINO_API_KEY = "your_api_key_here"
```

</CodeGroup>

The API base URL is `https://api.fastino.ai`. Send
`X-API-Key: $FASTINO_API_KEY` on each request. See
[API authentication](/authentication) for all supported authentication forms.

## Config-job quickstart

### 1. Prepare a dataset

[Prepare, upload, and process a training dataset](/concepts/datasets). Wait
until the dataset version is `ready`.

### 2. Choose a live base model

Query the catalog immediately before submission. It is the source of truth for
trainable model IDs.

```bash
curl "https://api.fastino.ai/v1/base-models?supports_training=true" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

### 3. Create the job

Keep the field name `base_model` and set `type` to `config`:

```bash
curl -X POST "https://api.fastino.ai/v1/training/jobs" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "config",
    "model_name": "my-gliner-model",
    "base_model": "BASE_MODEL_ID_FROM_CATALOG",
    "datasets": [
      {"name": "my-ready-dataset", "version": "VERSION_NUMBER"}
    ],
    "training_type": "lora"
  }'
```

Save the returned `id`; it is the `job_id` used by every job-specific route.

### 4. Poll and inspect

```bash
curl "https://api.fastino.ai/v1/training/jobs/JOB_ID" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

For config jobs, responses include:

- `status`: persisted job status.
- `normalized_status`: stable status intended for client polling.
- `is_terminal_status`: whether polling can stop.
- `error_message`: failure information when available.
- `is_deployable`: whether the completed artifact passes deployment validation.
- `deployability_reason`: why the artifact is not deployable.

Prefer `normalized_status` and `is_terminal_status` when polling a config job.
You can also inspect
[`GET /v1/training/jobs/{job_id}/logs`](/api-reference/training-jobs/logs),
[`GET /v1/training/jobs/{job_id}/billing`](/api-reference/training-jobs/billing),
and
[`GET /v1/training/jobs/{job_id}/checkpoints`](/api-reference/training-jobs/checkpoints).

## Config-job status lifecycle

The following persisted statuses describe managed config jobs. Interactive jobs
have caller-controlled behavior; do not infer their lifecycle from this table.

| Persisted status | Description |
| --- | --- |
| `requested` | The job was accepted and is awaiting dispatch or provisioning. |
| `running` | Training is actively running. |
| `complete` | Training completed successfully. Artifact preparation may continue. |
| `normalizing` | Fastino is preparing the trained artifact. |
| `artifact_ready` | The trained artifact is ready. |
| `deployed` | The artifact has been deployed. |
| `paused` | The managed job is paused. |
| `errored` | Training, dispatch, or artifact preparation failed. |
| `stopped` | The job was stopped while preserving existing checkpoints. |
| `terminated` | The job was terminated and its checkpoints were deleted. |

## Routes available to both job types

| Method | Route | Purpose |
| --- | --- | --- |
| `POST` | [`/v1/training/jobs`](/api-reference/training-jobs/create) | Create a config job directly; the supported SDK creates interactive jobs through the compatibility adapter |
| `GET` | [`/v1/training/jobs`](/api-reference/training-jobs/list) | List jobs |
| `GET` | [`/v1/training/jobs/{job_id}`](/api-reference/training-jobs/get) | Get a job |
| `POST` | [`/v1/training/jobs/{job_id}/stop`](/api-reference/training-jobs/stop) | Stop a job and free its training resources |
| `GET` | [`/v1/training/jobs/{job_id}/logs`](/api-reference/training-jobs/logs) | Read logs |
| `GET` | [`/v1/training/jobs/{job_id}/billing`](/api-reference/training-jobs/billing) | Read billing details |
| `POST` | `/v1/training/jobs/{job_id}/deploy` | Deploy a job artifact |
| `GET` | [`/v1/training/jobs/{job_id}/deployments`](/api-reference/training-jobs/deployments) | List deployments |
| `GET` | [`/v1/training/jobs/{job_id}/checkpoints`](/api-reference/training-jobs/checkpoints) | List checkpoints |
| `GET` | `/v1/training/jobs/{job_id}/checkpoints/{checkpoint_id}` | Get a checkpoint |
| `GET` | `/v1/training/jobs/{job_id}/checkpoints/{checkpoint_id}/download` | Download a checkpoint |
| `POST` / `DELETE` | `/v1/training/jobs/{job_id}/checkpoints/{checkpoint_id}/publish` | Publish or unpublish a checkpoint |
| `PUT` | `/v1/training/jobs/{job_id}/checkpoints/{checkpoint_id}/ttl` | Set checkpoint retention |
| `DELETE` | `/v1/training/jobs/{job_id}/checkpoints/{checkpoint_id}` | Delete a checkpoint |

## Config-only routes

| Method | Route | Purpose |
| --- | --- | --- |
| `POST` | [`/v1/training/jobs/{job_id}/terminate`](/api-reference/training-jobs/terminate) | Terminate a job and delete its checkpoints |
| `POST` | [`/v1/training/jobs/{job_id}/sync`](/api-reference/training-jobs/sync) | Refresh provider status |
| `GET` | [`/v1/training/jobs/{job_id}/download`](/api-reference/training-jobs/download) | Download the final model |
| `PATCH` | [`/v1/training/jobs/{job_id}/model-name`](/api-reference/training-jobs/update-model-name) | Change the model name |
| `POST` | [`/v1/training/jobs/{job_id}/push-to-hub`](/api-reference/training-jobs/push-to-hub) | Push the final model to Hugging Face Hub |

## Interactive-only routes

Interactive jobs expose the individual training operations:

| Method | Route | Purpose |
| --- | --- | --- |
| `POST` | `/v1/training/jobs/{job_id}/forward` | Run a forward pass |
| `POST` | `/v1/training/jobs/{job_id}/forward-backward` | Run a forward and backward pass |
| `POST` | `/v1/training/jobs/{job_id}/optim-step` | Apply an optimizer step |
| `GET` | `/v1/training/jobs/{job_id}/operations/{operation_id}` | Get an asynchronous operation |
| `POST` | `/v1/training/jobs/{job_id}/operations/{operation_id}/cancel` | Cancel an operation |
| `POST` | `/v1/training/jobs/{job_id}/checkpoints` | Save a state or sampler checkpoint |
| `POST` | `/v1/training/jobs/{job_id}/checkpoints/{checkpoint_id}/load` | Load a checkpoint |
| `POST` | `/v1/training/jobs/{job_id}/checkpoints/{checkpoint_id}/sample` | Sample from a checkpoint |

Calling an interactive step route on a `config` job returns `400`.
