loop, then use `/v1/training/jobs` to inspect the job.

## Choose a job type

Every job has a `type`:

| Type | Who controls the loop? | How it starts |
| --- | --- | --- |
| `config` | Fastino | Send a dataset and configuration to `POST /v1/training/jobs`. GLiNER encoders only. |
| `interactive` | Your application | Call `POST /v1/training/jobs/create-model` or create a Tinker training client. Decoders train this way. |

Both types share the same job identity. Canonical reads use
`GET /v1/training/jobs`, `GET /v1/training/jobs/{job_id}`, and
`GET /v1/training/jobs/{job_id}/checkpoints`.

Native JSON clients use the public interactive operations under
`/v1/training/jobs`. Existing Tinker clients keep `tinker==0.32.0` and set only
`TINKER_BASE_URL=https://api.fastino.ai/v1/training/compat/tinker` and
`TINKER_CREDENTIAL_CMD`.

## Config-job lifecycle

The following persisted statuses describe managed config jobs. Interactive jobs
have caller-controlled behavior; do not infer their lifecycle from this table.

| Persisted status | Description |
| --- | --- |
| `requested` | The job was accepted and is awaiting dispatch or provisioning. |
| `running` | Training is actively running. |
| `complete` | Training completed successfully. Artifact preparation may continue. |
| `normalizing` | Fastino is preparing the trained artifact. |
| `artifact_ready` | The trained artifact is ready. |
| `deployed` | The artifact has been deployed. |
| `paused` | The managed job is paused. |
| `errored` | Training, dispatch, or artifact preparation failed. |
| `stopped` | The job was stopped while preserving existing checkpoints. |
| `terminated` | The job was terminated. Checkpoints are preserved unless `delete_checkpoints` is `true`. |

`normalized_status` provides the stable polling value, including `failed` for a
terminal failure. `status` remains the persisted value, such as `errored`.

## Interactive-job lifecycle

An interactive job runs the calls you send it, in the order it receives
them. Each call returns a `future_id`; read its result at
`GET /v1/training/jobs/{job_id}/futures/{future_id}`.

- You don't number requests or send heartbeats.
- A job with no calls for 30 minutes is released. Its checkpoints are kept.
- `POST /v1/training/jobs/{job_id}/stop` returns immediately and stops accepting
  new calls. Already queued operations may finish before resources are released.
  Usage may continue until that release. Sampler checkpoints can still be
  sampled and downloaded after a stop.

## Interactive-job billing

Interactive jobs bill forward and forward/backward training tokens; sampling
input, cache-read, and output tokens; and checkpoint storage. Checkpoint storage
is metered daily at its GB-month rate.

Creating a model, applying an optimizer step, and saving or loading checkpoints
do not add interactive-training usage charges. Account and project spending
controls still apply when starting or extending compute. Use
[`GET /v1/training/usage`](/api-reference/training-jobs/interactive/storage-usage)
to read team-scoped interactive checkpoint storage and its monthly price. It
does not report compute or total billing. The job billing endpoint in the table
above is for config jobs.
