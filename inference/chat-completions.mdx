GLiNER turns text into schema-constrained data. Use it for entity extraction,
classification, structured records, relations, and constrained multi-task decisions.
Use [GLiDE](/inference/systemone) instead when you need structured choice or ranking.

## Choose an endpoint

| Workload | Endpoint | Reference |
| --- | --- | --- |
| Hosted models and fine-tuned models | `POST /v1/chat/completions` | [Request, response, schemas, and examples](/api-reference/inference/chat-completions) |
| Native synchronous GLiNER-2 | `POST /v1/gliner-2` | [Request, response, and examples](/api-reference/inference/gliner-2) |
| Native input over one million tokens | `POST /v1/gliner-2/async` | [Submit an async job](/api-reference/inference/gliner-2-async) |
| Poll a native async job | `GET /v1/gliner-2/jobs/{job_id}` | [Read job status and results](/api-reference/inference/gliner-2-job-status) |

For most integrations, start with `POST /v1/chat/completions`. It supports the
OpenAI-compatible `model` and `messages` envelope, fine-tuned model IDs, persisted
inference history, and the complete GLiNER schema family.

## Before you call

1. Export your key as `FASTINO_API_KEY`.
2. Query `GET /v1/base-models?supports_inference=true&task_type=encoder`.
3. Confirm the selected model's `encoder_features` support the schema features you need.
4. Follow the complete API reference instead of inferring fields or result shapes.
