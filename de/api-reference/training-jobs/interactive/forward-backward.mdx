`POST /v1/training/jobs/{job_id}/forward-backward`

Berechnet den Verlust eines Stapels von Daten auf Token-Ebene und akkumuliert ihn
Farbverläufe. Der nächste [Optimierungsschritt](/de/api-reference/training-jobs/interactive/optim-step)
wendet sie an. Die Antwort ist eine Zukunft; Lesen Sie das Verlust- und Pro-Token-Protokoll
Wahrscheinlichkeiten aus
[`GET /v1/training/jobs/{job_id}/futures/{future_id}`](/de/api-reference/training-jobs/interactive/get-future).

[`POST /v1/training/jobs/{job_id}/forward`](/de/api-reference/training-jobs/interactive/forward)
nimmt denselben Körper und berechnet den Verlust ohne Gradienten.

## Anfrage

<ParamField header="X-API-Key" type="string" required>
  Ihr Fastino-API-Schlüssel.
</ParamField>

<ParamField path="job_id" type="string" required>
  Interaktive Job-ID.
</ParamField>

<ParamField body="datums" type="object[]" required>
  Ein oder mehrere Trainingsbeispiele. Tokenisieren Sie sie selbst mit den Basismodellen
  Tokenizer.

  <Expandable title="properties">
    <ParamField body="model_input" type="object" required>
      `{"chunks": [{"type": "encoded_text", "tokens": [...]}]}`. Das Eingabetoken
      IDs, insgesamt N Token.
    </ParamField>
    <ParamField body="loss_fn_inputs" type="object" required>
      Tensoren pro Position, jeweils `{"data": [...], "dtype": "int64" | "float32"}`
      mit einem optionalen `shape`. Jeder Tensor hat N Werte.

      - `target_tokens` (`int64`, erforderlich): der an jeder Position erwartete Token,
        Normalerweise wird die Eingabe um eins nach links verschoben.
      - `weights` (`float32`): Verlustgewicht pro Position. Verwenden Sie `0` als Eingabeaufforderung
        Positionen und `1` für Abschlusspositionen.
      - `logprobs` und `advantages` (`float32`): erforderlich für alle Verluste außer
        `cross_entropy`. `logprobs` sind die Log-Wahrscheinlichkeiten des Probenehmers
        Ziele.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="loss_fn" type="string" default="cross_entropy">
  `cross_entropy`, `importance_sampling`, `ppo`, `cispo` oder `dro`.
</ParamField>

<ParamField body="loss_fn_config" type="object">
  Verlusteinstellungen. `ppo` und `cispo` nehmen `clip_low_threshold` und
  `clip_high_threshold`; `dro` nimmt `beta`. Unbekannte Schlüssel werden abgelehnt.
</ParamField>

Die numerischen Token-Arrays unten sind nur illustrative Platzhalter. Tokenisieren Sie Ihren tatsächlichen Text mit dem Tokenizer des `base_model` des Jobs.

<RequestExample>

```bash cURL
curl -X POST "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/forward-backward" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "loss_fn": "cross_entropy",
    "datums": [
      {
        "model_input": {"chunks": [{"type": "encoded_text", "tokens": [151644, 872, 198, 3838]}]},
        "loss_fn_inputs": {
          "target_tokens": {"data": [872, 198, 3838, 30], "dtype": "int64"},
          "weights": {"data": [0, 0, 1, 1], "dtype": "float32"}
        }
      }
    ]
  }'
```

</RequestExample>

## Fehler

| Status | Bedeutung |
| --- | --- |
| `400` | Unbekannter `loss_fn`, ein nicht ganzzahliger `target_tokens`-Tensor, Token-IDs außerhalb des Wortschatzes oder der Job wurde gestoppt. |
| `402` | Das Team hat kein Guthaben oder keine gültige Zahlungseinrichtung. |
| `404` | Der Job existiert nicht oder gehört zu einem anderen Team. |
| `422` | `datums` ist leer oder der Text enthält ein unbekanntes Feld. |

Während der Batch-Ausführung festgestellte Probleme, z. B. eine fehlende Verlusteingabe, stimmen nicht überein
Tensorlängen, ein unbekannter `loss_fn_config`-Schlüssel oder ein Datum, das länger als der ist
Die Grenze des Modells, die Zukunft scheitern. Sein `error.category` ist `user`.
