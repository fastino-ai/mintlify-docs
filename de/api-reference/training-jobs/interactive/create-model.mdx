`POST /v1/training/jobs/create-model`

Erstellt einen `interactive` LoRA-Trainingsjob auf einem Decoder-Basismodell oder einen neuen Job aus einem gespeicherten Trainingszustand. Ihre Anwendung sendet anschließend jeden Forward-Backward-Durchlauf, Optimiererschritt, Checkpoint und Sampling-Aufruf. Native JSON-Clients senden weder `seq_id`-Werte noch Heartbeats. Verwenden Sie für verwaltetes Training mit einem hochgeladenen Datensatz [`POST /v1/training/jobs`](/de/api-reference/training-jobs/create).

Der Job ist bereit, sobald sein `create`-Future abgeschlossen ist. Lesen Sie es mit [`GET /v1/training/jobs/{job_id}/futures/{future_id}`](/de/api-reference/training-jobs/interactive/get-future).

Jedes Team kann höchstens `16` aktive interaktive Jobs haben. Pro Job können gleichzeitig höchstens `512` Operationen eingereiht sein. Beim Überschreiten eines Limits wird `429` zurückgegeben.

## Anfrage

<ParamField header="X-API-Key" type="string" required>
  Ihr Fastino-API-Schlüssel.
</ParamField>

Senden Sie genau eines von `base_model` und `from_checkpoint`.

<ParamField body="base_model" type="string">
  `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16`,
  `nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-BF16` oder `Qwen/Qwen3.6-35B-A3B`.
</ParamField>

<ParamField body="from_checkpoint" type="string">
  Der `path`, den [`save-weights`](/de/api-reference/training-jobs/interactive/save-weights) für einen Ihrer Jobs zurückgegeben hat, z. B. `tinker://<job_id>/weights/<name>`. Der neue Job übernimmt das Basismodell und die LoRA-Einstellungen dieses Checkpoints; lassen Sie daher `lora_config` weg. Sampler-Checkpoints werden abgelehnt.
</ParamField>

<ParamField body="load_optimizer" type="boolean" default="false">
  Setzen Sie `load_optimizer` zusammen mit `from_checkpoint`, um den Optimiererzustand wiederherzustellen.
</ParamField>

<ParamField body="lora_config" type="object">
  LoRA-Einstellungen für einen neuen Job.

  <Expandable title="properties">
    <ParamField body="rank" type="integer" default="32">
      LoRA-Rang, von 1 bis 32.
    </ParamField>
    <ParamField body="seed" type="integer">
      Adapter-Initialisierungs-Seed.
    </ParamField>
    <ParamField body="train_attn" type="boolean" default="true">
      Aufmerksamkeitsschichten trainieren.
    </ParamField>
    <ParamField body="train_mlp" type="boolean" default="true">
      Trainieren Sie MLP-Ebenen.
    </ParamField>
    <ParamField body="train_unembed" type="boolean" default="true">
      Trainieren Sie die Ebene zum Aufheben der Einbettung.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="optimizer_config" type="object">
  Optimiererfamilie. Es wird nur `{"type": "adamw"}` bereitgestellt, was die Standardeinstellung ist.
</ParamField>

<ParamField body="project_id" type="string">
  Projekt, dem der Job und seine Nutzung zugeordnet sind. Standardmäßig Ihr Standardprojekt.
</ParamField>

<ParamField body="user_metadata" type="object">
  Ihre eigenen JSON-Metadaten für den Job.
</ParamField>

<RequestExample>

```bash cURL
curl -X POST "https://api.fastino.ai/v1/training/jobs/create-model" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "base_model": "Qwen/Qwen3.6-35B-A3B",
    "lora_config": {"rank": 32}
  }'
```

</RequestExample>

## Antwort

<ResponseField name="job_id" type="string">
  ID des interaktiven Jobs. Verwenden Sie sie für jede Route unter `/v1/training/jobs/{job_id}`.
</ResponseField>

<ResponseField name="type" type="string">
  Immer `interactive`.
</ResponseField>

<ResponseField name="base_model" type="string">
  Basismodell des Jobs.
</ResponseField>

<ResponseField name="future_id" type="string">
  Das `create`-Future des Jobs.
</ResponseField>

<ResponseField name="load_future_id" type="string | null">
  Bei `from_checkpoint` das Future, das den Checkpoint lädt.
</ResponseField>

<ResponseExample>

```json Response
{
  "job_id": "SESSION_ID:train:0",
  "type": "interactive",
  "base_model": "Qwen/Qwen3.6-35B-A3B",
  "future_id": "FUTURE_ID",
  "load_future_id": null
}
```

</ResponseExample>

## Fehler

| Status | Bedeutung |
| --- | --- |
| `400` | Das Modell wird nicht bereitgestellt, der Rang liegt außerhalb des Bereichs, `from_checkpoint` ist ein Sampler-Prüfpunkt oder `lora_config` wurde mit `from_checkpoint` gesendet. |
| `402` | Das Team hat kein Guthaben oder keine gültige Zahlungseinrichtung. |
| `404` | Dem Team steht kein interaktives Training zur Verfügung oder der Kontrollpunkt existiert nicht. |
| `429` | Das Team hat bereits `16` aktive interaktive Jobs. Stoppen Sie vor einem erneuten Versuch einen inaktiven Job. |
| `422` | `base_model` und `from_checkpoint` wurden beide oder keine gesendet, oder der Text enthält ein unbekanntes Feld. |
