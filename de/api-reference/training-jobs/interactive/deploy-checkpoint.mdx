`POST /v1/training/jobs/{job_id}/checkpoints/sampler_weights/{name}/deploy`

Stellt einen Sampler-Checkpoint des Jobs als trainiertes Modell bereit. Rufen Sie es mit [`POST /v1/chat/completions`](/de/api-reference/inference/chat-completions) und `"model": "<model_id>"` auf. Die Deployment-Verfügbarkeit wird pro Modell und Umgebung gesteuert. Nemotron 3.5 Lightning (`nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16`) und Qwen3.6-35B-A3B (`Qwen/Qwen3.6-35B-A3B`) sind derzeit aktiviert. Für Nemotron 3 Super (`nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-BF16`) ist die Serving-Implementierung vorhanden, es ist derzeit jedoch nicht aktiviert; das Deployment gibt `400` zurück.

Der `status` des Modells ist `deploying`, bis die Serving-Engine es geladen hat,
danach `deployed`. Ein erneutes Deployment desselben Checkpoints gibt dasselbe
Modell mit seinem aktuellen Status zurück; Sie können den Aufruf also
wiederholen, um den Fortschritt zu prüfen. Ist ein früherer Versuch
fehlgeschlagen, wiederholt der erneute Aufruf ihn.

## Anfrage

<ParamField header="X-API-Key" type="string" required>
  Ihr Fastino-API-Schlüssel.
</ParamField>

<ParamField path="job_id" type="string" required>
  ID des interaktiven Jobs.
</ParamField>

<ParamField path="name" type="string" required>
  Name eines Sampler-Checkpoints, der mit
  [`save-weights-for-sampler`](/de/api-reference/training-jobs/interactive/save-weights-for-sampler)
  gespeichert wurde.
</ParamField>

<ParamField body="model_name" type="string">
  Bis zu 64 Buchstaben, Ziffern, Bindestriche und Unterstriche, beginnend und
  endend mit einem Buchstaben oder einer Ziffer. Wird ohne Angabe aus dem
  Checkpoint-Namen abgeleitet. Der Body ist optional.
</ParamField>

<RequestExample>

```bash cURL
curl -X POST "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/checkpoints/sampler_weights/step-000100/deploy" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model_name": "support-replies-v1"}'
```

</RequestExample>

## Antwort

<ResponseField name="model_id" type="string">
  Die ID des trainierten Modells. Übergeben Sie sie für die Inferenz als `model`.
</ResponseField>

<ResponseField name="job_id" type="string">
  Der interaktive Job, der den Checkpoint gespeichert hat.
</ResponseField>

<ResponseField name="checkpoint_id" type="string">
  `sampler_weights/<name>`.
</ResponseField>

<ResponseField name="base_model" type="string">
  Das Basismodell des Modells.
</ResponseField>

<ResponseField name="project_id" type="string | null">
  Das Projekt des Jobs, falls vorhanden.
</ResponseField>

<ResponseField name="status" type="string">
  `deploying` oder `deployed`.
</ResponseField>

<ResponseExample>

```json Response
{
  "model_id": "MODEL_ID",
  "job_id": "SESSION_ID:train:0",
  "checkpoint_id": "sampler_weights/step-000100",
  "base_model": "nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16",
  "project_id": null,
  "status": "deploying"
}
```

</ResponseExample>

| Status | Bedeutung |
| --- | --- |
| `400` | Serving ist für das Basismodell nicht verfügbar, oder der Checkpoint ist kein Adapter, den die Serving-Engine akzeptiert. |
| `404` | Der Job oder Sampler-Checkpoint existiert nicht, gehört zu einem anderen Team oder hat keine Dateien. |
| `409` | Ein anderes Modell verwendet `model_name` bereits, oder das aus diesem Checkpoint ausgelieferte Modell wurde gelöscht. Speichern Sie die Gewichte unter einem neuen Namen, um sie erneut bereitzustellen. |
| `422` | `model_name` ist ungültig oder der Body enthält ein unbekanntes Feld. |
