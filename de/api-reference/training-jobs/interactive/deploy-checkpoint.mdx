`POST /v1/training/jobs/{job_id}/checkpoints/sampler_weights/{name}/deploy`

Dient als trainiertes Modell einem der Sampler-Kontrollpunkte des Jobs. Nennen Sie es mit
[`POST /v1/chat/completions`](/de/api-reference/inference/chat-completions) und
`"model": "<model_id>"`. Die aktuelle Bereitstellungszulassungsliste enthält nur Nemotron 3.5 Lightning
(`nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16`). Andere Stützpunkte kehren zurück
`400`.

Der `status` des Modells ist dann `deploying`, bis die bedienende Engine ihn dann geladen hat
`deployed`. Die erneute Bereitstellung desselben Prüfpunkts gibt dasselbe Modell und seine zurück
Aktueller Status, so dass Sie den Anruf wiederholen können, um den Fortschritt zu überprüfen. Wenn ein früher
Der Versuch ist fehlgeschlagen. Der Wiederholungsaufruf versucht es erneut.

## Anfrage

<ParamField header="X-API-Key" type="string" required>
  Ihr Fastino-API-Schlüssel.
</ParamField>

<ParamField path="job_id" type="string" required>
  Interaktive Job-ID.
</ParamField>

<ParamField path="name" type="string" required>
  Name eines Sampler-Checkpoints, der mit gespeichert wurde
  [`save-weights-for-sampler`](/de/api-reference/training-jobs/interactive/save-weights-for-sampler).
</ParamField>

<ParamField body="model_name" type="string">
  Bis zu 64 Buchstaben, Ziffern, Bindestriche und Unterstriche, beginnend und endend mit a
  Buchstabe oder Ziffer. Wird vom Prüfpunktnamen abgeleitet, wenn dieser weggelassen wird. Der Körper ist
  optional.
</ParamField>

<RequestExample>

```bash cURL
curl -X POST "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/checkpoints/sampler_weights/step-000100/deploy" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model_name": "support-replies-v1"}'
```

</RequestExample>

## Antwort

<ResponseField name="model_id" type="string">
  Die ID des trainierten Modells. Übergeben Sie es zur Schlussfolgerung als `model`.
</ResponseField>

<ResponseField name="job_id" type="string">
  Der interaktive Job, der den Prüfpunkt gespeichert hat.
</ResponseField>

<ResponseField name="checkpoint_id" type="string">
  `sampler_weights/<name>`.
</ResponseField>

<ResponseField name="base_model" type="string">
  Das Basismodell des Modells.
</ResponseField>

<ResponseField name="project_id" type="string | null">
  Das Projekt des Jobs, falls vorhanden.
</ResponseField>

<ResponseField name="status" type="string">
  `deploying` oder `deployed`.
</ResponseField>

<ResponseExample>

```json Response
{
  "model_id": "MODEL_ID",
  "job_id": "SESSION_ID:train:0",
  "checkpoint_id": "sampler_weights/step-000100",
  "base_model": "nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16",
  "project_id": null,
  "status": "deploying"
}
```

</ResponseExample>

| Status | Bedeutung |
| --- | --- |
| `400` | Das Basismodell ist nicht Nemotron 3.5 Lightning, oder der Prüfpunkt ist kein PEFT-Adapter, den die Serving Engine akzeptiert. |
| `404` | Der Job- oder Sampler-Prüfpunkt existiert nicht, gehört zu einem anderen Team oder hat keine Dateien. |
| `409` | Ein anderes Modell verwendet bereits `model_name` oder das von diesem Prüfpunkt bereitgestellte Modell wurde gelöscht. Speichern Sie die Gewichte unter einem neuen Namen, um sie erneut bereitzustellen. |
| `422` | `model_name` ist ungültig oder der Text enthält ein unbekanntes Feld. |
