`GET /v1/training/jobs/{job_id}/futures/{future_id}`

Jeder interaktive Jobaufruf, der funktioniert, gibt einen `future_id` zurück. Befragen Sie die Zukunft
bis sein `status` `completed`, `failed` oder `cancelled` ist. Verwenden Sie `wait=true`, um
bis zu 25 Sekunden pro Anfrage warten; Ein Timeout kann immer noch ein Nicht-Terminal zurückgeben
Zukunft. Die Ergebnisse werden eine Stunde lang gespeichert.

## Anfrage

<ParamField header="X-API-Key" type="string" required>
  Ihr Fastino-API-Schlüssel.
</ParamField>

<ParamField path="job_id" type="string" required>
  Interaktive Job-ID.
</ParamField>

<ParamField path="future_id" type="string" required>
  Die zukünftige ID wurde zurückgegeben, als die Arbeit in die Warteschlange gestellt wurde.
</ParamField>

<ParamField query="wait" type="boolean" default="false">
  Warten Sie bis zu 25 Sekunden auf eine unvollendete Zukunft, bevor Sie antworten. Wiederholen
  die Anfrage, bis sie abgeschlossen ist.
</ParamField>

<RequestExample>

```bash cURL
curl "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/futures/$FUTURE_ID?wait=true" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

</RequestExample>

## Antwort

<ResponseField name="future_id" type="string">
  Die Zukunft.
</ResponseField>

<ResponseField name="job_id" type="string">
  Der Job.
</ResponseField>

<ResponseField name="type" type="string">
  `create`, `load`, `forward`, `forward_backward`, `optim_step`, `save` oder `sample`.
</ResponseField>

<ResponseField name="status" type="string">
  `pending`, `running`, `completed`, `failed` oder `cancelled`.
</ResponseField>

<ResponseField name="queue_state" type="string | null">
  Im unvollendeten Zustand: `active` oder `paused_capacity`, während die GPU-Kapazität aufgewärmt wird.
</ResponseField>

<ResponseField name="queue_state_reason" type="string | null">
  Eine für Menschen lesbare Kapazitätserklärung, während `queue_state` ist
  `paused_capacity`; andernfalls `null`.
</ResponseField>

<ResponseField name="result" type="any">
  Einmal `completed`:

  - `forward` und `forward_backward`: `loss_fn_outputs` (ein Eintrag von Tensoren pro
    (z. B. `logprobs`) und `metrics`.
  - `sample`: `sequences`, jeweils mit `tokens`, `logprobs` und `stop_reason`,
    plus `prompt_logprobs` auf Anfrage.
  - `save`: der Prüfpunktpfad.
  - Andere Arten: eine Bestätigung.
</ResponseField>

<ResponseField name="error" type="object | null">
  Wenn `failed` oder `cancelled`: `message` und `category` (`user`) für ein Problem
  mit der Anfrage `server` für ein Fastino-Problem).
</ResponseField>

| Status | Bedeutung |
| --- | --- |
| `404` | Der Job oder die Zukunft existiert nicht oder gehört zu einem anderen Team. |
| `410` | Der Vorgang ging verloren oder das gespeicherte Ergebnis ist abgelaufen. Senden Sie den Vorgang erneut. Ein abgelaufenes Ergebnis kann nicht wiederhergestellt werden. |
