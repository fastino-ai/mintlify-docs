`GET /v1/training/jobs`

Gibt die für den authentifizierten Account sichtbaren Config- und
Interactive-Trainingsjobs zurück.

Ohne `type` werden Config- und interaktive Jobs nach `created_at` gemischt
aufgelistet, die neuesten zuerst. Haben zwei Jobs denselben Zeitstempel, steht
der Config-Job zuerst. Übergeben Sie `type=interactive`, um nur interaktive
Jobs aufzulisten.

## Request

<ParamField header="X-API-Key" type="string" required>
  Ihr Fastino-API-Schlüssel.
</ParamField>

<ParamField query="status" type="string">
  Beide Jobtypen nach Status filtern. Interaktive Jobs unterstützen `creating`, `active`, `stopping`, `stopped` und `failed`; `running` entspricht ebenfalls `active`, während `errored` und `error` `failed` entsprechen. `running`, `errored`, `error`, `stopped` und `failed` können beide Typen treffen. `creating`, `active` und `stopping` treffen nur interaktive Jobs; andere Config-Statuswerte nur Config-Jobs. Bei Config-Jobs gibt `status=complete` Jobs zurück, die als `complete`, `artifact_ready` oder `deployed` gespeichert sind.
</ParamField>

<ParamField query="type" type="string">
  Nach `config` oder `interactive` filtern.
</ParamField>

<ParamField query="project_id" type="string">
  Nach Projekt-ID filtern.
</ParamField>

<ParamField query="limit" type="integer" default="200">
  Seitengröße von `1` bis `200`.
</ParamField>

<ParamField query="offset" type="integer" default="0">
  Anzahl der zu überspringenden passenden Jobs.
</ParamField>

<RequestExample>

```bash cURL
curl "https://api.fastino.ai/v1/training/jobs?type=config&status=complete&limit=50&offset=0" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

</RequestExample>

## Response

<ResponseField name="success" type="boolean">
  Gibt an, ob die Anfrage erfolgreich war.
</ResponseField>

<ResponseField name="training_jobs" type="object[]">
  Trainingsjob-Datensätze für diese Seite.
</ResponseField>

Jeder Datensatz enthält `id` und `created_at`. Interaktive Datensätze
wiederholen `id` zur API- und SDK-Kompatibilität in `job_id` und
`training_run_id` und enthalten außerdem `status`, `stop_reason`,
`error_message` und `is_terminal_status`. Fragen Sie einen interaktiven Job über
`id` ab, bis das Terminal-Flag true ist.

Ein Datensatz mit `type: "config"` und `source: "interactive_checkpoint"` ist das bereitgestellte Modell aus einem interaktiven Sampler-Checkpoint. Seine Config-Trainingsfelder, darunter Epochen, Batch-Größe, Lernrate und Validierungsanteil, sind `null`.

<ResponseField name="count" type="integer">
  Anzahl der Jobs auf dieser Seite.
</ResponseField>

<ResponseField name="total" type="integer">
  Gesamtzahl der passenden Jobs vor Paginierung.
</ResponseField>

<ResponseField name="has_more" type="boolean">
  Gibt an, ob nach dieser Seite eine weitere existiert.
</ResponseField>

<ResponseExample>

```json Response
{
  "success": true,
  "training_jobs": [],
  "count": 0,
  "total": 0,
  "has_more": false
}
```

</ResponseExample>

Ungültige Paginierungswerte geben `422` zurück.

Die vollständige Liste der gespeicherten Status finden Sie in der [Übersicht zur Training API](/de/training).
