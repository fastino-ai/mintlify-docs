`POST /v1/training/jobs/{job_id}/stop`

Stoppt einen laufenden Job und erhält Checkpoints, die vor dem Stoppen erstellt wurden. Bei einem interaktiven Job antwortet die Anfrage sofort und lehnt neue Aufrufe ab. Bereits eingereihte Operationen können vor der Ressourcenfreigabe abgeschlossen werden. Die Nutzung kann bis zu dieser Freigabe weiterlaufen.

## Request

<ParamField header="X-API-Key" type="string" required>
  Ihr Fastino-API-Schlüssel.
</ParamField>

<ParamField path="job_id" type="string" required>
  UUID des Config-Jobs oder ID des interaktiven Jobs.
</ParamField>

### Config-Job

Der JSON-Body ist für einen Config-Job optional.

<ParamField body="reason" type="string">
  Grund für das Stoppen des Jobs.
</ParamField>

<ParamField body="scores" type="object">
  Numerische Metriken, auf denen die Stopp-Entscheidung basierte.
</ParamField>

<ParamField body="checkpoint" type="string">
  Checkpoint-Pfad oder -Schritt, der dem Stopp zugeordnet ist.
</ParamField>

### Interaktiver Job

Senden Sie keinen Request-Body. Die Antwort enthält die bestätigten gemeinsamen
Felder `success`, `job_id` und `status`.

### Request-Beispiel für einen Config-Job

<RequestExample>

```bash cURL
curl -X POST https://api.fastino.ai/v1/training/jobs/YOUR_TRAINING_JOB_ID/stop \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"reason": "Validation loss stopped improving"}'
```

</RequestExample>

### Request-Beispiel für einen interaktiven Job


<RequestExample>

```bash cURL
curl -X POST https://api.fastino.ai/v1/training/jobs/YOUR_INTERACTIVE_JOB_ID/stop \
  -H "X-API-Key: $FASTINO_API_KEY"
```

</RequestExample>

## Antwort für einen Config-Job

<ResponseExample>

```json Response
{
  "success": true,
  "message": "Training job stopped",
  "job_id": "YOUR_TRAINING_JOB_ID",
  "status": "stopped"
}
```

```json 202 — Abbruch ausstehend
{
  "success": true,
  "message": "Training job cancellation is still being confirmed.",
  "job_id": "YOUR_TRAINING_JOB_ID",
  "status": "stopping"
}
```

</ResponseExample>

Das Feld `message`, die Antwort `202` und die Polling-Regel gelten nur für
Config-Jobs. Fragen Sie nach einer `202`-Antwort für einen Config-Job
`GET /v1/training/jobs/{job_id}` ab. Wiederholen Sie den Stopp-Request nicht,
solange der Abbruch aussteht.

## Antwort für einen interaktiven Job

Ein interaktiver Job verwendet denselben Vorgang ohne Request-Body. Die Antwort
enthält die gemeinsamen Felder `success`, `job_id` und `status`. Verlangen Sie
nicht das Config-spezifische Feld `message`.

```json Response
{
  "success": true,
  "job_id": "YOUR_INTERACTIVE_JOB_ID",
  "status": "stopped"
}
```

## Status für Config-Jobs

Die folgenden Status- und Fehlerangaben gelten nur für Config-Jobs.

| Status | Bedeutung |
| --- | --- |
| `200` | Der Job ist gestoppt und vorhandene Checkpoints bleiben verfügbar. |
| `202` | Die Bestätigung des Anbieterabbruchs steht noch aus. |
| `400` | Die Config-Job-ID oder der Request ist ungültig. |
| `409 training_job_already_finished` | Der Job hat vor dem Stopp einen Endzustand erreicht. |
| `422` | Der JSON-Request-Body des Config-Jobs ist ungültig. |

## Autorisierung

Erfordert die Teamrolle Owner, Admin oder Editor. Andere Rollen erhalten `403 Forbidden`.
