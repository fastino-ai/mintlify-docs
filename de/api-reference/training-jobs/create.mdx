`POST /v1/training/jobs`

Erstellt einen asynchronen `config`-Trainingsjob und gibt dessen Job-Datensatz
zurück. Bei einem Config-Job stellen Sie einen Datensatz und eine Konfiguration
bereit, und Fastino führt den Trainingsloop aus. Um den Loop Schritt für Schritt
zu steuern, folgen Sie dem
[Pfad für einen eigenen Trainingsablauf](/de/training/decoder-quickstart),
der einen `interactive`-Job über
[`POST /v1/training/jobs/create-model`](/de/api-reference/training-jobs/interactive/create-model)
oder das unterstützte Tinker SDK erstellt. Dieser Endpunkt erstellt keine
interaktiven Jobs. Nach der Erstellung verwenden beide Jobtypen ihre kanonischen
IDs mit den dokumentierten Lebenszyklusoperationen unter
`/v1/training/jobs/{job_id}`.

Config-Jobs trainieren Encoder-Modelle, die von
`GET /v1/base-models?supports_training=true` zurückgegeben werden und eine
kompatible Dispatch-Route für Config-Jobs haben. Decoder-Basismodelle geben
`400` zurück; trainieren Sie Decoder stattdessen Schritt für Schritt mit einem
interaktiven Job.

Dieser Endpunkt ist auf 20 Anfragen pro Minute pro Benutzer begrenzt.

## Request

<ParamField header="X-API-Key" type="string" required>
  Ihr Fastino-API-Schlüssel.
</ParamField>

<ParamField header="Idempotency-Key" type="string">
  Vom Client erzeugter Retry-Schlüssel mit 1–255 Zeichen; eine UUID wird empfohlen. Derselbe Schlüssel mit demselben Body gibt den ursprünglichen Job zurück. Derselbe Schlüssel mit einem anderen Body gibt `422` zurück.
</ParamField>

<ParamField body="model_name" type="string" required>
  Anzeigename für das trainierte Modell. Länge: 1–100 Zeichen.
</ParamField>

<ParamField body="base_model" type="string" required>
  Eine trainierbare Encoder-ID aus `GET /v1/base-models?supports_training=true` oder eine unterstützte Checkpoint-UUID. Der ausgewählte `training_type` muss eine kompatible Dispatch-Route haben. Ein Decoder-Basismodell gibt `400` zurück.
</ParamField>

<ParamField body="datasets" type="object[]" required>
  Eine oder mehrere Referenzen auf [hochgeladene Datensätze](/de/concepts/datasets). Jeder Eintrag benötigt `name` und kann `version` enthalten; ausgelassene Versionen werden auf die neueste Version aufgelöst.
</ParamField>

<ParamField body="training_type" type="string" default="lora">
  `lora` oder `full`. Das ausgewählte Basismodell muss den angeforderten Typ unterstützen.
</ParamField>

<ParamField body="validation_data_percentage" type="number" default="0.2">
  Für die Validierung zurückgehaltener Anteil, von `0` bis `0.9` in Schritten von `0.01`.
</ParamField>

<ParamField body="nr_epochs" type="integer" default="100">
  Maximale Anzahl an Epochen, von `1` bis `10000`; Early Stopping kann früher beenden.
</ParamField>

<ParamField body="learning_rate" type="number">
  Maximale Lernrate von `1e-8` bis `1`. Lassen Sie das Feld weg, um das Trainingsrezept des ausgewählten Modells zu verwenden.
</ParamField>

<ParamField body="batch_size" type="integer" default="4">
  Batch-Größe pro Gerät von `1` bis `256`. Am besten weglassen, damit der Trainingsdienst den modellspezifischen Standardwert anwenden oder sicher begrenzen kann.
</ParamField>

<ParamField body="seed" type="integer">
  Optionaler Reproduzierbarkeits-Seed von `0` bis `2147483647`. Setzen Sie `provider_name` auf `modal`, wenn Sie ihn verwenden. Ein Seed reduziert eine Quelle von Variation, garantiert jedoch keine bit-identischen GPU-Läufe.
</ParamField>

<ParamField body="project_id" type="string">
  UUID des Projekts. Wird das Feld weggelassen, ordnet Fastino den Job dem Standardprojekt des Aufrufers zu.
</ParamField>

<Expandable title="Zusätzliche Trainingsparameter">
  <ParamField body="save_steps" type="integer" default="100">
    Speichert alle N Schritte einen Checkpoint, mit N von `1` bis `2147483647`.
  </ParamField>

  <ParamField body="profile_training" type="boolean" default="false">
    Persistiert ein strukturiertes Trainingsprofil als Artefakt.
  </ParamField>

  <ParamField body="wandb_api_key" type="string">

  </ParamField>

  </ParamField>

  <ParamField body="lora_dropout" type="number">

  <ParamField body="early_stopping_min_delta" type="number" default="0.0001">

  <ParamField body="gradient_accumulation_steps" type="integer">
    Positive Anzahl an Mini-Batch-Akkumulationen, bis `2147483647`.

  <ParamField body="auto_data_sizing" type="boolean">
    Aktiviert die automatische Größenanpassung des GLiNER-Datensatzes.

  <ParamField body="max_samples_per_dataset" type="integer">
    Obere Schranke der GLiNER-Auto-Größenanpassung von `1` bis `2147483647`.
  </ParamField>

  <ParamField body="samples_per_label" type="integer">
    Skalierungsfaktor pro Label bei der GLiNER-Auto-Größenanpassung von `1` bis `2147483647`.
  </ParamField>

  <ParamField body="min_training_steps" type="integer">
    Minimale Anzahl an GLiNER-Optimizer-Schritten von `0` bis `2147483647`.
  </ParamField>

  <ParamField body="eval_steps" type="integer">
    Intervall für periodische GLiNER2-Validierung, von `1` bis `2147483647` Optimizer-Schritten. Weglassen, um nur am Epochenende zu validieren.
  </ParamField>

  <ParamField body="max_eval_samples" type="integer">
    Obergrenze pro Datensatz für periodische GLiNER2-Validierung, von `1` bis `2147483647`. Weglassen, um keine Obergrenze zu setzen.
  </ParamField>

  <ParamField body="max_length" type="integer">
    Maximale GLiNER-Eingabelänge, von `1` bis `2147483647` Tokens. Weglassen, um das Kontextlimit des Modells zu verwenden.
  </ParamField>

  <ParamField body="max_gold_per_query" type="integer">
    Maximale Anzahl beibehaltener GLiNER2-Gold-Spans pro Abfrage, von `1` bis `1024`. Weglassen, um `32` zu verwenden.

  <ParamField body="on_capacity_exceeded" type="string">

  </ParamField>

  <ParamField body="training_algorithm" type="string" default="sft">
    Config-Jobs unterstützen nur `sft`. Weglassen, um den Standard zu verwenden.
  </ParamField>

</Expandable>

<RequestExample>

```bash cURL
curl -X POST https://api.fastino.ai/v1/training/jobs \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Idempotency-Key: YOUR_UNIQUE_RETRY_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model_name": "my-model-name",
    "base_model": "fastino/gliner2-multi-v1",
    "datasets": [{"name": "my-ready-dataset"}],
    "training_type": "lora",
    "nr_epochs": 5,
    "learning_rate": 5e-5,
    "validation_data_percentage": 0.2
  }'
```

</RequestExample>

## Response

Gibt `200` mit dem vollständigen Trainings-Job-Datensatz zurück, einschließlich einer UUID `id` und dem Anfangsstatus. Das folgende Beispiel ist gekürzt; die tatsächliche Antwort enthält alle durch `TrainingJobResponse` definierten Felder.

<ResponseExample>

```json Response
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "type": "config",
  "model_name": "my-model-name",
  "base_model": "fastino/gliner2-multi-v1",
  "status": "requested",
  "training_type": "lora",
  "nr_epochs": 5,
  "learning_rate": 5e-5,
  "validation_data_percentage": 0.2
}
```

</ResponseExample>

Speichern Sie die `id` aus dieser Antwort. Sie verwenden sie, um den Status abzufragen, Metriken und Artefakte abzurufen und Inferenz gegen das trainierte Modell auszuführen.

Ein fehlerhaft aufgebauter Body gibt `422` zurück. Eine gültige, aber nicht verfügbare Kombination aus Modell, Datensatz, Trainingstyp oder Anbieter gibt einen anfragespezifischen `4xx`-Fehler zurück.

Die Erstellung kann folgende codierte Konflikte zurückgeben:

| Status | Bedeutung |
| --- | --- |
| `409 duplicate_training_submission` | Ein identischer Job ist bereits aktiv. |
| `409 idempotency_key_job_deleted` | Der ursprünglich mit diesem Idempotenzschlüssel erstellte Job wurde gelöscht. Verwenden Sie für einen neuen Job einen neuen Schlüssel. |
| `409` | Ein referenzierter Datensatz wurde zwischen der Validierung und dem Anlegen des Jobs außer Betrieb genommen. Klären Sie das Problem mit dem Datensatz und versuchen Sie es mit einem neuen Schlüssel erneut. |

Derselbe `Idempotency-Key` und ein identischer Body geben den ursprünglichen Job erneut zurück, statt einen weiteren zu erstellen. Ein geänderter Body mit demselben Schlüssel gibt `422` zurück.

Ein Decoder-Basismodell gibt `400` zurück:

```json
{
  "detail": "Decoder training on this route is retired: 'Qwen/Qwen3.6-35B-A3B' cannot be trained here. Train decoders step by step with the training job routes under /v1/training/jobs (see https://docs.fastino.ai/training/quickstart)."
}
```

Um einen Decoder zu trainieren, erstellen Sie einen interaktiven Job mit
[`POST /v1/training/jobs/create-model`](/de/api-reference/training-jobs/interactive/create-model)
und folgen dem [eigenen Trainingsablauf](/de/training/decoder-quickstart).

## Autorisierung

Erfordert die Teamrolle Owner, Admin oder Editor. Andere Rollen erhalten `403 Forbidden`.
