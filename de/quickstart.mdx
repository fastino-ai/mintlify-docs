Dieser Leitfaden führt Sie auf dem schnellsten Weg zu einer funktionierenden Fastino-Integration. Am Ende haben Sie einen erfolgreichen GLiDE-Entscheidungsaufruf getätigt und verstehen den Aufbau der API. Alles, was Sie benötigen, ist ein Fastino-Konto und ein Terminal.

<Steps>
  <Step title="Registrieren und Ihren API-Schlüssel abrufen">
    Erstellen Sie ein Konto unter [Fastino](https://agent.fastino.ai/).

    Sobald Sie angemeldet sind, gehen Sie zu **Settings → API Keys** und generieren Sie einen neuen Schlüssel. Kopieren Sie ihn an einen sicheren Ort, da Sie ihn nach dem Schließen des Dialogs nicht mehr einsehen können.

    <Warning>
      Halten Sie Ihren API-Schlüssel aus der Versionskontrolle heraus. Verwenden Sie eine Umgebungsvariable oder einen Secrets-Manager, anstatt ihn in Ihren Quelldateien fest zu codieren.
    </Warning>

    Setzen Sie Ihren Schlüssel als Umgebungsvariable, damit die folgenden Beispiele unverändert funktionieren:

    ```bash
    export FASTINO_API_KEY="your_api_key_here"
    ```
  </Step>
  <Step title="Verfügbare Basismodelle auflisten (optional)">
    Sie können die in Fastino verfügbaren Modelle durchsuchen. Verwenden Sie `GET /v1/base-models`, um den vollständigen Katalog zu sehen.

    <CodeGroup>

    ```bash curl
    curl https://api.fastino.ai/v1/base-models \
      -H "X-API-Key: $FASTINO_API_KEY"
    ```

    ```python Python
    import os
    import requests
    
    response = requests.get(
        "https://api.fastino.ai/v1/base-models",
        headers={"X-API-Key": os.environ["FASTINO_API_KEY"]}
    )
    print(response.json())
    ```

    ```javascript JavaScript
    const response = await fetch(
      "https://api.fastino.ai/v1/base-models",
      {
        headers: {
          "X-API-Key": process.env.FASTINO_API_KEY
        }
      }
    );
    const data = await response.json();
    console.log(data);
    ```

    </CodeGroup>

    Die Antwort listet Modell-IDs auf, die Sie an `/v1/chat/completions` übergeben können. Zum Beispiel ist `fastino/gliner2-base-v1` das GLiNER-Basismodell für NER-Aufgaben.
  </Step>
  <Step title="Ihren ersten Inferenzaufruf ausführen">
    Rufen Sie `POST /v1/systemone` mit einem `model`, einem `state`, der die Situation beschreibt, und einer oder mehreren typisierten `questions` auf. GLiDE gibt kalibrierte Wahrscheinlichkeiten und Labels direkt zurück. Es gibt keinen generierten Text, der geparst werden muss. Das folgende Beispiel stellt eine einzelne Ja/Nein-Frage (`noul`).

    <CodeGroup>

    ```bash curl
    curl -X POST "https://api.fastino.ai/v1/systemone" \
      -H "X-API-Key: $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "fastino/glide",
        "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
        "questions": {
          "refund_allowed": {
            "type": "noul",
            "instructions": "Does this request qualify for a refund?",
            "criteria": { "true": "Qualifies", "false": "Does not qualify" }
          }
        }
      }'
    ```

    ```python Python
    import os
    import requests

    response = requests.post(
        "https://api.fastino.ai/v1/systemone",
        headers={
            "X-API-Key": os.environ["FASTINO_API_KEY"],
            "Content-Type": "application/json",
        },
        json={
            "model": "fastino/glide",
            "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
            "questions": {
                "refund_allowed": {
                    "type": "noul",
                    "instructions": "Does this request qualify for a refund?",
                    "criteria": {"true": "Qualifies", "false": "Does not qualify"},
                }
            },
        },
    )

    response.raise_for_status()
    print(response.json())
    ```

    ```javascript JavaScript
    const response = await fetch(
      "https://api.fastino.ai/v1/systemone",
      {
        method: "POST",
        headers: {
          "X-API-Key": process.env.FASTINO_API_KEY,
          "Content-Type": "application/json",
        },
        body: JSON.stringify({
          model: "fastino/glide",
          state: "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
          questions: {
            refund_allowed: {
              type: "noul",
              instructions: "Does this request qualify for a refund?",
              criteria: { true: "Qualifies", false: "Does not qualify" },
            },
          },
        }),
      }
    );

    if (!response.ok) {
      throw new Error(`Inference failed: ${response.status} ${await response.text()}`);
    }

    const result = await response.json();
    console.log(JSON.stringify(result, null, 2));
    ```

    </CodeGroup>

    Antwort:

    ```json
    {
      "model": "glide",
      "answers": {
        "refund_allowed": {
          "type": "noul",
          "noul": 0.9989566626894673,
          "confidence": 0.9979133253789345
        }
      },
      "usage": { "input_tokens": 443, "output_tokens": 62 },
      "token_usage": 505
    }
    ```

    `answers.refund_allowed.noul` ist die Wahrscheinlichkeit, dass die Antwort „Ja“ lautet. `0.999` ist ein starkes Signal dafür, dass die Anfrage die Voraussetzungen erfüllt. Unter [Entscheidungsmodelle](/de/concepts/decision-models) finden Sie die Fragetypen `choice` und `score`, konfidenzbasiertes Routing und die vollständige Referenz der Primitive.

    <Accordion title="Möchten Sie stattdessen Entitäten extrahieren? Nutzen Sie GLiNER über /v1/chat/completions">
      Wenn Sie statt einer Entscheidung eine Extraktion auf Span-Ebene benötigen (NER, Klassifikation, strukturierte Datensätze), rufen Sie `POST /v1/chat/completions` mit einem Modell, einer Nachricht und einem Schema auf, das definiert, was Sie extrahieren möchten:

      ```bash curl
      curl -X POST "https://api.fastino.ai/v1/chat/completions" \
        -H "Authorization: Bearer $FASTINO_API_KEY" \
        -H "Content-Type: application/json" \
        -d '{
          "model": "fastino/gliner2.5-multi-v1",
          "messages": [
            {
              "role": "user",
              "content": "Apple announced the MacBook Pro at WWDC in Cupertino."
            }
          ],
          "schema": {
            "entities": [
              { "name": "organization", "description": "business or institution name" },
              { "name": "product", "description": "named commercial product" },
              { "name": "event", "description": "named conference or event" },
              { "name": "location", "description": "city, region, or place" }
            ]
          },
          "threshold": 0.5
        }'
      ```

      Bei Encoder-Modellen (GLiNER) definiert das Objekt `schema` die Aufgabe und kann `entities`, `classifications`, `structures` und `relations` enthalten. Bei Decoder-Modellen (LLMs) lassen Sie `schema` weg und senden eine normale Chat-Nachricht. Den vollständigen Vertrag, Python-/JavaScript-Beispiele und Fehlercodes finden Sie in der [Inferenz-API](/de/inference).

      <Note>
        `model` muss eine inferenzfähige Basismodell-ID oder die UUID eines abgeschlossenen, deploybaren Trainingsjobs sein. Deployen Sie nach dem Training das ausgewählte Artefakt, bevor Sie die Job-UUID für Inferenz verwenden.
      </Note>
    </Accordion>
  </Step>
  <Step title="Einen Trainingsjob starten (optional)">
    Wenn Sie bereit sind, mit Ihren eigenen Daten feinabzustimmen, starten Sie einen Trainingsjob.

    <CodeGroup>

    ```bash curl
    curl -X POST https://api.fastino.ai/v1/training-jobs \
      -H "X-API-Key: $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model_name": "my-ner-model",
        "base_model": "fastino/gliner2-base-v1",
        "datasets": [{"name": "my-dataset"}],
        "training_type": "lora",
        "nr_epochs": 5,
        "learning_rate": 5e-5
      }'
    ```

    ```python Python
    import os
    import requests
    
    response = requests.post(
        "https://api.fastino.ai/v1/training-jobs",
        headers={
            "X-API-Key": os.environ["FASTINO_API_KEY"],
            "Content-Type": "application/json"
        },
        json={
            "model_name": "my-ner-model",
            "base_model": "fastino/gliner2-base-v1",
            "datasets": [{"name": "my-dataset"}],
            "training_type": "lora",
            "nr_epochs": 5,
            "learning_rate": 5e-5
        }
    )
    print(response.json())
    # {"id": "uuid-of-training-job", "status": "requested"}
    ```

    </CodeGroup>

    Die Antwort enthält eine Job-`id`. Fragen Sie `GET /v1/training-jobs/{id}` ab, um den Status zu prüfen. Sobald der Job den Status `complete` erreicht, verwenden Sie die Job-ID als `model` in `/v1/chat/completions`-Aufrufen.

    Job-Statuswerte: `requested` → `running` → `complete` (oder `failed` / `stopped`).
  </Step>
</Steps>
