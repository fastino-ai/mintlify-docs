Verwenden Sie GLiDE, wenn Ihre Anwendung eine Situation bewerten und strukturierte,
probabilistische Entscheidungen anstelle von generiertem Text zurückgeben muss. Senden
Sie einen `state` und eine oder mehrere typisierte `questions` an
[`POST /v1/systemone`](/de/inference/systemone).

## Grundtyp auswählen

| Entscheidungsform | Grundtyp | Ergebnis |
| --- | --- | --- |
| Ja oder Nein, mit einer Wahrscheinlichkeit | [Noul](/de/concepts/glide-noul) | `noul`, die Wahrscheinlichkeit für Ja |
| Genau eine benannte Option | [Choice](/de/concepts/glide-choice) | Ausgewähltes Label und Wahrscheinlichkeiten für jede Option |
| Eine Stufe auf einer geordneten Skala | [Score](/de/concepts/glide-score) | Ausgewählte Stufe, erwartete Stufe und Wahrscheinlichkeiten |

GLiDE beantwortet jede Frage unabhängig anhand desselben Zustands. Es gibt keinen
Grundtyp für mehrere Labels. Stellen Sie mehrere Noul-Fragen, wenn mehrere Labels
gleichzeitig zutreffen können.

## Triage in einem einzigen Aufruf

Eine Supportanfrage kann in einer einzigen Anfrage weitergeleitet, bewertet und auf
Rückerstattungsberechtigung geprüft werden. Jede Antwort bleibt separat, sodass Ihre
Anwendung für jede Antwort einen anderen Schwellenwert oder eine andere Aktion
verwenden kann.

```json
{
  "model": "fastino/glide",
  "state": {
    "message": "I was charged twice for order A-104. Please refund the duplicate.",
    "account_tier": "business",
    "refund_policy": "Duplicate charges qualify for an immediate refund."
  },
  "questions": {
    "team": {
      "type": "choice",
      "instructions": "Which team should handle this request?",
      "criteria": {
        "billing": "Payments, invoices, or duplicate charges",
        "returns": "Product returns or replacements",
        "technical": "Product defects or technical support"
      }
    },
    "urgency": {
      "type": "score",
      "instructions": "How urgently should the team respond?",
      "criteria": [
        "low: can wait for the normal queue",
        "medium: should be handled soon",
        "high: requires immediate attention"
      ]
    },
    "refund_allowed": {
      "type": "noul",
      "instructions": "Does the request qualify for a refund under the supplied policy?",
      "criteria": {
        "true": "The policy allows the refund",
        "false": "The policy does not allow the refund"
      }
    }
  }
}
```

Lesen Sie die Ergebnisse entsprechend ihrem Grundtyp:

- `answers.team.choice` ist die ausgewählte Route. Prüfen Sie mit `probabilities` die Alternativen.
- `answers.urgency.score` ist der Index der ausgewählten Stufe. Verwenden Sie `expected_level` für einen weniger sprunghaften Schwellenwert.
- `answers.refund_allowed.noul` ist die Wahrscheinlichkeit für Ja. Wählen und validieren Sie Ihren eigenen Aktionsschwellenwert.

## Gängige Muster

| Anwendungsfall | Zustand | Fragen |
| --- | --- | --- |
| Prüfung einer Agentenaktion | Vorgeschlagener Tool-Aufruf, sichtbarer Kontext und Richtlinie | Noul: Darf die Aktion ausgeführt werden? Choice: ausführen, überarbeiten oder eskalieren |
| Inhaltsmoderation | Inhalt sowie die geltende Richtlinie | Choice: Richtlinienkategorie. Score: Schweregrad. Noul: Zur menschlichen Prüfung weiterleiten? |
| Modell- oder Workflow-Routing | Anfrage, Latenzziel und verfügbare Routen | Choice: Route. Score: Komplexität. Noul: Den teuren Fallback verwenden? |
| Qualitätskontrolle | Ausgabe sowie explizite Anforderungen oder Bewertungsraster | Eine Noul-Frage pro Anforderung. Score: Gesamtqualität oder Risiko |
| Operative Triage | Ticket, Kontokontext und Betriebsrichtlinie | Choice: zuständige Stelle. Score: Dringlichkeit. Noul: Für eine automatisierte Aktion geeignet? |

Bewerten Sie bei der Agentenüberwachung nur Artefakte, die Ihr System erfassen darf,
etwa Tool-Aufrufe und für Benutzer sichtbare Logs. Verwenden Sie verborgene
Gedankenketten nicht als operative Überwachungsgrundlage.

## Zuverlässige Fragen entwerfen

- Nehmen Sie die für die Entscheidung erforderlichen Belege und Richtlinien in `state` auf.
- Gestalten Sie Choice-Optionen so, dass sie sich gegenseitig ausschließen. Fügen Sie
  `other` oder `none` hinzu, wenn die aufgeführten Optionen nicht vollständig sind.
- Schreiben Sie Score-Kriterien von der niedrigsten bis zur höchsten Stufe und
  beschreiben Sie jede Stufe eindeutig.
- Verwenden Sie unabhängige Noul-Fragen für Prüfungen mit mehreren Labels.
- Bewerten Sie Wahrscheinlichkeiten und Konfidenz anhand repräsentativer Daten, bevor
  Sie Schwellenwerte für die Automatisierung festlegen.
- Leiten Sie unsichere Ergebnisse oder Ergebnisse mit weitreichenden Folgen an einen
  sichereren Fallback weiter.

<Warning>
  GLiDE arbeitet probabilistisch. Verwenden Sie es nicht als alleinige
  Entscheidungsinstanz für unumkehrbare, sicherheitskritische, rechtliche,
  medizinische, beschäftigungsbezogene, kreditbezogene oder
  zugangskontrollbezogene Entscheidungen.
</Warning>

## Wann GLiDE nicht das richtige Werkzeug ist

| Bedarf | Stattdessen verwenden |
| --- | --- |
| Namen, Textspannen, Entitäten oder Beziehungen aus Text extrahieren | [GLiNER](/de/concepts/gliner) |
| Freitext generieren, zusammenfassen oder umschreiben | Ein generatives Sprachmodell |
| Eine exakte deterministische Regel durchsetzen | Anwendungscode oder eine Richtlinien-Engine |
| Mehrere Labels aus einer Frage zurückgeben | Separate Noul-Fragen, eine pro Label |

Beginnen Sie mit dem [Schnellstart](/de/quickstart) und verwenden Sie anschließend die
[GLiDE-Referenz](/de/concepts/decision-models), um das Fragenschema für Ihre
Produktivumgebung zu definieren.
