Nutzen Sie diese Übersicht, um Bereiche zu finden, in denen eine strukturierte,
probabilistische Entscheidung einen störanfälligen Prompt oder einen manuellen
Prüfschritt ersetzen kann. Öffnen Sie den passendsten Workflow, passen Sie das
Beispiel an Ihre eigenen Richtlinien und Daten an und verwenden Sie anschließend
die [GLiDE-Referenz](/de/concepts/decision-models) für den Anfragevertrag.

Dies sind Entscheidungsmuster, keine integrierten End-to-End-Workflows. Ihre
Anwendung stellt jeweils einen Fall bereit und übernimmt die nachgelagerte Aktion.
Stellen Sie für jede Eigenschaft, die gleichzeitig mit anderen vorliegen kann, eine
eigenständige Frage. Um eine Sammlung zu ordnen, bewerten Sie jedes Element einzeln
und sortieren Sie die Ergebnisse im Anwendungscode.

## KI-Agenten und Automatisierung

<AccordionGroup>
  <Accordion title="Prüfung von Agentenaktionen" icon="key-round">
    - Entscheiden Sie, ob ein vorgeschlagener Tool-Aufruf gemäß der aktuellen Richtlinie zulässig ist.
    - Leiten Sie eine Aktion zur Ausführung, Überarbeitung, Genehmigungsanfrage oder zum Abbruch weiter.
    - Bewerten Sie das Risiko, eine E-Mail zu senden, Daten zu ändern, Geld auszugeben oder Inhalte zu veröffentlichen.
    - Prüfen Sie, ob die sichtbaren Belege die vom Agenten angegebene Begründung für die Aktion stützen.
  </Accordion>
  <Accordion title="Modell- und Workflow-Routing" icon="sparkle">
    - Wählen Sie für jede Anfrage das beste Modell, den besten Agenten, das beste Tool oder den besten Workflow aus.
    - Klassifizieren Sie Absicht, Fachgebiet, Komplexität und Risiko, bevor Sie eine Route auswählen.
    - Entscheiden Sie, ob eine Anfrage einen Spezialisten oder einen leistungsfähigeren Fallback benötigt.
    - Leiten Sie unsichere Fälle an einen Menschen weiter, anstatt einen automatisierten Pfad zu erzwingen.
  </Accordion>
  <Accordion title="Überprüfung von KI-Ausgaben" icon="file-lines">
    - Prüfen Sie, ob eine Antwort die Anweisungen des Benutzers und das erforderliche Format einhält.
    - Bewerten Sie, ob die bereitgestellten Belege eine Behauptung oder Quellenangabe stützen.
    - Prüfen Sie jeden erforderlichen Schritt und erkennen Sie unbelegte Schlussfolgerungen oder Quellenkonflikte.
    - Bewerten Sie eine Ausgabe anhand eines produktspezifischen Qualitätsrasters.
  </Accordion>
  <Accordion title="Kontextauswahl" icon="map">
    - Entscheiden Sie, ob eine Passage relevant genug ist, um sie in das Kontextfenster einer KI aufzunehmen.
    - Bewerten Sie vor der Generierung die Relevanz eines Dokuments für eine Anfrage.
    - Erkennen Sie widersprüchlichen oder veralteten Kontext, der ausgeschlossen werden sollte.
    - Bewerten Sie mögliche Datensätze einzeln und sortieren Sie sie anschließend für den Abruf oder die Prüfung.
  </Accordion>
</AccordionGroup>

## Kunden- und Umsatzprozesse

<AccordionGroup>
  <Accordion title="Kundensupport" icon="circle-help">
    - Leiten Sie Tickets nach Produktbereich, Problemtyp, Kontostufe oder Kundenabsicht weiter.
    - Bewerten Sie Dringlichkeit, Frustration, Abwanderungsrisiko oder betriebliche Auswirkungen.
    - Prüfen Sie anhand einer bereitgestellten Richtlinie, ob Anspruch auf Rückerstattung, Ersatz oder Eskalation besteht.
    - Verifizieren Sie, dass eine vorgeschlagene Supportantwort auf die Anfrage eingeht und die Richtlinie einhält.
  </Accordion>
  <Accordion title="Vertrieb und Lead-Qualifizierung" icon="badge-dollar-sign">
    - Bewerten Sie, ob ein Konto dem idealen Kundenprofil entspricht.
    - Klassifizieren Sie Kaufabsicht, Anwendungsfall, Unternehmensreife oder Vertriebsansatz.
    - Bewerten Sie Eignung, Dringlichkeit und die Wahrscheinlichkeit einer zeitnahen Kontaktaufnahme.
    - Leiten Sie Leads an Self-Service-, Vertriebs-, Partnerschafts- oder Nurturing-Workflows weiter.
  </Accordion>
  <Accordion title="E-Commerce und Marktplätze" icon="table-list">
    - Ordnen Sie Angebote dem richtigen Katalog oder der richtigen Prüfwarteschlange zu.
    - Prüfen Sie, ob ein Angebot gegen Marktplatz- oder Werberichtlinien verstößt.
    - Bewerten Sie Hinweise auf Fälschungen, Bewertungsmissbrauch oder Verkäuferrisiken.
    - Leiten Sie unsichere Angebote an einen Spezialisten weiter, ohne den gesamten Katalog zu blockieren.
  </Accordion>
</AccordionGroup>

## Vertrauen, Sicherheit und Compliance

<AccordionGroup>
  <Accordion title="Inhaltsmoderation" icon="circle-alert">
    - Prüfen Sie anhand einer bereitgestellten Regel, ob Text gegen Vorgaben zu Belästigung, Spam, Betrug oder gefährlichen Ratschlägen verstößt.
    - Klassifizieren Sie die primäre Richtlinienkategorie eines Moderationsfalls.
    - Bewerten Sie den Schweregrad und entscheiden Sie, ob der Inhalt zugelassen, mit einer Warnung versehen, geprüft oder blockiert werden soll.
    - Erkennen Sie Opt-out-Anfragen, die Offenlegung personenbezogener Daten oder regulierte Aussagen.
  </Accordion>
  <Accordion title="Prompt- und Tool-Sicherheit" icon="key-round">
    - Erkennen Sie Prompt Injection, Jailbreak-Versuche oder Anfragen zur Offenlegung privater Daten.
    - Prüfen Sie, ob ein Tool-Aufruf die Autorisierung des Benutzers oder den Aufgabenbereich des Agenten überschreitet.
    - Bewerten Sie das Risiko abgerufener Anweisungen, bevor Sie sie dem Agentenkontext hinzufügen.
    - Leiten Sie verdächtige Aktivitäten an Protokollierung, Isolierung oder eine menschliche Prüfung weiter.
  </Accordion>
  <Accordion title="Rechtliche Prüfung und Richtlinienprüfung" icon="book-open">
    - Prüfen Sie jede erforderliche Bestimmung in einem Vertrag, einer Richtlinie, einer Einreichung oder einer Marketingaussage.
    - Erkennen Sie unzulässige Aussagen, fehlende Offenlegungen oder Richtlinienkonflikte.
    - Klassifizieren Sie Dokumente nach Prüfart, Rechtsraum oder zuständigem Team.
    - Priorisieren Sie unsichere oder risikoreiche Elemente für die Prüfung durch qualifizierte Fachkräfte.
  </Accordion>
  <Accordion title="Finanz- und Versicherungsprozesse" icon="database-zap">
    - Sichten Sie Transaktionsbeschreibungen, Schadensnotizen, KYC-Datensätze oder Vorfallsberichte.
    - Klassifizieren Sie Risikoart, Komplexität eines Schadensfalls oder den Status fehlender Informationen.
    - Bewerten Sie Betrugshinweise, Belegqualität oder Prüfpriorität.
    - Leiten Sie mehrdeutige Fälle an Ermittler, Schadensregulierer oder Compliance-Spezialisten weiter.
  </Accordion>
</AccordionGroup>

## Forschung, Daten und Produkt

<AccordionGroup>
  <Accordion title="Wissenschaftliche und qualitative Forschung" icon="book-open">
    - Prüfen Sie Fachartikel anhand expliziter Ein- und Ausschlusskriterien.
    - Prüfen Sie, ob eine Passage eine Forschungsbehauptung stützt.
    - Prüfen Sie separat auf erforderliche Kontrollen, Datensatzdetails und methodische Informationen.
    - Prüfen Sie jedes vordefinierte Thema anhand von Interview- und Umfragepassagen.
  </Accordion>
  <Accordion title="Produktfeedback und Prognosesignale" icon="gauge">
    - Klassifizieren Sie Feedback nach Produktbereich, Anfragetyp oder Kundensegment.
    - Erkennen Sie Kaufabsicht, Wettbewerbsdruck, Lieferengpässe oder Abwanderungssignale.
    - Bewerten Sie die Stärke der Stimmung, die Dringlichkeit und die wahrscheinlichen geschäftlichen Auswirkungen.
    - Wandeln Sie Wahrscheinlichkeiten in Merkmale für ein Prognose- oder Priorisierungsmodell um.
  </Accordion>
  <Accordion title="Qualität von Wissensgraphen" icon="blocks">
    - Klassifizieren Sie eine vorgeschlagene Beziehung zwischen bekannten Entitäten.
    - Prüfen Sie, ob eine Behauptung einem vorhandenen Datensatz widerspricht.
    - Bewerten Sie die Konfidenz einer möglichen Kante, bevor Sie sie einem Graphen hinzufügen.
    - Leiten Sie mehrdeutige Beziehungen an einen Verifizierungsworkflow weiter.
  </Accordion>
  <Accordion title="Semantische Qualitätsprüfungen" icon="braces">
    - Prüfen Sie generierten Code anhand teamspezifischer Architekturkonventionen.
    - Erkennen Sie, ob in einem Pull Request Tests, Migrationsschritte oder Dokumentation fehlen.
    - Bewerten Sie ein Dokument anhand eines Rasters für Schreibqualität, Barrierefreiheit oder Markenrichtlinien.
    - Führen Sie in CI einfache semantische Prüfungen aus, bevor Sie eine menschliche Prüfung anfordern.
  </Accordion>
</AccordionGroup>

<Warning>
  Verwenden Sie GLiDE zur Entscheidungsunterstützung, nicht als alleinige Instanz
  für unumkehrbare oder folgenreiche Entscheidungen in den Bereichen Sicherheit,
  Rechtsansprüche, Beschäftigung, Kredit, Gesundheitsversorgung oder
  Zugriffskontrolle. Validieren Sie Schwellenwerte anhand repräsentativer Daten und
  sehen Sie einen Pfad für die menschliche Prüfung vor.
</Warning>

GLiDE bewertet den bereitgestellten Kontext; es extrahiert weder Textspannen noch
generiert es Prosa. Verwenden Sie [GLiNER](/de/concepts/gliner) für die Extraktion
von Entitäten und Beziehungen und ein generatives Modell für offene Schreibaufgaben.
