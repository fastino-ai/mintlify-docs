description: "Verstehen Sie Operationen, Checkpoints, Wiederherstellung und Fehler eines interaktiven Fastino-Jobs."
---

Ein SDK-Trainingsclient ist ein interaktiver Fastino-Job. Interaktive
Operationen, Futures, Sampler-Clients und Checkpoints sind verschiedene
Ansichten von Arbeit oder Artefakten dieses Jobs, keine separaten
Trainingsläufe.

## Job identifizieren

Lesen Sie die Job-ID aus dem SDK:

```python
job_id = training_client.get_info().model_data.model_id
```

Derselbe Wert identifiziert die von folgendem Request zurückgegebene Ressource:

```bash
curl --fail-with-body \
  -H "Authorization: Bearer $FASTINO_API_KEY" \
  "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID"
```

Verwenden Sie kanonische Job- und Checkpoint-Routen zur Verwaltung. Verwenden
Sie das SDK für interaktive Modelloperationen; konstruieren Sie niemals
Adapter-HTTP-Requests.

## Futures sind Job-Operationen

SDK-Methoden können Futures für Operationen zurückgeben, die an den
interaktiven Job gesendet wurden. Future result/get löst die entsprechende
Operation auf. Future cancel entspricht dem Abbruch dieser Operation.

Lösen Sie Futures auf, bevor Ihre Anwendung mit einem abhängigen Schritt
fortfährt. Speichern Sie Anwendungsschritt, Datensatz-Cursor und relevante
Operations- oder Checkpoint-IDs dauerhaft, damit ein neu gestarteter Controller
ermitteln kann, was abgeschlossen wurde.

Der Batch-Abruf über `retrieve_futures` wird nicht unterstützt. Verfolgen und
auflösen Sie die einzelnen Futures, die von unterstützten Aufrufen
zurückgegeben werden.

## Checkpoints gehören zum Job

Zwei Checkpoint-Arten dienen verschiedenen Zwecken:

- `save_state(...)` erstellt einen Status-Checkpoint zur Wiederherstellung des Trainings.
- `save_weights_for_sampler(...)` erstellt einen Sampler-Checkpoint für Rollouts oder Evaluierung.

Das Laden des Status entspricht der Checkpoint-Load-Operation auf dem
interaktiven Job. Beim Erstellen oder Abrufen eines Samplers wird ein
Checkpoint aufgelöst; das Sampling wird anschließend auf diesem Checkpoint
ausgeführt.

Kanonische Checkpoint-Routen unterstützen Auflisten, Abrufen, Herunterladen,
Löschen, Veröffentlichen, Aufheben der Veröffentlichung, TTL-Verwaltung und
Verwaltung der Speichernutzung. Die Aufbewahrungsrichtlinie gehört der
Anwendung: Gehen Sie nicht von einer undokumentierten Lebensdauer oder
Speichergarantie aus.

Speichern Sie Checkpoint-IDs mit dem clientseitigen Status, der zum Fortfahren
benötigt wird, darunter Anwendungsschritt, Datensatzrevision, Reward-Revision
und Datensatz-Cursor.

## Authentifizierung

Das SDK erhält einen normalen Fastino-Schlüssel, indem es bei jedem
Token-Request `TINKER_CREDENTIAL_CMD` ausführt. Der Befehl muss nicht leere
Anmeldedaten auf der Standardausgabe ausgeben. Schlüssel beginnen mit
`fast_sk_`; Anmeldedaten, die mit `tml-` beginnen, werden abgelehnt. Setzen Sie
`TINKER_API_KEY` nicht.

## Fehler diagnostizieren

| Symptom | Prüfung |
| --- | --- |
| Authentifizierung schlägt fehl | Prüfen Sie, ob der Anmeldedatenbefehl einen aktuellen `fast_sk_`-Schlüssel und keine zusätzliche Ausgabe ausgibt |
| SDK kann keine Verbindung herstellen | Prüfen Sie, ob `TINKER_BASE_URL` exakt `https://api.fastino.ai/v1/training/compat/tinker` ist |
| Modell oder Operation wird abgelehnt | Fragen Sie die Fähigkeiten erneut ab und vergleichen Sie den Aufruf mit der Kompatibilitätstabelle |
| Future schlägt fehl | Zeichnen Sie Job-ID und Operationsergebnis auf; setzen Sie abhängigen Anwendungsstatus nicht fort |
| Checkpoint kann nicht geladen werden | Prüfen Sie Job, Checkpoint-Art und clientseitige Metadaten zur Fortsetzung |
| Kanonischer Job kann nicht abgerufen werden | Prüfen Sie, ob die ID aus `get_info().model_data.model_id` stammt und dasselbe Fastino-Team authentifiziert ist |

Leiten Sie Unterstützung nicht allein daraus ab, dass eine Methode im
installierten Paket vorhanden ist. Prüfen Sie die
[SDK-Kompatibilität](/de/rl-api/compatibility) und die aktuelle Antwort zu den
Fähigkeiten.
