Prüfen Sie mit dieser Referenz, welche Teile des Tinker-Client-Vertrags von
Fastinos RL API unterstützt werden. Das gepinnte Paket `tinker==0.32.0`
definiert die Methodensignaturen. Diese Seite definiert die
Fastino-spezifischen Unterstützungsgrenzen. Ein hier ausdrücklich als nicht
unterstützt gekennzeichneter Eintrag hat Vorrang vor seiner Verfügbarkeit im
Client-Paket.

## Client-Vertrag

| Element | Wert |
| --- | --- |
| Python-Paket | `tinker` |
| Getestete Version | `0.32.0` |
| Mindestens unterstützte Version | `0.25.0` |
| Basis-URL | `https://api.fastino.ai/tinker` |
| Anmeldedaten | `tml-`, gefolgt von einem Fastino-Schlüssel `fast_sk_...` |
| Teamzugriff | Eingeschränkter Zugang für das authentifizierte Fastino-Team |

Pinnen Sie für diese Vorschau `tinker==0.32.0`.

## Modelle

| Basismodell | Kontextfenster | Maximaler LoRA-Rang |
| --- | ---: | ---: |
| `Qwen/Qwen3.6-35B-A3B` | 32,768 | 32 |
| `nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-BF16` | 32,768 | 32 |
| `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16` | 65,536 | 32 |

Rufen Sie vor der Modellauswahl `get_server_capabilities()` auf. Die Antwort ist
für aktuelle Verfügbarkeit und Kontextfenster maßgeblich.

## Trainingsoperationen

| Fähigkeit | Unterstützung |
| --- | --- |
| Einen LoRA-Trainingsclient erstellen | Unterstützt |
| `forward` | Unterstützt |
| `forward_backward` | Unterstützt |
| `optim_step` | Unterstützt |
| Trainingsstatus speichern oder laden | Unterstützt |
| Einen neuen Client aus gespeichertem Status erstellen | Unterstützt |
| Sampler-Gewichte speichern | Unterstützt |
| Einen Sampling-Client aus Trainingsgewichten erstellen | Unterstützt |
| Einen Lauf entladen oder freigeben | Unterstützt |
| Andere Trainingslayouts als LoRA | Nicht unterstützt |

Die unterstützte Optimizer-Familie ist AdamW über `AdamParams` des SDK.

### Loss-Funktionen

Das Gateway akzeptiert diese integrierten Loss-Namen:

- `cross_entropy`
- `importance_sampling`
- `ppo`
- `cispo`
- `dro`

Die Annahme bestätigt den Client-Vertrag und die Form der Anfrage. Sie
bescheinigt nicht, dass jedes externe Rezept auf jedem Modell ein identisches
numerisches Verhalten aufweist. Qualifizieren Sie Loss-Funktion, Datum-Felder
und Modell gemeinsam mit einem kleinen Testlauf mit zurückgehaltenen Daten,
bevor Sie die Workload vergrößern.

[Mit verifizierbaren Rewards trainieren](/de/rl-api/verifiable-rewards) zeigt
die Datum-Form für `importance_sampling`.

## Sampling-Operationen

| Fähigkeit | Unterstützung |
| --- | --- |
| Aus einem Basismodell sampeln | Unterstützt |
| Aus benannten Sampler-Gewichten sampeln | Unterstützt |
| Aus aktuellen Trainingsgewichten sampeln | Unterstützt |
| Mehrere Samples anfordern | Unterstützt |
| Token-Log-Wahrscheinlichkeiten berechnen | Unterstützt |
| Ein wartendes Sampling-Future abbrechen | Unterstützt |
| Bild- oder multimodale Prompt-Chunks | Nicht unterstützt |
| `target_prompt_logprobs` | Nicht unterstützt |
| `prompt_alt_tokens_k` | Nicht unterstützt |

Aktuelle Modelle akzeptieren codierte Text-Token-Chunks. Sampling benötigt
einen `SamplingClient`.

## Weitere Unterschiede

| Fähigkeit | Verhalten |
| --- | --- |
| Export von Sitzungstraces | Nicht unterstützt |
| Audit-Endpunkt des SDK | Gibt keine Einträge zurück |
| Teamübergreifendes Laden von Checkpoints | Nicht unterstützt |
| OpenAPI-Discovery | RL-Routen fehlen absichtlich |

Verwenden Sie Ihre Anwendungsprotokolle und die Fastino-Projektnutzung für die
betriebliche Zuordnung.

Informationen zu Futures, Checkpoints, Wiederholungsversuchen, Abrechnung,
Limits und Fehlern finden Sie unter
[Laufzeitverhalten und Fehler](/de/rl-api/runtime).
