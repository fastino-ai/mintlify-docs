---
title: "Von Tinker migrieren"
description: "Verschieben Sie einen bestehenden Workload des Tinker SDK zur RL API von Fastino."
---

Die RL API von Fastino implementiert eine dokumentierte Teilmenge des Vertrags
des Tinker SDK. Die Aufrufformen des SDK können unverändert bleiben, wenn alle
Punkte der Kompatibilitätscheckliste erfüllt sind. Bei einer Migration werden
vier Integrationspunkte ersetzt:

1. Endpunkt
2. Anmeldedaten
3. Modellname
4. Betriebliche Annahmen

Verwenden Sie das bestehende Programm als Akzeptanztest. Ändern Sie zuerst die
Verbindung. Führen Sie dann einen kurzen Job aus. Passen Sie den Algorithmus
erst danach an.

## 1. Eine getestete SDK-Version pinnen

Fastino testet den Vertrag derzeit mit:

```text
tinker==0.32.0
```

Der mindestens unterstützte Client ist `0.25.0`. Pinnen Sie während der
Migration `0.32.0`. So verdeckt ein unabhängiges SDK-Upgrade kein Verbindungs-
oder Kompatibilitätsproblem.

<CodeGroup>

```bash uv
uv add "tinker==0.32.0"
```

```bash pip
pip install "tinker==0.32.0"
```

</CodeGroup>

## 2. Endpunkt und Schlüssel ersetzen

Bestehender Code, der `tinker.ServiceClient()` ohne explizite Argumente
erstellt, kann allein über Umgebungsvariablen migriert werden:

```bash
export FASTINO_API_KEY="fast_sk_..."
export TINKER_API_KEY="tml-${FASTINO_API_KEY}"
export TINKER_BASE_URL="https://api.fastino.ai/tinker"
```

Der Teil `tml-` ist ein Kompatibilitätspräfix des Tinker SDK. Fastino
authentifiziert den darin enthaltenen Schlüssel `fast_sk_...`.

Wenn Ihre Anwendung Werte explizit übergibt, nehmen Sie dieselbe Änderung vor:

```python
import os

import tinker


service_client = tinker.ServiceClient(
    base_url="https://api.fastino.ai/tinker",
    api_key=f"tml-{os.environ['FASTINO_API_KEY']}",
)
```

Hängen Sie nicht `/api/v1` an. Das SDK fügt seinen eigenen Routenpfad hinzu.

## 3. Ein von Fastino unterstütztes Modell auswählen

Gehen Sie nicht davon aus, dass ein Modell aus einer anderen Tinker-Umgebung
auch auf Fastino verfügbar ist. Fragen Sie bei der Migration die Fähigkeiten ab:

```python
capabilities = service_client.get_server_capabilities()
for model in capabilities.supported_models:
    print(model.model_name)
```

Verwenden Sie die aktuelle Antwort für Produktionsentscheidungen. Unter
[Client-Kompatibilität](/de/rl-api/compatibility) finden Sie Kontextfenster und
LoRA-Limits.

## 4. Den Lernloop vergleichen

Diese Kernaufrufe behalten ihre Formen aus dem Tinker SDK:

```python
training_client = service_client.create_lora_training_client(
    base_model=model_name,
    rank=32,
)

sampler_path = training_client.save_weights_for_sampler(
    "migration-smoke"
).result().path
sampling_client = service_client.create_sampling_client(
    model_path=sampler_path
)
sample_future = sampling_client.sample(prompt, num_samples, sampling_params)
sample_result = sample_future.result()

train_future = training_client.forward_backward(
    datums,
    loss_fn="importance_sampling",
)
optim_future = training_client.optim_step(adam_params)
train_result = train_future.result()
optim_result = optim_future.result()
```

Die obigen Aufrufformen sind kompatibel. Bevor Sie den umgebenden Loop
wiederverwenden, prüfen Sie, ob dessen Modell, LoRA-Rang, Loss-Name,
Datum-Felder, Sampling-Parameter, Checkpoint-Verhalten und betriebliche
Abhängigkeiten in der
[Kompatibilitätsreferenz](/de/rl-api/compatibility) als unterstützt aufgeführt
sind.

Renderer, Prompt-Erstellung, Reward-Funktionen, Advantage-Berechnungen,
Batching und Abbruchkriterien werden in Ihrer Anwendung ausgeführt. Behalten
Sie sie für den ersten Migrationstest nur dann bei, wenn diese Checkliste
erfüllt ist.

## 5. Einen kleinen Lauf prüfen

Führen Sie vor den Produktions-Batchgrößen einen kostengünstigen Akzeptanzlauf
durch:

- Fähigkeiten abrufen.
- Einen LoRA-Trainingsclient erstellen.
- Eine kleine Gruppe sampeln.
- Eine Forward-Backward-Operation senden.
- Einen Optimierungsschritt ausführen.
- Einen Status-Checkpoint speichern.
- Aus diesem Checkpoint einen neuen Trainingsclient erstellen.
- Den Service-Client schließen.

Vergleichen Sie semantische Ergebnisse, nicht exakte Gleitkommawerte.
Unterschiedliche unterstützte Modelle und Infrastrukturen können andere
Samples und Metriken erzeugen.

## 6. Betriebliche Unterschiede prüfen

| Bereich | Migrationsmaßnahme |
| --- | --- |
| Zugriff | Der RL-API-Zugriff wird pro Fastino-Team aktiviert. Ein nicht aktiviertes Team erhält `404 Not Found`. |
| Authentifizierung | Verwenden Sie einen Fastino-API-Schlüssel mit dem Kompatibilitätspräfix `tml-`. |
| Modelle | Wählen Sie aus der Antwort zu den Fähigkeiten. Behalten Sie kein nicht unterstütztes Quellmodell bei. |
| Sitzungslebenszyklus | Schließen Sie `ServiceClient`, um aktive Läufe freizugeben. |
| Wiederherstellung | Verwenden Sie explizite Checkpoints als anwendungskontrollierte Wiederherstellungsgrenze. |
| Future-Ergebnisse | Lösen Sie abgeschlossene Ergebnisse innerhalb einer Stunde auf und speichern Sie sie dauerhaft. |
| Abbruch | Der Abbruch gilt für Sampling, nicht für einzelne Trainingsoperationen. |
| Veröffentlichte Checkpoints | Durch die Veröffentlichung kann ein anderes Fastino-Team einen Checkpoint nicht laden. |
| Trace-Export | Entfernen Sie Code, der Tinkers Trace-Export benötigt. Er wird nicht unterstützt. |
| Audit-Einträge | Verlassen Sie sich nicht auf den Audit-Verlauf. Audit-Aufrufe geben keine Einträge zurück. |

Unter [Client-Kompatibilität](/de/rl-api/compatibility) finden Sie unterstützte
Loss-Funktionen und Methoden. Unter
[Laufzeitverhalten und Fehler](/de/rl-api/runtime) finden Sie
Wiederholungsversuche, Abrechnung, Checkpoints und Fehler.

## Migrationscheckliste

- [ ] `tinker==0.32.0` pinnen.
- [ ] `TINKER_BASE_URL` auf `https://api.fastino.ai/tinker` setzen.
- [ ] Den Fastino-Schlüssel als `tml-fast_sk_...` verpacken.
- [ ] Bestätigen, dass das Team Zugriff auf die RL API hat.
- [ ] Nicht unterstützte Modellnamen ersetzen.
- [ ] Einen Sampling- und Trainingsschritt ausführen.
- [ ] Einen Status-Checkpoint speichern und wiederherstellen.
- [ ] Abhängigkeiten von nicht unterstützten Trace- oder Audit-Daten entfernen.
- [ ] Den Service-Client schließen.
- [ ] Die Workload-Größe erst nach einem erfolgreichen Akzeptanzlauf erhöhen.
