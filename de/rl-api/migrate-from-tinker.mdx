---
title: "Von Tinker migrieren"
description: "Verschieben Sie einen bestehenden Tinker-SDK- oder Cookbook-Workload zur RL API von Fastino."
---

Die RL API von Fastino implementiert den Vertrag des Tinker SDK. Bei den meisten
Migrationen bleibt der Trainingsloop unverändert; vier Integrationspunkte werden
ersetzt:

1. Endpunkt
2. Anmeldedaten
3. Modellname
4. Betriebliche Annahmen

Dieser Leitfaden behandelt das bestehende Programm als Akzeptanztest. Ändern Sie
zuerst die Verbindung, führen Sie einen kurzen Job aus und optimieren Sie erst
danach den Algorithmus.

## 1. Eine getestete SDK-Version pinnen

Fastino testet den Vertrag derzeit mit:

```text
tinker==0.32.0
```

Der mindestens unterstützte Client ist `0.25.0`. Pinnen Sie während der
Migration `0.32.0`, damit ein unabhängiges SDK-Upgrade ein Verbindungs- oder
Kompatibilitätsproblem nicht verschleiert.

<CodeGroup>

```bash uv
uv add "tinker==0.32.0"
```

```bash pip
pip install "tinker==0.32.0"
```

</CodeGroup>

## 2. Endpunkt und Schlüssel ersetzen

Bestehender Code, der `tinker.ServiceClient()` ohne explizite Argumente
erstellt, kann allein über Umgebungsvariablen migriert werden:

```bash
export FASTINO_API_KEY="fast_sk_..."
export TINKER_API_KEY="tml-${FASTINO_API_KEY}"
export TINKER_BASE_URL="https://api.fastino.ai/tinker"
```

Der Teil `tml-` ist ein vom Tinker SDK verwendetes Kompatibilitätspräfix.
Fastino authentifiziert den darin enthaltenen Schlüssel `fast_sk_...`.

Wenn Ihre Anwendung Werte explizit übergibt, nehmen Sie die entsprechende
Änderung vor:

```python
import os

import tinker


service_client = tinker.ServiceClient(
    base_url="https://api.fastino.ai/tinker",
    api_key=f"tml-{os.environ['FASTINO_API_KEY']}",
)
```

Hängen Sie nicht `/api/v1` an. Das SDK fügt seinen eigenen Routenpfad hinzu.

## 3. Ein von Fastino unterstütztes Modell auswählen

Gehen Sie nicht davon aus, dass ein in einer anderen Tinker-Umgebung verfügbares
Modell auch auf Fastino verfügbar ist. Fragen Sie während der Migration die
Funktionen ab:

```python
capabilities = service_client.get_server_capabilities()
for model in capabilities.supported_models:
    print(model.model_name)
```

Der aktuelle Vertrag umfasst:

| Modell | Kontextfenster | Maximaler LoRA-Rang |
| --- | ---: | ---: |
| `Qwen/Qwen3.6-35B-A3B` | 32,768 tokens | 32 |
| `nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-BF16` | 32,768 tokens | 32 |
| `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16` | 65,536 tokens | 32 |

Verwenden Sie für Produktionsentscheidungen die Live-Funktionsantwort. Diese
Tabelle beschreibt den aktuellen Vertrag für den eingeschränkten Zugang und kann einem neu
bereitgestellten Modell hinterherhinken.

## 4. Den Lernloop beibehalten

Diese Kernaufrufe behalten ihre Formen aus dem Tinker SDK:

```python
training_client = service_client.create_lora_training_client(
    base_model=model_name,
    rank=32,
)

sampling_client = training_client.save_weights_and_get_sampling_client()
sample_future = sampling_client.sample(prompt, num_samples, sampling_params)
sample_result = sample_future.result()

train_future = training_client.forward_backward(
    datums,
    loss_fn="importance_sampling",
)
optim_future = training_client.optim_step(adam_params)
train_result = train_future.result()
optim_result = optim_future.result()
```

Lassen Sie Renderer, Prompt-Erstellung, Reward-Funktion,
Advantage-Berechnung, Batching und Abbruchkriterien für den ersten
Migrationstest unverändert.

## 5. Einen Cookbook-Befehl migrieren

Wenn ein Cookbook-Rezept `base_url` akzeptiert, übergeben Sie den Endpunkt von
Fastino und wählen Sie ein unterstütztes Modell:

```bash
python -m tinker_cookbook.recipes.rl_loop \
  base_url=https://api.fastino.ai/tinker \
  model_name=Qwen/Qwen3.6-35B-A3B \
  max_steps=2 \
  batch_size=4 \
  group_size=4 \
  log_path=./runs/fastino-migration-check
```

Verwenden Sie dasselbe Muster für andere Rezepte, die `base_url` bereitstellen.
Wenn ein Rezept `ServiceClient()` ohne Basis-URL-Argument erstellt, wird diese
durch die Umgebungsvariable `TINKER_BASE_URL` bereitgestellt.

<Warning>
  Ein aktueller Checkout des Upstream-Cookbooks kann Modelle nennen, die
  Fastino nicht bereitstellt. Ändern Sie das Modell auch dann, wenn der Rest des
  Rezepts kompatibel ist.
</Warning>

## 6. Einen kleinen Lauf prüfen

Führen Sie einen kostengünstigen Akzeptanzlauf durch, bevor Sie wieder
Produktions-Batchgrößen verwenden:

- Funktionen abrufen.
- Einen LoRA-Trainingsclient erstellen.
- Eine kleine Gruppe sampeln.
- Eine Forward-Backward-Operation übermitteln.
- Einen Optimierungsschritt anwenden.
- Einen Status-Checkpoint speichern.
- Aus diesem Checkpoint einen neuen Trainingsclient erstellen.
- Den Service-Client schließen.

Vergleichen Sie semantische Ergebnisse, nicht exakte Gleitkommawerte.
Unterschiedliche unterstützte Modelle und Infrastrukturen können
unterschiedliche Samples und Metriken erzeugen.

## 7. Betriebliche Unterschiede prüfen

| Bereich | Migrationsmaßnahme |
| --- | --- |
| Zugriff | Der RL-API-Zugriff wird pro Fastino-Team aktiviert. Ein nicht aktiviertes Team erhält `404 Not Found`. |
| Authentifizierung | Verwenden Sie einen Fastino-API-Schlüssel, der mit dem Kompatibilitätspräfix `tml-` verpackt ist. |
| Modelle | Wählen Sie aus der Funktionsantwort. Behalten Sie kein nicht unterstütztes Quellmodell bei. |
| Abrechnung | Die Nutzung wird dem Fastino-Team und -Projekt der Sitzung in Rechnung gestellt. |
| Sitzungslebenszyklus | Schließen Sie `ServiceClient`, um aktive Läufe freizugeben. |
| Wiederherstellung | Behalten Sie explizite Checkpoints als anwendungskontrollierte Wiederherstellungsgrenze bei. |
| Future-Ergebnisse | Lösen Sie abgeschlossene Ergebnisse innerhalb einer Stunde auf und speichern Sie sie dauerhaft. |
| Abbruch | Der Abbruch gilt für Sampling, nicht für einzelne Trainingsoperationen. |
| Veröffentlichte Checkpoints | Durch die Veröffentlichung kann ein anderes Fastino-Team einen Checkpoint nicht laden. |
| Trace-Export | Entfernen Sie Code, der Tinkers Trace-Export benötigt. Er wird nicht unterstützt. |
| Audit-Einträge | Verlassen Sie sich nicht auf den Audit-Verlauf. Audit-Aufrufe geben keine Einträge zurück. |

Unter [Kompatibilitätsreferenz](/de/rl-api/compatibility) finden Sie
unterstützte Loss-Funktionen, die Checkpoint-Verwaltung und bekannte
Unterschiede.

## Migrationscheckliste

- [ ] `tinker==0.32.0` pinnen.
- [ ] `TINKER_BASE_URL` auf `https://api.fastino.ai/tinker` setzen.
- [ ] Den Fastino-Schlüssel als `tml-fast_sk_...` verpacken.
- [ ] Bestätigen, dass das Team Zugriff auf die RL API hat.
- [ ] Nicht unterstützte Modellnamen ersetzen.
- [ ] Einen Sampling- und Trainingsschritt ausführen.
- [ ] Einen Status-Checkpoint speichern und wiederherstellen.
- [ ] Abhängigkeiten von nicht unterstützten Trace- oder Audit-Daten entfernen.
- [ ] Den Service-Client schließen.
- [ ] Die Workload-Größe erst erhöhen, nachdem der Akzeptanzlauf erfolgreich war.
