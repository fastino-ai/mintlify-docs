In diesem Tutorial verbinden Sie das Tinker SDK mit Fastino, prüfen den Zugriff
Ihres Teams und sampeln ein unterstütztes Modell. Damit testen Sie die Verbindung,
bevor Sie einen Trainingsloop erstellen.

<Warning>
  Die Funktionsprüfung ist schreibgeschützt. Die Sampling-Anfrage ist
  kostenpflichtige Inferenz. Dieser Schnellstart trainiert kein Modell und
  erstellt keinen Checkpoint.
</Warning>

## 1. API-Schlüssel einrichten

1. **Erstellen Sie ein [Fastino](https://agent.fastino.ai/)-Konto**
2. **Rufen Sie Ihren API-Schlüssel** in den [Einstellungen](https://agent.fastino.ai/api-keys) ab

Legen Sie Ihren Schlüssel als Umgebungsvariable fest, damit die folgenden
Beispiele unverändert funktionieren:

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="your_api_key_here"
```

```powershell Windows
$env:FASTINO_API_KEY = "your_api_key_here"
```

</CodeGroup>

Fastino-Schlüssel beginnen mit `fast_sk_`. Für Ihr Team muss außerdem der
Zugriff auf die RL API aktiviert sein. Durch die Installation des Tinker SDK
erhalten Sie keinen Zugriff.

## 2. Python-Umgebung erstellen

Sie benötigen Python 3.11 oder höher.

<CodeGroup>

```bash uv · macOS/Linux
uv init fastino-rl
cd fastino-rl
uv add "tinker==0.32.0"
source .venv/bin/activate
```

```powershell uv · Windows
uv init fastino-rl
cd fastino-rl
uv add "tinker==0.32.0"
.\.venv\Scripts\Activate.ps1
```

```bash pip · macOS/Linux
mkdir fastino-rl && cd fastino-rl
python -m venv .venv
source .venv/bin/activate
pip install "tinker==0.32.0"
```

```powershell pip · Windows
mkdir fastino-rl
cd fastino-rl
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install "tinker==0.32.0"
```

</CodeGroup>

## 3. Tinker-Client konfigurieren

Verweisen Sie das Tinker SDK auf Fastino und leiten Sie die von ihm erwartete
Umgebungsvariable ab:

<CodeGroup>

```bash macOS/Linux
export TINKER_API_KEY="tml-${FASTINO_API_KEY}"
export TINKER_BASE_URL="https://api.fastino.ai/tinker"
```

```powershell Windows
$env:TINKER_API_KEY = "tml-$env:FASTINO_API_KEY"
$env:TINKER_BASE_URL = "https://api.fastino.ai/tinker"
```

</CodeGroup>

Erstellen Sie keinen zweiten Schlüssel. `TINKER_API_KEY` ist der Name der
Umgebungsvariable des Tinker SDK, und `tml-` ist das erwartete
Kompatibilitätspräfix. Ihr Fastino-Schlüssel bleibt der Berechtigungsnachweis,
der die Anfrage authentifiziert. Committen Sie ihn nicht in die
Versionsverwaltung.

## 4. Zugriff prüfen

Erstellen Sie `check_rl_api.py`:

```python
import tinker


TUTORIAL_MODEL = "Qwen/Qwen3.6-35B-A3B"
client = tinker.ServiceClient()
try:
    capabilities = client.get_server_capabilities()
    model_names = {model.model_name for model in capabilities.supported_models}
    if TUTORIAL_MODEL not in model_names:
        available = ", ".join(sorted(model_names)) or "none"
        raise RuntimeError(
            f"{TUTORIAL_MODEL} is not available; available models: {available}. "
            "Stop before billable work and ask Fastino about tutorial-model access."
        )
    print(f"Ready to use {TUTORIAL_MODEL}")
except KeyboardInterrupt:
    client.close("interrupted").result()
    raise
except Exception:
    client.close("errored").result()
    raise
else:
    client.close("success").result()
```

Führen Sie die Datei aus:

```bash
python check_rl_api.py
```

Eine erfolgreiche Antwort bestätigt, dass das unten verwendete Modell derzeit
für Ihr Team verfügbar ist. Verwenden Sie die Funktionsantwort als maßgebliche
Quelle bei der Modellauswahl.

Wenn der Aufruf `404 Not Found` zurückgibt, prüfen Sie, ob die Basis-URL auf
`/tinker` endet. Ist dies der Fall, bitten Sie Fastino, den RL-API-Zugriff für
Ihr Team zu aktivieren.

## 5. Das erste Sample ausführen

Erstellen Sie `sample_rl_api.py`:

```python
import tinker


TUTORIAL_MODEL = "Qwen/Qwen3.6-35B-A3B"
service_client = tinker.ServiceClient()
try:
    sampling_client = service_client.create_sampling_client(
        base_model=TUTORIAL_MODEL
    )
    tokenizer = sampling_client.get_tokenizer()
    prompt_tokens = tokenizer.apply_chat_template(
        conversation=[
            {"role": "user", "content": "Explain what a reward function does in RL."}
        ],
        add_generation_prompt=True,
        return_dict=False,
    )
    result = sampling_client.sample(
        prompt=tinker.types.ModelInput.from_ints(prompt_tokens),
        num_samples=1,
        sampling_params=tinker.types.SamplingParams(
            max_tokens=128,
            temperature=0.7,
        ),
    ).result()
    print(tokenizer.decode(result.sequences[0].tokens))
except KeyboardInterrupt:
    service_client.close("interrupted").result()
    raise
except Exception:
    service_client.close("errored").result()
    raise
else:
    service_client.close("success").result()
```

Führen Sie die Datei aus:

```bash
python sample_rl_api.py
```

Ein erfolgreicher Lauf gibt eine Modellantwort aus. Ihre Anwendung hat einen
Text-Prompt über das SDK gesendet, Fastino hat die Inferenz ausgeführt und der
Client hat die zurückgegebenen Tokens decodiert.

<Note>
  `Qwen/Qwen3.6-35B-A3B` wird hier verwendet, weil es vom aktuellen
  RL-API-Vertrag unterstützt wird. Übernehmen Sie keinen Modellnamen aus einer
  anderen Tinker-Umgebung, ohne zuvor die Funktionsantwort zu prüfen.
</Note>

## 6. Clients im eigenen Code schließen

Das Beispiel schließt seinen `ServiceClient` bei Erfolg, Unterbrechung und
Fehler. Verwenden Sie dasselbe Muster in langlebigen Anwendungen.

Durch das Schließen des Clients wird seine Sitzung beendet und aktive
Trainingsläufe werden freigegeben. Gespeicherte Checkpoints bleiben gemäß ihren
Aufbewahrungseinstellungen verfügbar.

Verwenden Sie `success` nur nach einem abgeschlossenen Lauf. Schließen Sie mit
`errored`, wenn eine Ausnahme weitergegeben wird, und mit `interrupted` nach
einem Abbruch oder Herunterfahren.
