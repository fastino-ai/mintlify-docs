Fastino bietet zwei synchrone Inferenzschnittstellen. Wählen Sie die Schnittstelle, die zu Ihren
Anforderungen passt:

| Funktion | [`/v1/chat/completions`](/de/inference/chat-completions) | [`/v1/systemone`](/de/inference/systemone) |
| --- | --- | --- |
| Modell | Wählen Sie ein inferenzfähiges Basismodell oder die UUID eines abgeschlossenen Trainingsjobs | Verwendet immer `fastino/glide` |
| Anfrage | OpenAI-kompatible `model` und `messages` sowie Fastinos `schema` auf oberster Ebene | Nativer `state` sowie eine oder mehrere typisierte `questions` |
| Antwort | OpenAI-Chat-Completion-Umschlag; parsen Sie `choices[0].message.content` als JSON | Nativer `{ "answers": ..., "usage": ... }`-Body |
| Batch-Eingabe | Eine Konversation pro Anfrage | Ein `state` pro Anfrage, wobei mehrere `questions` gemeinsam ausgewertet werden |
| Geeignet für | Extraktion, Klassifikation, strukturierte Extraktion und Relationen, mit Basis- und feinabgestimmten Modellen | Klassifikations-, Routing- und Bewertungsentscheidungen mit kalibrierten Wahrscheinlichkeiten |

<Tip>
  Verwenden Sie [`/v1/chat/completions`](/de/inference/chat-completions) für Extraktion, Klassifikation,
  strukturierte Extraktion oder Relationen. Verwenden Sie [`/v1/systemone`](/de/inference/systemone) für
  strukturierte Entscheidungen – Klassifikation, Routing, Bewertung – statt für Extraktion.
</Tip>

Diese Seite behandelt, was beiden Schnittstellen gemeinsam ist. Den GLiNER-Anfrage-/Antwort-Vertrag
und Hinweise zur Migration veralteter Anfragen finden Sie unter
[`/v1/chat/completions`](/de/inference/chat-completions), den HTTP-Vertrag für GLiDE unter
[`/v1/systemone`](/de/inference/systemone) – die vollständigen Anfrage- und Antwortformen für
Noul/Choice/Score sind unter [Entscheidungsmodelle](/de/concepts/decision-models) dokumentiert.
SDK-Nutzung, Modelltraining, Evaluation, Inferenz-Historie und Feedback liegen außerhalb des
Umfangs dieser Seite.

## Authentifizierung

Senden Sie bei jeder Anfrage einen Fastino-API-Schlüssel, unabhängig von der Schnittstelle:

```bash
export FASTINO_API_KEY="fast_sk_..."
```

```http
Authorization: Bearer $FASTINO_API_KEY
Content-Type: application/json
```

## Kaltstarts und Wiederholungsversuche

Ein inaktives oder neu bereitgestelltes Modell kann bei beiden Schnittstellen einen Kaltstart
durchführen. Verwenden Sie ein Lese-Timeout von mindestens 300 Sekunden und wiederholen Sie
Antworten mit den Statuscodes `425`, `429` und `503`. Beachten Sie den Antwort-Header
`Retry-After`, sofern vorhanden.

Eine Anfrage, die in einen Timeout gelaufen ist, kann die Bereitstellung dennoch aufwärmen,
sodass die nächste Anfrage erfolgreich sein kann. Wiederholen Sie Fehler bei Authentifizierung,
Abrechnung, Validierung oder unbekanntem Modell nicht, ohne das zugrunde liegende Problem zu
beheben.

```bash
curl --max-time 300 -X POST "https://api.fastino.ai/v1/chat/completions" \
  -H "Authorization: Bearer $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d @request.json
```

Dasselbe Timeout- und Wiederholungsmuster gilt für `/v1/systemone`.
