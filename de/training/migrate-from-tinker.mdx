---
title: "Von Tinker migrieren"
description: "Migrieren Sie einen kompatiblen Workload des Tinker SDK zu interaktiven Fastino-Trainingsjobs."
---

Die Training API unterstützt das unveränderte Python-SDK `tinker==0.32.0` für
die unten aufgeführten Operationen. Ändern Sie nur die Basis-URL und die
Anmeldedaten. Ein migrierter Trainingsclient ist ein Fastino-Job in
`/v1/training/jobs`; seine SDK-Modell-ID und seine kanonische Fastino-Job-ID
sind identisch.

Behandeln Sie Ihr bestehendes Programm als Akzeptanztest. Ändern Sie die
Verbindung, prüfen Sie jede Operation und führen Sie einen kleinen Smoke-Test
aus, bevor Sie die Produktionsgröße wiederherstellen.

## 1. Getestetes Paket pinnen

<CodeGroup>

```bash uv
uv add "tinker==0.32.0"
```

```bash pip
pip install "tinker==0.32.0"
```

</CodeGroup>

## 2. Endpunkt und Authentifizierung ersetzen

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="fast_sk_..."
export TINKER_BASE_URL="https://api.fastino.ai/v1/training/compat/tinker"
export TINKER_CREDENTIAL_CMD='printf "%s\n" "$FASTINO_API_KEY"'
```

```powershell Windows
$env:FASTINO_API_KEY = "fast_sk_..."
$env:TINKER_BASE_URL = "https://api.fastino.ai/v1/training/compat/tinker"
$env:TINKER_CREDENTIAL_CMD = 'powershell -NoProfile -Command "[Console]::Out.WriteLine($env:FASTINO_API_KEY)"'
```

</CodeGroup>

`TINKER_CREDENTIAL_CMD` wird bei jedem Token-Request ausgeführt und muss
nicht leere Anmeldedaten ausgeben. Verwenden Sie einen normalen Fastino-
`fast_sk_`-Schlüssel; Anmeldedaten mit `tml-` werden abgelehnt. Setzen Sie
`TINKER_API_KEY` nicht.

## 3. Workload prüfen

1. Fragen Sie `ServiceClient.get_server_capabilities()` ab und wählen Sie ein
   verfügbares Basismodell. Behalten Sie den SDK-Parameternamen `base_model` bei.
2. Vergleichen Sie jede Methode in Ihrem Code mit dem
   [unterstützten Client-Verhalten](#supported-client-behavior).
3. Entfernen Sie Abhängigkeiten von nicht unterstütztem Batch-Abruf von
   Futures, externem Gewichtsexport oder externen Gewichts-URLs.
4. Behalten Sie Prompt-Rendering, Reward-Logik, Batching, Evaluierung und
   Abbruchkriterien in Ihrer Anwendung.

Capabilities listen nur aktivierte Modelle und deren Kontextlängen auf. Sie
enthalten keine LoRA-Ränge, Optimizer, Losses, optionalen Methoden oder
Operationslimits. Fastino akzeptiert derzeit LoRA-Ränge von 1 bis 32, verwendet
bei der Client-Erstellung `adamw` und unterstützt `cross_entropy`,
`importance_sampling`, `ppo`, `cispo` und `dro`. Der aktive Dienst validiert
diese Einstellungen beim Senden.

## 4. Smoke-Test ausführen

Verwenden Sie die kleinsten gültigen Datums und Optimierer-Einstellungen aus
Ihrem bestehenden Workload für einen kostengünstigen Test, der:

- einen Client mit `create_lora_training_client(base_model=...)` erstellt,
- `training_client.get_info().model_id` liest,
- Sampler-Gewichte speichert und einmal sampelt,
- eine unterstützte Forward-/Backward-Operation und einen Optimierungsschritt ausführt,
- einen Status-Checkpoint speichert und erneut lädt,
- die ID jedes Clients über `GET /v1/training/jobs/{job_id}` abruft; eine
  Factory-Wiederaufnahme erstellt eine neue Job-ID aus dem Quell-Checkpoint.

Greifen Sie für interaktive Operationen über das unterstützte Tinker-SDK auf
die Training API zu. Die HTTP-Schnittstelle des SDK fehlt absichtlich in
Fastinos OpenAPI und API-Referenz; konstruieren Sie keine entsprechenden
HTTP-Aufrufe.

## Unterstütztes Client-Verhalten

Die Training API unterstützt die folgenden Aufrufe aus `tinker==0.32.0` für
einen interaktiven Fastino-Job.

### Training und Sampling

| SDK-Methode oder -Operation | Fastino-Verhalten |
| --- | --- |
| `create_lora_training_client` | Erstellt einen interaktiven Job |
| `copy_weights` | Startet einen interaktiven Job aus einem Checkpoint |
| `TrainingClient.get_info` | Gibt den interaktiven Job zurück |
| `forward` | Führt eine reine Forward-Operation aus |
| `forward_backward` | Führt eine Forward- und Backward-Operation aus |
| Benutzerdefinierte Forward-/Backward-Operation | Führt eine unterstützte Custom-Loss-Operation aus |
| `optim_step` | Wendet ein Optimizer-Update an |
| `save_state` | Speichert den Trainingsstatus |
| `save_weights_for_sampler` | Speichert Sampler-Gewichte |
| Trainingsstatus laden | Stellt einen Status-Checkpoint wieder her |
| Sampling-Client erstellen oder abrufen | Löst Sampler-Gewichte auf |
| `SamplingClient.sample` | Sampelt über den ausgewählten Checkpoint |

Behalten Sie den SDK-Parameter `base_model` unverändert bei. Wählen Sie das
Modell über Capabilities; verwenden Sie für Rang und Loss die dokumentierten
Grenzen und behandeln Sie Validierungsfehler des aktiven Dienstes.

### Futures und Verwaltung

| SDK-Methode oder -Operation | Fastino-Verhalten |
| --- | --- |
| Future result/get | Ruft ein asynchrones Ergebnis ab |
| Future cancel | Bricht nur ein unvollendetes Sampling-Future von `sample` ab. Futures von Trainingsoperationen werden nicht abgebrochen |
| `list_training_runs` oder `get_training_run` | Liest nur interaktive Läufe. `/v1/training/jobs` liest Config- und Interactive-Jobs |
| `list_checkpoints` oder `list_user_checkpoints` | Liest Checkpoints, die zum Job oder zum Team gehören |
| `get_weights_info_by_tinker_path` | Liest die Gewichtsmetadaten eines Checkpoints, einschließlich des LoRA-Rangs |
| `get_checkpoint_archive_url` | Gibt einen signierten Archivlink für einen interaktiven Checkpoint zurück. Erfordert die Berechtigung zum Herunterladen von Gewichten |
| `delete_checkpoint_from_tinker_path` | Löscht einen Checkpoint |
| `publish_checkpoint_from_tinker_path` oder `unpublish_checkpoint_from_tinker_path` | Ändert die Veröffentlichung innerhalb des besitzenden Teams. Ein anderes Team kann den Pfad dadurch nicht laden |
| `set_checkpoint_ttl_from_tinker_path` | Setzt die Aufbewahrung des Checkpoints oder hebt sie auf |
| `get_current_checkpoint_storage_usage` | Liest die aktuelle Checkpoint-Speichernutzung, optional für ein Projekt |
| `get_billing_usage` | Liest stündliche Nutzungsereignisse für ein an der Stunde ausgerichtetes Fenster |

Beide Checkpoint-Downloadpfade erfordern die Berechtigung des Teams zum Herunterladen von Gewichten. Ein Pfad ist die SDK-Methode `get_checkpoint_archive_url`. Der andere ist die öffentliche Route [`GET /v1/training/jobs/{job_id}/checkpoints/{checkpoint_id}/download`](/de/api-reference/training-jobs/download-checkpoint). Ohne diese Berechtigung geben beide `403` mit `For downloading models, please contact sales@fastino.ai` zurück. Das SDK übernimmt den Tokenaustausch automatisch mit dem Schlüssel, den `TINKER_CREDENTIAL_CMD` ausgibt. Konstruieren Sie keine entsprechenden HTTP-Requests.

### Nicht unterstützte Aufrufe

Fastino unterstützt Folgendes nicht:

- Batch-Abruf von Futures über `retrieve_futures`
- `save_weights_external`
- `external_weights_urls`
- Export von Session-Traces
- Audit-Log-Einträge
- Sampling ohne `SamplingClient` und dessen Sampling-Session
- `target_prompt_logprobs` oder ein positives `prompt_alt_tokens_k`
- Andere Prompt-Chunks als `encoded_text`
- Andere Optimizer als AdamW
- LoRA-Ränge außerhalb von 1 bis 32

Diese Einschränkungen gelten für normale Fastino-API-Schlüssel. Ein
Sandbox-Run-Key hat einen engeren Schreibumfang: Er kann außerdem keine
Checkpoints löschen, veröffentlichen oder deren TTL ändern und kein Projekt einer
Session neu zuweisen. Die entsprechenden
Operationen bleiben mit normalen API-Schlüsseln unterstützt.

Leiten Sie Unterstützung nicht allein daraus ab, dass eine Methode im
installierten Paket vorhanden ist. Die Tabelle definiert Fastinos SDK-Teilmenge;
Capabilities melden nur aktivierte Modelle und Kontextlängen.

## Verbindungsprobleme beheben

| Symptom | Prüfung |
| --- | --- |
| Authentifizierung schlägt fehl | Prüfen Sie, ob `TINKER_CREDENTIAL_CMD` genau einen aktuellen `fast_sk_`-Schlüssel und keine zusätzliche Ausgabe ausgibt |
| Der Client kann keine Verbindung herstellen | Prüfen Sie, ob `TINKER_BASE_URL` exakt `https://api.fastino.ai/v1/training/compat/tinker` ist |
| Ein SDK-Aufruf oder Checkpoint-Download liefert `403` mit einer Meldung zur Löschung von Teamdaten | Die Löschung des Teams läuft. Wiederholen Sie den Vorgang nicht; wenden Sie sich bei einer unerwarteten Löschung an den Kontoadministrator oder Fastino-Support |
| Ein Checkpoint-Download liefert `403` und fordert auf, den Vertrieb zu kontaktieren | Dem Team fehlt die Berechtigung zum Herunterladen von Gewichten. Wenden Sie sich an sales@fastino.ai |
| Ein Modell wird abgelehnt | Fragen Sie Capabilities erneut ab und wählen Sie ein aktiviertes Modell |
| Rang, Loss oder Operation wird abgelehnt | Vergleichen Sie den Aufruf mit den dokumentierten Grenzen und der Unterstützungstabelle |
| Kanonischer Job kann nicht abgerufen werden | Prüfen Sie, ob die ID aus `get_info().model_id` stammt und dasselbe Fastino-Team authentifiziert ist |

## Migrationscheckliste

- [ ] `tinker==0.32.0` pinnen.
- [ ] Die Training-API-Basis-URL für das Tinker-SDK festlegen.
- [ ] Einen `fast_sk_`-Schlüssel über `TINKER_CREDENTIAL_CMD` bereitstellen.
- [ ] Jede SDK-Methode anhand des unterstützten Client-Verhaltens prüfen.
- [ ] Ein aktiviertes Modell aus den Capabilities auswählen und Rang, Loss und
      Operationen anhand dieses Leitfadens validieren.
- [ ] Ein Sampling- und Trainingsupdate abschließen.
- [ ] Einen Status-Checkpoint speichern und erneut laden.
- [ ] Die SDK-Modell-ID über den kanonischen Job-Endpunkt prüfen.
- [ ] Die Workload-Größe erst erhöhen, nachdem der Smoke-Test erfolgreich war.
