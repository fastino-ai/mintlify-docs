Dieser Schnellstart behandelt beide Wege der Training API. Verwenden Sie
verwaltetes Training, um einen GLiNER-Encoder feinabzustimmen, während Fastino
den Loop ausführt. Verwenden Sie einen benutzerdefinierten Trainingsloop, um ein
Decoder-LLM zu trainieren, wenn Ihre Anwendung Sampling, Rewards und
Modellupdates steuern muss.

## 1. Authentifizieren

1. Erstellen Sie ein [Fastino-Konto](https://agent.fastino.ai/).
2. Öffnen Sie [API-Schlüssel](https://agent.fastino.ai/api-keys).
3. Erstellen Sie einen Schlüssel und kopieren Sie ihn, sobald er angezeigt wird.

Speichern Sie den Schlüssel in einer Umgebungsvariable:

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="fast_sk_..."
```

```powershell Windows
$env:FASTINO_API_KEY = "fast_sk_..."
```

</CodeGroup>

Senden Sie diesen Schlüssel als `X-API-Key: $FASTINO_API_KEY`. Den vollständigen
Authentifizierungsvertrag finden Sie unter
[Authentifizierung](/de/authentication).

## 2. Weg auswählen

| Ziel | Weg |
| --- | --- |
| Einen GLiNER-Encoder aus einem Dataset feinabstimmen und Fastino das Training ausführen lassen | [Verwaltetes Training](#managed-training) |
| Ein Decoder-LLM trainieren und Sampling, Rewards und Updates in Ihrer Anwendung steuern | [Benutzerdefinierter Trainingsloop](#custom-training-loop) |

## Verwaltetes Training

### 3. Datensatz vorbereiten

[Laden Sie einen Trainingsdatensatz hoch und verarbeiten Sie ihn](/de/concepts/datasets).
Warten Sie anschließend, bis seine Version den Status `ready` hat.

### 4. Modell auswählen

Verwaltetes Training unterstützt `fastino/gliner2-multi-v1` und
`fastino/GLiNER-2.5-Decide`. Fragen Sie vor der Übermittlung den Live-Katalog ab:

```bash
curl "https://api.fastino.ai/v1/base-models?supports_training=true" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

Speichern Sie die ID des ausgewählten Modells.

### 5. Job erstellen

```bash
curl -X POST "https://api.fastino.ai/v1/training/jobs" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "model_name": "my-trained-model",
    "base_model": "MODEL_ID_FROM_CATALOG",
    "datasets": [
      {"name": "my-ready-dataset", "version": "VERSION_NUMBER"}
    ],
    "training_type": "lora"
  }'
```

Speichern Sie die zurückgegebene `id`. Sie ist die `job_id`, die von jeder
jobspezifischen Route verwendet wird. Verwenden Sie denselben
`Idempotency-Key` nur dann erneut, wenn Sie exakt diesen Erstellungsrequest
wiederholen.

### 6. Job abfragen

```bash
curl "https://api.fastino.ai/v1/training/jobs/JOB_ID" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

Für Config-Jobs gilt:

- `status` ist der gespeicherte Lebenszykluswert, beispielsweise `errored`.
- `normalized_status` ist der stabile Polling-Wert, beispielsweise `failed`.
- `is_terminal_status` zeigt Ihrem Client an, wann er das Polling beenden soll.
- `error_message` beschreibt einen Fehler, sofern verfügbar.

Fragen Sie den Job weiter ab, bis `is_terminal_status` den Wert `true` hat.
Prüfen Sie anschließend den endgültigen Status, die Checkpoints, Logs und die
Eignung für die Bereitstellung.

## Benutzerdefinierter Trainingsloop

Wählen Sie eine unterstützte Schnittstelle:

- Native JSON-Clients rufen
  [`POST /v1/training/jobs/create-model`](/de/api-reference/training-jobs/interactive/create-model)
  auf, reihen Modelloperationen unter `/v1/training/jobs/{job_id}` ein und fragen
  jede zurückgegebene `future_id` ab, bis sie `completed`, `failed` oder
  `cancelled` ist.
- Bestehende Tinker-Programme behalten `tinker==0.32.0` und verwenden die
  folgende Einrichtung.

Native Clients senden weder `seq_id` noch Heartbeats. Der Server weist die
Operationsreihenfolge zu und hält die interne Sitzung aktiv. Ein Request mit
`wait=true` wartet höchstens 25 Sekunden. Der Client muss eine nicht
abgeschlossene Operation daher weiter abfragen. Die native Routenfolge finden
Sie unter [Benutzerdefinierten Trainingsloop erstellen](/de/training/training-loop).

### Nativer JSON-Weg

1. Rufen Sie
   [`POST /v1/training/jobs/create-model`](/de/api-reference/training-jobs/interactive/create-model)
   mit `base_model` oder mit `from_checkpoint` und `load_optimizer` auf.
2. Fragen Sie die zurückgegebene Erstell-`future_id` über
   [Future abrufen](/de/api-reference/training-jobs/interactive/get-future)
   ab, bis sie `completed`, `failed` oder `cancelled` ist.
3. Reihen Sie
   [forward-backward](/de/api-reference/training-jobs/interactive/forward-backward)
   und [einen Optimizer-Schritt](/de/api-reference/training-jobs/interactive/optim-step)
   ein. Fragen Sie jede `future_id` bis zu einem Endstatus ab, bevor Sie den
   nächsten abhängigen Schritt starten.
4. [Speichern Sie Sampler-Gewichte](/de/api-reference/training-jobs/interactive/save-sampler-weights)
   und fragen Sie die Speicher-Future bis zu einem Endstatus ab.
5. Stoppen Sie den Job über den gemeinsamen
   [Stopp-Vorgang](/de/api-reference/training-jobs/stop).
6. [Sampeln Sie nach dem Stopp aus dem gespeicherten Checkpoint](/de/api-reference/training-jobs/interactive/sample)
   und fragen Sie die Sampling-Operation bis zu einem Endstatus ab.

Nur eine eingereihte oder laufende Sample-Future kann abgebrochen werden.
Eine HTTP-Ablehnung bedeutet, dass der Server die Operation nicht eingereiht
hat. Eine eingereihte Operation kann stattdessen mit `status: "failed"` enden.

### Tinker-SDK-Weg

Der Tinker-Weg erfordert Python 3.11 oder neuer. Konstruieren Sie keine privaten
Kompatibilitäts-Unterpfade.

### 3. Client-Bibliotheken installieren

Sie benötigen Python 3.10 oder neuer. `transformers` liefert den Tokenizer des
Modells; das Training selbst läuft auf Fastino.

<CodeGroup>

```bash uv
uv init fastino-training
cd fastino-training
uv add "tinker==0.32.0"
```

```bash pip
mkdir fastino-training && cd fastino-training
python -m venv .venv
source .venv/bin/activate
pip install "tinker==0.32.0"
```

```powershell pip · Windows
mkdir fastino-training
cd fastino-training
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install "tinker==0.32.0"
```

</CodeGroup>

### 4. Modell auswählen

| Modell-ID | Kontextlänge (Token) |
| --- | --- |
| `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16` | 65,536 |
| `nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-BF16` | 32,768 |
| `Qwen/Qwen3.6-35B-A3B` | 32,768 |

LoRA-Ränge von 1 bis 32 werden unterstützt; der Standard ist 32.

<CodeGroup>

```bash macOS/Linux
export FASTINO_TRAINING_MODEL="Qwen/Qwen3.6-35B-A3B"
```

```powershell Windows
$env:FASTINO_TRAINING_MODEL = "Qwen/Qwen3.6-35B-A3B"
```

</CodeGroup>

### 5. Job erstellen

```bash
curl -X POST "https://api.fastino.ai/v1/training/jobs/create-model" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"base_model": "Qwen/Qwen3.6-35B-A3B", "lora_config": {"rank": 32}}'
```

Die Antwort enthält eine `job_id` und die `future_id` des `create`-Futures
des Jobs:

```json
{
  "job_id": "SESSION_ID:train:0",
  "type": "interactive",
  "base_model": "Qwen/Qwen3.6-35B-A3B",
  "future_id": "FUTURE_ID",
  "load_future_id": null
}
```

Jeder Aufruf, der Arbeit ausführt, gibt ein Future zurück. Lesen Sie es,
bis `status` `completed` ist. Mit `wait=true` wartet die Anfrage bis zu
25 Sekunden:

```bash
curl "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/futures/$FUTURE_ID?wait=true" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

### 6. Trainieren, speichern und samplen

Das folgende Skript führt den ganzen Loop aus: Es erstellt einen Job, führt drei
Forward-Backward-Durchläufe und Optimiererschritte aus, speichert einen
Sampler-Checkpoint, sampelt daraus und stoppt den Job.

Erstellen Sie `quickstart.py`:

```python
import os

import requests
from transformers import AutoTokenizer

API = "https://api.fastino.ai"
MODEL = os.environ["FASTINO_TRAINING_MODEL"]

session = requests.Session()
session.headers["X-API-Key"] = os.environ["FASTINO_API_KEY"]


def call(method, path, body=None):
    response = session.request(method, API + path, json=body, timeout=60)
    response.raise_for_status()
    return response.json() if response.content else None


def wait(job_id, future_id):
    path = f"/v1/training/jobs/{job_id}/futures/{future_id}?wait=true"
    while True:
        future = call("GET", path)
        if future["status"] == "completed":
            return future["result"]
        if future["status"] in ("failed", "cancelled"):
            raise RuntimeError(future["error"])


def datum(prompt_tokens, completion_tokens):
    tokens = prompt_tokens + completion_tokens
    weights = [0.0] * (len(prompt_tokens) - 1) + [1.0] * len(completion_tokens)
    return {
        "model_input": {"chunks": [{"type": "encoded_text", "tokens": tokens[:-1]}]},
        "loss_fn_inputs": {
            "target_tokens": {"data": tokens[1:], "dtype": "int64"},
            "weights": {"data": weights, "dtype": "float32"},
        },
    }


tokenizer = AutoTokenizer.from_pretrained(MODEL)
prompt = tokenizer.apply_chat_template(
    [{"role": "user", "content": "What is the capital of France?"}],
    add_generation_prompt=True,
    return_dict=False,
)
completion = tokenizer.encode("Paris.", add_special_tokens=False)
completion.append(tokenizer.eos_token_id)
batch = {"datums": [datum(prompt, completion)], "loss_fn": "cross_entropy"}

created = call(
    "POST",
    "/v1/training/jobs/create-model",
    {"base_model": MODEL, "lora_config": {"rank": 32}},
)
job_id = created["job_id"]
jobs = f"/v1/training/jobs/{job_id}"
print(f"TRAINING_JOB_ID={job_id}")

try:
    wait(job_id, created["future_id"])

    for step in range(3):
        backward = call("POST", f"{jobs}/forward-backward", batch)
        update = call(
            "POST",
            f"{jobs}/optim-step",
            {"adam_params": {"learning_rate": 1e-4}},
        )
        result = wait(job_id, backward["future_id"])
        wait(job_id, update["future_id"])
        print(f"step {step}: loss {result['metrics']['loss:sum']:.4f}")

    saved = call(
        "POST",
        f"{jobs}/save-weights-for-sampler",
        {"name": "quickstart", "ttl_seconds": 24 * 60 * 60},
    )
    wait(job_id, saved["future_id"])

    sample = call(
        "POST",
        f"{jobs}/sample",
        {
            "checkpoint": "quickstart",
            "prompt_tokens": prompt,
            "sampling_params": {"max_tokens": 32},
        },
    )
    sequence = wait(job_id, sample["future_id"])["sequences"][0]
    print(tokenizer.decode(sequence["tokens"]))
finally:
    call("POST", f"{jobs}/stop")
```

Der Optimiererschritt wird direkt nach dem Forward-Backward-Durchlauf
eingereiht, ohne zu warten. Der Job führt Operationen in der Reihenfolge des
Eingangs aus.

Führen Sie das Skript aus:

```bash
python quickstart.py
```

Kopieren Sie den Wert nach `TRAINING_JOB_ID=`.

<Note>
  Ein interaktiver Job ohne Aufrufe für 30 Minuten wird freigegeben. Seine
  Checkpoints bleiben erhalten. Das Stoppen antwortet sofort und verhindert neue
  Aufrufe, aber bereits eingereihte Operationen können abgeschlossen werden,
  bevor Ressourcen freigegeben werden. Sie können seine Sampler-Checkpoints
  weiterhin samplen und herunterladen.
</Note>

### 7. Kanonischen Job prüfen

<CodeGroup>

```bash macOS/Linux
export TRAINING_JOB_ID="<ID printed by quickstart.py>"
curl --fail-with-body \
  -H "X-API-Key: $FASTINO_API_KEY" \
  "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID"
```

```powershell Windows
$env:TRAINING_JOB_ID = "<ID printed by quickstart.py>"
Invoke-RestMethod `
  -Headers @{ "X-API-Key" = "$env:FASTINO_API_KEY" } `
  -Uri "https://api.fastino.ai/v1/training/jobs/$env:TRAINING_JOB_ID"
```

</CodeGroup>

Die Antwort beschreibt denselben Job, der von
`create_lora_training_client(...)` erstellt wurde. Verwenden Sie weiterhin den
SDK-Client für Modelloperationen und die kanonische Jobs-API für dokumentierte
Job-Lesezugriffe. Native JSON-Clients verwenden die öffentlichen Seiten für
interaktive Operationen.
