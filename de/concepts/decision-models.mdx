Ein **Entscheidungsmodell** bewertet Text oder strukturierten Anwendungszustand anhand von Ergebnissen, die der Aufrufer definiert, und gibt strukturierte Entscheidungen – Labels, Wahrscheinlichkeiten, Scores und Konfidenz – statt generierter Prosa zurück.

Verwenden Sie Entscheidungsmodelle, wenn Anwendungscode eine Eingabe klassifizieren, eine Route auswählen, anhand einer Rubrik bewerten, Inhalte moderieren oder entscheiden muss, ob eine Aktion ausgeführt werden soll.

## Entscheidungsmodelle vs. generative Modelle

|  | Entscheidungsmodell | Generatives Modell |
| --- | --- | --- |
| Am besten für | Klassifizierung, Routing, Bewertung, Moderation und Gates | Offene Generierung, Konversation, Zusammenfassung und Programmierung |
| Ausgabe | Strukturierte Antworten über vom Aufrufer definierte Ergebnisse | Generierter Text oder Tool-Aufrufe |
| Unsicherheit | Explizite Wahrscheinlichkeiten und Konfidenz | Erfordert in der Regel zusätzliche Kalibrierung oder Validierung |
| Anwendungsmuster | Auf Basis eines begrenzten Ergebnisses handeln, weiterleiten oder eskalieren | Inhalte generieren, erklären, planen oder transformieren |

Die beiden Modelltypen können zusammenarbeiten. Ein Entscheidungsmodell kann eine Anfrage klassifizieren, einen Agenten oder ein Modell auswählen oder eine Aktion freigeben, bevor ein generatives Modell ein offenes Ergebnis erzeugt.

## Warum ein Entscheidungsmodell verwenden

- **Strukturiert per Definition** – nachgelagerter Code erhält eine begrenzte Antwort statt Prosa, die geparst werden muss.
- **Vom Aufrufer definierte Ergebnisse** – Ihre Anwendung kontrolliert die zulässigen Labels, Routen oder Stufen.
- **Explizite Unsicherheit** – mit Wahrscheinlichkeiten und Konfidenz können Sie eindeutige Fälle automatisieren und mehrdeutige Fälle an einen Fallback oder eine Prüfung weiterleiten.
