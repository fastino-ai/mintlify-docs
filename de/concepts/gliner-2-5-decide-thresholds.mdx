Evaluieren Sie GLiNER 2.5 Decide anhand beschrifteter Beispiele aus Ihrer Anwendung, bevor Sie mit seinen Klassifizierungen Produktionsaktionen auslösen.

## Verhalten von Schwellenwerten verstehen

`cls_threshold` gilt nur für Aufgaben mit `multi_label: true`:

```json
{
  "task": "topics",
  "labels": ["billing", "technical", "account", "security"],
  "multi_label": true,
  "cls_threshold": 0.5
}
```

- Erhöhen Sie den Schwellenwert, um weniger Labels zurückzugeben und im Allgemeinen Precision zu begünstigen.
- Senken Sie den Schwellenwert, um mehr Labels zurückzugeben und im Allgemeinen Recall zu begünstigen.
- Single-Label-Aufgaben geben immer das Label mit dem höchsten Wert zurück; `cls_threshold` ändert ihre Auswahl nicht.
- `cls_threshold` ist eine Inferenzeinstellung. Sie wirkt sich nicht auf das Training aus.

## Einen Evaluierungsdatensatz erstellen

Verwenden Sie Beispiele, die den Produktionsverkehr repräsentieren, darunter:

- Häufige Eingaben für jedes Label
- Seltene, aber wichtige Labels
- Mehrdeutige Eingaben nahe den Kategoriegrenzen
- Eingaben, die mehrere Labels erhalten sollten
- Eingaben, die beim ausgewählten Schwellenwert kein Multi-Label-Ergebnis erhalten sollten
- Domänenfremde oder fehlerhafte Eingaben, auf die Ihre Anwendung stoßen kann

Halten Sie Evaluierungsdaten von Fine-Tuning-Daten getrennt.

## Das für Ihre Anwendung erforderliche Verhalten messen

Prüfen Sie bei Single-Label-Aufgaben die Gesamtgenauigkeit und Fehler pro Label. Eine Konfusionsmatrix hilft, Labels aufzudecken, die das Modell häufig verwechselt.

Messen Sie bei Multi-Label-Aufgaben Precision, Recall und F1 sowohl insgesamt als auch pro Label. Prüfen Sie außerdem:

- Falsch-positive Ergebnisse, die fehlerhafte Aktionen auslösen
- Falsch-negative Ergebnisse, durch die erforderliche Aktionen ausbleiben
- Die Anzahl ausgewählter Labels pro Eingabe
- Die Häufigkeit leerer Auswahlen
- Ergebnisse nahe Ihrem Schwellenwert

## Einen Schwellenwert auswählen

1. Führen Sie den Evaluierungsdatensatz aus und bewahren Sie jedes ausgewählte Label und seine Konfidenz auf.
2. Testen Sie mehrere mögliche Schwellenwerte.
3. Vergleichen Sie Precision, Recall und geschäftliche Auswirkungen.
4. Wählen Sie einen Schwellenwert pro Aufgabe, wenn Aufgaben unterschiedliche Fehlerkosten haben.
5. Wiederholen Sie die Evaluierung, nachdem Sie Labels, Daten oder das Modell geändert haben.

Gehen Sie nicht davon aus, dass `0.5` universell geeignet ist. Verwenden Sie für weitreichende Aktionen konservative Automatisierungsschwellenwerte und erhalten Sie einen Prüf- oder Fallback-Pfad.

## Fine-Tuning durchführen

Beginnen Sie mit zur Laufzeit definierten Labels und evaluieren Sie zuerst das Basismodell. Nehmen Sie eine Feinabstimmung vor, wenn eine repräsentative Evaluierung zeigt, dass Schemaänderungen und die Abstimmung von Schwellenwerten die für Ihre Domäne erforderliche Qualität nicht erreichen.

### 1. Trainingsziel bestätigen

Fragen Sie den [Basismodellkatalog](/de/api-reference/training/base-models) ab und bestätigen Sie, dass das ausgewählte Klassifizierungsmodell den vorgesehenen Trainingstyp unterstützt.

### 2. Klassifizierungsdaten vorbereiten

Speichern Sie ein JSON-Objekt pro Zeile. Verwenden Sie `label` für Single-Label-Beispiele:

```jsonl
{"text":"The setup was straightforward.","label":"positive"}
{"text":"The application crashes during sign in.","label":"negative"}
```

Verwenden Sie `labels` für Multi-Label-Beispiele:

```jsonl
{"text":"The app crashes on login and I need help urgently.","labels":["technical_issue","login_problem","urgent"]}
```

Verwenden Sie stabile Labelnamen, die der Taxonomie Ihres Inferenzschemas entsprechen. Nehmen Sie repräsentative Beispiele für jedes Label auf und bewahren Sie eine separate Evaluierungsaufteilung.

### 3. Training starten und überwachen

Erstellen Sie mit dem vorbereiteten Datensatz und einem trainierbaren Klassifizierungsbasismodell einen Trainingsjob. Wählen Sie nur Trainingsparameter, die von diesem Modellrezept unterstützt werden.

<Card title="Trainingsjobs" icon="activity" href="/de/training">
  Übermitteln Sie einen Job, überwachen Sie seinen Status, prüfen Sie Metriken und Checkpoints und rufen Sie das resultierende Artefakt ab.
</Card>

### 4. Das trainierte Ergebnis evaluieren

Vergleichen Sie das trainierte Modell und das Basismodell anhand desselben zurückgehaltenen Datensatzes:

- Gesamtgenauigkeit und Genauigkeit pro Label für Single-Label-Aufgaben
- Precision, Recall und F1 für Multi-Label-Aufgaben
- Fehler bei seltenen und weitreichenden Labels
- Verhalten nahe den Produktionsschwellenwerten
- Latenz und betriebliche Anforderungen

Wählen Sie einen Checkpoint nicht allein anhand des Trainingsverlusts aus. Evaluieren Sie das Klassifizierungsverhalten, das Ihre Anwendung verwenden wird.

### 5. Das trainierte Modell verwenden

Wenn der ausgewählte Checkpoint bereitgestellt werden kann, verwenden Sie seine Modell-ID mit dem unterstützten Inferenzendpunkt und behalten Sie das von Ihrer Anwendung erwartete Klassifikationsschema bei. Validieren Sie Schwellenwerte erneut, da sich das Konfidenzverhalten nach dem Fine-Tuning ändern kann.
