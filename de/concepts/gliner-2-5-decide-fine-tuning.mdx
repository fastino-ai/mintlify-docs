Beginnen Sie mit zur Laufzeit definierten Labels und evaluieren Sie zuerst das Basismodell. Nehmen Sie eine Feinabstimmung vor, wenn eine repräsentative Evaluierung zeigt, dass Schemaänderungen und die Abstimmung von Schwellenwerten die für Ihre Domäne erforderliche Qualität nicht erreichen.

## 1. Trainingsziel bestätigen

Fragen Sie den [Basismodellkatalog](/de/api-reference/training/base-models) ab und bestätigen Sie, dass das ausgewählte Klassifizierungsmodell den vorgesehenen Trainingstyp unterstützt.

## 2. Klassifizierungsdaten vorbereiten

Speichern Sie ein JSON-Objekt pro Zeile. Verwenden Sie `label` für Single-Label-Beispiele:

```jsonl
{"text":"The setup was straightforward.","label":"positive"}
{"text":"The application crashes during sign in.","label":"negative"}
```

Verwenden Sie `labels` für Multi-Label-Beispiele:

```jsonl
{"text":"The app crashes on login and I need help urgently.","labels":["technical_issue","login_problem","urgent"]}
```

Verwenden Sie stabile Labelnamen, die der Taxonomie Ihres Inferenzschemas entsprechen. Nehmen Sie repräsentative Beispiele für jedes Label auf und bewahren Sie eine separate Evaluierungsaufteilung.

  Informieren Sie sich über unterstützte Klassifizierungsformate, Upload-Schritte, Validierung und Datensatzversionen.
</Card>

## 3. Training starten und überwachen

Erstellen Sie mit dem vorbereiteten Datensatz und einem trainierbaren Klassifizierungsbasismodell einen Trainingsjob. Wählen Sie nur Trainingsparameter, die von diesem Modellrezept unterstützt werden.

<Card title="Trainingsjobs" icon="activity" href="/de/training">
  Übermitteln Sie einen Job, überwachen Sie seinen Status, prüfen Sie Metriken und Checkpoints und rufen Sie das resultierende Artefakt ab.
</Card>

## 4. Das trainierte Ergebnis evaluieren

Vergleichen Sie das trainierte Modell und das Basismodell anhand desselben zurückgehaltenen Datensatzes:

- Gesamtgenauigkeit und Genauigkeit pro Label für Single-Label-Aufgaben
- Precision, Recall und F1 für Multi-Label-Aufgaben
- Fehler bei seltenen und weitreichenden Labels
- Verhalten nahe den Produktionsschwellenwerten
- Latenz und betriebliche Anforderungen

Wählen Sie einen Checkpoint nicht allein anhand des Trainingsverlusts aus. Evaluieren Sie das Klassifizierungsverhalten, das Ihre Anwendung verwenden wird.

## 5. Das trainierte Modell verwenden

Wenn der ausgewählte Checkpoint bereitgestellt werden kann, verwenden Sie seine Modell-ID mit dem unterstützten Inferenzendpunkt und behalten Sie das von Ihrer Anwendung erwartete Klassifikationsschema bei. Validieren Sie Schwellenwerte erneut, da sich das Konfidenzverhalten nach dem Fine-Tuning ändern kann.
