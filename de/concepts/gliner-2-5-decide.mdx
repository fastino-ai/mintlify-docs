GLiNER-2.5-Decide ist Fastinos englisches Entscheidungsmodell mit 340 Millionen Parametern für schema-definierte Klassifikation. Übergeben Sie Ihre Labels bei der Anfrage und erhalten Sie strukturierte Antworten, Wahrscheinlichkeiten und Konfidenzwerte, ohne ein generatives Modell zu prompten.

## Warum ein schema-definiertes Entscheidungsmodell verwenden

Ein schema-definiertes Modell eignet sich für Anwendungen, die Text in eine erlaubte Aktion überführen müssen:

- **Vorhersagbare Ausgaben** – das Modell wählt aus den von Ihnen definierten Labels; nachgelagerter Code muss keinen generierten Text parsen oder validieren.
- **Nutzbare Unsicherheit** – Wahrscheinlichkeiten und Konfidenz unterstützen Schwellenwerte, menschliche Prüfung und Fallbacks.
- **Zusammenhängende Urteile in einem Durchlauf** – klassifizieren Sie Absicht, Dringlichkeit, Route und Übergabe aus derselben Eingabe statt mit separaten Generierungsaufrufen.

## Warum GLiNER-2.5-Decide

- **Kompakt und schnell** – der veröffentlichte Checkpoint mit 340 Millionen Parametern erreichte im publizierten Kurztext-Benchmark 38,3 ms p50 auf einer NVIDIA V100 und 167,3 ms auf einer Intel-Xeon-CPU mit 48 vCPUs.
- **Offen und bereitstellbar** – Apache-2.0-Open-Weights unterstützen lokale CPU-Inferenz, Air-Gap-Bereitstellungen sowie vollständiges oder LoRA-Fine-Tuning.
- **Mehr als Klassifikation** – dieselbe GLiNER-Architektur kann Klassifikation mit Entitäten, Relationen und strukturierten Datensätzen kombinieren.
- **Flexible Schemas** – ändern Sie Labels und Beschreibungen pro Anfrage, statt bei jeder Taxonomieänderung neu zu trainieren.

Im 17-Datensätze umfassenden Fast-Decisions-Benchmark von Fastino erzielte GLiNER-2.5-Decide mit **60,1 %** den höchsten Durchschnittswert und führte in 9 Datensätzen. Es übertraf die JevK5-Reproduktion der 4B-Klasse (**57,5 %**) und SemIf (**56,4 %**) sowie die Encoder-Modelle GLiFormer und Laya. Dies ist ein interner Benchmark, nicht JevBench, und JevK5 ist nicht TypeSafes Jev.

Lesen Sie [GLiNER2.5-Decide: An Open-Weight Model for Structured Decision Making](https://fastino.ai/blog/gliner-2-5-decide-open-weight-decision-model) für Benchmarkdesign, vollständige Ergebnisse und Latenzmethodik.

## Wann Sie GLiNER-2.5-Decide verwenden sollten

Verwenden Sie GLiNER-2.5-Decide, wenn Klassifikation die Hauptaufgabe ist:

- **Absicht und Routing** - leiten Sie Support-Nachrichten, E-Mails oder Agentenanfragen an den richtigen Workflow weiter.
- **Mehrere Entscheidungen pro Eingabe** - klassifizieren Sie Absicht, Dringlichkeit, Route und menschliche Übergabe in einem Aufruf.
- **Single- und Multi-Label-Klassifikation** - wählen Sie eine Kategorie oder alle zutreffenden Labels.
- **Operative Gates** - bestimmen Sie, ob ein Agent fertig ist, ein Mensch übernehmen soll oder Inhalte gegen Richtlinien verstoßen.
- **Ordinale Labels** - bewerten Sie Schweregrad, Dringlichkeit oder Ratings mit einer geordneten Skala.
- **Benutzerdefinierte Taxonomien** - definieren Sie Labels und kurze Beschreibungen pro Anfrage, ohne neu zu trainieren.

Das gehostete Modell unterstützt weiterhin Entitäten, Relationen und strukturierte Extraktion, aber Klassifikation ist der Grund, es zu wählen. Verwenden Sie [GLiNER2.5](/de/concepts/gliner), wenn Extraktion im Vordergrund steht, Sie Span-Attribute oder gemeinsame Entitäten-Relations-Extraktion benötigen oder der Text mehrsprachig ist. Verwenden Sie ein universelles Sprachmodell, wenn das Ergebnis offener Text, eine Unterhaltung oder neu generierter Inhalt statt einer schema-definierten Entscheidung sein muss.

## So verwenden Sie GLiNER-2.5-Decide

Rufen Sie das Modell über denselben Fastino-Inferenz-Endpunkt wie jedes andere GLiNER-Modell auf und verwenden Sie dabei ein `classifications`-Schema. Jede Klassifikationsaufgabe benötigt mindestens zwei Kandidatenlabels. Bewerten Sie mehrere zusammenhängende Urteile in einem Aufruf, indem Sie weitere Aufgabeneinträge hinzufügen:

```bash
curl -X POST "https://api.fastino.ai/v1/chat/completions" \
  -H "Authorization: Bearer $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "fastino/GLiNER-2.5-Decide",
    "messages": [
      { "role": "user", "content": "My subscription renewed on April 15 after the service was already down. Can I get that refunded?" }
    ],
    "schema": {
      "classifications": [
        {
          "task": "intent",
          "labels": ["refund_request", "cancel_subscription", "login_problem", "speak_to_human"],
          "multi_label": false
        },
        {
          "task": "urgency",
          "labels": ["low", "normal", "high", "critical"],
          "multi_label": false
        }
      ]
    }
  }'
```

`intent` und `urgency` werden gemeinsam bewertet, sodass der Router beide Entscheidungen aus einer Anfrage erhält. Senden Sie ein explizites Schema für Ihre eigene Taxonomie. Wenn Sie sowohl `schema` als auch `response_format` weglassen, verwendet Decide seine Standardaufgabe `intent` (`book`, `cancel`, `change` und `status`) und gibt `x_fastino.default_schema_applied: true` zurück.

In der [Chat-Completions-API](/de/inference/chat-completions) finden Sie den Response-Vertrag, Multi-Label-Klassifikation und Konfidenzschwellen.
