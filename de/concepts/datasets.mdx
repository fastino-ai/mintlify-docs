Trainingsjobs referenzieren fertige Datensätze über ihren Namen. Bereiten Sie eine JSONL-Datei vor, laden Sie sie über die
zweistufige Datensatz-API hoch und vergewissern Sie sich, dass die verarbeitete Version existiert, bevor Sie
`POST /v1/training/jobs` aufrufen.

## Datensatzformat wählen

Jede Zeile der Datei muss ein JSON-Objekt sein. Verwenden Sie innerhalb eines
Datensatzes durchgehend dieselbe Struktur.

### Named Entity Recognition

Verwenden Sie `text` zusammen mit einer `entities`-Liste aus `[span, label]`-Paaren. Jeder Span muss im Text vorkommen, der Abgleich unterscheidet jedoch nicht zwischen Groß- und Kleinschreibung: `"ada lovelace"` ist für `"Ada Lovelace"` gültig. Nehmen Sie Negativbeispiele mit einer leeren Liste auf.

```jsonl
{"text":"Ada Lovelace worked in London.","entities":[["Ada Lovelace","PERSON"],["London","LOCATION"]]}
{"text":"No tagged entities here.","entities":[]}
```

### Klassifizierung

Verwenden Sie `label` für Daten mit einem Label oder `labels` für Multi-Label-Daten.
Verwenden Sie in jeder Zeile dasselbe Feld.

```jsonl
{"text":"The setup was straightforward.","label":"positive"}
{"text":"The request needs technical help.","label":"technical"}
```

### GLiNER2-Bibliotheksformat

NER- und Klassifizierungsuploads akzeptieren auch das kanonische GLiNER2-Format
mit `input` und `output`. Ordnen Sie bei NER jedem Entity-Label die passenden
Spans zu:

```jsonl
{"input":"Ada Lovelace worked in London.","output":{"entities":{"PERSON":["Ada Lovelace"],"LOCATION":["London"]}}}
{"input":"No tagged entities here.","output":{"entities":{"PERSON":[],"LOCATION":[]}}}
```

Bei der Klassifizierung kann `classifications` pro Zeile eine oder mehrere
Aufgaben enthalten:

```jsonl
{"input":"jump now","output":{"classifications":[{"task":"action","labels":["jump","wait"],"true_label":["jump"]},{"task":"urgency","labels":["now","later"],"true_label":["now"]}]}}
```

Verwenden Sie pro Zeile nur eine Struktur. Mischen Sie `text`, `label`, `labels`
oder `entities` nicht mit `input` und `output` in derselben Zeile.

### Gemeinsames NER und Klassifizierung

Eine Zeile kann sowohl `entities` als auch `label` enthalten, um beide Köpfe zu trainieren. Behalten Sie diese gemeinsame Struktur in jeder Zeile bei und mischen Sie das Single-Label-Feld `label` nicht mit dem Multi-Label-Feld `labels`.

```jsonl
{"text":"Ada Lovelace worked in London.","entities":[["Ada Lovelace","PERSON"],["London","LOCATION"]],"label":"biography"}
{"text":"No tagged entities here.","entities":[],"label":"other"}
```

### Decoder

Setzen Sie `dataset_type` auf `decoder` und geben Sie jeder Zeile ein
`messages`-Array mit Chat-Rollen und Inhalten.

```jsonl
{"messages":[{"role":"user","content":"What is 2+2?"},{"role":"assistant","content":"4"}]}
```

<Note>
  Der Dataset-Dienst akzeptiert Decoder-Datensätze für Fine-Tune-Agent- und Speicher-Workflows. Config-Jobs lehnen Decoder-Basismodelle ab; behandeln Sie `dataset_type: decoder` daher nicht als direkten Decoder-Trainingspfad über einen Config-Job. Interaktive Jobs akzeptieren keinen Dataset-Namen. Lesen und tokenisieren Sie die Beispiele in Ihrer Anwendung und senden Sie anschließend tokenisierte Datums wie im [Decoder-Schnellstart](/de/training/decoder-quickstart) gezeigt.
</Note>

## Datensatz hochladen

### 1. Upload-URL reservieren

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/upload/url \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "dataset_name": "docs-example-ner",
    "filename": "training.jsonl",
    "dataset_type": "ner"
  }' | tee dataset-upload.json

export PRESIGNED_URL="$(jq -r '.presigned_url' dataset-upload.json)"
export DATASET_ID="$(jq -r '.dataset_id' dataset-upload.json)"
export DATASET_VERSION="$(jq -r '.version_number' dataset-upload.json)"
```

Die Antwort enthält eine kurzlebige `presigned_url`, eine `dataset_id` und eine
`version_number`. Die obigen Befehle speichern alle drei Werte. Laden Sie die
exakten Dateibytes an die vorab signierte URL hoch:

```bash
curl --fail-with-body -X PUT \
  -H "Content-Type: application/octet-stream" \
  --upload-file training.jsonl "$PRESIGNED_URL"
```

### 2. Hochgeladene Datei verarbeiten

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/upload/process \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d "$(jq -n --arg dataset_id "$DATASET_ID" '{dataset_id: $dataset_id}')"
```

Die Verarbeitung gibt `202` zurück. Fragen Sie den Datensatz über seinen Namen
ab und wählen Sie den Eintrag aus, dessen `version_number` exakt mit der
Upload-Antwort übereinstimmt. Fragen Sie weiter ab, bis der `status` dieser
Version `ready` oder `failed` ist. Bei `failed` brechen Sie ab und zeigen
`processing_error` an; verwenden Sie diese Version nicht für das Training.

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/docs-example-ner \
  -H "X-API-Key: $FASTINO_API_KEY"
```

## Training starten

Übergeben Sie den exakten Datensatznamen an den [Endpunkt zum Erstellen
von Trainingsjobs](/de/api-reference/training-jobs/create):

```json
{
  "model_name": "my-ner-model",
  "base_model": "fastino/gliner2-base-v1",
  "datasets": [
    {"name": "docs-example-ner", "version": "VERSION_NUMBER_FROM_UPLOAD"}
  ],
  "training_type": "lora"
}
```

Rufen Sie `GET /v1/base-models?supports_training=true` unmittelbar vor dem Absenden auf, um ein
aktuell trainierbares Basismodell auszuwählen.

## Häufige Hindernisse

| Status | Ursache | Maßnahme |
| --- | --- | --- |
| `401` | Fehlender oder ungültiger API-Schlüssel | Senden Sie `X-API-Key: $FASTINO_API_KEY` |
| `404` | Datensatzname existiert nicht | Prüfen Sie den exakten Namen und warten Sie auf die Verarbeitung |
| `failed` | Asynchrone Inhaltsvalidierung fehlgeschlagen | Lesen Sie `processing_error`, korrigieren Sie das JSONL und laden Sie eine neue Version hoch |
| `422` | Die Request-Struktur wurde vor der Verarbeitung abgelehnt | Korrigieren Sie die Request-Felder und versuchen Sie es erneut |
