Trainingsjobs referenzieren fertige Datensätze über ihren Namen. Bereiten Sie eine JSONL-Datei vor, laden Sie sie über die
zweistufige Datensatz-API hoch und vergewissern Sie sich, dass die verarbeitete Version existiert, bevor Sie
`POST /v1/training/jobs` aufrufen.

## Datensatzformat wählen

Jede Zeile der Datei muss ein JSON-Objekt sein. Verwenden Sie innerhalb eines
Datensatzes durchgehend dieselbe Struktur.

### Named Entity Recognition

Verwenden Sie `text` zusammen mit einer `entities`-Liste aus `[span, label]`-Paaren. Jeder Span muss wörtlich
im Text vorkommen. Nehmen Sie Negativbeispiele mit einer leeren Liste auf.

```jsonl
{"text":"Ada Lovelace worked in London.","entities":[["Ada Lovelace","PERSON"],["London","LOCATION"]]}
{"text":"No tagged entities here.","entities":[]}
```

### Klassifizierung

Verwenden Sie `label` für Daten mit einem Label oder `labels` für Multi-Label-Daten.

```jsonl
{"text":"The setup was straightforward.","label":"positive"}
{"text":"The request needs billing and technical help.","labels":["billing","technical"]}
```

### Decoder-Fine-Tuning

Verwenden Sie ein `messages`-Array mit `system`-, `user`- oder `assistant`-Nachrichten.

```jsonl
{"messages":[{"role":"user","content":"What is 2 + 2?"},{"role":"assistant","content":"4"}]}
```

## Datensatz hochladen

### 1. Upload-URL reservieren

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/upload/url \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "dataset_name": "docs-example-ner",
    "filename": "training.jsonl",
    "dataset_type": "ner"
  }' | tee dataset-upload.json

export PRESIGNED_URL="$(jq -r '.presigned_url' dataset-upload.json)"
export DATASET_ID="$(jq -r '.dataset_id' dataset-upload.json)"
export DATASET_VERSION="$(jq -r '.version_number' dataset-upload.json)"
```

Die Antwort enthält eine kurzlebige `presigned_url`, eine `dataset_id` und eine
`version_number`. Die obigen Befehle speichern alle drei Werte. Laden Sie die
exakten Dateibytes an die vorab signierte URL hoch:

```bash
curl --fail-with-body -X PUT --upload-file training.jsonl "$PRESIGNED_URL"
```

### 2. Hochgeladene Datei verarbeiten

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/upload/process \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d "$(jq -n --arg dataset_id "$DATASET_ID" '{dataset_id: $dataset_id}')"
```

Die Verarbeitung gibt `202` zurück. Fragen Sie den Datensatz über seinen Namen ab, suchen Sie den Eintrag, dessen `version_number`
mit der Upload-Antwort übereinstimmt, und warten Sie, bis der `status` dieses Eintrags `ready` ist:

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/docs-example-ner \
  -H "X-API-Key: $FASTINO_API_KEY"
```

## Training starten

Übergeben Sie den exakten Datensatznamen an den [Endpunkt zum Erstellen
von Trainingsjobs](/de/api-reference/training-jobs/create):

```json
{
  "model_name": "my-ner-model",
  "base_model": "fastino/gliner2-base-v1",
  "datasets": [
    {"name": "docs-example-ner", "version": "VERSION_NUMBER_FROM_UPLOAD"}
  ],
  "training_type": "lora"
}
```

Rufen Sie `GET /v1/base-models?supports_training=true` unmittelbar vor dem Absenden auf, um ein
aktuell trainierbares Basismodell auszuwählen.

## Häufige Hindernisse

| Status | Ursache | Maßnahme |
| --- | --- | --- |
| `401` | Fehlender oder ungültiger API-Schlüssel | Senden Sie `X-API-Key: $FASTINO_API_KEY` |
| `404` | Datensatzname existiert nicht | Prüfen Sie den exakten Namen und warten Sie auf die Verarbeitung |
| `422` | Ungültige Zeilen oder ungültiger Datensatztyp | Korrigieren Sie die von der Validierung gemeldete JSONL-Struktur |

Laden Sie nicht die interne `{"input": ..., "output": ...}`-Struktur des GLiNER-Trainers hoch. Konvertieren Sie sie
zuerst in das öffentliche Format aus `text` und `entities`.
