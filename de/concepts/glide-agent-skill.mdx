Das [Fastino GLiDE Agent Skill](https://api.fastino.ai/.well-known/agent-skills/fastino-glide/SKILL.md) hilft Cursor, Claude Code und Codex dabei, Fastinos gehostetes GLiDE-Entscheidungsmodell zu nutzen, um strukturierte Entscheidungen zu klassifizieren, zu routen und zu bewerten, und GLiDE-Inferenz in ein Projekt zu integrieren.

## Installation

Führe diesen Befehl in deinem Projekt aus:

```bash
npx skills add https://api.fastino.ai --skill fastino-glide
```

Der Installer lässt dich auswählen, welche unterstützten Agenten das Skill erhalten.

Bevor du das Skill verwendest, stelle deinen Fastino-API-Schlüssel in der Umgebung des Agenten bereit:

```bash
export FASTINO_API_KEY="..."
```

Rufe es anschließend explizit mit `/fastino-glide` auf oder bitte deinen Agenten um eine auf GLiDE basierende Klassifikations-, Routing- oder Bewertungsentscheidung.

## Nicht-interaktive Installation

Verwende den Befehl für deinen Agenten, um das Skill ohne Rückfragen im aktuellen Projekt zu installieren:

<CodeGroup initialSelectedTab={0}>

```bash Cursor
npx skills add https://api.fastino.ai --skill fastino-glide -a cursor -y
```

```bash Claude Code
npx skills add https://api.fastino.ai --skill fastino-glide -a claude-code -y
```

```bash Codex
npx skills add https://api.fastino.ai --skill fastino-glide -a codex -y
```

```text Any agent
"Install the Fastino GLiDE agent skill. Follow the installation
instructions in Fastino's documentation at
https://docs.fastino.ai/concepts/glide-agent-skill. Use one
installation method appropriate for your agent environment. Then use
the Fastino GLiDE skill when working on this project, especially for
classification, routing, and scoring decisions with calibrated
probabilities instead of generated text."
```

</CodeGroup>

Für Cursor, Claude Code und Codex wählt die Option `-a` den Ziel-Agenten aus und `-y` bestätigt die Installationsaufforderungen, wodurch diese Befehle für Skripte und CI geeignet sind.

## Von TypeSafe migrieren?

Installiere das GLiDE-Skill und kopiere dann den folgenden Prompt in deinen Coding-Agenten:

<div style={{ maxHeight: "10rem", overflowY: "auto" }}>

```text title="Copy this prompt"
Use the Fastino GLiDE skill to migrate this project from TypeSafe/Jev to
Fastino GLiDE. Find every TypeSafe API and SDK integration, then:

1. Change the endpoint to https://api.fastino.ai/v1/systemone.
2. Replace TYPESAFE_API_KEY with FASTINO_API_KEY and send it as X-API-Key.
3. Replace jev-latest with fastino/GLiDE.
4. Expect the response model field to be glide.
5. Preserve non-empty state, question names, and primitive types.
6. Make every instruction a non-empty string. Make Noul true/false criteria
   strings, and use ordered arrays for Score criteria where possible.
7. Remove unsupported top-level request fields.
8. Replace TypeSafe SDK calls with direct HTTP requests. Remove typesafe-sdk or
   @typesafe-ai/sdk dependencies and imports after replacing all TypeSafeClient,
   AsyncTypeSafeClient, question-constructor, and typed-response usage.
9. Convert SDK object access to decoded JSON access. Check non-2xx responses and
   use a read timeout of at least 300 seconds.
10. Where code uses TypeSafe's floating-point score, read GLiDE's
   expected_level. Use GLiDE's score only for the integer winning level.
11. Handle Score probabilities and legend as string-keyed maps, and expect
    legend values to be strings.
12. Replace 529 retry handling with bounded retries for transport failures, 425,
    and 503. Keep bounded backoff for 429 and honor Retry-After.
13. Update tests, model assertions, telemetry, and caches. Revalidate all
    decision thresholds on representative data.

Do not change unrelated business logic. Show me every changed integration point
and any behavior that could not be migrated mechanically. Follow
https://docs.fastino.ai/inference/systemone for the canonical contract.
```

</div>

Die Anfragestruktur ist ähnlich, aber die Score-Semantik unterscheidet sich. Lies
[Von TypeSafe migrieren](/de/inference/systemone#von-typesafe-migrieren)
für weitere Details.
