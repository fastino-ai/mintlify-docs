Ce guide vous propose le chemin le plus rapide vers une intégration Fastino opérationnelle. À la fin, vous aurez effectué un appel de décision GLiDE réussi et compris la structure de l'API. Il vous suffit d'un compte Fastino et d'un terminal.

<Steps>
  <Step title="Inscrivez-vous et récupérez votre clé d'API">
    Créez un compte sur [Fastino](https://agent.fastino.ai/).

    Une fois connecté, rendez-vous dans **Settings → API Keys** et générez une nouvelle clé. Copiez-la dans un endroit sûr, car vous ne pourrez plus la consulter après avoir fermé la boîte de dialogue.

    <Warning>
      Ne versionnez pas votre clé d'API. Utilisez une variable d'environnement ou un gestionnaire de secrets plutôt que de l'inscrire en dur dans vos fichiers sources.
    </Warning>

    Définissez votre clé comme variable d'environnement afin que les exemples ci-dessous fonctionnent tels quels :

    ```bash
    export FASTINO_API_KEY="your_api_key_here"
    ```
  </Step>
  <Step title="Listez les modèles de base disponibles (facultatif)">
    Vous pouvez parcourir les modèles proposés par Fastino. Utilisez `GET /v1/base-models` pour consulter le catalogue complet.

    <CodeGroup>

    ```bash curl
    curl https://api.fastino.ai/v1/base-models \
      -H "X-API-Key: $FASTINO_API_KEY"
    ```

    ```python Python
    import os
    import requests
    
    response = requests.get(
        "https://api.fastino.ai/v1/base-models",
        headers={"X-API-Key": os.environ["FASTINO_API_KEY"]}
    )
    print(response.json())
    ```

    ```javascript JavaScript
    const response = await fetch(
      "https://api.fastino.ai/v1/base-models",
      {
        headers: {
          "X-API-Key": process.env.FASTINO_API_KEY
        }
      }
    );
    const data = await response.json();
    console.log(data);
    ```

    </CodeGroup>

    La réponse liste les IDs de modèles que vous pouvez passer à `/v1/chat/completions`. Par exemple, `fastino/gliner2-base-v1` est le modèle de base GLiNER pour les tâches de NER.
  </Step>
  <Step title="Exécutez votre premier appel d'inférence">
    Appelez `POST /v1/systemone` avec un `model`, un `state` décrivant la situation et une ou plusieurs `questions` typées. GLiDE renvoie directement des probabilités calibrées et des libellés. Aucun texte généré n'est à analyser. L'exemple ci-dessous pose une seule question oui/non (`noul`).

    <CodeGroup>

    ```bash curl
    curl -X POST "https://api.fastino.ai/v1/systemone" \
      -H "X-API-Key: $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "fastino/glide",
        "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
        "questions": {
          "refund_allowed": {
            "type": "noul",
            "instructions": "Does this request qualify for a refund?",
            "criteria": { "true": "Qualifies", "false": "Does not qualify" }
          }
        }
      }'
    ```

    ```python Python
    import os
    import requests

    response = requests.post(
        "https://api.fastino.ai/v1/systemone",
        headers={
            "X-API-Key": os.environ["FASTINO_API_KEY"],
            "Content-Type": "application/json",
        },
        json={
            "model": "fastino/glide",
            "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
            "questions": {
                "refund_allowed": {
                    "type": "noul",
                    "instructions": "Does this request qualify for a refund?",
                    "criteria": {"true": "Qualifies", "false": "Does not qualify"},
                }
            },
        },
    )

    response.raise_for_status()
    print(response.json())
    ```

    ```javascript JavaScript
    const response = await fetch(
      "https://api.fastino.ai/v1/systemone",
      {
        method: "POST",
        headers: {
          "X-API-Key": process.env.FASTINO_API_KEY,
          "Content-Type": "application/json",
        },
        body: JSON.stringify({
          model: "fastino/glide",
          state: "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
          questions: {
            refund_allowed: {
              type: "noul",
              instructions: "Does this request qualify for a refund?",
              criteria: { true: "Qualifies", false: "Does not qualify" },
            },
          },
        }),
      }
    );

    if (!response.ok) {
      throw new Error(`Inference failed: ${response.status} ${await response.text()}`);
    }

    const result = await response.json();
    console.log(JSON.stringify(result, null, 2));
    ```

    </CodeGroup>

    Réponse :

    ```json
    {
      "model": "glide",
      "answers": {
        "refund_allowed": {
          "type": "noul",
          "noul": 0.9989566626894673,
          "confidence": 0.9979133253789345
        }
      },
      "usage": { "input_tokens": 443, "output_tokens": 62 },
      "token_usage": 505
    }
    ```

    `answers.refund_allowed.noul` est la probabilité que la réponse soit « oui ». Une valeur de `0.999` indique clairement que la demande est éligible. Consultez [Modèles de décision](/fr/concepts/decision-models) pour les types de questions `choice` et `score`, le routage conditionné par la confiance et la référence complète des primitives.

    <Accordion title="Vous souhaitez plutôt extraire des entités ? Utilisez GLiNER via /v1/chat/completions">
      Si vous avez besoin d'une extraction au niveau des segments (NER, classification, enregistrements structurés) plutôt que d'une décision, appelez `POST /v1/chat/completions` avec un modèle, un message et un schéma définissant ce que vous souhaitez extraire :

      ```bash curl
      curl -X POST "https://api.fastino.ai/v1/chat/completions" \
        -H "Authorization: Bearer $FASTINO_API_KEY" \
        -H "Content-Type: application/json" \
        -d '{
          "model": "fastino/gliner2.5-multi-v1",
          "messages": [
            {
              "role": "user",
              "content": "Apple announced the MacBook Pro at WWDC in Cupertino."
            }
          ],
          "schema": {
            "entities": [
              { "name": "organization", "description": "business or institution name" },
              { "name": "product", "description": "named commercial product" },
              { "name": "event", "description": "named conference or event" },
              { "name": "location", "description": "city, region, or place" }
            ]
          },
          "threshold": 0.5
        }'
      ```

      Pour les modèles encodeurs (GLiNER), l'objet `schema` définit la tâche et peut inclure `entities`, `classifications`, `structures` et `relations`. Pour les modèles décodeurs (LLM), omettez `schema` et envoyez un message de chat classique. Consultez l'[API d'inférence](/fr/inference) pour le contrat complet, des exemples Python/JavaScript et les codes d'erreur.

      <Note>
        `model` doit être l'ID d'un modèle de base compatible avec l'inférence ou l'UUID d'une tâche d'entraînement terminée et déployable. Après l'entraînement, déployez l'artefact sélectionné avant d'utiliser l'UUID de la tâche pour l'inférence.
      </Note>
    </Accordion>
  </Step>
  <Step title="Lancez une tâche d'entraînement (facultatif)">
    Lorsque vous êtes prêt à affiner un modèle sur vos propres données, lancez une tâche d'entraînement.

    <CodeGroup>

    ```bash curl
    curl -X POST https://api.fastino.ai/v1/training-jobs \
      -H "X-API-Key: $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model_name": "my-ner-model",
        "base_model": "fastino/gliner2-base-v1",
        "datasets": [{"name": "my-dataset"}],
        "training_type": "lora",
        "nr_epochs": 5,
        "learning_rate": 5e-5
      }'
    ```

    ```python Python
    import os
    import requests
    
    response = requests.post(
        "https://api.fastino.ai/v1/training-jobs",
        headers={
            "X-API-Key": os.environ["FASTINO_API_KEY"],
            "Content-Type": "application/json"
        },
        json={
            "model_name": "my-ner-model",
            "base_model": "fastino/gliner2-base-v1",
            "datasets": [{"name": "my-dataset"}],
            "training_type": "lora",
            "nr_epochs": 5,
            "learning_rate": 5e-5
        }
    )
    print(response.json())
    # {"id": "uuid-of-training-job", "status": "requested"}
    ```

    </CodeGroup>

    La réponse inclut l'`id` de la tâche. Interrogez régulièrement `GET /v1/training-jobs/{id}` pour vérifier son statut. Une fois que la tâche atteint `complete`, utilisez son ID comme `model` dans vos appels à `/v1/chat/completions`.

    Valeurs de statut de la tâche : `requested` → `running` → `complete` (ou `failed` / `stopped`).
  </Step>
</Steps>
