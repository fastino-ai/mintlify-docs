## Configurez votre clé d'API

1. **Créez un compte [Fastino](https://agent.fastino.ai/)**
2. **Obtenez votre clé d'API** depuis [Settings](https://agent.fastino.ai/api-keys)

Définissez votre clé comme variable d'environnement afin que les exemples ci-dessous fonctionnent tels quels :

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="your_api_key_here"
```

```powershell Windows
setx FASTINO_API_KEY "your_api_key_here"
```

</CodeGroup>

## Exécutez votre premier appel d'inférence

Appelez `POST /v1/systemone` avec un `model`, un `state` décrivant la situation et une ou plusieurs `questions` typées. GLiDE renvoie directement des probabilités calibrées et des libellés. Aucun texte généré n'est à analyser. L'exemple ci-dessous pose une seule question oui/non (`noul`).

<Tabs>
  <Tab title="cURL">
    **Pour exécuter un appel de décision GLiDE** :

    ```bash
    curl -X POST "https://api.fastino.ai/v1/systemone" \
      -H "X-API-Key: $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "fastino/glide",
        "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
        "questions": {
          "refund_allowed": {
            "type": "noul",
            "instructions": "Does this request qualify for a refund?",
            "criteria": { "true": "Qualifies", "false": "Does not qualify" }
          }
        }
      }'
    ```
  </Tab>

  <Tab title="Python">
    **Pour exécuter un appel de décision GLiDE** :

    ```python
    import os
    import requests

    response = requests.post(
        "https://api.fastino.ai/v1/systemone",
        headers={
            "X-API-Key": os.environ["FASTINO_API_KEY"],
            "Content-Type": "application/json",
        },
        json={
            "model": "fastino/glide",
            "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
            "questions": {
                "refund_allowed": {
                    "type": "noul",
                    "instructions": "Does this request qualify for a refund?",
                    "criteria": {"true": "Qualifies", "false": "Does not qualify"},
                }
            },
        },
    )

    response.raise_for_status()
    print(response.json())
    ```
  </Tab>

  <Tab title="JavaScript">
    **Pour exécuter un appel de décision GLiDE** :

    ```javascript
    const response = await fetch(
      "https://api.fastino.ai/v1/systemone",
      {
        method: "POST",
        headers: {
          "X-API-Key": process.env.FASTINO_API_KEY,
          "Content-Type": "application/json",
        },
        body: JSON.stringify({
          model: "fastino/glide",
          state: "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
          questions: {
            refund_allowed: {
              type: "noul",
              instructions: "Does this request qualify for a refund?",
              criteria: { true: "Qualifies", false: "Does not qualify" },
            },
          },
        }),
      }
    );

    if (!response.ok) {
      throw new Error(`Inference failed: ${response.status} ${await response.text()}`);
    }

    const result = await response.json();
    console.log(JSON.stringify(result, null, 2));
    ```
  </Tab>
</Tabs>

Voici à quoi ressemble une réponse réussie :

```json
{
  "model": "glide",
  "answers": {
    "refund_allowed": {
      "type": "noul",
      "noul": 0.99767683794902,
      "confidence": 0.9953536758980399
    }
  },
  "usage": { "input_tokens": 89, "output_tokens": 1 },
  "token_usage": 90
}
```

`answers.refund_allowed.noul` est la probabilité que la réponse soit « oui ». Une valeur de `0.999` indique clairement que la demande est éligible. Consultez [Modèles de décision](/fr/concepts/decision-models) pour les types de questions `choice` et `score`, le routage conditionné par la confiance et la référence complète des primitives.

<Accordion title="Vous souhaitez plutôt extraire des entités ? Utilisez GLiNER 2.5">
  Si vous avez besoin d'une extraction au niveau des segments (NER, classification, enregistrements structurés) plutôt que d'une décision, appelez `POST /v1/chat/completions` avec un modèle, un message et un schéma définissant ce que vous souhaitez extraire :

  ```bash
  curl -X POST "https://api.fastino.ai/v1/chat/completions" \
    -H "Authorization: Bearer $FASTINO_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "fastino/gliner2.5-multi-v1",
      "messages": [
        {
          "role": "user",
          "content": "Apple announced the MacBook Pro at WWDC in Cupertino."
        }
      ],
      "schema": {
        "entities": [
          { "name": "organization", "description": "business or institution name" },
          { "name": "product", "description": "named commercial product" },
          { "name": "event", "description": "named conference or event" },
          { "name": "location", "description": "city, region, or place" }
        ]
      },
      "threshold": 0.5
    }'
  ```

  Pour les modèles encodeurs (GLiNER), l'objet `schema` définit la tâche et peut inclure `entities`, `classifications`, `structures` et `relations`. Pour les modèles décodeurs (LLM), omettez `schema` et envoyez un message de chat classique. Consultez l'[API d'inférence](/fr/inference) pour le contrat complet, des exemples Python/JavaScript et les codes d'erreur.

  <Note>
    `model` doit être l'ID d'un modèle de base compatible avec l'inférence ou l'UUID d'une tâche d'entraînement terminée et déployable. Après l'entraînement, déployez l'artefact sélectionné avant d'utiliser l'UUID de la tâche pour l'inférence.
  </Note>
</Accordion>
