L'API RL est l'interface programmable de Fastino pour l'apprentissage par
renforcement et le post-entraînement personnalisé. Elle implémente le contrat du
SDK Tinker, ce qui vous permet de réutiliser une boucle d'entraînement Tinker
existante ou de partir du livre de recettes Tinker open source.

<Note>
  L'accès à l'API RL est limité. Vérifiez que Fastino l'a activé pour votre
  équipe avant de planifier une migration en production.
</Note>

Vous contrôlez la boucle :

1. Échantillonnez des réponses depuis la politique actuelle.
2. Évaluez chaque réponse avec votre fonction de récompense.
3. Transformez les récompenses en avantages.
4. Envoyez le lot d'entraînement à l'API RL.
5. Appliquez une étape d'optimisation et créez un checkpoint du résultat.

Fastino gère l'infrastructure d'entraînement et d'échantillonnage derrière cette
boucle. Votre code conserve la maîtrise du jeu de données, de la fonction de
récompense, de la stratégie de rollout et des critères d'arrêt.

<Tip>
  Vous utilisez déjà Tinker ? Conservez vos appels au SDK et configurez le point
  de terminaison ainsi que la clé d'API Fastino. Commencez par
  [Migrer depuis Tinker](/fr/rl-api/migrate-from-tinker).
</Tip>

## Pourquoi utiliser l'API RL

- **Réutilisez votre code existant.** Le package Python officiel `tinker` fait
  office de client.
- **Définissez n'importe quelle récompense programmable.** Évaluez les
  mathématiques, le code, l'utilisation d'outils, les sorties structurées ou
  votre propre environnement.
- **Séparez l'orchestration du calcul.** Conservez l'algorithme d'apprentissage
  dans votre application tandis que Fastino exécute les opérations sur le
  modèle.
- **Reprenez depuis des checkpoints durables.** Enregistrez les poids ou l'état
  de l'optimiseur et reprenez une exécution ultérieurement.
- **Suivez l'utilisation avec Fastino.** L'entraînement, l'échantillonnage et le
  stockage des checkpoints utilisent les mêmes limites de compte et de projet
  pour la facturation que vos autres workloads Fastino.

## Avant de commencer

Vous avez besoin des éléments suivants :

- Une clé d'API Fastino commençant par `fast_sk_`
- L'accès à l'API RL activé pour votre équipe Fastino
- Python 3.11 ou version ultérieure
- `tinker==0.32.0` pour le contrat client testé

L'API RL est volontairement documentée séparément de la référence OpenAPI de
Fastino. Utilisez ces pages et les types du SDK Tinker pour les opérations RL.
Utilisez la [référence de l'API](/fr/api-reference/inference/overview) pour les
API HTTP natives de Fastino.
