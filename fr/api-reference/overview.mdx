Ce guide vous présente le chemin le plus rapide vers une intégration Fastino fonctionnelle. À la fin,
vous aurez effectué un appel d'inférence réussi et compris la structure de l'API. Il vous suffit
d'un compte Fastino et d'un terminal.

<Steps>
  <Step title="Créer un compte et obtenir votre clé API">
    Créez un compte sur [Fastino](https://fastino.ai).

    Une fois connecté, accédez à **Settings → API Keys** et générez une nouvelle clé. Copiez-la
    en lieu sûr, car vous ne pourrez plus l'afficher après avoir fermé la boîte de dialogue.

    <Warning>
      Ne placez jamais votre clé API sous contrôle de version. Utilisez une variable d'environnement
      ou un gestionnaire de secrets plutôt que de l'écrire en dur dans vos fichiers sources.
    </Warning>

    Définissez votre clé comme variable d'environnement pour que les exemples ci-dessous fonctionnent tels quels :

    ```bash
    export FASTINO_API_KEY="your_api_key_here"
    ```
  </Step>

  <Step title="Lister les modèles de base disponibles (facultatif)">
    Utilisez `GET /v1/base-models` pour parcourir les modèles disponibles chez Fastino.

    <CodeGroup>

    ```bash curl
    curl https://api.fastino.ai/v1/base-models \
      -H "X-API-Key: $FASTINO_API_KEY"
    ```

    ```python Python
    import os
    import requests

    response = requests.get(
        "https://api.fastino.ai/v1/base-models",
        headers={"X-API-Key": os.environ["FASTINO_API_KEY"]},
    )
    response.raise_for_status()
    print(response.json())
    ```

    ```javascript JavaScript
    const response = await fetch(
      "https://api.fastino.ai/v1/base-models",
      {
        headers: {
          "X-API-Key": process.env.FASTINO_API_KEY
        }
      }
    );

    if (!response.ok) {
      throw new Error(`Model request failed: ${response.status}`);
    }

    console.log(await response.json());
    ```

    </CodeGroup>

    La réponse liste les ID de modèles que vous pouvez passer à `/v1/chat/completions`. Par exemple,
    `fastino/gliner2-base-v1` est un modèle de base GLiNER destiné aux tâches d'extraction.
  </Step>

  <Step title="Effectuer votre premier appel d'inférence">
    Appelez `POST /v1/chat/completions` avec un modèle, un message et un schéma qui définit ce
    que vous souhaitez extraire. Cet exemple utilise GLiNER pour extraire les entités nommées d'une phrase.

    <CodeGroup>

    ```bash curl
    curl -X POST "https://api.fastino.ai/v1/chat/completions" \
      -H "Authorization: Bearer $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "fastino/gliner2.5-multi-v1",
        "messages": [
          {
            "role": "user",
            "content": "Apple announced the MacBook Pro at WWDC in Cupertino."
          }
        ],
        "schema": {
          "entities": [
            {
              "name": "organization",
              "description": "business or institution name"
            },
            {
              "name": "product",
              "description": "named commercial product"
            },
            {
              "name": "event",
              "description": "named conference or event"
            },
            {
              "name": "location",
              "description": "city, region, or place"
            }
          ]
        },
        "threshold": 0.5
      }'
    ```

    ```python Python
    import json
    import os

    import requests

    response = requests.post(
        "https://api.fastino.ai/v1/chat/completions",
        headers={
            "Authorization": f"Bearer {os.environ['FASTINO_API_KEY']}",
            "Content-Type": "application/json",
        },
        json={
            "model": "fastino/gliner2.5-multi-v1",
            "messages": [
                {
                    "role": "user",
                    "content": "Apple announced the MacBook Pro at WWDC in Cupertino.",
                }
            ],
            "schema": {
                "entities": [
                    {"name": "organization", "description": "business or institution name"},
                    {"name": "product", "description": "named commercial product"},
                    {"name": "event", "description": "named conference or event"},
                    {"name": "location", "description": "city, region, or place"},
                ]
            },
            "threshold": 0.5,
        },
    )
    response.raise_for_status()

    result = response.json()
    entities = json.loads(result["choices"][0]["message"]["content"])
    print(json.dumps(entities, indent=2))
    ```

    ```javascript JavaScript
    const response = await fetch(
      "https://api.fastino.ai/v1/chat/completions",
      {
        method: "POST",
        headers: {
          Authorization: `Bearer ${process.env.FASTINO_API_KEY}`,
          "Content-Type": "application/json",
        },
        body: JSON.stringify({
          model: "fastino/gliner2.5-multi-v1",
          messages: [
            {
              role: "user",
              content: "Apple announced the MacBook Pro at WWDC in Cupertino.",
            },
          ],
          schema: {
            entities: [
              { name: "organization", description: "business or institution name" },
              { name: "product", description: "named commercial product" },
              { name: "event", description: "named conference or event" },
              { name: "location", description: "city, region, or place" },
            ],
          },
          threshold: 0.5,
        }),
      }
    );

    if (!response.ok) {
      throw new Error(`Inference failed: ${response.status} ${await response.text()}`);
    }

    const result = await response.json();
    const entities = JSON.parse(result.choices[0].message.content);
    console.log(JSON.stringify(entities, null, 2));
    ```

    </CodeGroup>

    Pour les modèles encodeurs tels que GLiNER, l'objet `schema` définit la tâche et peut inclure :

    - `entities` — définitions d'entités pour l'extraction d'entités nommées
    - `classifications` — définitions `{task, labels}` pour la classification de texte
    - `structures` — définitions d'enregistrements structurés pour l'extraction JSON
    - `relations` — définitions de relations

    Pour les modèles décodeurs, omettez `schema` et envoyez un message de chat classique.

    <Note>
      `model` doit être l'ID d'un modèle de base compatible avec l'inférence ou l'UUID d'un job
      d'entraînement terminé et déployable. Après l'entraînement, déployez l'artefact sélectionné
      avant d'utiliser l'UUID du job pour l'inférence.
    </Note>
  </Step>

  <Step title="Lancer un job d'entraînement (facultatif)">
    Lorsque vous êtes prêt à effectuer un fine-tuning sur vos propres données, lancez un job d'entraînement :

    <CodeGroup>

    ```bash curl
    curl -X POST https://api.fastino.ai/v1/training-jobs \
      -H "X-API-Key: $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model_name": "my-ner-model",
        "base_model": "fastino/gliner2-base-v1",
        "datasets": [{"name": "my-dataset"}],
        "training_type": "lora",
        "nr_epochs": 5,
        "learning_rate": 5e-5
      }'
    ```

    ```python Python
    import os
    import requests

    response = requests.post(
        "https://api.fastino.ai/v1/training-jobs",
        headers={
            "X-API-Key": os.environ["FASTINO_API_KEY"],
            "Content-Type": "application/json",
        },
        json={
            "model_name": "my-ner-model",
            "base_model": "fastino/gliner2-base-v1",
            "datasets": [{"name": "my-dataset"}],
            "training_type": "lora",
            "nr_epochs": 5,
            "learning_rate": 5e-5,
        },
    )
    response.raise_for_status()
    print(response.json())
    ```

    </CodeGroup>

    La réponse inclut l'`id` du job. Interrogez `GET /v1/training-jobs/{id}` pour vérifier son statut.
    Une fois que le job atteint le statut `complete`, déployez l'artefact sélectionné avant d'utiliser
    l'ID du job comme `model` dans `/v1/chat/completions`.

    Les statuts du job progressent de `requested` → `running` → `complete`, ou se terminent par
    `failed` ou `stopped`.
  </Step>
</Steps>

## Migrer depuis l'origine de l'API Pioneer

Si une intégration d'entraînement ou d'inférence existante appelle `https://api.pioneer.ai`, mettez à jour son
URL de base vers `https://api.fastino.ai`.

Les routes d'entraînement utilisent désormais le préfixe `/v1`. Par exemple, `/felix/training-jobs` devient
`/v1/training-jobs`, et ses opérations propres à chaque job restent sous cette nouvelle famille de routes.

Les intégrations directes à l'API doivent utiliser `FASTINO_API_KEY` avec une clé `fast_sk_` nouvellement générée ;
les anciennes clés `pio_sk_` sont retirées. Les authentifications `X-API-Key` et Bearer restent toutes deux valides.
