`GET /v1/training/jobs`

Renvoie les jobs d'entraînement de configuration et interactifs visibles par le
compte authentifié.

Sans `type`, les jobs de configuration et interactifs sont entrelacés selon
`created_at`, du plus récent au plus ancien. Si deux jobs ont le même horodatage,
le job de configuration apparaît en premier. Passez `type=interactive` pour ne
lister que les jobs interactifs.

## Requête

<ParamField header="X-API-Key" type="string" required>
  Votre clé API Fastino.
</ParamField>

<ParamField query="status" type="string">
  Filtrez les deux types de jobs par statut. Les jobs interactifs prennent en charge `creating`, `active`, `stopping`, `stopped` et `failed` ; `running` correspond également à `active`, tandis que `errored` et `error` correspondent à `failed`. `running`, `errored`, `error`, `stopped` et `failed` peuvent correspondre aux deux types. `creating`, `active` et `stopping` correspondent uniquement aux jobs interactifs ; les autres statuts config uniquement aux jobs config. Pour les jobs config, `status=complete` renvoie les jobs persistés avec le statut `complete`, `artifact_ready` ou `deployed`.
</ParamField>

<ParamField query="type" type="string">
  Filtrer par `config` ou `interactive`.
</ParamField>

<ParamField query="project_id" type="string">
  Filtrer par ID de projet.
</ParamField>

<ParamField query="limit" type="integer" default="200">
  Taille de page, de `1` à `200`.
</ParamField>

<ParamField query="offset" type="integer" default="0">
  Nombre de jobs correspondants à ignorer.
</ParamField>

<RequestExample>

```bash cURL
curl "https://api.fastino.ai/v1/training/jobs?type=config&status=complete&limit=50&offset=0" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

</RequestExample>

## Réponse

<ResponseField name="success" type="boolean">
  Indique si la requête a abouti.
</ResponseField>

<ResponseField name="training_jobs" type="object[]">
  Enregistrements des jobs d'entraînement pour cette page.
</ResponseField>

Tous les enregistrements incluent `id` et `created_at`. Les enregistrements
interactifs répètent également `id` dans `job_id` et `training_run_id` pour la
compatibilité de l’API et du SDK, et incluent `status`, `stop_reason`,
`error_message` et `is_terminal_status`. Interrogez un job interactif avec `id`
jusqu'à ce que l'indicateur terminal soit true.

Un enregistrement avec `type: "config"` et `source: "interactive_checkpoint"` est le modèle servi créé à partir d'un checkpoint sampler interactif. Ses champs d'entraînement config, notamment les époques, la taille de lot, le taux d'apprentissage et le pourcentage de validation, valent `null`.

<ResponseField name="count" type="integer">
  Nombre de jobs dans cette page.
</ResponseField>

<ResponseField name="total" type="integer">
  Nombre total de jobs correspondants avant pagination.
</ResponseField>

<ResponseField name="has_more" type="boolean">
  Indique si une autre page existe après celle-ci.
</ResponseField>

<ResponseExample>

```json Response
{
  "success": true,
  "training_jobs": [],
  "count": 0,
  "total": 0,
  "has_more": false
}
```

</ResponseExample>

Des valeurs de pagination invalides renvoient `422`.

Consultez la [vue d’ensemble de l’API d’entraînement](/fr/training) pour connaître l’ensemble complet des statuts persistés.
