`POST /v1/training/jobs/{job_id}/stop`

Arrête un job en cours et conserve les checkpoints créés avant l'arrêt.

## Requête

<ParamField header="X-API-Key" type="string" required>
  Votre clé API Fastino.
</ParamField>

<ParamField path="job_id" type="string" required>
  UUID d'un job config ou ID d'un job interactif.
</ParamField>

### Job de configuration

Le corps JSON est facultatif pour un job de configuration.

<ParamField body="reason" type="string">
  Raison pour laquelle le job a été arrêté.
</ParamField>

<ParamField body="scores" type="object">
  Métriques numériques utilisées pour prendre la décision d'arrêt.
</ParamField>

<ParamField body="checkpoint" type="string">
  Chemin ou pas du checkpoint associé à l'arrêt.
</ParamField>

### Job interactif

N'envoyez aucun corps. L'opération renvoie immédiatement `success`, `job_id` et
`status`, et le job n'accepte plus de nouveaux appels. Les opérations déjà en
file peuvent se terminer avant la libération des ressources ; l'utilisation
peut donc continuer jusque-là. Les checkpoints sampler restent disponibles
pour l'échantillonnage et le téléchargement.

### Exemple de requête pour un job de configuration

```bash cURL
curl -X POST https://api.fastino.ai/v1/training/jobs/YOUR_TRAINING_JOB_ID/stop \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"reason": "Validation loss stopped improving"}'
```

### Exemple de requête pour un job interactif

```bash cURL
curl -X POST https://api.fastino.ai/v1/training/jobs/SESSION_ID:train:0/stop \
  -H "X-API-Key: $FASTINO_API_KEY"
```

## Réponse d'un job de configuration

<ResponseExample>

```json Response
{
  "success": true,
  "message": "Training job stopped",
  "job_id": "YOUR_TRAINING_JOB_ID",
  "status": "stopped"
}
```

```json 202 — annulation en attente
{
  "success": true,
  "message": "Training job cancellation is still being confirmed.",
  "job_id": "YOUR_TRAINING_JOB_ID",
  "status": "stopping"
}
```

</ResponseExample>

Le champ `message`, la réponse `202`, la règle d'interrogation et les erreurs
propres à la configuration s'appliquent uniquement aux jobs de configuration.
Après une réponse de configuration `202`, interrogez
`GET /v1/training/jobs/{job_id}`. Ne répétez pas la requête d'arrêt pendant que
l'annulation est en attente.

## Réponse d'un job interactif

Un arrêt interactif renvoie immédiatement `200` sans interrogation ultérieure.

```json Interactive job
{
  "success": true,
  "job_id": "SESSION_ID:train:0",
  "status": "stopped"
}
```

## Statuts d'un job de configuration

| Statut | Signification |
| --- | --- |
| `200` | Le job est arrêté et les checkpoints existants restent disponibles. |
| `202` | La confirmation de l'annulation par le fournisseur est toujours en attente. |
| `400` | L'ID ou la requête du job de configuration n'est pas valide. |
| `409 training_job_already_finished` | Le job a atteint un état terminal avant l'arrêt. |
| `422` | Le corps JSON du job de configuration n'est pas valide. |
