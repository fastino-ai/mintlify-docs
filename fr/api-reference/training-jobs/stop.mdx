`POST /v1/training/jobs/{job_id}/stop`

Arrête un job en cours et conserve les checkpoints créés avant l'arrêt. Pour un job interactif, la requête répond immédiatement et rejette les nouveaux appels. Les opérations déjà en file peuvent se terminer avant la libération des ressources. L'utilisation peut continuer jusqu'à cette libération.

## Requête

<ParamField header="X-API-Key" type="string" required>
  Votre clé API Fastino.
</ParamField>

<ParamField path="job_id" type="string" required>
  UUID du job de configuration ou ID du job interactif.
</ParamField>

### Job de configuration

Le corps JSON est facultatif pour un job de configuration.

<ParamField body="reason" type="string">
  Raison pour laquelle le job a été arrêté.
</ParamField>

<ParamField body="scores" type="object">
  Métriques numériques utilisées pour prendre la décision d'arrêt.
</ParamField>

<ParamField body="checkpoint" type="string">
  Chemin ou pas du checkpoint associé à l'arrêt.
</ParamField>

### Job interactif

N'envoyez aucun corps de requête. La réponse contient les champs communs
vérifiés `success`, `job_id` et `status`.

### Exemple de requête pour un job de configuration

<RequestExample>

```bash cURL
curl -X POST https://api.fastino.ai/v1/training/jobs/YOUR_TRAINING_JOB_ID/stop \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"reason": "Validation loss stopped improving"}'
```

</RequestExample>

### Exemple de requête pour un job interactif


<RequestExample>

```bash cURL
curl -X POST https://api.fastino.ai/v1/training/jobs/YOUR_INTERACTIVE_JOB_ID/stop \
  -H "X-API-Key: $FASTINO_API_KEY"
```

</RequestExample>

## Réponse d'un job de configuration

<ResponseExample>

```json Response
{
  "success": true,
  "message": "Training job stopped successfully. Checkpoints preserved.",
  "job_id": "YOUR_TRAINING_JOB_ID",
  "status": "stopped"
}
```

```json 202 — annulation en attente
{
  "success": true,
  "message": "Cancellation in progress. The job moves to 'stopped' once the provider confirms; checkpoints are preserved.",
  "job_id": "YOUR_TRAINING_JOB_ID",
  "status": "stopping"
}
```

</ResponseExample>

Le champ `message`, la réponse `202` et la règle d'interrogation concernent
uniquement les jobs de configuration. Après une réponse `202` pour un job de
configuration, interrogez `GET /v1/training/jobs/{job_id}`. Ne répétez pas la
requête d'arrêt pendant que l'annulation est en attente.

## Réponse d'un job interactif

Un job interactif utilise la même opération sans corps. La réponse contient les
champs communs `success`, `job_id` et `status`. N'exigez pas le champ `message`,
propre aux jobs de configuration.

```json Response
{
  "success": true,
  "job_id": "YOUR_INTERACTIVE_JOB_ID",
  "status": "stopped"
}
```

## Statuts des jobs de configuration

Les statuts et détails d'erreur suivants concernent uniquement les jobs de
configuration.

| Statut | Signification |
| --- | --- |
| `200` | Le job est arrêté et les checkpoints existants restent disponibles. |
| `202` | L'annulation est en cours pendant que le fournisseur la confirme. |
| `400` | L'ID du job de configuration ou la requête n'est pas valide. |
| `409 training_job_already_finished` | Le job a atteint un état terminal avant l'arrêt. |
| `409 cancellation_unconfirmed` | Le fournisseur n'a pas confirmé l'annulation. Consultez l'état du job, puis réessayez si nécessaire. |
| `422` | Le corps JSON de la requête du job de configuration n'est pas valide. |

## Autorisation des jobs de configuration

Pour les jobs de configuration, cette opération nécessite le rôle Owner, Admin ou Editor de l'équipe. Les autres rôles reçoivent `403 Forbidden`. Le gestionnaire interactif natif utilise l'autorisation de l'appelant du runtime interactif ; ne déduisez pas la RBAC des jobs de configuration de ce chemin partagé.
