`GET /v1/training/jobs/{job_id}/futures/{future_id}`

Chaque appel de travail interactif qui fonctionne renvoie un `future_id`. Sondez l'avenir
jusqu'à ce que son `status` soit `completed`, `failed` ou `cancelled`. Utilisez `wait=true` pour
attendez jusqu'à 25 secondes par demande ; un timeout peut toujours renvoyer un non-terminal
futur. Les résultats sont conservés pendant une heure.

## Demande

<ParamField header="X-API-Key" type="string" required>
  Votre clé API Fastino.
</ParamField>

<ParamField path="job_id" type="string" required>
  ID de travail interactif.
</ParamField>

<ParamField path="future_id" type="string" required>
  L'ID futur est renvoyé lorsque le travail a été mis en file d'attente.
</ParamField>

<ParamField query="wait" type="boolean" default="false">
  Attendez jusqu'à 25 secondes pour un futur inachevé avant de répondre. Répéter
  la demande jusqu'à ce qu'elle se termine.
</ParamField>

<RequestExample>

```bash cURL
curl "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/futures/$FUTURE_ID?wait=true" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

</RequestExample>

## Réponse

<ResponseField name="future_id" type="string">
  L'avenir.
</ResponseField>

<ResponseField name="job_id" type="string">
  Le travail.
</ResponseField>

<ResponseField name="type" type="string">
  `create`, `load`, `forward`, `forward_backward`, `optim_step`, `save` ou `sample`.
</ResponseField>

<ResponseField name="status" type="string">
  `pending`, `running`, `completed`, `failed` ou `cancelled`.
</ResponseField>

<ResponseField name="queue_state" type="string | null">
  Tant qu'il n'est pas terminé : `active` ou `paused_capacity` pendant que la capacité du GPU se réchauffe.
</ResponseField>

<ResponseField name="queue_state_reason" type="string | null">
  Une explication de capacité lisible par l'homme alors que `queue_state` est
  `paused_capacity` ; sinon `null`.
</ResponseField>

<ResponseField name="result" type="any">
  Une fois `completed` :

  - `forward` et `forward_backward` : `loss_fn_outputs` (une entrée de tenseurs par
    donnée, telle que `logprobs`) et `metrics`.
  - `sample` : `sequences`, chacun avec `tokens`, `logprobs` et `stop_reason`,
    plus `prompt_logprobs` sur demande.
  - `save` : le chemin du point de contrôle.
  - Autres types : un accusé de réception.
</ResponseField>

<ResponseField name="error" type="object | null">
  Lorsque `failed` ou `cancelled` : `message`, et `category` (`user` pour un problème
  avec la demande, `server` pour un problème Fastino).
</ResponseField>

```json Pending

  "queue_state_reason": null,

  "error": null

```


</ResponseExample>

| Statut | Signification |
| --- | --- |
| `404` | Le travail ou l'avenir n'existe pas ou appartient à une autre équipe. |
| `410` | L'opération a été perdue ou son résultat conservé a expiré. Soumettez à nouveau l'opération ; un résultat expiré ne peut pas être récupéré. |
