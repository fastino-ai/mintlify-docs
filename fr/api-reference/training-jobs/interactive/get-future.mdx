`GET /v1/training/jobs/{job_id}/futures/{future_id}`

Chaque appel d'un job interactif qui effectue un travail renvoie un `future_id`.
Interrogez le future jusqu'à ce que son `status` soit `completed`, `failed` ou
`cancelled`. Utilisez `wait=true` pour attendre au maximum 25 secondes par
requête ; un délai d'attente expiré peut tout de même renvoyer un future non
terminal. Les résultats sont conservés pendant une heure.

## Requête

<ParamField header="X-API-Key" type="string" required>
  Votre clé API Fastino.
</ParamField>

<ParamField path="job_id" type="string" required>
  ID du job interactif.
</ParamField>

<ParamField path="future_id" type="string" required>
  ID du future renvoyé lors de la mise en file d'attente du travail.
</ParamField>

<ParamField query="wait" type="boolean" default="false">
  Attendre jusqu'à 25 secondes qu'un future inachevé se termine avant de
  répondre. Répétez la requête jusqu'à ce qu'il soit terminé.
</ParamField>

<RequestExample>

```bash cURL
curl "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/futures/$FUTURE_ID?wait=true" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

</RequestExample>

## Réponse

<ResponseField name="future_id" type="string">
  Le future.
</ResponseField>

<ResponseField name="job_id" type="string">
  Le job.
</ResponseField>

<ResponseField name="type" type="string">
  `create`, `load`, `forward`, `forward_backward`, `optim_step`, `save` ou `sample`.
</ResponseField>

<ResponseField name="status" type="string">
  `pending`, `running`, `completed`, `failed` ou `cancelled`.
</ResponseField>

<ResponseField name="queue_state" type="string | null">
  Tant qu'il n'est pas terminé : `active` ou `paused_capacity` pendant le préchauffage de la capacité GPU.
</ResponseField>

<ResponseField name="queue_state_reason" type="string | null">
  Une explication lisible de l'état de la capacité lorsque `queue_state` vaut
  `paused_capacity` ; sinon `null`.
</ResponseField>

<ResponseField name="result" type="any">
  Une fois `completed` :

  - `forward` et `forward_backward` : `loss_fn_outputs` (une entrée de tenseurs par
    datum, comme `logprobs`) et `metrics`.
  - `sample` : `sequences`, chacune avec `tokens`, `logprobs` et `stop_reason`,
    ainsi que `prompt_logprobs` si demandé.
  - `save` : le chemin du checkpoint.
  - Autres types : un accusé de réception.
</ResponseField>

<ResponseField name="error" type="object | null">
  Lorsque `failed` ou `cancelled` : `message`, et `category` (`user` pour un problème
  lié à la requête, `server` pour un problème Fastino).
</ResponseField>

<ResponseExample>

```json Pending
{
  "future_id": "FUTURE_ID",
  "job_id": "SESSION_ID:train:0",
  "type": "forward_backward",
  "status": "pending",
  "queue_state": "paused_capacity",
  "queue_state_reason": null,
  "result": null,
  "error": null
}
```

```json Completed sample
{
  "future_id": "FUTURE_ID",
  "job_id": "SESSION_ID:train:0",
  "type": "sample",
  "status": "completed",
  "queue_state": null,
  "queue_state_reason": null,
  "result": {
    "sequences": [
      {"tokens": [59604, 13, 151645], "logprobs": [-0.21, -0.05, -0.01], "stop_reason": "stop", "topk_logprobs": null}
    ],
    "prompt_logprobs": null,
    "topk_prompt_logprobs": null,
    "prompt_cache_hit_tokens": 0
  },
  "error": null
}
```

</ResponseExample>

| Statut | Signification |
| --- | --- |
| `404` | Le job ou le future n'existe pas ou appartient à une autre équipe. |
| `410` | L'opération a été perdue ou son résultat conservé a expiré. Soumettez à nouveau l'opération ; un résultat expiré ne peut pas être récupéré. |
