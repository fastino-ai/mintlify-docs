`POST /v1/training/jobs/{job_id}/forward-backward`

Calcule la perte d’un lot de données au niveau des tokens et accumule ses gradients. L’[étape d’optimisation](/fr/api-reference/training-jobs/interactive/optim-step) suivante les applique. La réponse est un future ; lisez la perte et les log-probabilités par token via
[`GET /v1/training/jobs/{job_id}/futures/{future_id}`](/fr/api-reference/training-jobs/interactive/get-future).

[`POST /v1/training/jobs/{job_id}/forward`](/fr/api-reference/training-jobs/interactive/forward) utilise le même corps et calcule la perte sans gradients.

## Demande

<ParamField header="X-API-Key" type="string" required>
  Votre clé API Fastino.
</ParamField>

<ParamField path="job_id" type="string" required>
  ID du job interactif.
</ParamField>

<ParamField body="datums" type="object[]" required>
  Un ou plusieurs exemples d’entraînement. Tokenisez-les vous-même avec le tokenizer du modèle de base.

  <Expandable title="properties">
    <ParamField body="model_input" type="object" required>
      `{"chunks": [{"type": "encoded_text", "tokens": [...]}]}`. Les ID des tokens d’entrée, soit N tokens au total.
    </ParamField>
    <ParamField body="loss_fn_inputs" type="object" required>
      Tenseurs par position, chacun `{"data": [...], "dtype": "int64" | "float32"}`
      avec un `shape` en option. Chaque tenseur a N valeurs.

      - `target_tokens` (`int64`, obligatoire) : le token attendu à chaque position,
        généralement, l'entrée est décalée de un vers la gauche.
      - `weights` (`float32`) : perte de poids par position. Utilisez `0` pour l'invite
        positions et `1` pour les positions d'achèvement.
      - `logprobs` et `advantages` (`float32`) : requis par tout sinistre sauf
        `cross_entropy`. `logprobs` sont les probabilités du journal de l'échantillonneur du
        cibles.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="loss_fn" type="string" default="cross_entropy">
  `cross_entropy`, `importance_sampling`, `ppo`, `cispo` ou `dro`.
</ParamField>

<ParamField body="loss_fn_config" type="object">
  Paramètres de perte. `ppo` et `cispo` prennent `clip_low_threshold` et
  `clip_high_threshold` ; `dro` prend `beta`. Les clés inconnues sont rejetées.
</ParamField>

Les tableaux numériques de tokens ci-dessous sont uniquement des espaces réservés à titre d’illustration. Tokenisez votre texte réel avec le tokenizer du `base_model` du job.

<RequestExample>

```bash cURL
curl -X POST "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/forward-backward" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "loss_fn": "cross_entropy",
    "datums": [
      {
        "model_input": {"chunks": [{"type": "encoded_text", "tokens": [151644, 872, 198, 3838]}]},
        "loss_fn_inputs": {
          "target_tokens": {"data": [872, 198, 3838, 30], "dtype": "int64"},
          "weights": {"data": [0, 0, 1, 1], "dtype": "float32"}
        }
      }
    ]
  }'
```

</RequestExample>

## Erreurs

| Statut | Signification |
| --- | --- |
| `400` | `loss_fn` inconnu, un tenseur `target_tokens` non entier, des ID de tokens hors vocabulaire ou la tâche a été arrêtée. |
| `402` | L'équipe n'a plus de crédits ou n'a pas de configuration de paiement valide. |
| `404` | Le travail n'existe pas ou appartient à une autre équipe. |
| `422` | `datums` est vide ou le corps possède un champ inconnu. |

Les problèmes détectés pendant l’exécution du lot, comme une entrée de perte manquante, des longueurs de tenseur incompatibles, une clé `loss_fn_config` inconnue ou une donnée dépassant la limite du modèle, font échouer le future. Son `error.category` vaut `user`.
