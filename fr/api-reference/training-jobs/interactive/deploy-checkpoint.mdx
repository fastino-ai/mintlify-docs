`POST /v1/training/jobs/{job_id}/checkpoints/sampler_weights/{name}/deploy`

Sert l’un des checkpoints sampler du job comme modèle entraîné. Appelez-le avec [`POST /v1/chat/completions`](/fr/api-reference/inference/chat-completions) et `"model": "<model_id>"`. La disponibilité du déploiement est contrôlée par modèle et par environnement. Nemotron 3.5 Super VL (`nvidia/NVIDIA-Nemotron-3.5-Super-VL-120B-A12B-NVFP4`), Nemotron 3.5 Lightning (`nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16`) et Qwen3.6-35B-A3B (`Qwen/Qwen3.6-35B-A3B`) sont actuellement activés.

Le `status` du modèle vaut `deploying` jusqu'à ce que le moteur de service l'ait
chargé, puis `deployed`. Déployer à nouveau le même checkpoint renvoie le même
modèle et son statut actuel : vous pouvez donc répéter l'appel pour suivre la
progression. Si une tentative précédente a échoué, l'appel répété la relance.

## Requête

<ParamField header="X-API-Key" type="string" required>
  Votre clé API Fastino.
</ParamField>

<ParamField path="job_id" type="string" required>
  ID du job interactif.
</ParamField>

<ParamField path="name" type="string" required>
  Nom d'un checkpoint sampler enregistré avec
  [`save-weights-for-sampler`](/fr/api-reference/training-jobs/interactive/save-weights-for-sampler).
</ParamField>

<ParamField body="model_name" type="string">
  Jusqu'à 64 lettres, chiffres, traits d'union et underscores, commençant et se
  terminant par une lettre ou un chiffre. Dérivé du nom du checkpoint s'il est
  omis. Le corps est facultatif.
</ParamField>

<RequestExample>

```bash cURL
curl -X POST "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/checkpoints/sampler_weights/step-000100/deploy" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model_name": "support-replies-v1"}'
```

</RequestExample>

## Réponse

<ResponseField name="model_id" type="string">
  L'ID du modèle entraîné. Transmettez-le sous le nom `model` pour l'inférence.
</ResponseField>

<ResponseField name="job_id" type="string">
  Le job interactif qui a enregistré le checkpoint.
</ResponseField>

<ResponseField name="checkpoint_id" type="string">
  `sampler_weights/<name>`.
</ResponseField>

<ResponseField name="base_model" type="string">
  Le modèle de base du modèle.
</ResponseField>

<ResponseField name="project_id" type="string | null">
  Le projet du job, s'il en a un.
</ResponseField>

<ResponseField name="status" type="string">
  `deploying` ou `deployed`.
</ResponseField>

<ResponseExample>

```json Response
{
  "model_id": "MODEL_ID",
  "job_id": "SESSION_ID:train:0",
  "checkpoint_id": "sampler_weights/step-000100",
  "base_model": "nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16",
  "project_id": null,
  "status": "deploying"
}
```

</ResponseExample>

| Statut | Signification |
| --- | --- |
| `400` | Le serving n’est pas disponible pour le modèle de base, ou le checkpoint n’est pas un adaptateur accepté par le moteur de serving. |
| `404` | Le job ou le checkpoint sampler n'existe pas, appartient à une autre équipe ou ne contient aucun fichier. |
| `409` | Un autre modèle utilise déjà `model_name`, ou le modèle servi à partir de ce checkpoint a été supprimé. Enregistrez les poids sous un nouveau nom pour les déployer à nouveau. |
| `422` | `model_name` n'est pas valide ou le corps comporte un champ inconnu. |
