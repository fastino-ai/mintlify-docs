Les clients natifs créent une tâche `interactive` avec [`POST /v1/training/jobs/create-model`](/fr/api-reference/training-jobs/interactive/create). Les clients Tinker créent le même type via le SDK pris en charge.

`GET /v1/training/jobs/{job_id}/checkpoints`

Renvoie les checkpoints visibles pour un job d'entraînement.

## Requête

<ParamField header="X-API-Key" type="string" required>
  Votre clé API Fastino.
</ParamField>

<ParamField path="job_id" type="string" required>
  UUID d'un job config ou ID de job interactive renvoyé par le SDK pris en charge.
</ParamField>

<RequestExample>

```bash cURL
curl https://api.fastino.ai/v1/training/jobs/YOUR_TRAINING_JOB_ID/checkpoints \
  -H "X-API-Key: $FASTINO_API_KEY"
```

</RequestExample>

## Réponse

<ResponseField name="success" type="boolean">
  Indique si la requête a abouti.
</ResponseField>

<ResponseField name="checkpoints" type="object[]">
  Checkpoints enregistrés. La forme des éléments dépend du type de job.
</ResponseField>

<ResponseField name="count" type="integer">
  Nombre de checkpoints renvoyés.
</ResponseField>

### Job config

Les checkpoints config comprennent `id`, `job_id`, epoch, step, pertes,
métriques, déploiement et horodatages. Leur `id` n'est pas accepté par
l'endpoint de téléchargement des checkpoints interactifs.

<ResponseExample>

```json Response
{
  "success": true,
  "checkpoints": [
    {
      "id": "CHECKPOINT_ID",
      "job_id": "YOUR_TRAINING_JOB_ID",
      "epoch": 5,
      "step": 500,
      "training_loss": 0.12,
      "validation_loss": 0.18,
      "is_deployable": true,
      "is_best": true,
      "is_final": true,
      "created_at": "2026-09-22T20:30:00Z",
      "updated_at": "2026-09-22T20:30:00Z"
    }
  ],
  "count": 1
}
```

</ResponseExample>

### Job interactive

Les jobs interactive renvoient aussi `run_id`. Leurs checkpoints sont triés du
plus récent au plus ancien. Utilisez `checkpoint_id`, par exemple
`sampler_weights/checkpoint-1`, avec
[l'endpoint de téléchargement interactif](/fr/api-reference/training-jobs/download-checkpoint).
N'envoyez pas l'`id` du checkpoint config ni `tinker_path`.

<ResponseExample>

```json Response
{
  "success": true,
  "run_id": "session-1:train:0",
  "checkpoints": [
    {
      "checkpoint_id": "sampler_weights/checkpoint-1",
      "checkpoint_type": "sampler",
      "time": "2026-09-22T20:30:00Z",
      "tinker_path": "tinker://session-1:train:0/sampler_weights/checkpoint-1",
      "size_bytes": 12345,
      "public": false,
      "user_metadata": null,
      "expires_at": null
    }
  ],
  "count": 1
}
```

</ResponseExample>

Un job inconnu ou inaccessible renvoie `404`.
