GLiNER 2.5 Decide est un modèle anglais compact de 340 millions de paramètres, optimisé pour la classification définie par schéma.

## Capacités de classification

- Définir les étiquettes lors de la requête sans réentraîner le modèle à chaque changement de taxonomie.
- Exécuter une classification mono-étiquette lorsqu'une seule étiquette doit l'emporter.
- Exécuter une classification multi-étiquettes lorsque plusieurs étiquettes peuvent s'appliquer.
- Évaluer plusieurs tâches de classification nommées indépendamment en une seule passe avant.
- Renvoyer une ou plusieurs étiquettes sélectionnées avec un niveau de confiance.
- Utiliser `cls_threshold` pour contrôler la sélection dans les tâches multi-étiquettes.
- Utiliser une tâche de classification par défaut du catalogue lorsque `schema` et `response_format` sont tous deux omis.

Les cas d'usage courants incluent l'intention, le routage, le sentiment, la priorité, la modération, les tags, les contrôles opérationnels et les taxonomies de texte personnalisées.

## Caractéristiques de performance

Le checkpoint publié a atteint **38,3 ms p50** sur NVIDIA V100 et **167,3 ms** sur un Intel Xeon à 48 vCPU dans le benchmark publié sur des entrées courtes. Consultez l'[article sur le modèle](https://fastino.ai/blog/gliner-2-5-decide-open-weight-decision-model) pour la configuration du benchmark et la méthodologie.

## Limites du schéma

- Chaque tâche nécessite au moins deux étiquettes.
- `labels` doit être un tableau de chaînes.
- Les objets associant étiquettes et descriptions ne sont pas pris en charge.
- Une tâche de classification accepte uniquement `task`, `labels`, `multi_label`, `cls_threshold` et `top_k`.
- `top_k` est accepté mais n'a actuellement aucun effet.
- `cls_threshold` affecte uniquement la sélection multi-étiquette.
- Les tâches mono-étiquette renvoient toujours l'étiquette ayant le score le plus élevé.

## Limites de décision

- Les étiquettes de classification classique ne sont pas ordonnées. L'ordre des étiquettes ne crée pas d'échelle ordinale.
- Les tâches d'une même requête sont indépendantes.
- La classification classique n'impose pas d'implications, d'exclusions, de relations de cardinalité ni de bornes ordinales entre les tâches.
- Decide ne génère pas d'explications, de conversations ni de texte libre.

Utilisez [GLiNER 2.5 Multi](/fr/concepts/gliner) lorsque l'extraction, la couverture multilingue, les descriptions d'étiquettes ou les relations contraintes entre les tâches sont prioritaires. Utilisez [GLiDE Score](/fr/concepts/glide-score) lorsque votre application a besoin d'une grille explicitement ordonnée.
