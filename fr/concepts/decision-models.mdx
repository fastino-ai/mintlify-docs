Un **modèle de décision** évalue du texte ou l'état structuré d'une application par rapport à des résultats définis par l'appelant et renvoie des décisions structurées — étiquettes, probabilités, scores et confiance — plutôt que de la prose générée.

Utilisez les modèles de décision lorsque le code de l'application doit classifier une entrée, sélectionner une route, noter selon une grille, modérer du contenu ou décider si une action doit être exécutée.

## Modèles de décision et modèles génératifs

|  | Modèle de décision | Modèle génératif |
| --- | --- | --- |
| Idéal pour | Classification, routage, notation, modération et garde-fous | Génération ouverte, conversation, résumé et code |
| Sortie | Réponses structurées sur des résultats définis par l'appelant | Texte généré ou appels d'outils |
| Incertitude | Probabilités et confiance explicites | Nécessite généralement une calibration ou une validation supplémentaire |
| Modèle d'application | Agir, router ou escalader à partir d'un résultat borné | Générer, expliquer, planifier ou transformer du contenu |

Les deux types de modèles peuvent fonctionner ensemble. Un modèle de décision peut classifier une requête, sélectionner un agent ou un modèle, ou conditionner une action avant qu'un modèle génératif produise un résultat ouvert.

## Pourquoi utiliser un modèle de décision

- **Structuré par construction** — le code en aval reçoit une réponse bornée plutôt que de la prose qui doit être analysée.
- **Résultats définis par l'appelant** — votre application contrôle les étiquettes, routes ou niveaux autorisés.
- **Incertitude explicite** — les probabilités et la confiance permettent d'automatiser les cas clairs et d'envoyer les cas ambigus vers une voie de repli ou de revue.
