Évaluez GLiNER 2.5 Decide sur des exemples étiquetés issus de votre application avant d'utiliser ses classifications pour déclencher des actions en production.

## Comprendre le comportement des seuils

`cls_threshold` s'applique uniquement aux tâches avec `multi_label: true` :

```json
{
  "task": "topics",
  "labels": ["billing", "technical", "account", "security"],
  "multi_label": true,
  "cls_threshold": 0.5
}
```

- Augmentez le seuil pour renvoyer moins d'étiquettes et favoriser généralement la précision.
- Diminuez le seuil pour renvoyer davantage d'étiquettes et favoriser généralement le rappel.
- Les tâches mono-étiquette renvoient toujours l'étiquette ayant le score le plus élevé ; `cls_threshold` ne modifie pas leur sélection.
- `cls_threshold` est un paramètre d'inférence. Il n'affecte pas l'entraînement.

## Constituer un jeu d'évaluation

Utilisez des exemples représentatifs du trafic de production, notamment :

- Des entrées courantes pour chaque étiquette
- Des étiquettes rares mais importantes
- Des entrées ambiguës proches des frontières entre catégories
- Des entrées qui doivent recevoir plusieurs étiquettes
- Des entrées qui ne doivent produire aucun résultat multi-étiquette au seuil sélectionné
- Des entrées hors domaine ou mal formées que votre application peut rencontrer

Conservez les données d'évaluation séparément des données de fine-tuning.

## Mesurer le comportement requis par votre application

Pour les tâches mono-étiquette, examinez l'exactitude globale et les erreurs par étiquette. Une matrice de confusion aide à détecter les étiquettes que le modèle confond fréquemment.

Pour les tâches multi-étiquettes, mesurez la précision, le rappel et le score F1 à la fois globalement et par étiquette. Examinez également :

- Les faux positifs qui déclenchent des actions incorrectes
- Les faux négatifs qui omettent des actions requises
- Le nombre d'étiquettes sélectionnées par entrée
- La fréquence des sélections vides
- Les résultats proches de votre seuil

## Sélectionner un seuil

1. Exécutez le jeu d'évaluation et conservez chaque étiquette sélectionnée ainsi que son niveau de confiance.
2. Testez plusieurs seuils candidats.
3. Comparez la précision, le rappel et l'impact métier.
4. Choisissez un seuil par tâche lorsque les coûts d'erreur diffèrent selon les tâches.
5. Réexécutez l'évaluation après avoir modifié les étiquettes, les données ou le modèle.

Ne supposez pas que `0.5` convient universellement. Pour les actions à fort impact, utilisez des seuils d'automatisation prudents et conservez une voie de revue ou de repli.

## Effectuer un fine-tuning pour votre domaine

Commencez avec des étiquettes définies à l'exécution et évaluez d'abord le modèle de base. Procédez au fine-tuning lorsque l'évaluation représentative montre que les modifications de schéma et l'ajustement des seuils n'atteignent pas la qualité requise pour votre domaine.

### 1. Confirmer la cible d'entraînement

Interrogez le [catalogue des modèles de base](/fr/api-reference/training/base-models) et vérifiez que le modèle de classification sélectionné prend en charge le type d'entraînement que vous souhaitez utiliser.

### 2. Préparer les données de classification

Stockez un objet JSON par ligne. Utilisez `label` pour les exemples mono-étiquette :

```jsonl
{"text":"The setup was straightforward.","label":"positive"}
{"text":"The application crashes during sign in.","label":"negative"}
```

Utilisez `labels` pour les exemples multi-étiquettes :

```jsonl
{"text":"The app crashes on login and I need help urgently.","labels":["technical_issue","login_problem","urgent"]}
```

Utilisez des noms d'étiquettes stables qui correspondent à la taxonomie employée par votre schéma d'inférence. Incluez des exemples représentatifs pour chaque étiquette et conservez un jeu d'évaluation distinct.

### 3. Lancer et suivre l'entraînement

Créez une tâche d'entraînement avec le jeu de données préparé et un modèle de base de classification pouvant être entraîné. Choisissez uniquement les paramètres d'entraînement pris en charge par la recette de ce modèle.

<Card title="Tâches d'entraînement" icon="activity" href="/fr/training">
  Soumettez une tâche, suivez son état, examinez les métriques et checkpoints, puis récupérez l'artefact obtenu.
</Card>

### 4. Évaluer le résultat entraîné

Comparez le modèle entraîné au modèle de base sur le même jeu de données réservé :

- Exactitude globale et par étiquette pour les tâches mono-étiquette
- Précision, rappel et score F1 pour les tâches multi-étiquettes
- Erreurs sur les étiquettes rares et à fort impact
- Comportement près des seuils de production
- Latence et exigences opérationnelles

Ne sélectionnez pas un checkpoint en vous fondant uniquement sur la perte d'entraînement. Évaluez le comportement de classification que votre application utilisera.

### 5. Utiliser le modèle entraîné

Une fois le checkpoint sélectionné déployable, utilisez son identifiant de modèle avec l'endpoint d'inférence pris en charge et conservez le même schéma de classification que celui attendu par votre application. Revalidez les seuils, car le comportement de la confiance peut changer après le fine-tuning.
