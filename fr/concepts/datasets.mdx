Les jobs d'entraînement référencent des datasets prêts par leur nom. Préparez un fichier JSONL, importez-le via
l'API de datasets en deux étapes, puis vérifiez que la version traitée existe avant d'appeler
`POST /v1/training/jobs`.

## Choisir un format de dataset

Chaque ligne du fichier doit être un objet JSON. Utilisez une structure cohérente dans tout le
dataset.

### Reconnaissance d'entités nommées

Utilisez `text` avec une liste `entities` de paires `[span, label]`. Chaque span doit apparaître mot pour mot
dans le texte. Incluez des exemples négatifs avec une liste vide.

```jsonl
{"text":"Ada Lovelace worked in London.","entities":[["Ada Lovelace","PERSON"],["London","LOCATION"]]}
{"text":"No tagged entities here.","entities":[]}
```

### Classification

Utilisez `label` pour des données à étiquette unique ou `labels` pour des données
multi-étiquettes. Utilisez le même champ dans chaque ligne.

```jsonl
{"text":"The setup was straightforward.","label":"positive"}
{"text":"The request needs technical help.","label":"technical"}
```

### Décodeur

Définissez `dataset_type` sur `decoder` et donnez à chaque ligne un tableau
`messages` avec les rôles et le contenu du chat.

```jsonl
{"messages":[{"role":"user","content":"What is 2+2?"},{"role":"assistant","content":"4"}]}
```

<Note>
  Les jobs de configuration n'acceptent pas les modèles de base décodeurs : un
  dataset de décodeur ne peut donc pas lancer un
  [job de configuration](/fr/api-reference/training-jobs/create). Pour
  entraîner un décodeur, tokenisez vos exemples et traitez-les dans un
  [job interactif](/fr/training/decoder-quickstart).
</Note>

## Importer un dataset

### 1. Réserver une URL d'import

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/upload/url \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "dataset_name": "docs-example-ner",
    "filename": "training.jsonl",
    "dataset_type": "ner"
  }' | tee dataset-upload.json

export PRESIGNED_URL="$(jq -r '.presigned_url' dataset-upload.json)"
export DATASET_ID="$(jq -r '.dataset_id' dataset-upload.json)"
export DATASET_VERSION="$(jq -r '.version_number' dataset-upload.json)"
```

La réponse contient une `presigned_url` de courte durée, un `dataset_id` et un
`version_number`. Les commandes ci-dessus conservent ces trois valeurs.
Importez les octets exacts du fichier vers l'URL présignée :

```bash
curl --fail-with-body -X PUT \
  -H "Content-Type: application/octet-stream" \
  --upload-file training.jsonl "$PRESIGNED_URL"
```

### 2. Traiter le fichier importé

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/upload/process \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d "$(jq -n --arg dataset_id "$DATASET_ID" '{dataset_id: $dataset_id}')"
```

Le traitement renvoie `202`. Interrogez le dataset par son nom et sélectionnez
l'entrée dont le `version_number` correspond exactement à la réponse de
l'import. Continuez jusqu'à ce que le `status` de cette version soit `ready` ou
`failed`. S'il vaut `failed`, arrêtez et affichez son `processing_error` ;
n'utilisez pas cette version pour l'entraînement.

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/docs-example-ner \
  -H "X-API-Key: $FASTINO_API_KEY"
```

## Lancer l'entraînement

Transmettez le nom exact du dataset à l'[endpoint de création de
jobs d'entraînement](/fr/api-reference/training-jobs/create) :

```json
{
  "model_name": "my-ner-model",
  "base_model": "fastino/gliner2-multi-v1",
  "datasets": [
    {"name": "docs-example-ner", "version": "VERSION_NUMBER_FROM_UPLOAD"}
  ],
  "training_type": "lora"
}
```

Utilisez `GET /v1/base-models?supports_training=true` juste avant la soumission pour sélectionner un
modèle de base actuellement entraînable.

## Blocages courants

| Statut | Cause | Action |
| --- | --- | --- |
| `401` | Clé d'API manquante ou invalide | Envoyez `X-API-Key: $FASTINO_API_KEY` |
| `404` | Le nom du dataset n'existe pas | Vérifiez le nom exact et attendez la fin du traitement |
| `failed` | Échec de la validation asynchrone du contenu | Lisez `processing_error`, corrigez le JSONL et importez une nouvelle version |
| `422` | La structure de la requête a été rejetée avant le traitement | Corrigez les champs de la requête avant de réessayer |

N'importez pas la structure interne `{"input": ..., "output": ...}` de l'entraîneur GLiNER. Convertissez-la
d'abord au format public `text` plus `entities`.
