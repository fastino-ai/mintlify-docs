Ce tutoriel connecte le SDK Tinker à Fastino, vérifie l'accès de votre équipe et
exécute deux petites étapes d'apprentissage par renforcement sur GSM8K.

<Warning>
  La vérification des capacités est en lecture seule. La commande d'entraînement
  soumet des opérations d'échantillonnage et d'entraînement facturables, puis
  stocke un checkpoint.
</Warning>

## 1. Configurer votre clé d'API

1. **Créez un compte [Fastino](https://agent.fastino.ai/)**
2. **Obtenez votre clé d'API** dans les [paramètres](https://agent.fastino.ai/api-keys)

Définissez votre clé comme variable d'environnement afin que les exemples
ci-dessous fonctionnent tels quels :

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="your_api_key_here"
```

```powershell Windows
$env:FASTINO_API_KEY = "your_api_key_here"
```

</CodeGroup>

Les clés Fastino commencent par `fast_sk_`. L'accès à l'API RL doit également
être activé pour votre équipe. Installer le SDK Tinker ne donne pas accès à
l'API.

## 2. Créer un environnement Python

Vous avez besoin de Python 3.11 ou d'une version ultérieure.

<CodeGroup>

```bash uv · macOS/Linux
uv init fastino-rl
cd fastino-rl
uv add "tinker==0.32.0" "tinker-cookbook[math-rl]"
source .venv/bin/activate
```

```powershell uv · Windows
uv init fastino-rl
cd fastino-rl
uv add "tinker==0.32.0" "tinker-cookbook[math-rl]"
.\.venv\Scripts\Activate.ps1
```

```bash pip · macOS/Linux
mkdir fastino-rl && cd fastino-rl
python -m venv .venv
source .venv/bin/activate
pip install "tinker==0.32.0" "tinker-cookbook[math-rl]"
```

```powershell pip · Windows
mkdir fastino-rl
cd fastino-rl
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install "tinker==0.32.0" "tinker-cookbook[math-rl]"
```

</CodeGroup>

## 3. Configurer le client Tinker

Configurez le SDK Tinker pour utiliser Fastino et dérivez la variable
d'environnement qu'il attend :

<CodeGroup>

```bash macOS/Linux
export TINKER_API_KEY="tml-${FASTINO_API_KEY}"
export TINKER_BASE_URL="https://api.fastino.ai/tinker"
```

```powershell Windows
$env:TINKER_API_KEY = "tml-$env:FASTINO_API_KEY"
$env:TINKER_BASE_URL = "https://api.fastino.ai/tinker"
```

</CodeGroup>

Ne créez pas de seconde clé. `TINKER_API_KEY` est le nom de variable
d'environnement utilisé par le SDK Tinker, et `tml-` est le préfixe de
compatibilité qu'il attend. Votre clé Fastino reste l'identifiant qui
authentifie la requête. Ne la validez pas dans le contrôle de version.

## 4. Vérifier l'accès

Créez `check_rl_api.py` :

```python
import tinker


TUTORIAL_MODEL = "Qwen/Qwen3.6-35B-A3B"
client = tinker.ServiceClient()
try:
    capabilities = client.get_server_capabilities()
    model_names = {model.model_name for model in capabilities.supported_models}
    if TUTORIAL_MODEL not in model_names:
        available = ", ".join(sorted(model_names)) or "none"
        raise RuntimeError(
            f"{TUTORIAL_MODEL} is not available; available models: {available}. "
            "Stop before billable work and ask Fastino about tutorial-model access."
        )
    print(f"Ready to use {TUTORIAL_MODEL}")
except KeyboardInterrupt:
    client.close("interrupted").result()
    raise
except Exception:
    client.close("errored").result()
    raise
else:
    client.close("success").result()
```

Exécutez-le :

```bash
python check_rl_api.py
```

Une réponse réussie confirme que le modèle utilisé ci-dessous est actuellement
disponible pour votre équipe. Utilisez la réponse de capacités comme source de
vérité lors du choix d'un modèle.

Si l'appel renvoie `404 Not Found`, vérifiez que l'URL de base se termine par
`/tinker`. Si c'est le cas, demandez à Fastino d'activer l'accès à l'API RL pour
votre équipe.

## 5. Exécuter deux étapes RL

Le package installé comprend une boucle minimale de type GRPO. Elle
échantillonne plusieurs réponses pour chaque problème GSM8K, évalue la réponse
numérique encadrée, centre les récompenses au sein de chaque groupe et applique
une mise à jour par échantillonnage d'importance.

Commencez par une tâche volontairement petite :

<CodeGroup>

```bash macOS/Linux
python -m tinker_cookbook.recipes.rl_loop \
  base_url=https://api.fastino.ai/tinker \
  model_name=Qwen/Qwen3.6-35B-A3B \
  batch_size=4 \
  group_size=4 \
  max_steps=2 \
  save_every=1 \
  log_path=./runs/first-fastino-rl
```

```powershell Windows
python -m tinker_cookbook.recipes.rl_loop `
  base_url=https://api.fastino.ai/tinker `
  model_name=Qwen/Qwen3.6-35B-A3B `
  batch_size=4 `
  group_size=4 `
  max_steps=2 `
  save_every=1 `
  log_path=./runs/first-fastino-rl
```

</CodeGroup>

La première exécution télécharge le jeu de données GSM8K et le tokenizer.
Pendant l'exécution, la recette affiche la progression de
l'échantillonnage, les métriques de récompense et celles de l'optimiseur. À la
fin, il enregistre un checkpoint final de l'état et les métadonnées locales de
l'exécution sous le `log_path` choisi.

<Note>
  `Qwen/Qwen3.6-35B-A3B` est utilisé ici, car il est pris en charge par le
  contrat actuel de l'API RL. Ne copiez pas le nom d'un modèle depuis un autre
  environnement Tinker sans vérifier d'abord la réponse de capacités.
</Note>

## 6. Confirmer que l'apprentissage a bien été effectué

Vérifiez que la sortie de la commande contient ces trois signaux :

- Un lot d'échantillonnage s'est terminé.
- L'exécution a journalisé une valeur `reward/total`.
- Une étape d'optimisation a renvoyé des métriques.

Une récompense constante sur deux étapes ne constitue pas un échec. Cette petite
exécution vérifie le parcours de bout en bout, et non la convergence du modèle.

## 7. Fermer les clients dans votre propre code

La recette gère le cycle de vie de son processus. Dans les applications
de longue durée, fermez chaque `ServiceClient` une fois l'exécution terminée :

```python
service_client.close("success").result()
```

La fermeture du client met fin à sa session et libère les entraînements actifs.
Les checkpoints enregistrés restent disponibles conformément à leurs paramètres
de rétention.

Utilisez `success` uniquement après une exécution terminée. Fermez avec
`errored` lorsqu'une exception se propage, et avec `interrupted` après une
annulation ou un arrêt.
