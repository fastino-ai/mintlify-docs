---
title: "Migrer depuis Tinker"
description: "Migrez un workload existant utilisant le SDK Tinker vers l'API RL de Fastino."
---

L'API RL de Fastino implémente un sous-ensemble documenté du contrat du SDK
Tinker. La forme des appels du SDK peut rester inchangée lorsque tous les
éléments de la checklist de compatibilité sont satisfaits. Une migration
remplace quatre points d'intégration :

1. Point de terminaison
2. Identifiant
3. Nom du modèle
4. Hypothèses opérationnelles

Ce guide considère le programme existant comme le test d'acceptation. Modifiez
d'abord la connexion, exécutez une petite tâche, puis ajustez l'algorithme.

## 1. Épingler une version testée du SDK

Fastino teste actuellement le contrat avec :

```text
tinker==0.32.0
```

La version minimale du client prise en charge est `0.25.0`. Épinglez `0.32.0`
pendant la migration afin qu'une mise à niveau sans rapport du SDK ne masque pas
un problème de connexion ou de compatibilité.

<CodeGroup>

```bash uv
uv add "tinker==0.32.0"
```

```bash pip
pip install "tinker==0.32.0"
```

</CodeGroup>

## 2. Remplacer le point de terminaison et la clé

Le code existant qui construit `tinker.ServiceClient()` sans arguments
explicites peut être migré uniquement à l'aide de variables d'environnement :

```bash
export FASTINO_API_KEY="fast_sk_..."
export TINKER_API_KEY="tml-${FASTINO_API_KEY}"
export TINKER_BASE_URL="https://api.fastino.ai/tinker"
```

La partie `tml-` est un préfixe de compatibilité utilisé par le SDK Tinker.
Fastino authentifie la clé `fast_sk_...` qu'il contient.

Si votre application transmet explicitement les valeurs, effectuez la
modification équivalente :

```python
import os

import tinker


service_client = tinker.ServiceClient(
    base_url="https://api.fastino.ai/tinker",
    api_key=f"tml-{os.environ['FASTINO_API_KEY']}",
)
```

N'ajoutez pas `/api/v1`. Le SDK ajoute son propre chemin de route.

## 3. Sélectionner un modèle pris en charge par Fastino

Ne supposez pas qu'un modèle disponible dans un autre environnement Tinker est
disponible sur Fastino. Interrogez les capacités pendant la migration :

```python
capabilities = service_client.get_server_capabilities()
for model in capabilities.supported_models:
    print(model.model_name)
```

Utilisez la réponse de capacités active pour prendre vos décisions en
production. Comparez le résultat avec la
[compatibilité du client](/fr/rl-api/compatibility) pour connaître les fenêtres de
contexte et les limites LoRA.

## 4. Comparer la boucle d'apprentissage

Ces appels principaux conservent leur forme dans le SDK Tinker :

```python
training_client = service_client.create_lora_training_client(
    base_model=model_name,
    rank=32,
)

sampler_path = training_client.save_weights_for_sampler(
    "migration-smoke"
).result().path
sampling_client = service_client.create_sampling_client(
    model_path=sampler_path
)
sample_future = sampling_client.sample(prompt, num_samples, sampling_params)
sample_result = sample_future.result()

train_future = training_client.forward_backward(
    datums,
    loss_fn="importance_sampling",
)
optim_future = training_client.optim_step(adam_params)
train_result = train_future.result()
optim_result = optim_future.result()
```

La forme des appels ci-dessus est compatible. Avant de réutiliser la boucle qui
les entoure, vérifiez que son modèle, son rang LoRA, le nom de sa fonction de
perte, les champs de ses datums, ses paramètres d'échantillonnage, son
comportement de checkpoint et ses dépendances opérationnelles sont tous
indiqués comme pris en charge dans la
[référence de compatibilité](/fr/rl-api/compatibility).

Le renderer, la construction du prompt, les fonctions de récompense, le calcul
des avantages, la mise en lots et les critères d'arrêt s'exécutent dans votre
application. Ne les conservez pour le premier test de migration qu'une fois
cette checklist satisfaite.

## 5. Vérifier une petite exécution

Effectuez une exécution d'acceptation peu coûteuse avant de rétablir la taille
des lots de production :

- Récupérez les capacités.
- Créez un client d'entraînement LoRA.
- Échantillonnez un petit groupe.
- Soumettez une opération avant-arrière.
- Appliquez une étape d'optimisation.
- Enregistrez un checkpoint d'état.
- Créez un nouveau client d'entraînement depuis ce checkpoint.
- Fermez le client de service.

Comparez les résultats sémantiques, et non les valeurs exactes en virgule
flottante. Des modèles et infrastructures pris en charge différents peuvent
produire des échantillons et des métriques différents.

## 6. Examiner les différences opérationnelles

| Domaine | Action de migration |
| --- | --- |
| Accès | L'accès à l'API RL est activé par équipe Fastino. Une équipe pour laquelle il est désactivé reçoit `404 Not Found`. |
| Authentification | Utilisez une clé d'API Fastino encapsulée avec le préfixe de compatibilité `tml-`. |
| Modèles | Choisissez un modèle dans la réponse de capacités. Ne conservez pas un modèle source non pris en charge. |
| Cycle de vie de la session | Fermez `ServiceClient` pour libérer les exécutions actives. |
| Récupération | Conservez des checkpoints explicites comme limite de récupération contrôlée par votre application. |
| Résultats des futures | Récupérez et conservez les résultats terminés dans un délai d'une heure. |
| Annulation | L'annulation s'applique à l'échantillonnage, et non aux opérations d'entraînement individuelles. |
| Checkpoints publiés | La publication ne permet pas à une autre équipe Fastino de charger un checkpoint. |
| Exportation des traces | Supprimez le code qui dépend de l'exportation des traces Tinker. Elle n'est pas prise en charge. |
| Entrées d'audit | Ne dépendez pas de l'historique d'audit. Les appels d'audit ne renvoient aucune entrée. |

Consultez la [compatibilité du client](/fr/rl-api/compatibility) pour les fonctions
de perte et les méthodes prises en charge. Consultez le
[comportement à l'exécution et les erreurs](/fr/rl-api/runtime) pour les
nouvelles tentatives, la facturation, les checkpoints et les échecs.

## Checklist de migration

- [ ] Épingler `tinker==0.32.0`.
- [ ] Définir `TINKER_BASE_URL` sur `https://api.fastino.ai/tinker`.
- [ ] Encapsuler la clé Fastino sous la forme `tml-fast_sk_...`.
- [ ] Confirmer que l'équipe a accès à l'API RL.
- [ ] Remplacer les noms de modèles non pris en charge.
- [ ] Exécuter une étape d'échantillonnage et d'entraînement.
- [ ] Enregistrer et restaurer un checkpoint d'état.
- [ ] Supprimer les dépendances aux traces ou aux données d'audit non prises en charge.
- [ ] Fermer le client de service.
- [ ] Augmenter la taille du workload uniquement après la réussite de l'exécution d'acceptation.
