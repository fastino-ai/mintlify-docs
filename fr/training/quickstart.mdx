Ce démarrage rapide couvre les deux voies de l'API d'entraînement. Utilisez
l'entraînement géré lorsque vous souhaitez que Fastino exécute la boucle.
Utilisez une boucle d'entraînement personnalisée lorsque votre application doit
contrôler l'échantillonnage, les récompenses et les mises à jour du modèle.

## 1. S'authentifier

1. Créez un [compte Fastino](https://agent.fastino.ai/).
2. Ouvrez la page des [clés API](https://agent.fastino.ai/api-keys).
3. Créez une clé et copiez-la lorsqu'elle s'affiche.

Enregistrez la clé dans une variable d'environnement :

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="fast_sk_..."
```

```powershell Windows
$env:FASTINO_API_KEY = "fast_sk_..."
```

</CodeGroup>

Envoyez cette clé sous la forme `X-API-Key: $FASTINO_API_KEY`. Consultez
[Authentification](/fr/authentication) pour le contrat d'authentification
complet.

## 2. Choisir une voie

| Objectif | Voie |
| --- | --- |
| Fournir des données et une configuration, puis laisser Fastino exécuter l'entraînement | [Entraînement géré](#managed-training) |
| Contrôler l'échantillonnage, les récompenses et les mises à jour dans votre application | [Boucle d'entraînement personnalisée](#custom-training-loop) |

## Entraînement géré

### 3. Préparer un dataset

[Importez et traitez un dataset d'entraînement](/fr/concepts/datasets), puis
attendez que sa version soit `ready`.

### 4. Choisir un modèle

Interrogez le catalogue actif avant la soumission :

```bash
curl "https://api.fastino.ai/v1/base-models?supports_training=true" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

Conservez l'ID du modèle sélectionné.

### 5. Créer le job

```bash
curl -X POST "https://api.fastino.ai/v1/training/jobs" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "model_name": "my-trained-model",
    "base_model": "MODEL_ID_FROM_CATALOG",
    "datasets": [
      {"name": "my-ready-dataset", "version": "VERSION_NUMBER"}
    ],
    "training_type": "lora"
  }'
```

Conservez l'`id` renvoyé. Il s'agit du `job_id` utilisé par chaque route propre
à un job. Réutilisez la même valeur `Idempotency-Key` uniquement lorsque vous
réessayez exactement cette requête de création.

### 6. Interroger le job

```bash
curl "https://api.fastino.ai/v1/training/jobs/JOB_ID" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

Pour les jobs de configuration :

- `status` est la valeur persistée du cycle de vie, telle que `errored`.
- `normalized_status` est la valeur stable d'interrogation, telle que `failed`.
- `is_terminal_status` indique à votre client quand arrêter les interrogations.
- `error_message` décrit un échec lorsque cette information est disponible.

Continuez jusqu'à ce que `is_terminal_status` soit `true`, puis examinez le
statut final, les checkpoints, les logs et l'admissibilité au déploiement.

## Boucle d'entraînement personnalisée

Choisissez une interface prise en charge :

- Les clients JSON natifs appellent
  [`POST /v1/training/jobs/create-model`](/fr/api-reference/training-jobs/interactive/create-model),
  mettent en file les opérations de modèle sous `/v1/training/jobs/{job_id}` et
  interrogent chaque `future_id` renvoyé jusqu'à l'état `completed`, `failed`
  ou `cancelled`.
- Les programmes Tinker existants conservent `tinker==0.32.0` et utilisent la
  configuration ci-dessous.

Les clients natifs n'envoient ni `seq_id` ni signal de présence. Le serveur
attribue l'ordre des opérations et maintient la session interne active. Une
requête avec `wait=true` attend au maximum 25 secondes. Le client doit donc
continuer à interroger une opération non finale. Consultez
[Construire une boucle d'entraînement personnalisée](/fr/training/training-loop)
pour la séquence des routes natives.

### Voie JSON native

1. Appelez
   [`POST /v1/training/jobs/create-model`](/fr/api-reference/training-jobs/interactive/create-model)
   avec `base_model`, ou avec `from_checkpoint` et `load_optimizer`.
2. Interrogez le `future_id` de création via
   [Obtenir une future](/fr/api-reference/training-jobs/interactive/get-future)
   jusqu'à l'état `completed`, `failed` ou `cancelled`.
3. Mettez en file
   [forward-backward](/fr/api-reference/training-jobs/interactive/forward-backward)
   et [une étape d'optimiseur](/fr/api-reference/training-jobs/interactive/optim-step).
   Interrogez chaque `future_id` jusqu'à un état final avant l'étape
   dépendante suivante.
4. [Enregistrez les poids du sampler](/fr/api-reference/training-jobs/interactive/save-sampler-weights)
   et interrogez l'future d'enregistrement jusqu'à un état final.
5. Arrêtez le job via
   [l'opération d'arrêt partagée](/fr/api-reference/training-jobs/stop).
6. [Échantillonnez depuis le checkpoint enregistré](/fr/api-reference/training-jobs/interactive/sample)
   après l'arrêt, puis interrogez l'opération d'échantillonnage jusqu'à un état
   final.

Seule une future d'échantillonnage en file ou en cours peut être annulée. Un refus HTTP
signifie que le serveur n'a pas mis l'opération en file. Une opération en file
peut se terminer avec `status: "failed"`.

### Voie du SDK Tinker

La voie Tinker nécessite Python 3.11 ou une version ultérieure. Ne construisez
pas de routes enfants privées de compatibilité.

### 3. Installer le client testé

<CodeGroup>

```bash uv
uv init fastino-training
cd fastino-training
uv add "tinker==0.32.0"
```

```bash pip
mkdir fastino-training && cd fastino-training
python -m venv .venv
source .venv/bin/activate
pip install "tinker==0.32.0"
```

```powershell pip · Windows
mkdir fastino-training
cd fastino-training
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install "tinker==0.32.0"
```

</CodeGroup>

### 4. Configurer le client

`TINKER_CREDENTIAL_CMD` est exécuté à chaque demande de token et doit afficher
un seul identifiant non vide.

<CodeGroup>

```bash macOS/Linux
export TINKER_BASE_URL="https://api.fastino.ai/v1/training/compat/tinker"
export TINKER_CREDENTIAL_CMD='printf "%s\n" "$FASTINO_API_KEY"'
```

```powershell Windows
$env:TINKER_BASE_URL = "https://api.fastino.ai/v1/training/compat/tinker"
$env:TINKER_CREDENTIAL_CMD = 'powershell -NoProfile -Command "[Console]::Out.WriteLine($env:FASTINO_API_KEY)"'
```

</CodeGroup>

Utilisez une clé Fastino normale commençant par `fast_sk_`. Les identifiants
commençant par `tml-` sont rejetés. Ne définissez pas `TINKER_API_KEY`.

### 5. Choisir un modèle activé

Appelez `ServiceClient.get_server_capabilities()` et sélectionnez un modèle
activé. Capabilities indique les noms et longueurs de contexte, mais pas les
rangs LoRA, optimiseurs, pertes, méthodes facultatives ou limites d'opération.
Fastino accepte actuellement les rangs LoRA de 1 à 32 et utilise 32 par défaut.

<CodeGroup>

```bash macOS/Linux
export FASTINO_TRAINING_MODEL="<model from capabilities>"
export FASTINO_TRAINING_LORA_RANK="32"
```

```powershell Windows
$env:FASTINO_TRAINING_MODEL = "<model from capabilities>"
$env:FASTINO_TRAINING_LORA_RANK = "32"
```

</CodeGroup>

### 6. Créer le job et échantillonner

Créez `quickstart.py` :

```python
import os

import tinker


service_client = tinker.ServiceClient()
outcome = "errored"
try:
    capabilities = service_client.get_server_capabilities()
    print(capabilities)

    training_client = service_client.create_lora_training_client(
        base_model=os.environ["FASTINO_TRAINING_MODEL"],
        rank=int(os.environ["FASTINO_TRAINING_LORA_RANK"]),
    )

    job_id = training_client.get_info().model_id
    print(f"TRAINING_JOB_ID={job_id}")

    checkpoint = training_client.save_weights_for_sampler(
        "quickstart-sampler",
        ttl_seconds=24 * 60 * 60,
    ).result()
    sampling_client = service_client.create_sampling_client(
        model_path=checkpoint.path
    )

    tokenizer = sampling_client.get_tokenizer()
    prompt_tokens = tokenizer.apply_chat_template(
        conversation=[
            {
                "role": "user",
                "content": "Explain the purpose of a reward function in one sentence.",
            }
        ],
        add_generation_prompt=True,
        return_dict=False,
    )
    result = sampling_client.sample(
        prompt=tinker.types.ModelInput.from_ints(prompt_tokens),
        num_samples=1,
        sampling_params=tinker.types.SamplingParams(max_tokens=64),
    ).result()

    print(tokenizer.decode(result.sequences[0].tokens))
except KeyboardInterrupt:
    outcome = "interrupted"
    raise
else:
    outcome = "success"
finally:
    service_client.close(outcome).result()
```

Exécutez le script :

```bash
python quickstart.py
```

Copiez la valeur affichée après `TRAINING_JOB_ID=`.

### 7. Vérifier le job canonique

<CodeGroup>

```bash macOS/Linux
export TRAINING_JOB_ID="<ID printed by quickstart.py>"
curl --fail-with-body \
  -H "X-API-Key: $FASTINO_API_KEY" \
  "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID"
```

```powershell Windows
$env:TRAINING_JOB_ID = "<ID printed by quickstart.py>"
Invoke-RestMethod `
  -Headers @{ "X-API-Key" = "$env:FASTINO_API_KEY" } `
  -Uri "https://api.fastino.ai/v1/training/jobs/$env:TRAINING_JOB_ID"
```

</CodeGroup>

La réponse décrit le même job que celui créé par
`create_lora_training_client(...)`. Continuez à utiliser le client SDK pour les
opérations sur le modèle et l'API canonique des jobs pour les lectures de jobs
documentées. Les clients JSON natifs utilisent les pages publiques des
opérations interactives.
