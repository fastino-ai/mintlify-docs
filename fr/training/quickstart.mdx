Ce démarrage rapide couvre les deux voies de l'API d'entraînement. Utilisez
l'entraînement géré pour fine-tuner un encodeur GLiNER pendant que Fastino
exécute la boucle. Utilisez une boucle d'entraînement personnalisée pour
entraîner un LLM décodeur lorsque votre application doit contrôler
l'échantillonnage, les récompenses et les mises à jour du modèle.

## 1. S'authentifier

1. Créez un [compte Fastino](https://agent.fastino.ai/).
2. Ouvrez la page des [clés API](https://agent.fastino.ai/api-keys).
3. Créez une clé et copiez-la lorsqu'elle s'affiche.

Enregistrez la clé dans une variable d'environnement :

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="fast_sk_..."
```

```powershell Windows
$env:FASTINO_API_KEY = "fast_sk_..."
```

</CodeGroup>

Envoyez cette clé sous la forme `X-API-Key: $FASTINO_API_KEY`. Consultez
[Authentification](/fr/authentication) pour le contrat d'authentification
complet.

## 2. Choisir une voie

| Objectif | Voie |
| --- | --- |
| Fine-tuner un encodeur GLiNER à partir d'un dataset et laisser Fastino exécuter l'entraînement | [Entraînement géré](#managed-training) |
| Entraîner un LLM décodeur et contrôler l'échantillonnage, les récompenses et les mises à jour dans votre application | [Boucle d'entraînement personnalisée](#custom-training-loop) |

## Entraînement géré

### 3. Préparer un dataset

[Importez et traitez un dataset d'entraînement](/fr/concepts/datasets), puis
attendez que sa version soit `ready`.

### 4. Choisir un modèle

L'entraînement géré prend en charge `fastino/gliner2-multi-v1` et
`fastino/GLiNER-2.5-Decide`. Interrogez le catalogue actif avant la soumission :

```bash
curl "https://api.fastino.ai/v1/base-models?supports_training=true" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

Conservez l'ID du modèle sélectionné.

### 5. Créer le job

```bash
curl -X POST "https://api.fastino.ai/v1/training/jobs" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "model_name": "my-trained-model",
    "base_model": "MODEL_ID_FROM_CATALOG",
    "datasets": [
      {"name": "my-ready-dataset", "version": "VERSION_NUMBER"}
    ],
    "training_type": "lora"
  }'
```

Conservez l'`id` renvoyé. Il s'agit du `job_id` utilisé par chaque route propre
à un job. Réutilisez la même valeur `Idempotency-Key` uniquement lorsque vous
réessayez exactement cette requête de création.

### 6. Interroger le job

```bash
curl "https://api.fastino.ai/v1/training/jobs/JOB_ID" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

Pour les jobs de configuration :

- `status` est la valeur persistée du cycle de vie, telle que `errored`.
- `normalized_status` est la valeur stable d'interrogation, telle que `failed`.
- `is_terminal_status` indique à votre client quand arrêter les interrogations.
- `error_message` décrit un échec lorsque cette information est disponible.

Continuez jusqu'à ce que `is_terminal_status` soit `true`, puis examinez le
statut final, les checkpoints, les logs et l'admissibilité au déploiement.

## Boucle d'entraînement personnalisée

Une boucle personnalisée crée un job `interactive` sur un modèle décodeur. Votre
code tokenise les données, envoie chaque étape d'entraînement en JSON et lit les
résultats. Tous les appels utilisent la même clé API Fastino ; vous ne numérotez
pas les requêtes et n'envoyez pas de heartbeats.

### 3. Installer les bibliothèques clientes

Python 3.10 ou une version ultérieure est requis. `transformers` fournit le
tokenizer du modèle ; l'entraînement lui-même s'exécute sur Fastino.

<CodeGroup>

```bash uv
uv init fastino-training
cd fastino-training
uv add requests transformers
```

```bash pip
mkdir fastino-training && cd fastino-training
python -m venv .venv
source .venv/bin/activate
pip install requests transformers
```

</CodeGroup>

### 4. Choisir un modèle

| ID du modèle | Longueur de contexte (tokens) |
| --- | --- |
| `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16` | 65,536 |
| `nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-BF16` | 32,768 |
| `Qwen/Qwen3.6-35B-A3B` | 32,768 |

Les rangs LoRA de 1 à 32 sont pris en charge ; la valeur par défaut est 32.

<CodeGroup>

```bash macOS/Linux
export FASTINO_TRAINING_MODEL="Qwen/Qwen3.6-35B-A3B"
```

```powershell Windows
$env:FASTINO_TRAINING_MODEL = "Qwen/Qwen3.6-35B-A3B"
```

</CodeGroup>

### 5. Créer le job

```bash
curl -X POST "https://api.fastino.ai/v1/training/jobs/create-model" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"base_model": "Qwen/Qwen3.6-35B-A3B", "lora_config": {"rank": 32}}'
```

La réponse contient un `job_id` et le `future_id` du future `create` du
job :

```json
{
  "job_id": "SESSION_ID:train:0",
  "type": "interactive",
  "base_model": "Qwen/Qwen3.6-35B-A3B",
  "future_id": "FUTURE_ID",
  "load_future_id": null
}
```

Chaque appel qui effectue un travail renvoie un future. Lisez-le jusqu'à ce
que `status` vaille `completed`. Avec `wait=true`, la requête attend jusqu'à
25 secondes :

```bash
curl "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/futures/$FUTURE_ID?wait=true" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

### 6. Entraîner, enregistrer et échantillonner

Le script ci-dessous exécute toute la boucle : il crée un job, exécute trois
passes forward-backward et étapes d'optimiseur, enregistre un checkpoint
sampler, échantillonne depuis celui-ci et arrête le job.

Créez `quickstart.py` :

```python
import os

import requests
from transformers import AutoTokenizer

API = "https://api.fastino.ai"
MODEL = os.environ["FASTINO_TRAINING_MODEL"]

session = requests.Session()
session.headers["X-API-Key"] = os.environ["FASTINO_API_KEY"]


def call(method, path, body=None):
    response = session.request(method, API + path, json=body, timeout=60)
    response.raise_for_status()
    return response.json() if response.content else None


def wait(job_id, future_id):
    path = f"/v1/training/jobs/{job_id}/futures/{future_id}?wait=true"
    while True:
        future = call("GET", path)
        if future["status"] == "completed":
            return future["result"]
        if future["status"] in ("failed", "cancelled"):
            raise RuntimeError(future["error"])


def datum(prompt_tokens, completion_tokens):
    tokens = prompt_tokens + completion_tokens
    weights = [0.0] * (len(prompt_tokens) - 1) + [1.0] * len(completion_tokens)
    return {
        "model_input": {"chunks": [{"type": "encoded_text", "tokens": tokens[:-1]}]},
        "loss_fn_inputs": {
            "target_tokens": {"data": tokens[1:], "dtype": "int64"},
            "weights": {"data": weights, "dtype": "float32"},
        },
    }


tokenizer = AutoTokenizer.from_pretrained(MODEL)
prompt = tokenizer.apply_chat_template(
    [{"role": "user", "content": "What is the capital of France?"}],
    add_generation_prompt=True,
    return_dict=False,
)
completion = tokenizer.encode("Paris.", add_special_tokens=False)
completion.append(tokenizer.eos_token_id)
batch = {"datums": [datum(prompt, completion)], "loss_fn": "cross_entropy"}

created = call(
    "POST",
    "/v1/training/jobs/create-model",
    {"base_model": MODEL, "lora_config": {"rank": 32}},
)
job_id = created["job_id"]
jobs = f"/v1/training/jobs/{job_id}"
print(f"TRAINING_JOB_ID={job_id}")

try:
    wait(job_id, created["future_id"])

    for step in range(3):
        backward = call("POST", f"{jobs}/forward-backward", batch)
        update = call(
            "POST",
            f"{jobs}/optim-step",
            {"adam_params": {"learning_rate": 1e-4}},
        )
        result = wait(job_id, backward["future_id"])
        wait(job_id, update["future_id"])
        print(f"step {step}: loss {result['metrics']['loss:sum']:.4f}")

    saved = call(
        "POST",
        f"{jobs}/save-weights-for-sampler",
        {"name": "quickstart", "ttl_seconds": 24 * 60 * 60},
    )
    wait(job_id, saved["future_id"])

    sample = call(
        "POST",
        f"{jobs}/sample",
        {
            "checkpoint": "quickstart",
            "prompt_tokens": prompt,
            "sampling_params": {"max_tokens": 32},
        },
    )
    sequence = wait(job_id, sample["future_id"])["sequences"][0]
    print(tokenizer.decode(sequence["tokens"]))
finally:
    call("POST", f"{jobs}/stop")
```

L'étape d'optimiseur est mise en file juste après la passe forward-backward,
sans attendre. Le job exécute les opérations dans l'ordre de réception.

Exécutez le script :

```bash
python quickstart.py
```

Copiez la valeur affichée après `TRAINING_JOB_ID=`.

<Note>
  Un job interactif sans appel pendant 30 minutes est libéré. Ses checkpoints
  sont conservés. L'arrêt répond immédiatement et empêche de nouveaux appels,
  mais les opérations déjà en file peuvent se terminer avant la libération des
  ressources. Vous pouvez encore échantillonner et télécharger ses checkpoints
  sampler.
</Note>

### 7. Vérifier le job canonique

<CodeGroup>

```bash macOS/Linux
export TRAINING_JOB_ID="<ID printed by quickstart.py>"
curl --fail-with-body \
  -H "X-API-Key: $FASTINO_API_KEY" \
  "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID"
```

```powershell Windows
$env:TRAINING_JOB_ID = "<ID printed by quickstart.py>"
Invoke-RestMethod `
  -Headers @{ "X-API-Key" = "$env:FASTINO_API_KEY" } `
  -Uri "https://api.fastino.ai/v1/training/jobs/$env:TRAINING_JOB_ID"
```

</CodeGroup>

La réponse décrit le job avec `type` `interactive` et ses derniers checkpoints.
Pour télécharger le checkpoint sampler en fichiers PEFT LoRA, utilisez
[Télécharger un checkpoint interactif](/fr/api-reference/training-jobs/download-checkpoint).
