Fastino provides two synchronous inference interfaces. Choose the one that matches what you
need:

| Capability | [`/v1/chat/completions`](/inference/chat-completions) | [`/v1/systemone`](/inference/systemone) |
| --- | --- | --- |
| Model | Select an inference-capable base model or completed training-job UUID | Always uses `fastino/glide` |
| Request | OpenAI-compatible `model` and `messages`, plus Fastino's top-level `schema` | Native `state` plus one or more typed `questions` |
| Response | OpenAI chat-completion envelope; parse `choices[0].message.content` as JSON | Native `{ "answers": ..., "usage": ... }` body |
| Batch input | One conversation per request | One `state` per request, with multiple `questions` evaluated together |
| Best for | Extraction, classification, structured extraction, and relations, on base and fine-tuned models | Classification, routing, and scoring decisions with calibrated probabilities |

<Tip>
  Use [`/v1/chat/completions`](/inference/chat-completions) for extraction, classification,
  structured extraction, or relations. Use [`/v1/systemone`](/inference/systemone) for
  structured decisions — classification, routing, scoring — instead of extraction.
</Tip>

This page covers what's shared across both interfaces. See
[`/v1/chat/completions`](/inference/chat-completions) for the GLiNER request/response contract
and legacy migration guidance, or [`/v1/systemone`](/inference/systemone) for the GLiDE HTTP
contract — the full Noul/Choice/Score request and response shapes live on
[Decision Models](/concepts/decision-models). SDK usage, model training, evaluation, inference
history, and feedback are outside this page's scope.

## Authentication

Send a Fastino API key on every request, regardless of interface:

```bash
export FASTINO_API_KEY="fast_sk_..."
```

```http
Authorization: Bearer $FASTINO_API_KEY
Content-Type: application/json
```

## Cold starts and retries

An idle or newly deployed model may cold-start, on either interface. Use a read timeout of at
least 300 seconds and retry `425`, `429`, and `503` responses. Respect the `Retry-After`
response header when present.

A timed-out request can still warm the deployment, allowing the next request to succeed. Do
not retry authentication, billing, validation, or unknown-model errors without correcting the
underlying problem.

```bash
curl --max-time 300 -X POST "https://api.fastino.ai/v1/chat/completions" \
  -H "Authorization: Bearer $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d @request.json
```

The same timeout and retry pattern applies to `/v1/systemone`.
