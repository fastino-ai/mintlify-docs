The Fastino REST API lets you run inference, manage datasets, start training jobs, and evaluate models programmatically. All resources live under a single base URL, and every request is authenticated with your API key. Fastino also exposes OpenAI- and Anthropic-compatible endpoints so you can integrate with any tool that already supports those formats.

**Base URL:** `https://api.fastino.ai`

## Authentication

Every request requires an `X-API-Key` header. Create your key in the Fastino dashboard at [agent.pioneer.ai/api-keys](https://agent.pioneer.ai/api-keys), or open **Settings** -> **API Keys** after signing in. See the [Authentication](/api-reference/authentication) page for full details, including key management endpoints.

## Recommended workflow

Follow this sequence when you're building a fine-tuned model end to end:

<Steps>
  <Step title="Create or upload a dataset">
    Use `POST /v1/generate` to generate synthetic labeled data — the response includes a `job_id`, poll `GET /v1/generate/jobs/{job_id}` until status returns `ready`.

    To upload your own labeled data, use the three-step upload flow:

    1. Call `POST /v1/felix/datasets/upload/url` to get a presigned S3 URL,
    2. `PUT` your file directly to S3
    3. Call `POST /v1/felix/datasets/upload/process` to trigger processing.

    Poll `GET /v1/felix/datasets/{name}/{version}` until status is `ready`.<br />See the [Datasets](/api-reference/datasets) page for full details.
  </Step>
  <Step title="Start a training job">
    Call `POST /v1/felix/training-jobs` with your model\_name, datasets, and base\_model. The response includes a `job_id` — save it for the following steps.
  </Step>
  <Step title="Poll training status">
    Call `GET /v1/felix/training-jobs/:id` repeatedly until the status field is `complete`. Completed jobs include F1, precision, and recall metrics.
  </Step>
  <Step title="Run an evaluation">
    Create an evaluation suite with `POST /v1/projects/{project_id}/evaluation-suites`, then run it against the selected model before you serve traffic.
  </Step>
  <Step title="Run inference">
    Call `POST /v1/chat/completions` with `model` set to your training job ID and pass your input in `messages`. You can also use a supported base model ID without fine-tuning.
  </Step>
</Steps>

<Note>
  Replace placeholder values such as `YOUR_DATASET_NAME` and `YOUR_TRAINING_JOB_ID` with real values before running any example commands.
</Note>

## OpenAI and Anthropic compatibility

Fastino exposes drop-in replacements for the OpenAI and Anthropic SDKs. Point your existing client at `https://api.fastino.ai/v1` and use your Fastino API key — no other changes are required.

| SDK | Base URL | Notes |
| --- | --- | --- |
| OpenAI | `https://api.fastino.ai/v1` | Set `base_url`; pass Fastino-specific fields via `extra_body` |
| Anthropic | `https://api.fastino.ai/v1` | Set `base_url`; supports streaming |

Pass Fastino-specific fields like `schema` using `extra_body` (OpenAI SDK) or the equivalent extra-parameters mechanism for your client library.

## `/v1` and root-route exceptions

Native product routes use the `/v1` prefix. OpenAI- and Anthropic-compatible routes keep their existing `/v1` paths. Protocol and operational resources remain at the root, including `/health`, `/openapi.json`, and `/.well-known/*`.

Do not prepend `/v1` blindly. Use the exact path in this reference or the curated OpenAPI document.

## Migrating from the Pioneer API origin

If an existing integration calls `https://api.pioneer.ai`, update its base URL to `https://api.fastino.ai`. Native dataset, training, project, model-catalog, and inference-history routes now use the `/v1` prefix. For example, `/felix/training-jobs` is now `/v1/felix/training-jobs`.

OpenAI- and Anthropic-compatible routes already begin with `/v1` and keep their existing paths. Do not add a second prefix: `/v1/chat/completions` stays `/v1/chat/completions`, not `/v1/v1/chat/completions`. Direct API integrations should use `FASTINO_API_KEY`; existing API key values and authentication headers remain valid. The Fastino CLI continues to read `PIONEER_API_KEY` until its separate configuration migration is released.
