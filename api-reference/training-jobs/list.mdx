`GET /v1/training/jobs`

Returns config and interactive training jobs visible to the authenticated
account.

Without `type`, config and interactive jobs are interleaved by `created_at`,
newest first. If two jobs have the same timestamp, the config job appears
first. Pass `type=interactive` to list only interactive jobs.

## Request

<ParamField header="X-API-Key" type="string" required>
  Your Fastino API key.
</ParamField>

<ParamField query="status" type="string">
  Filter both job types by status. Interactive jobs support `creating`, `active`,
  `stopping`, `stopped`, and `failed`; `running` also matches `active`, while
  `errored` and `error` match `failed`. `running`, `errored`, `error`, `stopped`,
  and `failed` can match both types. `creating`, `active`, and `stopping` match
  only interactive jobs; other config statuses match only config jobs. For
  config jobs, `status=complete` returns jobs persisted as `complete`,
  `artifact_ready`, or `deployed`.
</ParamField>

<ParamField query="type" type="string">
  Filter by `config` or `interactive`.
</ParamField>

<ParamField query="project_id" type="string">
  Filter by project ID.
</ParamField>

<ParamField query="limit" type="integer" default="200">
  Page size from `1` through `200`.
</ParamField>

<ParamField query="offset" type="integer" default="0">
  Number of matching jobs to skip.
</ParamField>

<RequestExample>

```bash cURL
curl "https://api.fastino.ai/v1/training/jobs?type=config&status=complete&limit=50&offset=0" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

</RequestExample>

## Response

<ResponseField name="success" type="boolean">
  Whether the request succeeded.
</ResponseField>

<ResponseField name="training_jobs" type="object[]">
  Training-job records for this page.
</ResponseField>

Every record includes `id` and `created_at`. Interactive records also repeat
`id` in `job_id` and `training_run_id` for API and SDK compatibility, and
include `status`, `stop_reason`, `error_message`, and `is_terminal_status`.
Poll an interactive job by `id` until the terminal flag is true.

A record with `type: "config"` and `source: "interactive_checkpoint"` is the
served model created from an interactive sampler checkpoint. Its config-training
fields, including epochs, batch size, learning rate, and validation percentage,
are `null`.

<ResponseField name="count" type="integer">
  Number of jobs in this page.
</ResponseField>

<ResponseField name="total" type="integer">
  Total number of matching jobs before pagination.
</ResponseField>

<ResponseField name="has_more" type="boolean">
  Whether another page exists after this one.
</ResponseField>

<ResponseExample>

```json Response
{
  "success": true,
  "training_jobs": [],
  "count": 0,
  "total": 0,
  "has_more": false
}
```

</ResponseExample>

Invalid pagination values return `422`.

See the [config-job lifecycle](/training#config-job-lifecycle) for the complete
set of persisted statuses.
