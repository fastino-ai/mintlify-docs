`POST /v1/training/jobs/{job_id}/save-weights-for-sampler`

Saves the job's LoRA weights as `sampler_weights/<name>`. You can
[sample](/api-reference/training-jobs/interactive/sample) from it, also after the job is
stopped, or [download](/api-reference/training-jobs/download-checkpoint) it as
an adapter archive. Downloaded decoder adapters use Fastino's training-cell
layout and are not currently compatible with stock PEFT or standard vLLM. It
has no optimizer state, so a job can't load it or start from it; use
[`POST /v1/training/jobs/{job_id}/save-weights`](/api-reference/training-jobs/interactive/save-weights)
for that.

The save runs in order with the job's other calls.

## Request

<ParamField header="X-API-Key" type="string" required>
  Your Fastino API key.
</ParamField>

<ParamField path="job_id" type="string" required>
  Interactive job ID.
</ParamField>

<ParamField body="name" type="string" required>
  1–128 characters from `A-Z`, `a-z`, `0-9`, `.`, `_`, and `-`.
</ParamField>

<ParamField body="ttl_seconds" type="integer | null">
  Delete the checkpoint automatically after this many seconds, from `3600`
  (1 hour) to `315360000` (10 years). Omit it or send `null` to keep the checkpoint until you delete it. Live checkpoints count toward [storage usage](/api-reference/training-jobs/interactive/storage-usage).
</ParamField>

<ParamField body="user_metadata" type="object">
  String key-value metadata stored with the checkpoint.
</ParamField>

<RequestExample>

```bash cURL
curl -X POST "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/save-weights-for-sampler" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "step-000100", "ttl_seconds": 86400}'
```

</RequestExample>

## Response

<ResponseField name="future_id" type="string">
  The `save` future.
</ResponseField>

<ResponseField name="checkpoint_id" type="string">
  `sampler_weights/<name>`.
</ResponseField>

<ResponseField name="path" type="string">
  Full checkpoint path.
</ResponseField>

<ResponseExample>

```json Response
{
  "future_id": "FUTURE_ID",
  "job_id": "SESSION_ID:train:0",
  "type": "save",
  "checkpoint_id": "sampler_weights/step-000100",
  "path": "tinker://SESSION_ID:train:0/sampler_weights/step-000100"
}
```

</ResponseExample>

| Status | Meaning |
| --- | --- |
| `400` | The name has invalid characters or length, the TTL is out of range, or the job was stopped. |
| `404` | The job doesn't exist or belongs to another team. |
| `422` | The body is missing `name` or has an unknown field. |
