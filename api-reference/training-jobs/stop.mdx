`POST /v1/training/jobs/{job_id}/stop`

Stops a running job and preserves checkpoints created before the stop.

## Request

<ParamField header="X-API-Key" type="string" required>
  Your Fastino API key.
</ParamField>

<ParamField path="job_id" type="string" required>
  Config-job UUID or interactive job ID.
</ParamField>

### Config job

The JSON body is optional for a config job.

<ParamField body="reason" type="string">
  Why the job was stopped.
</ParamField>

<ParamField body="scores" type="object">
  Numeric metrics used to make the stop decision.
</ParamField>

<ParamField body="checkpoint" type="string">
  Checkpoint path or step associated with the stop.
</ParamField>

### Interactive job

Send no request body. The operation returns `success`, `job_id`, and `status`
immediately. The job accepts no more training calls, but its sampler
checkpoints remain available for sampling and download.

### Config-job request example

```bash cURL
curl -X POST https://api.fastino.ai/v1/training/jobs/YOUR_TRAINING_JOB_ID/stop \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"reason": "Validation loss stopped improving"}'
```

### Interactive-job request example

```bash cURL
curl -X POST https://api.fastino.ai/v1/training/jobs/SESSION_ID:train:0/stop \
  -H "X-API-Key: $FASTINO_API_KEY"
```

## Config-job response

<ResponseExample>

```json Response
{
  "success": true,
  "message": "Training job stopped",
  "job_id": "YOUR_TRAINING_JOB_ID",
  "status": "stopped"
}
```

```json 202 — cancellation pending
{
  "success": true,
  "message": "Training job cancellation is still being confirmed.",
  "job_id": "YOUR_TRAINING_JOB_ID",
  "status": "stopping"
}
```

</ResponseExample>

The `message` field, `202` response, polling rule, and config-specific errors
apply only to config jobs. Poll `GET /v1/training/jobs/{job_id}` after a
config-job `202`. Do not repeat the stop request while cancellation is pending.

## Interactive-job response

An interactive stop returns `200` immediately with no polling step.

```json Interactive job
{
  "success": true,
  "job_id": "SESSION_ID:train:0",
  "status": "stopped"
}
```

## Config-job statuses

| Status | Meaning |
| --- | --- |
| `200` | The job is stopped and existing checkpoints remain available. |
| `202` | Provider cancellation is still being confirmed. |
| `400` | The config-job ID or request is invalid. |
| `409 training_job_already_finished` | The job reached a terminal state before the stop. |
| `422` | The config-job JSON request body is invalid. |
