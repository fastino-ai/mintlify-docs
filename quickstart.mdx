This guide walks you through the fastest path to a working Fastino integration. By the end, you'll have made a successful inference call and understand the shape of the API. All you need is a Fastino account and a terminal.

<Steps>
  <Step title="Sign up and get your API key">
    Create an account at [Fastino](https://fastino.ai). 

    Once you're signed in, go to **Settings → API Keys** and generate a new key. Copy it somewhere safe as you won't be able to view it again after closing the dialog.

    <Warning>
      Keep your API key out of version control. Use an environment variable or a secrets manager rather than hardcoding it in your source files.
    </Warning>

    Set your key as an environment variable so the examples below work as-is:

    ```bash
    export FASTINO_API_KEY="your_api_key_here"
    ```
  </Step>
  <Step title="List available base models (optional)">
    You can browse the models Fastino has available. Use `GET /base-models` to see the full catalog.  You can browse the models Fastino has available. Use `GET /v1/base-models` to see the full catalog.

    <CodeGroup>

    ```bash curl
    curl https://api.fastino.ai/v1/base-models \
      -H "X-API-Key: $FASTINO_API_KEY"
    ```

    ```python Python
    import os
    import requests
    
    response = requests.get(
        "https://api.fastino.ai/v1/base-models",
        headers={"X-API-Key": os.environ["FASTINO_API_KEY"]}
    )
    print(response.json())
    ```

    ```javascript JavaScript
    const response = await fetch(
      "https://api.fastino.ai/v1/base-models",
      {
        headers: {
          "X-API-Key": process.env.FASTINO_API_KEY
        }
      }
    );
    const data = await response.json();
    console.log(data);
    ```

    </CodeGroup>

    The response lists model IDs you can pass to `/v1/chat/completions`. For example, `fastino/gliner2-base-v1` is the GLiNER base model for NER tasks.
  </Step>
  <Step title="Run your first inference call">
    Call `POST /v1/chat/completions` with a model, a message, and a schema that defines what you want to extract. The example below uses the GLiNER base model to extract named entities from a sentence.

    <CodeGroup>

    ```bash curl
    curl -X POST "https://api.fastino.ai/v1/chat/completions" \
      -H "Authorization: Bearer $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "fastino/gliner2.5-multi-v1",
        "messages": [
          {
            "role": "user",
            "content": "Apple announced the MacBook Pro at WWDC in Cupertino."
          }
        ],
        "schema": {
          "entities": [
            {
              "name": "organization",
              "description": "business or institution name"
            },
            {
              "name": "product",
              "description": "named commercial product"
            },
            {
              "name": "event",
              "description": "named conference or event"
            },
            {
              "name": "location",
              "description": "city, region, or place"
            }
          ]
        },
        "threshold": 0.5
      }'
    ```

    ```python Python
    import json
    import os
    
    import requests
    
    response = requests.post(
        "https://api.fastino.ai/v1/chat/completions",
        headers={
            "Authorization": f"Bearer {os.environ['FASTINO_API_KEY']}",
            "Content-Type": "application/json",
        },
        json={
            "model": "fastino/gliner2.5-multi-v1",
            "messages": [
                {
                    "role": "user",
                    "content": "Apple announced the MacBook Pro at WWDC in Cupertino.",
                }
            ],
            "schema": {
                "entities": [
                    {"name": "organization", "description": "business or institution name"},
                    {"name": "product", "description": "named commercial product"},
                    {"name": "event", "description": "named conference or event"},
                    {"name": "location", "description": "city, region, or place"},
                ]
            },
            "threshold": 0.5,
        },
    )
    
    response.raise_for_status()
    result = response.json()
    entities = json.loads(result["choices"][0]["message"]["content"])
    
    print(json.dumps(entities, indent=2))
    ```

    ```javascript JavaScript
    const response = await fetch(
      "https://api.fastino.ai/v1/chat/completions",
      {
        method: "POST",
        headers: {
          Authorization: `Bearer ${process.env.FASTINO_API_KEY}`,
          "Content-Type": "application/json",
        },
        body: JSON.stringify({
          model: "fastino/gliner2.5-multi-v1",
          messages: [
            {
              role: "user",
              content: "Apple announced the MacBook Pro at WWDC in Cupertino.",
            },
          ],
          schema: {
            entities: [
              { name: "organization", description: "business or institution name" },
              { name: "product", description: "named commercial product" },
              { name: "event", description: "named conference or event" },
              { name: "location", description: "city, region, or place" },
            ],
          },
          threshold: 0.5,
        }),
      }
    );
    
    if (!response.ok) {
      throw new Error(`Inference failed: ${response.status} ${await response.text()}`);
    }
    
    const result = await response.json();
    const entities = JSON.parse(result.choices[0].message.content);
    
    console.log(JSON.stringify(entities, null, 2));
    ```

    </CodeGroup>

    For encoder models (GLiNER), the `schema` object defines the  task and can include `entities`, `classifications`, `structures`, and `relations`:

    - `entities` — a list of entity type strings for NER
    - `classifications` — a list of `{task, labels}` objects for text classification
    - `structures` — a dict of structure definitions for JSON extraction
    - `relations` — a list of relation definitions

    For decoder models (LLMs), omit `schema` and send a normal chat message.

    <Note>
      `model` must be an inference-capable base-model ID or the UUID of a completed, deployable training job. After training, deploy the selected artifact before using the job UUID for inference.
    </Note>
  </Step>
  <Step title="Start a training job (optional)">
    When you're ready to fine-tune on your own data, start a training job. 

    <CodeGroup>

    ```bash curl
    curl -X POST https://api.fastino.ai/v1/training-jobs \
      -H "X-API-Key: $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model_name": "my-ner-model",
        "base_model": "fastino/gliner2-base-v1",
        "datasets": [{"name": "my-dataset"}],
        "training_type": "lora",
        "nr_epochs": 5,
        "learning_rate": 5e-5
      }'
    ```

    ```python Python
    import os
    import requests
    
    response = requests.post(
        "https://api.fastino.ai/v1/training-jobs",
        headers={
            "X-API-Key": os.environ["FASTINO_API_KEY"],
            "Content-Type": "application/json"
        },
        json={
            "model_name": "my-ner-model",
            "base_model": "fastino/gliner2-base-v1",
            "datasets": [{"name": "my-dataset"}],
            "training_type": "lora",
            "nr_epochs": 5,
            "learning_rate": 5e-5
        }
    )
    print(response.json())
    # {"id": "uuid-of-training-job", "status": "requested"}
    ```

    </CodeGroup>

    The response includes a job `id`. Poll `GET /v1/training-jobs/{id}` to check status. Once the job reaches `complete`, use the job ID as `model` in `/v1/chat/completions` calls.

    Job status values: `requested` → `running` → `complete` (or `failed` / `stopped`).
  </Step>
</Steps>
