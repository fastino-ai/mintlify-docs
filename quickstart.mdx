## Set up your API key

1. **Create a [Fastino](https://agent.fastino.ai/) account**
2. **Get your API key** from [Settings](https://agent.fastino.ai/api-keys)

Set your key as an environment variable so the examples below work as-is:

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="your_api_key_here"
```

```powershell Windows
$env:FASTINO_API_KEY = "your_api_key_here"
```

</CodeGroup>

## Run your first inference call

Call `POST /v1/systemone` with a `model`, a `state` describing the situation, and one or more typed `questions`. GLiDE returns calibrated probabilities and labels directly - there's no generated text to parse. The example below asks a single yes/no (`noul`) question.

GLiDE costs **\$0.15 per 1 million input tokens**. Output tokens are **free (\$0)**.
See [Pricing](/pricing) for the current inference rates.

<Tabs>
  <Tab title="cURL">
    **To run a GLiDE decision call**:

    ```bash
    curl -X POST "https://api.fastino.ai/v1/systemone" \
      -H "X-API-Key: $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "fastino/GLiDE",
        "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
        "questions": {
          "refund_allowed": {
            "type": "noul",
            "instructions": "Does this request qualify for a refund?",
            "criteria": { "true": "Qualifies", "false": "Does not qualify" }
          }
        }
      }'
    ```
  </Tab>

  <Tab title="Python">
    **To run a GLiDE decision call**:

    ```python
    import os
    import requests

    response = requests.post(
        "https://api.fastino.ai/v1/systemone",
        headers={
            "X-API-Key": os.environ["FASTINO_API_KEY"],
            "Content-Type": "application/json",
        },
        json={
            "model": "fastino/GLiDE",
            "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
            "questions": {
                "refund_allowed": {
                    "type": "noul",
                    "instructions": "Does this request qualify for a refund?",
                    "criteria": {"true": "Qualifies", "false": "Does not qualify"},
                }
            },
        },
    )

    response.raise_for_status()
    print(response.json())
    ```
  </Tab>

  <Tab title="JavaScript">
    **To run a GLiDE decision call**:

    ```javascript
    const response = await fetch(
      "https://api.fastino.ai/v1/systemone",
      {
        method: "POST",
        headers: {
          "X-API-Key": process.env.FASTINO_API_KEY,
          "Content-Type": "application/json",
        },
        body: JSON.stringify({
          model: "fastino/GLiDE",
          state: "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
          questions: {
            refund_allowed: {
              type: "noul",
              instructions: "Does this request qualify for a refund?",
              criteria: { true: "Qualifies", false: "Does not qualify" },
            },
          },
        }),
      }
    );

    if (!response.ok) {
      throw new Error(`Inference failed: ${response.status} ${await response.text()}`);
    }

    const result = await response.json();
    console.log(JSON.stringify(result, null, 2));
    ```
  </Tab>
</Tabs>

Success looks like this:

```json
{
  "model": "glide",
  "answers": {
    "refund_allowed": {
      "type": "noul",
      "noul": 0.99767683794902,
      "confidence": 0.9953536758980399
    }
  },
  "usage": { "input_tokens": 89, "output_tokens": 1 },
  "token_usage": 90
}
```

`answers.refund_allowed.noul` is the probability the answer is "yes" - `0.998` when rounded to three decimal places is a strong qualifying signal. Continue with the [Noul](/concepts/glide-noul), [Choice](/concepts/glide-choice), and [Score](/concepts/glide-score) references, or use the [routing guide](/guides/glide-routing) to turn confidence into an action.

<Accordion title="Extracting entities instead? Use GLiNER 2.5">
  If you need span-level extraction (NER, classification, structured records) rather than a decision, call `POST /v1/chat/completions` with a model, a message, and a schema that defines what you want to extract:

  ```bash
  curl -X POST "https://api.fastino.ai/v1/chat/completions" \
    -H "Authorization: Bearer $FASTINO_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "fastino/gliner2.5-multi-v1",
      "messages": [
        {
          "role": "user",
          "content": "Apple announced the MacBook Pro at WWDC in Cupertino."
        }
      ],
      "schema": {
        "entities": [
          { "name": "organization", "description": "business or institution name" },
          { "name": "product", "description": "named commercial product" },
          { "name": "event", "description": "named conference or event" },
          { "name": "location", "description": "city, region, or place" }
        ]
      },
      "threshold": 0.5
    }'
  ```

  For encoder models (GLiNER), the `schema` object defines the task and can include `entities`, `classifications`, `structures`, and `relations`. For decoder models (LLMs), omit `schema` and send a normal chat message. See the [Inference API](/inference/chat-completions) for the full contract, Python/JavaScript examples, and error codes.
</Accordion>

## Create a decoder training job

Create an interactive LoRA job when your application controls decoder training
step by step:

Query `GET /v1/base-models?supports_training=true` before creating the job and
use an exact decoder model ID returned for your team. An interactive-training
context limit describes that training operation; it can differ from the
catalog model's inference context or an inference endpoint's request limit.

```bash
curl -X POST "https://api.fastino.ai/v1/training/jobs/create-model" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "base_model": "nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-BF16",
    "lora_config": {"rank": 32}
  }'
```

The response contains the `job_id` and its create `future_id`. Continue with the
[Decoder Quickstart](/training/decoder-quickstart) to run forward-backward and
optimizer operations and save a checkpoint.
