## Set up your API key

1. **Create a [Fastino](https://agent.fastino.ai/) account**
2. **Get your API key** from [Settings](https://agent.fastino.ai/api-keys)

Set your key as an environment variable so the examples below work as-is:

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="your_api_key_here"
```

```powershell Windows
setx FASTINO_API_KEY "your_api_key_here"
```

</CodeGroup>

## Run your first inference call

Call `POST /v1/systemone` with a `model`, a `state` describing the situation, and one or more typed `questions`. GLiDE returns calibrated probabilities and labels directly - there's no generated text to parse. The example below asks a single yes/no (`noul`) question.

<Tabs>
  <Tab title="cURL">
    **To run a GLiDE decision call**:

    ```bash
    curl -X POST "https://api.fastino.ai/v1/systemone" \
      -H "X-API-Key: $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "fastino/GLiDE",
        "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
        "questions": {
          "refund_allowed": {
            "type": "noul",
            "instructions": "Does this request qualify for a refund?",
            "criteria": { "true": "Qualifies", "false": "Does not qualify" }
          }
        }
      }'
    ```
  </Tab>

  <Tab title="Python">
    **To run a GLiDE decision call**:

    ```python
    import os
    import requests

    response = requests.post(
        "https://api.fastino.ai/v1/systemone",
        headers={
            "X-API-Key": os.environ["FASTINO_API_KEY"],
            "Content-Type": "application/json",
        },
        json={
            "model": "fastino/GLiDE",
            "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
            "questions": {
                "refund_allowed": {
                    "type": "noul",
                    "instructions": "Does this request qualify for a refund?",
                    "criteria": {"true": "Qualifies", "false": "Does not qualify"},
                }
            },
        },
    )

    response.raise_for_status()
    print(response.json())
    ```
  </Tab>

  <Tab title="JavaScript">
    **To run a GLiDE decision call**:


Success looks like this:

```json
{
  "model": "glide",
  "answers": {
    "refund_allowed": {
      "type": "noul",
      "noul": 0.99767683794902,
      "confidence": 0.9953536758980399
    }
  },
  "usage": { "input_tokens": 89, "output_tokens": 1 },
  "token_usage": 90
}
```

`answers.refund_allowed.noul` is the probability the answer is "yes" - `0.999` is a strong qualifying signal. See [Decision models](/concepts/decision-models) for the `choice` and `score` question types, confidence-gated routing, and the full primitive reference.

<Accordion title="Extracting entities instead? Use GLiNER 2.5">
  If you need span-level extraction (NER, classification, structured records) rather than a decision, call `POST /v1/chat/completions` with a model, a message, and a schema that defines what you want to extract:

  ```bash
  curl -X POST "https://api.fastino.ai/v1/chat/completions" \
    -H "Authorization: Bearer $FASTINO_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "fastino/gliner2.5-multi-v1",
      "messages": [
        {
          "role": "user",
          "content": "Apple announced the MacBook Pro at WWDC in Cupertino."
        }
      ],
      "schema": {
        "entities": [
          { "name": "organization", "description": "business or institution name" },
          { "name": "product", "description": "named commercial product" },
          { "name": "event", "description": "named conference or event" },
          { "name": "location", "description": "city, region, or place" }
        ]
      },
      "threshold": 0.5
    }'
  ```

  For encoder models (GLiNER), the `schema` object defines the task and can include `entities`, `classifications`, `structures`, and `relations`. For decoder models (LLMs), omit `schema` and send a normal chat message. See the [Inference API](/inference/chat-completions) for the full contract, Python/JavaScript examples, and error codes.
</Accordion>

## First call after idle

<Note>
  When a model has scaled to zero after a period without traffic, your first request can return HTTP `425` with error code `model_warming`. This is expected and does not mean your request is wrong. The model is usually ready within 30 to 60 seconds. The response includes a `Retry-After` header with the number of seconds to wait, and `x-should-retry: true`.
</Note>

Send the same request again after the `Retry-After` delay. Each example retries at most 5 times, waits `Retry-After` seconds (30 if the header is missing), sets a 300-second client timeout, and stops on any other non-2xx response.

<CodeGroup>

```bash cURL
for attempt in 0 1 2 3 4 5; do
  http_code=$(curl -sS --max-time 300 -o response.json -D headers.txt -w "%{http_code}" \
    https://api.fastino.ai/v1/systemone \
    -H "X-API-Key: $FASTINO_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "fastino/GLiDE",
      "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
      "questions": {
        "refund_allowed": { "type": "noul", "instructions": "Does this request qualify for a refund?" }
      }
    }')
  [ "$http_code" = "425" ] && [ "$attempt" -lt 5 ] || break
  delay=$(awk 'tolower($1) == "retry-after:" && $2 + 0 > 0 { print $2 + 0 }' headers.txt)
  sleep "${delay:-30}"
done

if [ "$http_code" -ge 200 ] && [ "$http_code" -lt 300 ]; then
  cat response.json
else
  echo "Request failed with HTTP $http_code: $(cat response.json)" >&2
fi
```

```python Python
import os
import time
import requests

MAX_RETRIES = 5

for attempt in range(MAX_RETRIES + 1):
    response = requests.post(
        "https://api.fastino.ai/v1/systemone",
        headers={"X-API-Key": os.environ["FASTINO_API_KEY"]},
        json={
            "model": "fastino/GLiDE",
            "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
            "questions": {
                "refund_allowed": {
                    "type": "noul",
                    "instructions": "Does this request qualify for a refund?",
                }
            },
        },
        timeout=300,
    )
    if response.status_code != 425 or attempt == MAX_RETRIES:
        break
    retry_after = response.headers.get("Retry-After", "")
    time.sleep(int(retry_after) if retry_after.isdigit() else 30)

if not 200 <= response.status_code < 300:
    raise RuntimeError(f"Request failed: {response.status_code} {response.text}")
print(response.json())
```

```javascript JavaScript
const MAX_RETRIES = 5;
let response;

for (let attempt = 0; attempt <= MAX_RETRIES; attempt++) {
  response = await fetch("https://api.fastino.ai/v1/systemone", {
    method: "POST",
    headers: {
      "X-API-Key": process.env.FASTINO_API_KEY,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      model: "fastino/GLiDE",
      state: "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
      questions: {
        refund_allowed: { type: "noul", instructions: "Does this request qualify for a refund?" },
      },
    }),
    signal: AbortSignal.timeout(300_000),
  });
  if (response.status !== 425 || attempt === MAX_RETRIES) break;
  const retryAfter = Number(response.headers.get("Retry-After"));
  await new Promise((resolve) => setTimeout(resolve, (retryAfter || 30) * 1000));
}

if (!response.ok) {
  throw new Error(`Request failed: ${response.status} ${await response.text()}`);
}
console.log(await response.json());
```

</CodeGroup>

The official OpenAI and Anthropic SDKs retry this response automatically because it carries `x-should-retry: true`. See [OpenAI-compatible inference](/api-reference/inference/openai-compatible#first-call-after-idle) to raise the SDK retry limit for a first call.
