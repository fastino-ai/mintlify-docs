## Set up your API key

1. **Create a [Fastino](https://agent.fastino.ai/) account**
2. **Get your API key** from [Settings](https://agent.fastino.ai/api-keys)

Copy your key somewhere safe as you won't be able to view it again after closing the dialog.

<Warning>
  Keep your API key out of version control. Use an environment variable or a secrets manager rather than hardcoding it in your source files.
</Warning>

Set your key as an environment variable so the examples below work as-is:

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="your_api_key_here"
```

```powershell Windows
setx FASTINO_API_KEY "your_api_key_here"
```

</CodeGroup>

## List available models (optional)

You can browse the models Fastino has available. Use `GET /v1/base-models` to see the full catalog.

<Tabs>
  <Tab title="cURL">
    **To list available models**:

    ```bash
    curl https://api.fastino.ai/v1/base-models \
      -H "X-API-Key: $FASTINO_API_KEY"
    ```
  </Tab>

  <Tab title="Python">
    **To list available models**:

    ```python
    import os
    import requests

    response = requests.get(
        "https://api.fastino.ai/v1/base-models",
        headers={"X-API-Key": os.environ["FASTINO_API_KEY"]}
    )
    print(response.json())
    ```
  </Tab>

  <Tab title="JavaScript">
    **To list available models**:

    ```javascript
    const response = await fetch(
      "https://api.fastino.ai/v1/base-models",
      {
        headers: {
          "X-API-Key": process.env.FASTINO_API_KEY
        }
      }
    );
    const data = await response.json();
    console.log(data);
    ```
  </Tab>
</Tabs>

The response lists model IDs you can pass to `/v1/systemone` or `/v1/chat/completions`. For example, `fastino/gliner2-base-v1` is the GLiNER base model for NER tasks.

## Run your first inference call

Call `POST /v1/systemone` with a `model`, a `state` describing the situation, and one or more typed `questions`. GLiDE returns calibrated probabilities and labels directly — there's no generated text to parse. The example below asks a single yes/no (`noul`) question.

<Tabs>
  <Tab title="cURL">
    **To run a GLiDE decision call**:

    ```bash
    curl -X POST "https://api.fastino.ai/v1/systemone" \
      -H "X-API-Key: $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "fastino/glide",
        "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
        "questions": {
          "refund_allowed": {
            "type": "noul",
            "instructions": "Does this request qualify for a refund?",
            "criteria": { "true": "Qualifies", "false": "Does not qualify" }
          }
        }
      }'
    ```
  </Tab>

  <Tab title="Python">
    **To run a GLiDE decision call**:

    ```python
    import os
    import requests

    response = requests.post(
        "https://api.fastino.ai/v1/systemone",
        headers={
            "X-API-Key": os.environ["FASTINO_API_KEY"],
            "Content-Type": "application/json",
        },
        json={
            "model": "fastino/glide",
            "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
            "questions": {
                "refund_allowed": {
                    "type": "noul",
                    "instructions": "Does this request qualify for a refund?",
                    "criteria": {"true": "Qualifies", "false": "Does not qualify"},
                }
            },
        },
    )

    response.raise_for_status()
    print(response.json())
    ```
  </Tab>

  <Tab title="JavaScript">
    **To run a GLiDE decision call**:

    ```javascript
    const response = await fetch(
      "https://api.fastino.ai/v1/systemone",
      {
        method: "POST",
        headers: {
          "X-API-Key": process.env.FASTINO_API_KEY,
          "Content-Type": "application/json",
        },
        body: JSON.stringify({
          model: "fastino/glide",
          state: "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
          questions: {
            refund_allowed: {
              type: "noul",
              instructions: "Does this request qualify for a refund?",
              criteria: { true: "Qualifies", false: "Does not qualify" },
            },
          },
        }),
      }
    );

    if (!response.ok) {
      throw new Error(`Inference failed: ${response.status} ${await response.text()}`);
    }

    const result = await response.json();
    console.log(JSON.stringify(result, null, 2));
    ```
  </Tab>
</Tabs>

Success looks like this:

```json
{
  "model": "glide",
  "answers": {
    "refund_allowed": {
      "type": "noul",
      "noul": 0.9989566626894673,
      "confidence": 0.9979133253789345
    }
  },
  "usage": { "input_tokens": 443, "output_tokens": 62 },
  "token_usage": 505
}
```

`answers.refund_allowed.noul` is the probability the answer is "yes" — `0.999` is a strong qualifying signal. See [Decision models](/concepts/decision-models) for the `choice` and `score` question types, confidence-gated routing, and the full primitive reference.

<Accordion title="Extracting entities instead? Use GLiNER via /v1/chat/completions">
  If you need span-level extraction (NER, classification, structured records) rather than a decision, call `POST /v1/chat/completions` with a model, a message, and a schema that defines what you want to extract:

  ```bash
  curl -X POST "https://api.fastino.ai/v1/chat/completions" \
    -H "Authorization: Bearer $FASTINO_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "model": "fastino/gliner2.5-multi-v1",
      "messages": [
        {
          "role": "user",
          "content": "Apple announced the MacBook Pro at WWDC in Cupertino."
        }
      ],
      "schema": {
        "entities": [
          { "name": "organization", "description": "business or institution name" },
          { "name": "product", "description": "named commercial product" },
          { "name": "event", "description": "named conference or event" },
          { "name": "location", "description": "city, region, or place" }
        ]
      },
      "threshold": 0.5
    }'
  ```

  For encoder models (GLiNER), the `schema` object defines the task and can include `entities`, `classifications`, `structures`, and `relations`. For decoder models (LLMs), omit `schema` and send a normal chat message. See the [Inference API](/inference) for the full contract, Python/JavaScript examples, and error codes.

  <Note>
    `model` must be an inference-capable base-model ID or the UUID of a completed, deployable training job. After training, deploy the selected artifact before using the job UUID for inference.
  </Note>
</Accordion>

## Start a training job (optional)

When you're ready to fine-tune on your own data, start a training job.

<Tabs>
  <Tab title="cURL">
    **To start a training job**:

    ```bash
    curl -X POST https://api.fastino.ai/v1/training-jobs \
      -H "X-API-Key: $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model_name": "my-ner-model",
        "base_model": "fastino/gliner2-base-v1",
        "datasets": [{"name": "my-dataset"}],
        "training_type": "lora",
        "nr_epochs": 5,
        "learning_rate": 5e-5
      }'
    ```
  </Tab>

  <Tab title="Python">
    **To start a training job**:

    ```python
    import os
    import requests

    response = requests.post(
        "https://api.fastino.ai/v1/training-jobs",
        headers={
            "X-API-Key": os.environ["FASTINO_API_KEY"],
            "Content-Type": "application/json"
        },
        json={
            "model_name": "my-ner-model",
            "base_model": "fastino/gliner2-base-v1",
            "datasets": [{"name": "my-dataset"}],
            "training_type": "lora",
            "nr_epochs": 5,
            "learning_rate": 5e-5
        }
    )
    print(response.json())
    # {"id": "uuid-of-training-job", "status": "requested"}
    ```
  </Tab>
</Tabs>

The response includes a job `id`. Poll `GET /v1/training-jobs/{id}` to check status. Once the job reaches `complete`, use the job ID as `model` in `/v1/chat/completions` calls.

Job status values: `requested` → `running` → `complete` (or `failed` / `stopped`).
