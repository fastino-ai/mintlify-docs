状态检查点保护服务器端的训练状态。完整的恢复记录还会保护由用户持有、告诉控制器下一步做什么的状态。

示例使用[快速入门脚本](/cn/training/quickstart#custom-training-loop)中的 `call` 和 `wait` 辅助函数。

## 保存什么

| 记录 | 内容 | 存储方 |
| --- | --- | --- |
| 状态检查点 | LoRA 权重和优化器状态 | Fastino |
| 循环记录 | 源任务 ID、检查点路径、步骤、数据集游标、配置和恢复谱系 | 你的应用 |

## 1. 保存状态和循环进度

使用 `save-weights` 保存状态并等待其完成，然后将其路径与继续所需的客户端字段一起持久化：

```python
import json
from pathlib import Path


state = call(
    "POST",
    f"/v1/training/jobs/{job_id}/save-weights",
    {"name": f"step-{step:06d}"},
)
wait(job_id, state["future_id"])
record = {
    "source_job_id": job_id,
    "state_path": state["path"],
    "model": model_name,
    "dataset_revision": dataset_revision,
    "optimizer": adam_params,
    "step": step,
    "dataset_cursor": dataset_cursor,
    "reward_version": reward_version,
}

with Path(log_path).open("a", encoding="utf-8") as checkpoint_log:
    checkpoint_log.write(json.dumps(record, sort_keys=True) + "\n")
```

请使用唯一的检查点名称，使每条循环记录都对应一个明确的恢复边界。名称由 1–128 个字符组成，取自
`A-Z`、`a-z`、`0-9`、`.`、`_` 和 `-`。

## 2. 读取最新的完整记录

进程可能在写入最后一行时停止。请从后向前扫描并跳过格式错误的尾行：

```python
def get_last_checkpoint(log_path: str) -> dict[str, object] | None:
    path = Path(log_path)
    if not path.exists():
        return None

    for line in reversed(path.read_text(encoding="utf-8").splitlines()):
        try:
            record = json.loads(line)
        except json.JSONDecodeError:
            continue
        if isinstance(record, dict) and isinstance(record.get("state_path"), str):
            return record
    return None
```

## 3. 加载前验证

将记录与源检查点和请求的继续方式进行比较：

- 检查点路径中的源任务 ID
- 基础模型和 LoRA 配置
- 数据集修订版本和游标
- 奖励实现的修订版本
- 优化器设置
- tokenizer 和聊天模板假设

如果这些字段存在冲突，请停下来做出明确决定。不要在无提示的情况下将检查点与其他实验混用。

原生客户端使用 `from_checkpoint` 创建新任务，或将状态名称或同一任务的
`tinker://` 路径传给
[`load-weights`](/cn/api-reference/training-jobs/interactive/load-weights)。
Tinker 客户端使用受支持的状态加载流程：

```python
resumed = call(
    "POST",
    "/v1/training/jobs/create-model",
    {"from_checkpoint": resume["state_path"], "load_optimizer": True},
)
wait(resumed["job_id"], resumed["future_id"])
wait(resumed["job_id"], resumed["load_future_id"])
resumed_job_id = resumed["job_id"]
```

此工厂方法先创建新的交互式任务，再将来源检查点的权重和优化器状态加载到新任务中。
恢复后的任务 ID 通常与来源任务 ID 不同。将 `source_job_id`、`state_path` 和
`resumed_job_id` 记录为应用负责的沿袭关系。不要因为两个任务 ID 不同而拒绝恢复。
请勿构造私有兼容性子路由。

## 4. 让边界可恢复

按以下顺序操作：

1. 等待 forward-backward 和优化器步骤 future 完成。
2. 保存状态检查点并等待保存 future 完成。
3. 持久化包含其路径的循环记录。
4. 将应用步骤标记为完成。
5. 开始下一步。

如果进程在保存检查点之后、持久化循环记录之前退出，请保留上一条完整记录作为可信的恢复点。
在记录持久保存之前，不要将步骤标记为完成。

## 5. 区分检查点类型

```python
name = f"step-{step:06d}"
state = call(
    "POST",
    f"/v1/training/jobs/{job_id}/save-weights",
    {"name": name},
)
sampler = call(
    "POST",
    f"/v1/training/jobs/{job_id}/save-weights-for-sampler",
    {"name": name, "ttl_seconds": 24 * 60 * 60},
)
```

| 保存方式 | 路径 | 用途 |
| --- | --- | --- |
| `save-weights` | `weights/<name>` | 训练恢复：加载它或从它启动新任务 |
| `save-weights-for-sampler` | `sampler_weights/<name>` | rollout、评估，以及以 PEFT LoRA 文件下载 |

不要将 sampler 检查点用作恢复点；它不含优化器状态，也无法用来启动新任务。

公开训练 API 通过
[`save-weights`](/cn/api-reference/training-jobs/interactive/save-weights)
保存训练状态，并通过
[`save-weights-for-sampler`](/cn/api-reference/training-jobs/interactive/save-sampler-weights)
保存采样权重。直接加载和采样路由接受检查点名称或同一任务的 `tinker://` 路径。
停止任务后仍可采样。共享的列表和下载路由适用于交互式检查点，下载仍需要权重下载
权限。Tinker 提供匹配的 SDK 方法。请勿构造私有兼容性子路由，也不要假设未记录的
保留期。

使用以下路由管理检查点：

| 任务 | 路由 |
| --- | --- |
| 列出任务的检查点 | [`GET /v1/training/jobs/{job_id}/checkpoints`](/cn/api-reference/training-jobs/checkpoints) |
| 获取单个检查点 | [`GET /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}`](/cn/api-reference/interactive-jobs/get-checkpoint) |
| 下载为 `.tar` 归档 | [`GET /v1/training/jobs/{job_id}/checkpoints/{checkpoint_id}/download`](/cn/api-reference/training-jobs/download-checkpoint) |
| 修改 TTL | [`PUT /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}/ttl`](/cn/api-reference/interactive-jobs/set-checkpoint-ttl) |
| 发布或取消发布 | [`POST /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}/publish`](/cn/api-reference/interactive-jobs/publish-checkpoint) |
| 删除 | [`DELETE /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}`](/cn/api-reference/interactive-jobs/delete-checkpoint) |
| 读取存储用量 | [`GET /v1/training/usage`](/cn/api-reference/interactive-jobs/usage) |

下载需要团队具备权重下载权限。

## 6. 验证继续结果

在扩大恢复后的工作负载之前：

1. 从所选状态检查点启动新任务。
2. 将其 ID 持久化为 `resumed_job_id`，并通过 `GET /v1/training/jobs/{resumed_job_id}` 确认。
3. 运行一次小规模的留出集评估。
4. 提交一次训练更新。
5. 以新名称保存新的状态检查点。
6. 持久化下一条循环记录。

交互式模型操作可以使用原生 JSON 路由或受支持的 Tinker SDK。

## 诊断恢复错误

| 现象 | 检查 |
| --- | --- |
| Future 失败 | 记录任务 ID 和操作结果。不要推进依赖的应用状态 |
| 无法加载检查点 | 验证其任务、检查点类型和客户端负责的恢复记录 |
| 来源检查点被拒绝 | 确认其来源任务、检查点类型和持久化的 `state_path`；不要要求新任务 ID 等于来源 ID |
| 恢复后的任务查找失败 | 确认 ID 来自恢复后客户端的 `get_info().model_id`，且已通过同一 Fastino 团队的身份验证 |
