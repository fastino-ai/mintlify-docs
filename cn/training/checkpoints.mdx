状态检查点保护服务器端的训练状态。完整的恢复记录还会保护由用户持有、告诉控制器下一步做什么的状态。

示例使用[快速入门脚本](/cn/training/decoder-quickstart)中的 `call` 和 `wait` 辅助函数。

## 保存什么

| 记录 | 内容 | 存储方 |
| --- | --- | --- |
| 状态检查点 | LoRA 权重和优化器状态 | Fastino |
| 循环记录 | 源任务 ID、检查点路径、步骤、数据集游标、配置和恢复谱系 | 你的应用 |

## 1. 保存状态和循环进度

使用 `save-weights` 保存状态并等待其完成，然后将其路径与继续所需的客户端字段一起持久化：

```python
import json
from pathlib import Path


state = call(
    "POST",
    f"/v1/training/jobs/{job_id}/save-weights",
    {"name": f"step-{step:06d}"},
)
state_path = wait(job_id, state["future_id"])["path"]
record = {
    "source_job_id": job_id,
    "state_path": state_path,
    "model": model_name,
    "dataset_revision": dataset_revision,
    "optimizer": adam_params,
    "step": step,
    "dataset_cursor": dataset_cursor,
    "reward_version": reward_version,
}

with Path(log_path).open("a", encoding="utf-8") as checkpoint_log:
    checkpoint_log.write(json.dumps(record, sort_keys=True) + "\n")
```

初始保存响应中的路径只是临时路径。只有在保存 future 完成后，检查点才会持久保存；如果该 future 失败或被取消，请勿持久化或使用该路径。

请使用唯一的检查点名称，使每条循环记录都对应一个明确的恢复边界。名称由 1–128 个字符组成，取自 `A-Z`、`a-z`、`0-9`、`.`、`_` 和 `-`。以 `__park-` 或 `__snap-` 开头的名称为保留名称。

## 2. 读取最新的完整记录

进程可能在写入最后一行时停止。请从后向前扫描并跳过格式错误的尾行：

```python
def get_last_checkpoint(log_path: str) -> dict[str, object] | None:
    path = Path(log_path)
    if not path.exists():
        return None

    for line in reversed(path.read_text(encoding="utf-8").splitlines()):
        try:
            record = json.loads(line)
        except json.JSONDecodeError:
            continue
        if isinstance(record, dict) and isinstance(record.get("state_path"), str):
            return record
    return None
```

## 3. 加载前验证

将记录与源检查点和请求的继续方式进行比较：

- 检查点路径中的源任务 ID
- 基础模型和 LoRA 配置
- 数据集修订版本和游标
- 奖励实现的修订版本
- 优化器设置
- tokenizer 和聊天模板假设

如果这些字段存在冲突，请停下来做出明确决定。不要在无提示的情况下将检查点与其他实验混用。

然后选择继续方式：

| 情况 | 调用 |
| --- | --- |
| 源任务仍处于活动状态，且你想回滚 | 使用 `{"path": "<name>", "optimizer": true}` 调用 `POST /v1/training/jobs/{job_id}/load-weights` |
| 源任务已停止或已释放 | 使用 `from_checkpoint` 和 `load_optimizer` 调用 `POST /v1/training/jobs/create-model` |

在新任务中继续：

```python
resume = get_last_checkpoint(log_path)
if resume is None:
    raise RuntimeError("no durable checkpoint record found")

resumed = call(
    "POST",
    "/v1/training/jobs/create-model",
    {"from_checkpoint": resume["state_path"], "load_optimizer": True},
)
wait(resumed["job_id"], resumed["future_id"])
wait(resumed["job_id"], resumed["load_future_id"])
resumed_job_id = resumed["job_id"]
```

新任务沿用检查点的基础模型和 LoRA 设置，因此不要发送 `lora_config`。其 ID 与源任务 ID 不同。请将 `source_job_id`、`state_path` 和 `resumed_job_id` 记录为应用自有的谱系。

## 4. 让边界可恢复

按以下顺序操作：

1. 等待 forward-backward 和优化器步骤 future 完成。
2. 保存状态检查点并等待保存 future 完成。
3. 持久化包含其路径的循环记录。
4. 将应用步骤标记为完成。
5. 开始下一步。

如果进程在保存检查点之后、持久化循环记录之前退出，请保留上一条完整记录作为可信的恢复点。在记录持久保存之前，不要将步骤标记为完成。

Future 结果在一小时内可恢复。在此期间，请先轮询已知的保存 `future_id`，再判断实际发生了什么。如果返回 `410`，请勿盲目重复保存，而应将任务的检查点与你持久保存的循环记录进行核对。长期的提交边界是已完成的检查点及其持久保存的应用记录，而不是 future 本身。

## 5. 区分检查点类型

```python
name = f"step-{step:06d}"
state = call(
    "POST",
    f"/v1/training/jobs/{job_id}/save-weights",
    {"name": name},
)
sampler = call(
    "POST",
    f"/v1/training/jobs/{job_id}/save-weights-for-sampler",
    {"name": name, "ttl_seconds": 24 * 60 * 60},
)
```

| 保存方式 | 检查点 ID 后缀 | 完整路径 | 用途 |
| --- | --- | --- | --- |
| `save-weights` | `weights/<name>` | `tinker://<job_id>/weights/<name>` | 训练恢复：加载它或从它启动新任务 |
| `save-weights-for-sampler` | `sampler_weights/<name>` | `tinker://<job_id>/sampler_weights/<name>` | rollout、评估，以及以 PEFT LoRA 文件下载 |

不要将 sampler 检查点用作恢复点；它不含优化器状态，也无法用来启动新任务。请将完整的 `tinker://.../weights/<name>` 路径（而不是检查点 ID 后缀）作为 `from_checkpoint` 传入。

`ttl_seconds` 默认为 `null`，因此省略 TTL 时检查点会一直保留到你删除为止。未删除的检查点计入检查点存储。要启用自动清理，请传入 `3600` 到 `315360000` 秒（1 小时到 10 年）之间的值。

使用以下路由管理检查点：

| 任务 | 路由 |
| --- | --- |
| 列出任务的检查点 | [`GET /v1/training/jobs/{job_id}/checkpoints`](/cn/api-reference/training-jobs/checkpoints) |
| 获取单个检查点 | [`GET /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}`](/cn/api-reference/training-jobs/interactive/get-checkpoint) |
| 下载为 `.tar` 归档 | [`GET /v1/training/jobs/{job_id}/checkpoints/{checkpoint_id}/download`](/cn/api-reference/training-jobs/download-checkpoint) |
| 修改 TTL | [`PUT /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}/ttl`](/cn/api-reference/training-jobs/interactive/set-checkpoint-ttl) |
| 发布或取消发布 | [`POST /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}/publish`](/cn/api-reference/training-jobs/interactive/publish-checkpoint) |
| 删除 | [`DELETE /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}`](/cn/api-reference/training-jobs/interactive/delete-checkpoint) |
| 读取存储用量 | [`GET /v1/training/usage`](/cn/api-reference/training-jobs/interactive/storage-usage) |

下载需要团队具备权重下载权限。

任务停止后，会修改状态的训练操作将被拒绝，但你仍可列出、查看、下载、发布和删除其检查点，以及修改检查点的 TTL，也仍可从其 sampler 检查点采样。

## 6. 验证继续结果

在扩大恢复后的工作负载之前：

1. 从所选状态检查点启动新任务。
2. 将其 ID 持久化为 `resumed_job_id`，并通过 `GET /v1/training/jobs/{resumed_job_id}` 确认。
3. 运行一次小规模的留出集评估。
4. 提交一次训练更新。
5. 以新名称保存新的状态检查点。
6. 持久化下一条循环记录。

## 部署训练好的模型

部署 sampler 检查点即可将其作为模型提供服务。部署适用于受支持的基础模型；其他基础模型返回 `400`。

```bash
curl -X POST "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/checkpoints/sampler_weights/step-000100/deploy" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model_name": "support-replies-v1"}'
```

响应包含模型的 `model_id`，`status` 为 `deploying`。重复同一调用即可查看进度：它返回同一个模型，模型就绪后 `status` 变为 `deployed`。然后按 ID 调用它：

```bash
curl -X POST "https://api.fastino.ai/v1/chat/completions" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "Summarize this ticket in one sentence."}]
  }'
```

将 `MODEL_ID` 替换为返回的 `model_id`。请求字段和错误请参阅[部署检查点](/cn/api-reference/training-jobs/interactive/deploy-checkpoint)。

## 诊断恢复错误

| 现象 | 检查 |
| --- | --- |
| future 失败 | 记录任务 ID 和 future 的 `error`。不要推进依赖它的应用状态 |
| 暂停后训练调用返回 `400` | 任务已停止，或在空闲 30 分钟后被释放。会修改状态的训练操作不可用，但检查点管理和 sampler 检查点采样仍可用。要继续训练，请从最新状态检查点启动新任务 |
| 检查点无法加载 | 核实其任务、检查点类型以及客户端持有的恢复记录 |
| `from_checkpoint` 被拒绝 | 确认它是你团队的完整 `tinker://<job_id>/weights/<name>` 路径；sampler 检查点无法用于启动任务 |
| 查询恢复后的任务失败 | 确认 ID 来自新任务的创建响应，且已使用同一 Fastino 团队进行身份验证 |
