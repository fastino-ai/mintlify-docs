当代码可以检查响应时（例如数学答案、测试结果、schema 约束、精确抽取或工具结果），请使用可验证奖励。

```text
prompt -> sample a group -> grade -> center rewards -> build datums -> update
```

采样、forward-backward、优化器步骤和检查点都属于同一个 Fastino 交互式任务。奖励计算和应用状态保留在你的代码中。

## 前提条件

先从可运行的[自定义训练循环](/cn/training/decoder-quickstart)开始，并确认基准 datum
能够成功训练。本指南复用其中的 `call` 和 `wait` 辅助函数、`tokenizer` 以及 `job_id`。

你的应用负责采样响应、评分，并将奖励转换为逐 token 优势。Fastino 使用受支持的损失函数应用这些优势：
`importance_sampling`、`ppo`、`cispo` 或 `dro`。自定义损失函数无法在训练任务内部运行。

## 1. 定义范围明确的评分器

将解析与评分分开，以便发现格式错误的输出：

<Warning>
  仅在隔离且资源受限的环境中运行生成的代码或工具。Fastino 不会执行你的奖励函数，也不会管理其副作用。
</Warning>

```python
def get_reward(response: str, expected: str) -> float:
    actual = parse_answer(response)
    if actual is None:
        return 0.0
    return 1.0 if actual == expected else 0.0
```

维护一组固定的测试用例，包括正确、错误、格式错误以及格式不同但等价的答案。将解析失败与有效但错误的响应分开记录。

## 2. 为采样保存任务快照

从当前权重保存 sampler 检查点，然后从中采样一组响应：

```python
name = f"rollout-{step:06d}"
saved = call(
    "POST",
    f"/v1/training/jobs/{job_id}/save-weights-for-sampler",
    {"name": name, "ttl_seconds": 24 * 60 * 60},
)
wait(job_id, saved["future_id"])

prompt_tokens = tokenizer.apply_chat_template(
    [{"role": "user", "content": question}],
    add_generation_prompt=True,
    enable_thinking=False,
    return_dict=False,
)
sampled = call(
    "POST",
    f"/v1/training/jobs/{job_id}/sample",
    {
        "checkpoint": name,
        "prompt_tokens": prompt_tokens,
        "num_samples": group_size,
        "sampling_params": {"max_tokens": 512, "temperature": 1.0},
    },
)
sample_result = wait(job_id, sampled["future_id"])
```

这不会创建新任务。检查点和样本都属于同一个 交互式任务。

## 3. 将奖励转换为优势

```python
sequences = sample_result["sequences"]
rewards = [
    get_reward(tokenizer.decode(sequence["tokens"]), expected)
    for sequence in sequences
]

mean_reward = sum(rewards) / len(rewards)
advantages = [reward - mean_reward for reward in rewards]

if all(advantage == 0.0 for advantage in advantages):
    continue
```

跟踪奖励没有方差的组。这可能说明任务过于简单、过于困难，或者解析有误。

## 4. 构建对齐的 datum

提示是上下文，因此提示位置的优势为零。补全位置使用该响应的组相对优势和 sampler 的对数概率。每个张量在每个输入位置上都有一个值：

```python
def rl_datum(prompt_tokens, sequence, advantage):
    completion = sequence["tokens"]
    tokens = prompt_tokens + completion
    padding = [0.0] * (len(prompt_tokens) - 1)
    logprobs = padding + sequence["logprobs"]
    advantages = padding + [advantage] * len(completion)
    if not (len(tokens) - 1 == len(logprobs) == len(advantages)):
        raise ValueError("training datum arrays are not aligned")
    return {
        "model_input": {"chunks": [{"type": "encoded_text", "tokens": tokens[:-1]}]},
        "loss_fn_inputs": {
            "target_tokens": {"data": tokens[1:], "dtype": "int64"},
            "logprobs": {"data": logprobs, "dtype": "float32"},
            "advantages": {"data": advantages, "dtype": "float32"},
        },
    }


datums = [
    rl_datum(prompt_tokens, sequence, advantage)
    for sequence, advantage in zip(sequences, advantages)
]
```

提示和解码都使用任务 `base_model` 的 tokenizer。

## 5. 更新 交互式任务

```python
backward = call(
    "POST",
    f"/v1/training/jobs/{job_id}/forward-backward",
    {"datums": datums, "loss_fn": "importance_sampling"},
)
train_result = wait(job_id, backward["future_id"])
update = call(
    "POST",
    f"/v1/training/jobs/{job_id}/optim-step",
    {"adam_params": {"learning_rate": 1e-5}},
)
optim_result = wait(job_id, update["future_id"])
```

请等待 forward-backward 成功完成后再提交优化器步骤。在推进应用步骤之前，请等待优化器结果并将其记录下来。

支持的 `loss_fn_config` 字段和默认值：

| 适用范围 | 字段和默认值 |
| --- | --- |
| `ppo` | `clip_low_threshold: 0.8`、`clip_high_threshold: 1.2` |
| `cispo` | `clip_low_threshold: 0.0`、`clip_high_threshold: 4.0` |
| `dro` | `beta: 0.05` |
| 奖励损失 | `tis_cap: 2`、`icepop_low: 0.5`、`icepop_high: 5` |

最后一行中的奖励损失保护机制默认启用。未知的配置字段会被拒绝。

## 6. 保存恢复边界

```python
state = call(
    "POST",
    f"/v1/training/jobs/{job_id}/save-weights",
    {"name": f"step-{step:06d}"},
)
wait(job_id, state["future_id"])
```

将返回的 `path` 与以下信息一起持久化：

- 任务 ID
- 应用步骤和数据集游标
- 数据集和奖励实现的修订版本
- 基础模型和训练配置
- 评估指标

有了这些元数据，控制器无需根据名称猜测就能选择检查点。

## 扩大规模前验证

- 评分器能够区分已知的正确和错误用例。
- 格式错误的响应不会使应用循环崩溃。
- 至少有一个样本组存在奖励方差。
- 每个 datum 的张量在每个输入位置上都有一个值。
- forward-backward 和优化器步骤 operation 在同一个任务上完成。
- 新任务可以凭借客户端持有的恢复元数据，从状态检查点启动。
- 留出集评估与训练奖励批次保持分离。

关于完整的生命周期，请阅读[构建自定义训练循环](/cn/training/training-loop)。
