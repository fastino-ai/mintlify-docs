**决策模型**会根据调用方定义的结果来评估文本或结构化的应用状态，并返回结构化决策（标签、概率分布、分数和置信度），而不是生成的文本。当应用代码必须基于有界答案采取行动时，可以将决策模型用于分类、智能体和模型路由、评分、内容审核、护栏以及是/否关卡。

Fastino 的 [GLiDE 决策模型](/cn/concepts/glide)通过 System One API 接收一个共享的 `state` 以及一个或多个带类型的 `questions`。调用方定义允许的结果，GLiDE 返回经过校准的概率，代码可以据此设定阈值、进行路由或升级为人工审核。

## 决策模型与生成式 LLM 对比

|  | 决策模型 | 生成式 LLM |
| --- | --- | --- |
| 最适合 | 分类、路由、评分、内容审核和关卡 | 开放式生成、对话、摘要和编程 |
| 输出 | 基于调用方定义结果的带类型答案 | 生成的文本或工具调用 |
| 不确定性 | 明确的概率和置信度 | 通常需要额外的校准或验证 |
| 应用模式 | 基于有界结果执行、路由或升级 | 生成、解释、规划或转换内容 |

这两类模型可以协同工作：使用决策模型对请求进行分类、选择智能体或模型，或对某个操作进行把关，然后仅在工作流需要开放式输出时才调用生成式 LLM。

## 为什么使用决策模型

决策模型适合需要执行明确操作，而不是展示生成文本的应用：

- **原生结构化** — 每个答案都符合 Noul、Choice 或 Score 格式，无需解析或验证生成文本。
- **调用方定义结果** — 应用控制允许的操作，并可将每个结果直接映射到代码。
- **显式不确定性** — 概率和置信度可自动处理明确情况，并将模糊情况送交审批、复核或后备流程。

## 决策模型基本类型

你向 [GLiDE](/cn/concepts/glide) 提出的每个问题都使用以下三种类型之一，并针对共享的 `state` 发送到 `POST /v1/systemone`：

- **[Noul](/cn/concepts/glide-noul)**：是/否问题，返回 0 到 1 之间的概率。可以把它看作一个按连续刻度取值的布尔值。“此请求是否符合退款条件？”可能返回 `0.999`，即答案为“是”的概率为 99.9%。
- **[Choice](/cn/concepts/glide-choice)**：多选一问题，返回 2 到 255 个具名选项上的概率分布。“应由哪个团队处理此请求？”可能返回 `{"billing": 0.0006, "returns": 0.999, "shipping": 0.0005}`。
- **[Score](/cn/concepts/glide-score)**：按量表评分的问题，基于你定义的有序评分标准。“此请求有多紧急？”在三个等级下可能返回 `score: 0`（低）和 `expected_level: 0.276`，这是一个介于低与中等之间、但更接近低的概率加权结果。

请根据代码所需答案的形式选择类型。

<Tip>
  Noul 与 Score 的区别：Noul 为 `0.5` 表示在是与否之间存在最大不确定性，它并不表达程度。如果需要衡量程度（紧急程度、严重程度、不满程度），请使用定义了等级的 Score。如果需要二元判断关卡，请使用 Noul。
</Tip>

不存在多标签基本类型，每个问题都是单标签的。如果需要同时做出多个判断，可以在一次调用中提出多个相互独立的问题；请参阅[组合多个问题](/cn/inference/systemone#组合多个问题)。

## 置信度

每个答案都带有一个 `confidence` 值。答案告诉你 GLiDE 得出了*什么*结论；置信度则告诉你*是否应据此采取行动*。请将二者视为两个独立的维度，而不是同一个。

| 问题类型 | 公式 | 范围 |
| --- | --- | --- |
| Noul | `\|2 × noul − 1\|` | 从 `0`（最大不确定性，`noul = 0.5`）到 `1`（完全确定，`noul = 0` 或 `1`） |
| Choice / Score | `top1 − top2`（最佳与次佳选项或等级之间的概率差） | 从 `0`（两个选项持平）到 `1`（某个选项占据几乎全部概率质量） |

低置信度的答案并不代表错误，而是表示概率质量分散在两个或更多结果上，而不是集中在一个结果上，这本身就是有用的信号。一种常见模式是**置信度门控路由**：对高置信度答案自动执行操作，将低置信度答案路由到备用流程（人工审核、更宽泛的类别或二次检查）：

```python
answer = response["answers"]["department"]

if answer["confidence"] >= 0.6:
    route_to(answer["choice"])
else:
    route_to("triage-queue")  # ambiguous - let a human or a broader handler decide
```

请根据你使用场景的真实数据调整阈值，而不要假定 `0.5` 就是正确的。置信度是按模型校准的，并不保证与任何特定业务对模糊性的容忍度相对应。

每个基本类型的页面都提供了完整示例以及更多关于如何使用其结果的说明：[Noul](/cn/concepts/glide-noul)、[Choice](/cn/concepts/glide-choice)、[Score](/cn/concepts/glide-score)。
