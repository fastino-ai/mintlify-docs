添加顶层 `schema.classifications` 数组，以定义一个或多个分类任务。每个任务仅接受以下键：

<ParamField body="task" type="string" required>
  分类任务的稳定名称。解析后的结果中会出现相同名称。
</ParamField>

<ParamField body="labels" type="string[]" required>
  至少两个允许的标签。Decide 不接受标签描述对象。
</ParamField>

<ParamField body="multi_label" type="boolean" default="false">
  当为 `false` 时，返回得分最高的单个标签。当为 `true` 时，返回每个达到 `cls_threshold` 的标签。
</ParamField>

<ParamField body="cls_threshold" type="number">
  多标签任务在推理时使用的临界值，取值范围为 `0` 到 `1`。它不影响训练，也不会改变单标签选择。
</ParamField>

<ParamField body="top_k" type="integer">
  为兼容性而接受，但目前对 GLiNER 2.5 Decide 不起作用。
</ParamField>

## 单标签分类

```json
{
  "classifications": [
    {
      "task": "intent",
      "labels": ["refund_request", "cancel_subscription", "login_problem"],
      "multi_label": false
    }
  ]
}
```

单标签任务始终返回得分最高的标签。标签是无序的；按此顺序列出 `low`、`medium` 和 `high` 并不会创建有序量表。

## 多标签分类

```json
{
  "classifications": [
    {
      "task": "tags",
      "labels": ["technical_issue", "login_problem", "urgent", "human_handoff"],
      "multi_label": true,
      "cls_threshold": 0.2
    }
  ]
}
```

多标签任务返回一个数组，其中包含每个选中的标签及其置信度。提高 `cls_threshold` 更偏向精确率；降低它更偏向召回率。

## 在一个请求中运行多个任务

```json
{
  "classifications": [
    {
      "task": "intent",
      "labels": ["refund_request", "cancel_subscription", "login_problem"],
      "multi_label": false
    },
    {
      "task": "urgency",
      "labels": ["low", "normal", "high", "critical"],
      "multi_label": false
    }
  ]
}
```

任务会在一次前向传播中完成评分，但仍然彼此独立。经典分类不会在任务之间强制执行蕴含、排斥、基数规则或有序关系。

## 默认 schema

如果同时省略 `schema` 和 `response_format`，Decide 会使用目录中默认的 `intent` 任务及 `book`、`cancel`、`change` 和 `status`。使用该默认值时，响应会报告 `x_fastino.default_schema_applied: true`。

## 常见验证错误

| 无效输入 | 应改为 |
| --- | --- |
| `"labels": {"book": "user wants to book"}` | `"labels": ["book", "cancel"]` |
| `label_descriptions` 键 | 删除该键，并将标签保留为字符串 |
| 任务上的 `description` 键 | 删除该键 |
| 任务内的 `"threshold": 0.5` | `"cls_threshold": 0.5`，并设置 `"multi_label": true` |
| 少于两个标签 | 至少提供两个标签 |
