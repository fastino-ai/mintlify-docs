GLiDE（Generalized Lightweight Decision Engine）是一款思考型决策模型。它不生成自由格式文本，而是根据一个或多个类型化问题评估你提供的应用状态，并针对你定义的结果返回结构化标签、概率和置信度分数。

## 为什么使用决策模型

决策模型适合需要执行明确操作，而不是展示生成文本的应用：

- **原生结构化** — 每个答案都符合 Noul、Choice 或 Score 格式，无需解析或验证生成文本。
- **调用方定义结果** — 应用控制允许的操作，并可将每个结果直接映射到代码。
- **显式不确定性** — 概率和置信度可自动处理明确情况，并将模糊情况送交审批、复核或后备流程。

## 为什么选择 GLiDE

GLiDE 会先快速评估，再为不确定的决策分配额外推理。最终概率会纳入这些推理，因此同一套接口既适用于常规分类，也适用于需要算术、代码追踪、时间逻辑、政策解读或关联多项事实的决策。

GLiDE 每个问题可在 40,000 个 token 的上下文窗口内评估最多 255 个选项或等级。在 Decision Index 0.2.1 上，GLiDE 得分为 **64.81**，高于 Jev 公布的 **57.91**，并在全部五个评估领域以及 38 项基准中的 31 项领先。

## 何时使用 GLiDE

当软件必须从预定义结果中作出选择时，GLiDE 非常适合：

| 使用场景 | 决策示例 |
| --- | --- |
| 智能体和工具路由 | 在考虑权限和先前结果后，从大量工具中选择下一步操作 |
| 高风险操作控制 | 执行、转入沙箱、请求批准或阻止拟议操作 |
| 生产事件响应 | 根据告警、日志和运行手册选择监控、重启、回滚、隔离或升级 |
| 合同和政策 | 将交叉引用、日期、阈值和例外条款应用于具体情况 |
| 模型输出验证 | 接受、拒绝或要求修改需要复杂推理的输出 |
| 日常分类 | 路由工单、审核内容、评估紧急程度或替代 LLM-as-judge 步骤 |

对于自由格式生成、多轮对话、开放式问答、摘要或代码生成，请改用通用语言模型。

## 从模型概念到推理

1. 阅读[决策模型参考](/cn/concepts/decision-models)，了解共享的 `state`、`questions`、
   限制以及置信度约定。
2. 根据应用所需的答案形式，选择 [Noul](/cn/concepts/glide-noul)、[Choice](/cn/concepts/glide-choice) 或
   [Score](/cn/concepts/glide-score)。
3. 调用 [`POST /v1/systemone`](/cn/inference/systemone)。GLiDE 不使用
   `/v1/chat/completions`。
