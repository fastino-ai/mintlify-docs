训练任务通过名称引用已就绪的数据集。请准备一个 JSONL 文件，通过两步式数据集 API 上传，
并在调用 `POST /v1/training/jobs` 之前确认已处理的版本存在。

## 选择数据集格式

文件中的每一行都必须是一个 JSON 对象。同一数据集中请始终使用一致的结构。

### 命名实体识别

使用 `text` 加上由 `[span, label]` 对组成的 `entities` 列表。每个 span 都必须出现在文本中，但匹配不区分大小写：对于 `"Ada Lovelace"`，`"ada lovelace"` 是有效值。请使用空列表来包含负样本。

```jsonl
{"text":"Ada Lovelace worked in London.","entities":[["Ada Lovelace","PERSON"],["London","LOCATION"]]}
{"text":"No tagged entities here.","entities":[]}
```

### 分类

单标签数据使用 `label`，多标签数据使用 `labels`。每一行必须使用相同的字段。

```jsonl
{"text":"The setup was straightforward.","label":"positive"}
{"text":"The request needs technical help.","label":"technical"}
```

### GLiNER2 库格式

NER 和分类上传也接受 GLiNER2 的规范 `input` 和 `output` 结构。对于 NER，
请将每个实体标签映射到匹配的 span：

```jsonl
{"input":"Ada Lovelace worked in London.","output":{"entities":{"PERSON":["Ada Lovelace"],"LOCATION":["London"]}}}
{"input":"No tagged entities here.","output":{"entities":{"PERSON":[],"LOCATION":[]}}}
```

对于分类，每行的 `classifications` 可以包含一个或多个任务：

```jsonl
{"input":"jump now","output":{"classifications":[{"task":"action","labels":["jump","wait"],"true_label":["jump"]},{"task":"urgency","labels":["now","later"],"true_label":["now"]}]}}
```

每行只能使用一种结构。请勿在同一行中混用 `text`、`label`、`labels` 或
`entities` 与 `input` 和 `output` 字段。

### 联合 NER 与分类

一行可以同时包含 `entities` 和 `label`，以训练两个输出头。每一行都应保持相同的联合结构，并且不要混用单标签 `label` 与多标签 `labels`。

```jsonl
{"text":"Ada Lovelace worked in London.","entities":[["Ada Lovelace","PERSON"],["London","LOCATION"]],"label":"biography"}
{"text":"No tagged entities here.","entities":[],"label":"other"}
```

### 解码器

将 `dataset_type` 设为 `decoder`，并让每一行都包含带聊天 role 和 content 的 `messages` 数组。

```jsonl
{"messages":[{"role":"user","content":"What is 2+2?"},{"role":"assistant","content":"4"}]}
```

<Note>
  数据集服务接受用于微调代理和存储工作流的解码器数据集。配置任务会拒绝解码器基础模型，因此不要将 `dataset_type: decoder` 视为直接通过配置任务训练解码器的路径。交互式任务不接受数据集名称；请在应用中读取示例并进行分词，然后按照[解码器快速入门](/cn/training/decoder-quickstart)发送已分词的 datums。
</Note>

## 上传数据集

### 1. 预留上传 URL

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/upload/url \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "dataset_name": "docs-example-ner",
    "filename": "training.jsonl",
    "dataset_type": "ner"
  }' | tee dataset-upload.json

export PRESIGNED_URL="$(jq -r '.presigned_url' dataset-upload.json)"
export DATASET_ID="$(jq -r '.dataset_id' dataset-upload.json)"
export DATASET_VERSION="$(jq -r '.version_number' dataset-upload.json)"
```

响应包含一个短时有效的 `presigned_url`、一个 `dataset_id` 和一个 `version_number`。
上述命令会保留这三个值。将文件的原始字节上传到预签名 URL：

```bash
curl --fail-with-body -X PUT \
  -H "Content-Type: application/octet-stream" \
  --upload-file training.jsonl "$PRESIGNED_URL"
```

### 2. 处理已上传的文件

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/upload/process \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d "$(jq -n --arg dataset_id "$DATASET_ID" '{dataset_id: $dataset_id}')"
```

处理请求返回 `202`。按名称轮询数据集，并选择 `version_number` 与上传响应完全一致的条目。
持续轮询，直到该版本的 `status` 变为 `ready` 或 `failed`。如果状态为 `failed`，
请停止轮询并显示其 `processing_error`；不要将该版本提交给训练。

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/docs-example-ner \
  -H "X-API-Key: $FASTINO_API_KEY"
```

## 开始训练

将确切的数据集名称传递给[训练任务创建端点](/cn/api-reference/training-jobs/create)：

```json
{
  "model_name": "my-ner-model",
  "base_model": "fastino/gliner2-base-v1",
  "datasets": [
    {"name": "docs-example-ner", "version": "VERSION_NUMBER_FROM_UPLOAD"}
  ],
  "training_type": "lora"
}
```

请在提交前立即调用 `GET /v1/base-models?supports_training=true`，以选择当前可训练的基础模型。

## 常见阻碍

| 状态 | 原因 | 处理方式 |
| --- | --- | --- |
| `401` | API 密钥缺失或无效 | 发送 `X-API-Key: $FASTINO_API_KEY` |
| `404` | 数据集名称不存在 | 确认确切名称并等待处理完成 |
| `failed` | 异步内容验证失败 | 查看 `processing_error`，修正 JSONL，然后上传新版本 |
| `422` | 请求结构在处理前被拒绝 | 修正请求字段后重试 |
