训练任务通过名称引用已就绪的数据集。请准备一个 JSONL 文件，通过两步式数据集 API 上传，
并在调用 `POST /v1/training/jobs` 之前确认已处理的版本存在。

## 选择数据集格式

文件中的每一行都必须是一个 JSON 对象。同一数据集中请始终使用一致的结构。

### 命名实体识别

使用 `text` 加上由 `[span, label]` 对组成的 `entities` 列表。每个 span 都必须逐字出现在文本中。
请使用空列表来包含负样本。

```jsonl
{"text":"Ada Lovelace worked in London.","entities":[["Ada Lovelace","PERSON"],["London","LOCATION"]]}
{"text":"No tagged entities here.","entities":[]}
```

### 分类

单标签数据使用 `label`，多标签数据使用 `labels`。

```jsonl
{"text":"The setup was straightforward.","label":"positive"}
{"text":"The request needs billing and technical help.","labels":["billing","technical"]}
```

### 解码器 SFT 和 GRPO

将 `dataset_type` 设为 `decoder`。SFT 使用包含聊天 role 和 content 的
`messages` 数组。GRPO 接受相同的 prompt 数据，并在配置任务中使用
`training_algorithm: "grpo"` 和 `rl_config`。

```jsonl
{"messages":[{"role":"user","content":"What is 2+2?"},{"role":"assistant","content":"4"}]}
```

<Warning>
  使用 `dataset_type: decoder` 的公开上传要求每一行都包含 `messages`
  数组。仅包含 `prompt`、`chosen` 和 `rejected` 的 DPO 行无法通过上传验证。
</Warning>

<Note>
  解码器数据集适用于托管式[配置任务](/cn/api-reference/training-jobs/create)。当应用必须对示例分词并控制每个训练步骤时，请使用[交互式任务](/cn/training/quickstart#custom-training-loop)。
</Note>

## 上传数据集

### 1. 预留上传 URL

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/upload/url \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "dataset_name": "docs-example-ner",
    "filename": "training.jsonl",
    "dataset_type": "ner"
  }' | tee dataset-upload.json

export PRESIGNED_URL="$(jq -r '.presigned_url' dataset-upload.json)"
export DATASET_ID="$(jq -r '.dataset_id' dataset-upload.json)"
export DATASET_VERSION="$(jq -r '.version_number' dataset-upload.json)"
```

响应包含一个短时有效的 `presigned_url`、一个 `dataset_id` 和一个 `version_number`。
上述命令会保留这三个值。将文件的原始字节上传到预签名 URL：

```bash
curl --fail-with-body -X PUT --upload-file training.jsonl "$PRESIGNED_URL"
```

### 2. 处理已上传的文件

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/upload/process \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d "$(jq -n --arg dataset_id "$DATASET_ID" '{dataset_id: $dataset_id}')"
```

处理请求返回 `202`。按名称轮询数据集，并选择 `version_number` 与上传响应完全一致的条目。
持续轮询，直到该版本的 `status` 变为 `ready` 或 `failed`。如果状态为 `failed`，
请停止轮询并显示其 `processing_error`；不要将该版本提交给训练。

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/docs-example-ner \
  -H "X-API-Key: $FASTINO_API_KEY"
```

## 开始训练

将确切的数据集名称传递给[训练任务创建端点](/cn/api-reference/training-jobs/create)：

```json
{
  "model_name": "my-ner-model",
  "base_model": "fastino/gliner2-multi-v1",
  "datasets": [
    {"name": "docs-example-ner", "version": "VERSION_NUMBER_FROM_UPLOAD"}
  ],
  "training_type": "lora"
}
```

请在提交前立即调用 `GET /v1/base-models?supports_training=true`，以选择当前可训练的基础模型。

## 常见阻碍

| 状态 | 原因 | 处理方式 |
| --- | --- | --- |
| `401` | API 密钥缺失或无效 | 发送 `X-API-Key: $FASTINO_API_KEY` |
| `404` | 数据集名称不存在 | 确认确切名称并等待处理完成 |
| `failed` | 异步内容验证失败 | 查看 `processing_error`，修正 JSONL，然后上传新版本 |
| `422` | 请求结构在处理前被拒绝 | 修正请求字段后重试 |

请勿上传 GLiNER 训练器内部使用的 `{"input": ..., "output": ...}` 结构。请先将其转换为公开的
`text` 加 `entities` 格式。
