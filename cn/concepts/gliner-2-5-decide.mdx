GLiNER-2.5-Decide 是 Fastino 针对英文分类任务调优的 GLiNER 模型。你可以在请求时提供自定义标签，无需提示生成式模型，即可完成意图、路由、情感、优先级和策略等运营决策。

## 何时使用 GLiNER-2.5-Decide

当分类是主要任务时，请使用 GLiNER-2.5-Decide：

- **意图和路由** — 将支持消息、邮件或智能体请求发送到正确的工作流。
- **一次完成多个决策** — 在一次模型调用中分类意图、紧急程度、路由和人工接管需求。
- **单标签和多标签分类** — 选择一个类别，或返回所有适用标签。
- **运营门控** — 判断智能体是否完成任务、是否需要人工接管或内容是否违反策略。
- **有序标签** — 使用有序标签集评估严重程度、紧急程度或评分。
- **自定义分类体系** — 在请求时定义标签和简短描述，无需为每次类别变更重新训练。

托管模型仍支持实体、关系和结构化抽取，但分类是选择它的主要原因。如果抽取是主要任务、需要 span 属性或联合实体关系解码，或输入是多语言，请使用 [GLiNER2.5](/cn/concepts/gliner)。

## 如何使用 GLiNER-2.5-Decide

通过与任何 GLiNER 模型相同的 Fastino 推理端点调用它，并使用 `classifications` schema。添加更多任务条目，即可在一次调用中对多个相关判断进行评分：

```bash
curl -X POST "https://api.fastino.ai/v1/chat/completions" \
  -H "Authorization: Bearer $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "fastino/GLiNER-2.5-Decide",
    "messages": [
      { "role": "user", "content": "My subscription renewed on April 15 after the service was already down. Can I get that refunded?" }
    ],
    "schema": {
      "classifications": [
        {
          "task": "intent",
          "labels": ["refund_request", "cancel_subscription", "login_problem", "speak_to_human"],
          "multi_label": false
        },
        {
          "task": "urgency",
          "labels": ["low", "normal", "high", "critical"],
          "multi_label": false
        }
      ]
    }
  }'
```

`intent` 和 `urgency` 会一起评分，因此路由器只需一次请求即可获得两个判断。有关响应约定、多标签分类和置信度阈值，请参阅 [Chat Completions API](/cn/inference/chat-completions)。
