GLiNER-2.5-Decide 是 Fastino 面向 schema 定义分类的 3.4 亿参数英文决策模型。你可以在请求时提供标签，无需提示生成式模型，即可获得结构化答案、概率和置信度分数。

<Note>
  Decide 不是生成式模型。它只从 schema 中声明的标签中进行选择，不会生成解释、对话或开放式回答。
</Note>

## 为什么使用 schema 定义的决策模型

当应用需要将文本转换为允许的操作时，schema 定义模型非常适合：

- **可预测的输出** - 模型只从你定义的标签中选择，下游代码无需解析或验证生成文本。
- **可操作的不确定性** - 概率和置信度支持阈值、人工复核和后备处理。
- **一次完成相关判断** - 从同一输入中分类意图、紧急程度、路由和人工接管需求，无需多次生成调用。

## 为什么选择 GLiNER-2.5-Decide

- **紧凑且快速** - 在已发布的短输入基准中，3.4 亿参数检查点在 NVIDIA V100 上达到 38.3 ms p50，在 48-vCPU Intel Xeon 上达到 167.3 ms。
- **开放且易于部署** - Apache 2.0 开放权重支持本地 CPU 推理、隔离网络部署，以及在 Fastino 上进行 LoRA 微调。
- **不仅限于分类** - 同一 GLiNER 架构可将分类与实体、关系和结构化记录结合。
- **灵活的 schema** - 可在请求时更改标签，无需为每次分类体系变化重新训练。

## 何时使用 GLiNER-2.5-Decide

当分类是主要任务时，请使用 GLiNER-2.5-Decide：

- **意图和路由** - 将支持消息、邮件或智能体请求发送到正确的工作流。
- **一次完成多个决策** - 在一次模型调用中分类意图、紧急程度、路由和人工接管需求。
- **单标签和多标签分类** - 选择一个类别，或返回所有适用标签。
- **运营门控** - 判断智能体是否完成任务、是否需要人工接管或内容是否违反策略。
- **严重程度和评分类别** - 为紧急程度、严重程度或评分选择一个由调用方定义的类别。
- **自定义分类体系** - 在请求时定义标签，无需为每次类别变更重新训练。

托管模型仍支持实体、关系和结构化抽取，但分类是选择它的主要原因。Decide 的托管 `classifications` schema 支持单标签和多标签任务，包括在一次前向传播中处理多个任务。经典分类标签是无序的；按从低到高的顺序列出严重程度或评分标签并不会产生有序约束。如果抽取或多语言覆盖是主要需求，或者相关分类需要硬性的蕴含、排斥、基数规则或等级界限，请使用 [GLiNER2.5 Multi](/cn/concepts/gliner)。如果结果需要开放式文本、对话或新生成的内容，而不是 schema 定义的决策，请使用通用语言模型。

## 如何使用 GLiNER-2.5-Decide

通过 Fastino 兼容 OpenAI 的推理端点调用它，并使用 `classifications` schema。每个分类任务至少需要两个候选标签。添加多个任务，即可在一次调用中对同一文本的多个方面进行分类：

```bash
curl -X POST "https://api.fastino.ai/v1/chat/completions" \
  -H "Authorization: Bearer $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "fastino/GLiNER-2.5-Decide",
    "messages": [
      { "role": "user", "content": "My subscription renewed on April 15 after the service was already down. Can I get that refunded?" }
    ],
    "schema": {
      "classifications": [
        {
          "task": "intent",
          "labels": ["refund_request", "cancel_subscription", "login_problem", "speak_to_human"],
          "multi_label": false
        },
        {
          "task": "urgency",
          "labels": ["low", "normal", "high", "critical"],
          "multi_label": false
        }
      ]
    }
  }'
```

`intent` 和 `urgency` 会在一次前向传播中完成评分，因此路由器只需一次请求即可获得两个判断。这种经典分类 schema 不会在任务之间强制执行规则。如需在跨任务约束下获得全局一致的分配，请使用 GLiNER2.5 Multi 的[受约束分类 schema](/cn/inference/chat-completions#受约束分类-schema)。

如需使用自己的分类体系，请发送显式 schema。如果同时省略 `schema` 和 `response_format`，Decide 会使用目录中默认的 `intent` 任务（`book`、`cancel`、`change` 和 `status`），并返回 `x_fastino.default_schema_applied: true`。

有关响应约定、多标签分类和置信度阈值，请参阅 [Chat Completions API](/cn/inference/chat-completions)。

## 分类 schema

`classifications` 中的每个条目只接受以下键：`task`、`labels`、`multi_label`、`cls_threshold` 和 `top_k`。任何其他键都会被拒绝并返回 `400`，错误信息会指出该键。

- `task` 为分类任务命名。
- `labels` 是至少包含两个字符串的列表，例如 `"labels": ["book", "cancel", "reschedule"]`。
- `multi_label` 为 `true` 时选择所有适用的标签。默认值为 `false`，即返回得分最高的单个标签。
- `cls_threshold` 是推理时使用的阈值，取值范围为 `0` 到 `1`：在多标签任务中，标签得分必须达到该值才会被选中。它不影响训练。单标签任务始终返回得分最高的标签。
- `top_k` 可以传入，但目前对 Decide 不起作用：使用不同 `top_k` 值的请求会返回相同的标签。请使用 `multi_label` 和 `cls_threshold` 控制返回哪些标签。

Decide 不支持标签描述，无论是在 `labels` 中使用 `{label: description}` 对象，还是使用单独的 `label_descriptions` 键。标签描述是 GLiNER2.5 Multi 的功能；参见[受约束分类 schema](/cn/inference/chat-completions#受约束分类-schema)。

<Warning>
  **常见错误。** Decide 会对以下每种结构返回 `400`：

  | 你发送的内容 | 应改为发送 |
  | --- | --- |
  | `"labels": {"book": "user wants to book", "cancel": "user wants to cancel"}` | `"labels": ["book", "cancel"]` |
  | `label_descriptions` 键 | 删除该键，并将 `labels` 保持为字符串列表 |
  | 分类条目上的 `description` 键 | 删除该键 |
  | 分类条目上的 `"threshold": 0.5` | `"cls_threshold": 0.5`，并设置 `"multi_label": true` |
</Warning>

## 评估

在 Fastino 包含 17 个数据集的 Fast Decisions 基准上，GLiNER-2.5-Decide 以 **60.1%** 获得最高平均分，并在 9 个数据集上领先。它超过了 4B 级 JevK5 复现版（**57.5%**）、SemIf（**56.4%**）以及编码器模型 GLiFormer 和 Laya。这是内部基准，不是 JevBench；JevK5 也不是 TypeSafe 的 Jev。

请阅读 [GLiNER2.5-Decide: An Open-Weight Model for Structured Decision Making](https://fastino.ai/blog/gliner-2-5-decide-open-weight-decision-model)，了解基准设计、完整结果和延迟测试方法。
