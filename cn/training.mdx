`/v1/training/jobs` 检查该任务。

## 选择任务类型

每个任务都有一个 `type`：

| 类型 | 谁控制循环？ | 如何启动 |
| --- | --- | --- |
| `config` | Fastino | 将数据集和配置发送到 `POST /v1/training/jobs`。 |
| `interactive` | 你的应用 | 通过受支持的 SDK 客户端创建训练客户端。 |

两种类型共享同一套任务标识。规范读取操作使用
`GET /v1/training/jobs`、`GET /v1/training/jobs/{job_id}` 和
`GET /v1/training/jobs/{job_id}/checkpoints`。

对于自定义循环，SDK 客户端使用 Fastino 的 HTTP 兼容适配器。该适配器既不是 SDK，
也不是第二套训练服务。其操作不会出现在 OpenAPI 和 API 参考中。请勿自行构造适配器请求。

## 配置任务生命周期

以下持久化状态描述托管式配置任务。交互式任务的行为由调用方控制；不要根据此表推断其生命周期。

| 持久化状态 | 说明 |
| --- | --- |
| `requested` | 任务已被接受，正在等待调度或资源预置。 |
| `running` | 训练正在进行中。 |
| `complete` | 训练已成功完成。工件准备可能仍在继续。 |
| `normalizing` | Fastino 正在准备训练好的工件。 |
| `artifact_ready` | 训练好的工件已就绪。 |
| `deployed` | 工件已部署。 |
| `paused` | 托管式任务已暂停。 |
| `errored` | 训练、调度或工件准备失败。 |
| `stopped` | 任务已停止，同时保留现有检查点。 |
| `terminated` | 任务已终止。除非 `delete_checkpoints` 为 `true`，否则会保留检查点。 |

`normalized_status` 提供稳定的轮询值，包括以 `failed` 表示最终失败状态。
`status` 则保留持久化值，例如 `errored`。

## 交互式任务计费

交互式任务会对 forward 和 forward/backward 的训练 token、采样的输入、
缓存读取和输出 token，以及检查点存储计费。检查点存储按 GB-月费率每日计量。

创建模型、执行优化器步骤以及保存或加载检查点不会增加交互式训练用量费用。
启动或扩展计算时，账户和项目支出控制仍然适用。请使用 SDK 计费方法读取
交互式用量；上表中的 REST 计费端点仅适用于配置任务。
