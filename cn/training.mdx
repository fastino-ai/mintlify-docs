## 选择任务类型

每个任务都有一个 `type`：

| 类型 | 谁控制训练循环？ | 如何启动 |
| --- | --- | --- |
| `config` | Fastino | 将数据集和配置发送到 `POST /v1/training/jobs`。仅限 GLiNER 编码器。 |
| `interactive` | 你的应用 | 调用 `POST /v1/training/jobs/create-model` 或创建 Tinker 训练客户端。解码器通过这种方式训练。 |

两种类型共用同一任务标识。规范读取使用 `GET /v1/training/jobs`、
`GET /v1/training/jobs/{job_id}` 和 `GET /v1/training/jobs/{job_id}/checkpoints`。

原生 JSON 客户端使用 OpenAPI 中 `/v1/training/jobs` 下的公共操作。现有 Tinker 客户端保留 `tinker==0.32.0`，并仅设置 `TINKER_BASE_URL=https://api.fastino.ai/v1/training/compat/tinker` 和 `TINKER_CREDENTIAL_CMD`。

## 配置任务生命周期

以下持久化状态描述托管式配置任务。交互式任务的行为由调用方控制；不要根据此表推断其生命周期。

| 持久化状态 | 说明 |
| --- | --- |
| `requested` | 任务已被接受，正在等待调度或资源预置。 |
| `running` | 训练正在进行中。 |
| `complete` | 训练已成功完成。工件准备可能仍在继续。 |
| `normalizing` | Fastino 正在准备训练好的工件。 |
| `artifact_ready` | 训练好的工件已就绪。 |
| `deployed` | 工件已部署。 |
| `paused` | 托管式任务已暂停。 |
| `errored` | 训练、调度或工件准备失败。 |
| `stopped` | 任务已停止，同时保留现有检查点。 |
| `terminated` | 任务已终止。除非 `delete_checkpoints` 为 `true`，否则会保留检查点。 |

`normalized_status` 提供稳定的轮询值，包括以 `failed` 表示最终失败状态。
`status` 则保留持久化值，例如 `errored`。

## 交互式任务生命周期

交互式任务按接收顺序运行你发送的 operation。每次调用都会返回 `future_id`；
在 `GET /v1/training/jobs/{job_id}/futures/{future_id}` 读取结果。

- 无需为请求编号，也无需发送心跳。
- 任务 30 分钟内没有调用就会被释放，其检查点会保留。
- `POST /v1/training/jobs/{job_id}/stop` 会立即返回并停止接受新调用。已排队的 operation
  可能会在资源释放前完成，用量也可能持续到资源释放。停止后仍可从 sampler 检查点采样并下载。

## 交互式任务计费

交互式任务会对 forward 和 forward/backward 训练 token、采样的输入 token、缓存读取 token 和输出 token，以及检查点存储计费。检查点存储按天计量，价格为 \$0.05 / GB·月。各模型的预填充、缓存读取、采样输出和训练 token 费率请参阅[定价](/cn/pricing)。

创建模型、执行优化器步骤以及保存或加载检查点不会产生额外的交互式训练用量费用。启动或扩展计算时，账户和项目支出控制仍然适用。使用 [`GET /v1/training/usage`](/cn/api-reference/training-jobs/interactive/storage-usage) 读取团队范围的交互式检查点存储量和月度价格；它不返回计算用量或总账单。任务计费端点仅适用于配置任务。
