每个 Fastino 训练工作负载都是一个任务。先选择由谁控制训练循环，然后使用
`/v1/training/jobs` 检查该任务。

## 选择任务类型

每个任务都有一个 `type`：

| 类型 | 谁控制训练循环？ | 模型 | 如何启动 |
| --- | --- | --- | --- |
| `config` | Fastino | 支持的编码器和解码器 | 将数据集和配置发送到 `POST /v1/training/jobs`。 |
| `interactive` | 你的应用 | 支持的解码器 | 将基础模型发送到 `POST /v1/training/jobs/create-model`。 |

两种类型共用同一任务标识。规范读取使用 `GET /v1/training/jobs`、
`GET /v1/training/jobs/{job_id}` 和 `GET /v1/training/jobs/{job_id}/checkpoints`。

## 可训练模型

创建任务前请调用 `GET /v1/base-models?supports_training=true`。目录会列出当前可训练的模型及其能力。

配置任务使用上传的数据集运行托管式 LoRA 训练。解码器配置任务支持 SFT、DPO 和 GRPO。
当应用必须控制每次前向传播、优化器步骤、检查点和采样时，交互式任务提供另一种解码器训练方式。

## 配置任务生命周期

以下持久化状态描述托管式配置任务。交互式任务的行为由调用方控制；不要根据此表推断其生命周期。

| 持久化状态 | 说明 |
| --- | --- |
| `requested` | 任务已被接受，正在等待调度或资源预置。 |
| `running` | 训练正在进行中。 |
| `complete` | 训练已成功完成。工件准备可能仍在继续。 |
| `normalizing` | Fastino 正在准备训练好的工件。 |
| `artifact_ready` | 训练好的工件已就绪。 |
| `deployed` | 工件已部署。 |
| `paused` | 托管式任务已暂停。 |
| `errored` | 训练、调度或工件准备失败。 |
| `stopped` | 任务已停止，同时保留现有检查点。 |
| `terminated` | 任务已终止。除非 `delete_checkpoints` 为 `true`，否则会保留检查点。 |

`normalized_status` 提供稳定的轮询值，包括以 `failed` 表示最终失败状态。
`status` 则保留持久化值，例如 `errored`。

## 交互式任务生命周期

交互式任务按接收顺序运行你发送的 operation。每次调用都会返回 `future_id`；
在 `GET /v1/training/jobs/{job_id}/futures/{future_id}` 读取结果。

- 无需为请求编号，也无需发送心跳。
- 任务 30 分钟内没有调用就会被释放，其检查点会保留。
- `POST /v1/training/jobs/{job_id}/stop` 会立即释放任务。停止后仍可从 sampler 检查点采样并下载。
