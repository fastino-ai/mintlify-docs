`GET /v1/training/jobs/{job_id}/checkpoints`

返回训练任务可见的检查点。

## 请求

<ParamField header="X-API-Key" type="string" required>
  您的 Fastino API 密钥。
</ParamField>

<ParamField path="job_id" type="string" required>
  配置任务 UUID 或受支持的 SDK 返回的交互式任务 ID。
</ParamField>

<RequestExample>

```bash cURL
curl https://api.fastino.ai/v1/training/jobs/YOUR_TRAINING_JOB_ID/checkpoints \
  -H "X-API-Key: $FASTINO_API_KEY"
```

</RequestExample>

## 响应

<ResponseField name="success" type="boolean">
  请求是否成功。
</ResponseField>

<ResponseField name="checkpoints" type="object[]">
  已保存的检查点。条目结构取决于任务类型。
</ResponseField>

<ResponseField name="count" type="integer">
  返回的检查点数量。
</ResponseField>

### 配置任务

配置检查点包含 `id`、`job_id`、epoch、step、损失、指标、部署和时间戳字段。
其 `id` 不能用于交互式检查点下载端点。

<ResponseExample>

```json Response
{
  "success": true,
  "checkpoints": [
    {
      "id": "CHECKPOINT_ID",
      "job_id": "YOUR_TRAINING_JOB_ID",
      "epoch": 5,
      "step": 500,
      "training_loss": 0.12,
      "validation_loss": 0.18,
      "is_deployable": true,
      "is_best": true,
      "is_final": true,
      "created_at": "2026-09-22T20:30:00Z",
      "updated_at": "2026-09-22T20:30:00Z"
    }
  ],
  "count": 1
}
```

</ResponseExample>

### 交互式任务

交互式任务还返回 `run_id`，检查点按从新到旧排序。将 `checkpoint_id`
（例如 `sampler_weights/checkpoint-1`）传给
[交互式检查点下载端点](/cn/api-reference/training-jobs/download-checkpoint)。
不要传递配置检查点的 `id` 或 `tinker_path`。

<ResponseExample>

```json Response
{
  "success": true,
  "run_id": "session-1:train:0",
  "checkpoints": [
    {
      "checkpoint_id": "sampler_weights/checkpoint-1",
      "checkpoint_type": "sampler",
      "time": "2026-09-22T20:30:00Z",
      "tinker_path": "tinker://session-1:train:0/sampler_weights/checkpoint-1",
      "size_bytes": 12345,
      "public": false,
      "user_metadata": null,
      "expires_at": null
    }
  ],
  "count": 1
}
```

</ResponseExample>

未知或无法访问的任务返回 `404`。
