`POST /v1/training/jobs/{job_id}/forward-backward`

计算一批代币级别数据的损失并累积其
梯度。下一步[优化器步骤](/cn/api-reference/training-jobs/interactive/optim-step)
应用它们。回应是未来；读取损失和每个代币的日志
概率来自
[`GET /v1/training/jobs/{job_id}/futures/{future_id}`](/cn/api-reference/training-jobs/interactive/get-future)。

[`POST /v1/training/jobs/{job_id}/forward`](/cn/api-reference/training-jobs/interactive/forward)
采用相同的主体并计算没有梯度的损失。

## 请求

<ParamField header="X-API-Key" type="string" required>
  您的 Fastino API 密钥。
</ParamField>

<ParamField path="job_id" type="string" required>
  交互式作业 ID。
</ParamField>

<ParamField body="datums" type="object[]" required>
  一个或多个训练示例。使用基本模型自行标记它们
  分词器。

  <Expandable title="properties">
    <ParamField body="model_input" type="object" required>
      `{"chunks": [{"type": "encoded_text", "tokens": [...]}]}`。输入令牌
      ID，总共N个token。
    </ParamField>
    <ParamField body="loss_fn_inputs" type="object" required>
      每个位置张量，每个 `{"data": [...], "dtype": "int64" | "float32"}`
      带有可选的 `shape`。每个张量都有 N 个值。

      - `target_tokens`（`int64`，必需）：每个位置预期的代币，
        通常输入左移一位。
      - `weights` (`float32`)：每个位置的损失重量。使用 `0` 进行提示
        位置和 `1` 为完成位置。
      - `logprobs` 和 `advantages` (`float32`)：除
        `cross_entropy`。 `logprobs` 是采样器的对数概率
        目标。
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="loss_fn" type="string" default="cross_entropy">
  `cross_entropy`、`importance_sampling`、`ppo`、`cispo` 或 `dro`。
</ParamField>

<ParamField body="loss_fn_config" type="object">
  损失设置。 `ppo` 和 `cispo` 取 `clip_low_threshold` 和
  `clip_high_threshold`； `dro` 采用 `beta`。未知的密钥将被拒绝。
</ParamField>

<RequestExample>

```bash cURL
curl -X POST "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/forward-backward" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "loss_fn": "cross_entropy",
    "datums": [
      {
        "model_input": {"chunks": [{"type": "encoded_text", "tokens": [151644, 872, 198, 3838]}]},
        "loss_fn_inputs": {
          "target_tokens": {"data": [872, 198, 3838, 30], "dtype": "int64"},
          "weights": {"data": [0, 0, 1, 1], "dtype": "float32"}
        }
      }
    ]
  }'
```

</RequestExample>

## 错误

|状态 |意义|
| ---| ---|
| `400` |未知的 `loss_fn`、非整数 `target_tokens` 张量、词汇表标记 ID 之外，或者作业已停止。 |
| `402` |团队积分用完或没有有效的付款设置。 |
| `404` |该职位不存在或属于另一个团队。 |
| `422` | `datums` 为空或主体有未知字段。 |

批处理运行时发现的问题，例如丢失损失输入、不匹配
张量长度、未知的 `loss_fn_config` 密钥或比
模型的极限，失败的未来。其`error.category`为`user`。
