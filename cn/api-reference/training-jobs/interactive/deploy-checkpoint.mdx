`POST /v1/training/jobs/{job_id}/checkpoints/sampler_weights/{name}/deploy`

将作业的采样器检查点之一作为经过训练的模型提供服务。调用它
[`POST /v1/chat/completions`](/cn/api-reference/inference/chat-completions) 和
`"model": "<model_id>"`。当前部署允许列表仅包含 Nemotron 3.5 Lightning
（`nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16`）。其他基地返回
`400`。

该模型的 `status` 是 `deploying`，直到服务引擎加载它，然后
`deployed`。再次部署相同的检查点将返回相同的模型及其
当前状态，以便您可以重复调用以检查进度。如果较早的
尝试失败，重复调用会重试。

## 请求

<ParamField header="X-API-Key" type="string" required>
  您的 Fastino API 密钥。
</ParamField>

<ParamField path="job_id" type="string" required>
  交互式作业 ID。
</ParamField>

<ParamField path="name" type="string" required>
  保存的采样器检查点的名称
  [`save-weights-for-sampler`](/cn/api-reference/training-jobs/interactive/save-weights-for-sampler)。
</ParamField>

<ParamField body="model_name" type="string">
  最多 64 个字母、数字、连字符和下划线，以 a 开头和结尾
  字母或数字。省略时从检查点名称派生。身体是
  可选的。
</ParamField>

<RequestExample>

```bash cURL
curl -X POST "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/checkpoints/sampler_weights/step-000100/deploy" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model_name": "support-replies-v1"}'
```

</RequestExample>

## 回应

<ResponseField name="model_id" type="string">
  训练后模型的 ID。将其传递为 `model` 进行推理。
</ResponseField>

<ResponseField name="job_id" type="string">
  保存检查点的交互式作业。
</ResponseField>

<ResponseField name="checkpoint_id" type="string">
  `sampler_weights/<name>`。
</ResponseField>

<ResponseField name="base_model" type="string">
  模型的基础模型。
</ResponseField>

<ResponseField name="project_id" type="string | null">
  工作的项目（如果有）。
</ResponseField>

<ResponseField name="status" type="string">
  `deploying` 或 `deployed`。
</ResponseField>

<ResponseExample>

```json Response
{
  "model_id": "MODEL_ID",
  "job_id": "SESSION_ID:train:0",
  "checkpoint_id": "sampler_weights/step-000100",
  "base_model": "nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16",
  "project_id": null,
  "status": "deploying"
}
```

</ResponseExample>

|状态 |意义|
| ---| ---|
| `400` |基本模型不是 Nemotron 3.5 Lightning，或者检查点不是服务引擎接受的 PEFT 适配器。 |
| `404` |作业或采样器检查点不存在、属于另一个团队或没有文件。 |
| `409` |另一个模型已使用 `model_name`，或者从此检查点提供服务的模型已被删除。以新名称保存权重以再次部署它们。 |
| `422` | `model_name` 无效或正文有未知字段。 |
