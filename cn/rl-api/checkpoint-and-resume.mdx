---
title: "创建检查点并恢复 RL 运行"
description: "保存模型和优化器状态，持久化循环进度，并在不重放已完成工作的情况下恢复 RL。"
---

RL 检查点用于保护模型状态。完整的恢复记录还会保护应用状态，使循环知道接下来要执行什么。

此模式适用于长时间运行的任务、可抢占的编排器，以及由智能体管理的实验。

## 必须保存的内容

将可恢复步骤视为两条相互协调的记录：

| 记录 | 包含内容 | 存储方 |
| --- | --- | --- |
| 状态检查点 | LoRA 权重和优化器状态 | RL API |
| 循环记录 | 步骤、数据集游标、配置和检查点路径 | 你的应用 |

仅保存模型状态可以恢复策略，却无法告诉应用哪些样本已经处理。仅保存步骤编号则无法恢复生成该编号的策略。

## 开始之前

请先完成[快速入门](/cn/rl-api/quickstart)，以验证身份验证、模型访问权限和采样。
快速入门不会创建训练运行。只有在你已启用的 Fastino 环境中成功完成一次小型训练更新，
并能保存和恢复状态检查点后，才能继续。

## 1. 保存状态和循环进度

保存服务器端训练状态，然后将返回的路径与重建运行所需、由客户端负责的字段一起
持久化：

```python
import json
from pathlib import Path


state = training_client.save_state(f"step-{step:06d}").result()
record = {
    "state_path": state.path,
    "model": model_name,
    "rank": lora_rank,
    "dataset_revision": dataset_revision,
    "optimizer": optimizer_config,
    "renderer": renderer_name,
    "tokenizer": tokenizer_name,
    "step": step,
    "dataset_cursor": dataset_cursor,
    "reward_version": reward_version,
}
with Path(log_path).open("a", encoding="utf-8") as checkpoint_log:
    checkpoint_log.write(json.dumps(record, sort_keys=True) + "\n")

print(state.path)
```

返回路径的格式如下：

```text
tinker://<run-id>/weights/step-000100
```

上述代码片段没有设置生存时间。对于滚动恢复产物，请通过受支持的检查点管理操作显式
设置保留时间。如果最终检查点是你打算保留的产物，请不要为它设置 TTL。

<Warning>
  `save_state(...)` 不会请求覆盖，因此重复使用检查点名称会被拒绝。
  `save_state(..., overwrite=True)` 可以显式替换状态检查点，但唯一名称是更安全的恢复标记。
</Warning>

## 2. 查找最新记录的恢复点

进程启动时，从后向前扫描，查找最新一条可解析且包含状态路径的本地记录。进程可能会在
写入最后一行 JSONL 时停止，因此应跳过格式错误的末尾记录，而不是丢失之前的恢复点：

```python
def get_last_checkpoint(log_path: str) -> dict[str, object] | None:
    path = Path(log_path)
    if not path.exists():
        return None
    for line in reversed(path.read_text(encoding="utf-8").splitlines()):
        try:
            record = json.loads(line)
        except json.JSONDecodeError:
            continue
        if isinstance(record, dict) and isinstance(record.get("state_path"), str):
            return record
    return None


resume = get_last_checkpoint(log_path)
```

显式处理两种情况：

```python
if resume is None:
    training_client = service_client.create_lora_training_client(
        base_model=model_name,
        rank=lora_rank,
    )
    start_step = 0
    dataset_cursor = 0
else:
    saved_step = resume.get("step")
    saved_cursor = resume.get("dataset_cursor")
    if not isinstance(saved_step, int) or not isinstance(saved_cursor, int):
        raise ValueError("resume record has no valid step or dataset cursor")

    training_client = (
        service_client.create_training_client_from_state_with_optimizer(
            str(resume["state_path"])
        )
    )
    start_step = saved_step + 1
    dataset_cursor = saved_cursor
```

`create_training_client_from_state_with_optimizer(...)`
会根据已保存的权重和优化器状态创建新的有序训练运行。

## 3. 验证恢复记录

继续训练之前，将存储的循环记录与请求的运行进行比较：

```python
if resume is not None and resume.get("reward_version") != reward_version:
    raise ValueError(
        "reward implementation changed; start a new run or approve the change"
    )
```

至少验证：

- 基础模型
- LoRA rank 和可训练布局
- 数据集修订版本和游标
- 奖励实现修订版本
- 优化器系列和预期调度
- Renderer 和 tokenizer 假设

当这些字段冲突时，智能体应停止并请求决策，不应静默地将检查点与另一个实验组合。

## 4. 使步骤边界具备原子性

请按以下顺序执行：

1. 解析训练和优化器 future。
2. 保存状态检查点。
3. 持久化包含返回路径的循环记录。
4. 将应用步骤标记为完成。
5. 开始下一步。

如果进程在第 2 步之后、第 3 步之前退出，服务器可能会保留一个未被引用的检查点。这会浪费存储空间，但不会破坏之前的恢复点，之后可以将其清理。

检查点路径持久化之前，不要将步骤标记为完成。

## 5. 将采样器产物分开保存

使用状态检查点恢复训练：

```python
state = training_client.save_state("step-000100").result()
```

使用采样器权重进行评估、rollout 或 SDK 推理：

```python
sampler = training_client.save_weights_for_sampler(
    "step-000100"
).result()
```

这两种路径的用途不同：

```text
tinker://<run-id>/weights/<name>
tinker://<run-id>/sampler_weights/<name>
```

不要选择采样器检查点作为优化器恢复点。

## 6. 限制存储

实用的保留策略包括：

- 用于崩溃恢复的短期滚动状态检查点
- 用于比较的长期定期状态检查点和采样器检查点
- 一个永久最终检查点

请在应用中实现保留策略：为检查点分配唯一名称，通过受支持的检查点操作显式设置
TTL，并删除不再处于恢复或评估窗口内的产物。检查点存储按时间计量。

## 智能体的恢复决策

| 情况 | 操作 |
| --- | --- |
| 没有本地恢复记录 | 开始新的运行 |
| 恢复记录和检查点均存在 | 验证元数据，然后恢复 |
| 本地记录存在，但检查点已不存在 | 停止并询问用户；不要假设更早的记录属于预期运行 |
| 检查点存在，但没有本地记录 | 将其视为未分类；不要猜测其数据集游标 |
| 奖励或数据集修订版本发生变化 | 除非用户批准继续，否则开始新的实验 |
| 实时运行报告状态无法恢复 | 从最新的显式状态检查点恢复 |

## 验证恢复后的运行

在大规模继续运行之前：

1. 恢复检查点。
2. 运行一个小型留出评估。
3. 将结果与保存时记录的指标进行比较。
4. 提交一个训练步骤。
5. 使用新名称保存新的检查点。

确切样本可能有所不同。恢复后的模型应保留预期质量，优化器步骤应能完成，并且新的检查点应可寻址。

始终关闭服务客户端，并准确记录运行结果：

```python
service_client.close("success").result()  # completed run
```

运行完成时使用 `success`；异常继续向外抛出时使用 `errored`；取消或关闭后使用
`interrupted`。不要将失败的恢复标记为成功。

有关完整生命周期和管理操作，请参阅[运行时行为和错误参考](/cn/rl-api/runtime)。
