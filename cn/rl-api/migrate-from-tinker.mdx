---
title: "从 Tinker 迁移"
description: "将现有 Tinker SDK 工作负载迁移到 Fastino 的 RL API。"
---

Fastino 的 RL API 实现了 Tinker SDK 契约中有文档说明的子集。只有当兼容性
检查清单中的每一项都通过时，SDK 调用形式才可以保持不变。迁移需要替换四个集成点：

1. 端点
2. 凭据
3. 模型名称
4. 运维假设

本指南将现有程序视为验收测试。先更改连接，运行一个短任务，然后再调整算法。

## 1. 固定经过测试的 SDK

Fastino 当前使用以下版本测试契约：

```text
tinker==0.32.0
```

支持的最低客户端版本为 `0.25.0`。迁移期间请固定使用 `0.32.0`，避免无关的 SDK
升级掩盖连接或兼容性问题。

<CodeGroup>

```bash uv
uv add "tinker==0.32.0"
```

```bash pip
pip install "tinker==0.32.0"
```

</CodeGroup>

## 2. 替换端点和密钥

如果现有代码构造 `tinker.ServiceClient()` 时没有传入显式参数，只需通过环境变量即可迁移：

```bash
export FASTINO_API_KEY="fast_sk_..."
export TINKER_API_KEY="tml-${FASTINO_API_KEY}"
export TINKER_BASE_URL="https://api.fastino.ai/tinker"
```

`tml-` 部分是供 Tinker SDK 使用的兼容性前缀。Fastino 会验证其中的 `fast_sk_...` 密钥。

如果应用显式传值，请进行等效更改：

```python
import os

import tinker


service_client = tinker.ServiceClient(
    base_url="https://api.fastino.ai/tinker",
    api_key=f"tml-{os.environ['FASTINO_API_KEY']}",
)
```

不要追加 `/api/v1`。SDK 会自行添加路由路径。

## 3. 选择 Fastino 支持的模型

不要假设其他 Tinker 环境中可用的模型也能在 Fastino 上使用。迁移期间请查询功能：

```python
capabilities = service_client.get_server_capabilities()
for model in capabilities.supported_models:
    print(model.model_name)
```

生产决策请以实时功能响应为准。如果需要查看上下文窗口或 LoRA 限制，请将结果与
[客户端兼容性](/cn/rl-api/compatibility)对照。

## 4. 对照检查学习循环

以下核心调用保持其 Tinker SDK 形式不变：

```python
training_client = service_client.create_lora_training_client(
    base_model=model_name,
    rank=32,
)

sampler_path = training_client.save_weights_for_sampler(
    "migration-smoke"
).result().path
sampling_client = service_client.create_sampling_client(
    model_path=sampler_path
)
sample_future = sampling_client.sample(prompt, num_samples, sampling_params)
sample_result = sample_future.result()

train_future = training_client.forward_backward(
    datums,
    loss_fn="importance_sampling",
)
optim_future = training_client.optim_step(adam_params)
train_result = train_future.result()
optim_result = optim_future.result()
```

上述调用形式是兼容的。在复用外围循环之前，请确认其模型、LoRA rank、损失函数名称、
datum 字段、采样参数、检查点行为和运维依赖都在
[兼容性参考](/cn/rl-api/compatibility)中列为受支持。

Renderer、提示词构建、奖励函数、优势值计算、批处理和停止条件都在你的应用中运行。
只有在上述检查清单通过后，才应在首次迁移测试中保持这些部分不变。

## 5. 验证小型运行

恢复生产批次大小之前，先进行低成本验收运行：

- 获取功能。
- 创建一个 LoRA 训练客户端。
- 采样一个小组。
- 提交一次前向-反向操作。
- 执行一次优化器步骤。
- 保存一个状态检查点。
- 从该检查点创建新的训练客户端。
- 关闭服务客户端。

比较语义结果，而非精确的浮点值。不同的受支持模型和基础设施可能产生不同的样本和指标。

## 6. 查看运维差异

| 领域 | 迁移操作 |
| --- | --- |
| 访问权限 | RL API 访问权限按 Fastino 团队启用。未启用的团队会收到 `404 Not Found`。 |
| 身份验证 | 使用由 `tml-` 兼容性前缀封装的 Fastino API 密钥。 |
| 模型 | 从功能响应中选择。不要保留不受支持的源模型。 |
| 会话生命周期 | 关闭 `ServiceClient` 以释放活跃运行。 |
| 恢复 | 使用显式检查点作为由应用掌控的恢复边界。 |
| Future 结果 | 在一小时内解析并持久化已完成的结果。 |
| 取消 | 取消操作适用于采样，但不适用于单个训练操作。 |
| 已发布的检查点 | 发布检查点不会让其他 Fastino 团队加载该检查点。 |
| Trace 导出 | 删除依赖 Tinker trace 导出的代码。此功能不受支持。 |
| 审计条目 | 不要依赖审计历史记录。审计调用不返回任何条目。 |

支持的损失函数和方法请参阅[客户端兼容性](/cn/rl-api/compatibility)。
重试、计费、检查点和失败行为请参阅
[运行时行为和错误](/cn/rl-api/runtime)。

## 迁移检查清单

- [ ] 固定 `tinker==0.32.0`。
- [ ] 将 `TINKER_BASE_URL` 设为 `https://api.fastino.ai/tinker`。
- [ ] 将 Fastino 密钥封装为 `tml-fast_sk_...`。
- [ ] 确认团队已启用 RL API 访问权限。
- [ ] 替换不受支持的模型名称。
- [ ] 运行一个采样和训练步骤。
- [ ] 保存并恢复一个状态检查点。
- [ ] 删除对不受支持的 trace 或审计数据的依赖。
- [ ] 关闭服务客户端。
- [ ] 仅在验收运行通过后增加工作负载规模。
