Fastino 提供两种同步推理接口。请选择与你的需求相匹配的接口：

| 功能 | [`/v1/chat/completions`](/cn/inference/chat-completions) | [`/v1/systemone`](/cn/inference/systemone) |
| --- | --- | --- |
| 模型 | 选择支持推理的基础模型或已完成训练任务的 UUID | 始终使用 `fastino/glide` |
| 请求 | 与 OpenAI 兼容的 `model` 和 `messages`，外加 Fastino 的顶层 `schema` | 原生 `state`，外加一个或多个带类型的 `questions` |
| 响应 | OpenAI chat-completion 信封；将 `choices[0].message.content` 解析为 JSON | 原生 `{ "answers": ..., "usage": ... }` 响应体 |
| 批量输入 | 每个请求一个对话 | 每个请求一个 `state`，多个 `questions` 一并评估 |
| 适用场景 | 在基础模型和微调模型上进行提取、分类、结构化提取和关系抽取 | 带有校准概率的分类、路由和评分决策 |

<Tip>
  进行提取、分类、结构化提取或关系抽取时，请使用 [`/v1/chat/completions`](/cn/inference/chat-completions)。
  需要结构化决策（分类、路由、评分）而非提取时，请使用 [`/v1/systemone`](/cn/inference/systemone)。
</Tip>

本页介绍两种接口的共同内容。有关 GLiNER 请求/响应契约和旧版迁移指南，请参阅
[`/v1/chat/completions`](/cn/inference/chat-completions)；有关 GLiDE HTTP 契约，请参阅
[`/v1/systemone`](/cn/inference/systemone)——完整的 Noul/Choice/Score 请求和响应结构位于
[决策模型](/cn/concepts/decision-models)。SDK 使用、模型训练、评估、推理历史和反馈不在本页范围内。

## 身份验证

无论使用哪种接口，每个请求都需要发送 Fastino API 密钥：

```bash
export FASTINO_API_KEY="fast_sk_..."
```

```http
Authorization: Bearer $FASTINO_API_KEY
Content-Type: application/json
```

## 冷启动与重试

无论使用哪种接口，空闲或新部署的模型都可能会冷启动。请将读取超时设置为至少 300 秒，并对
`425`、`429` 和 `503` 响应进行重试。当响应头中包含 `Retry-After` 时，请遵循该值。

已超时的请求仍可能预热部署，从而让下一次请求成功。对于身份验证、计费、校验或未知模型等错误，
请在解决根本问题之前不要重试。

```bash
curl --max-time 300 -X POST "https://api.fastino.ai/v1/chat/completions" \
  -H "Authorization: Bearer $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d @request.json
```

同样的超时和重试模式也适用于 `/v1/systemone`。
