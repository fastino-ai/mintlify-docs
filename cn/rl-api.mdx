Fastino 的 RL API 以**交互式训练任务**的形式运行强化学习和自定义后训练工作负载。
交互式任务与其他所有 Fastino 训练工作负载使用相同的训练任务资源和任务 ID：
`/v1/training/jobs`。

你的应用负责控制循环：提示词、数据集、奖励、优势值、评估和停止条件。Fastino
负责执行该循环请求的模型操作，包括采样、前向和反向传播、优化器步骤及检查点。

<Note>
  RL API 目前为限量开放。在规划生产工作负载之前，请确认 Fastino 已为你的团队启用交互式训练。
</Note>

## 一个任务，两种视图

通过受支持的 SDK 创建的训练客户端代表一个 Fastino 交互式任务。
`training_client.get_info().model_data.model_id` 返回的值是规范的训练任务 ID。
在 `GET /v1/training/jobs/{job_id}` 及其他有文档说明的训练任务或检查点管理路由中使用同一个 ID。

该任务背后不存在单独的 Tinker 运行，也不会将请求传出到其他训练服务。
`tinker` Python 软件包是一个客户端兼容层，供已经使用其对象和方法形式的应用使用。

## 受支持的客户端

Fastino 测试 `tinker==0.33.1`。配置如下：

- 基础 URL：`https://api.fastino.ai/v1/training/compat/tinker`
- 凭据来源：`TINKER_CREDENTIAL_CMD`
- 凭据：以 `fast_sk_` 开头的普通 Fastino API 密钥

SDK 会将 `/api/v1/<operation>` 追加到配置的基础 URL。适配器路由有意不出现在
Fastino 的 OpenAPI 和 API 参考中。请勿自行构造适配器 HTTP 请求；使用 SDK
执行交互式操作，并使用规范的 Fastino 路由管理任务和检查点。

## 循环的工作方式

1. 创建一个交互式训练客户端。
2. 为采样创建权重快照。
3. 在你的应用中生成候选响应并评分。
4. 将奖励转换为训练数据。
5. 要求 SDK 在同一个任务上运行前向/反向传播和优化器操作。
6. 保存状态或采样器检查点，然后继续。

选择模型或依赖可选 SDK 功能之前，请查询 `ServiceClient.get_server_capabilities()`。
功能响应是你的团队所用环境的权威来源。
