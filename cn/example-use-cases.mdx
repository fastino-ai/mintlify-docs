当你的应用需要评估某种情形并返回结构化的概率决策，而不是生成文本时，请使用 GLiDE。将一个 `state` 和一个或多个带类型的 `questions` 发送至 [`POST /v1/systemone`](/cn/inference/systemone)。

## 选择一种原语

| 决策形式 | 原语 | 结果 |
| --- | --- | --- |
| 是或否，并附带概率 | [Noul](/cn/concepts/glide-noul) | `noul`，回答为“是”的概率 |
| 从有名称的选项中恰好选择一个 | [Choice](/cn/concepts/glide-choice) | 胜出标签以及每个选项的概率 |
| 在有序量表上选择一个等级 | [Score](/cn/concepts/glide-score) | 胜出等级、期望等级以及各等级的概率 |

GLiDE 会根据同一个 state 独立回答每个问题。它没有多标签原语。当多个标签可能同时适用时，请提出多个 Noul 问题。

## 一次调用完成分诊

一个支持请求可以在一次请求中完成路由、评分和退款资格检查。每个答案彼此独立，因此你的应用可以为每个答案采用不同的阈值或操作。

```json
{
  "model": "fastino/glide",
  "state": {
    "message": "I was charged twice for order A-104. Please refund the duplicate.",
    "account_tier": "business",
    "refund_policy": "Duplicate charges qualify for an immediate refund."
  },
  "questions": {
    "team": {
      "type": "choice",
      "instructions": "Which team should handle this request?",
      "criteria": {
        "billing": "Payments, invoices, or duplicate charges",
        "returns": "Product returns or replacements",
        "technical": "Product defects or technical support"
      }
    },
    "urgency": {
      "type": "score",
      "instructions": "How urgently should the team respond?",
      "criteria": [
        "low: can wait for the normal queue",
        "medium: should be handled soon",
        "high: requires immediate attention"
      ]
    },
    "refund_allowed": {
      "type": "noul",
      "instructions": "Does the request qualify for a refund under the supplied policy?",
      "criteria": {
        "true": "The policy allows the refund",
        "false": "The policy does not allow the refund"
      }
    }
  }
}
```

请根据各自的原语读取结果：

- `answers.team.choice` 是所选路由。使用 `probabilities` 查看其他选项。
- `answers.urgency.score` 是胜出等级的索引。使用 `expected_level` 获得更平滑的阈值。
- `answers.refund_allowed.noul` 是回答为“是”的概率。请自行选择并验证操作阈值。

## 常见模式

| 用例 | 状态 | 问题 |
| --- | --- | --- |
| 智能体操作审核 | 建议的工具调用、可见上下文和策略 | Noul：是否可以执行该操作？Choice：执行、修改或升级处理 |
| 内容审核 | 内容以及适用的策略 | Choice：策略类别。Score：严重程度。Noul：是否交由人工审核？ |
| 模型或工作流路由 | 请求、延迟目标和可用路由 | Choice：路由。Score：复杂度。Noul：是否使用成本较高的回退方案？ |
| 质量控制 | 输出以及明确的要求或评分标准 | 每项要求对应一个 Noul。Score：整体质量或风险 |
| 运营分诊 | 工单、账户上下文和运营策略 | Choice：负责人。Score：紧急程度。Noul：是否符合自动执行操作的条件？ |

进行智能体监控时，只评估你的系统获准收集的产物，例如工具调用和用户可见的日志。不要将隐藏的思维链用作运营监控依据。

## 设计可靠的问题

- 在 `state` 中包含决策所需的证据和策略。
- 确保 Choice 选项互斥。当列出的选项并不完备时，请添加 `other` 或 `none`。
- 按从低到高的顺序编写 Score 标准，并清楚描述每个等级。
- 使用相互独立的 Noul 问题进行多标签检查。
- 在设置自动化阈值之前，先使用有代表性的数据评估概率和置信度。
- 对不确定或影响重大的结果采用更安全的回退方案。

<Warning>
  GLiDE 具有概率性。对于不可逆、安全关键、法律、医疗、就业、信贷或访问控制决策，请勿将其作为唯一的判断依据。
</Warning>

## 不适合使用 GLiDE 的情形

| 需求 | 替代方案 |
| --- | --- |
| 从文本中抽取名称、文本跨度、实体或关系 | [GLiNER](/cn/concepts/gliner) |
| 生成、总结或改写自由形式文本 | 生成式语言模型 |
| 执行精确的确定性规则 | 应用代码或策略引擎 |
| 通过一个问题返回多个标签 | 使用相互独立的 Noul 问题，每个标签对应一个问题 |

请先阅读[快速入门](/cn/quickstart)，然后使用 [GLiDE 参考文档](/cn/concepts/decision-models)定义你的生产问题模式。
