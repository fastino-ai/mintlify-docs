GLiNER-2.5-Decide is a decision model for applications that need to make several related judgments from the same text. It combines typed decisions with explicit constraints, span extraction, relations, and structured records.

## When to use GLiNER-2.5-Decide

Reach for GLiNER-2.5-Decide when the task is a decision — a label, a route, a score — rather than the underlying extracted text. It's particularly useful when software must make several related judgments from the same input in one low-latency call.

1. **Model routing.** Route requests by destination, complexity, or escalation level. Return the selected route with probabilities and confidence scores.
2. **Tool calling.** Select from a permitted set of tools and capture arguments from the request as structured records.
3. **Browser and computer use.** Evaluate the current state to select the next action. Represent the action, target, and parameters as a structured record.
4. **Guardrails.** Evaluate safety, harm type, and escalation together, extracting harmful spans verbatim. Apply constraints when combinations of answers would be contradictory.
5. **Context pruning.** Decide which information in the context is relevant and return the exact character spans associated with that decision.
6. **LLM-as-a-judge.** Express rubric criteria as categorical or ordinal questions. Return selected values with probability distributions and confidence scores.
7. **Games and simulations.** Evaluate game state to determine intent, action, or outcome. Represent actors and state information through entities, relations, and structured records.

Use [GLiNER 2.5](/concepts/gliner) instead when you need the literal spans, structured records, or a relation graph back, not a decision label.

## How to use GLiNER-2.5-Decide

Call it through the same Fastino inference endpoint as any GLiNER model, using a `classifications` schema. Score several related judgments in one call by adding more task entries:

```bash
curl -X POST "https://api.fastino.ai/v1/chat/completions" \
  -H "Authorization: Bearer $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "fastino/gliner2.5-decide",
    "messages": [
      { "role": "user", "content": "My subscription renewed on April 15 after the service was already down. Can I get that refunded?" }
    ],
    "schema": {
      "classifications": [
        {
          "task": "intent",
          "labels": ["refund_request", "cancel_subscription", "login_problem", "speak_to_human"],
          "multi_label": false
        },
        {
          "task": "urgency",
          "labels": ["low", "normal", "high", "critical"],
          "multi_label": false
        }
      ]
    }
  }'
```

`intent` and `urgency` are both scored in the same forward pass, so a router gets every judgment it needs from one call instead of chaining several model requests. See the [Inference API](/inference) reference for the full request and response contract, including multi-label classification and confidence thresholds.
