GLiNER-2.5-Decide is Fastino's English classification-tuned GLiNER model. Supply your own labels at request time and classify intent, routing, sentiment, priority, policy, and other operational decisions without prompting a generative model.

## When to use GLiNER-2.5-Decide

Use GLiNER-2.5-Decide when classification is the primary task:

- **Intent and routing** - send support messages, emails, or agent requests to the right workflow.
- **Several decisions per input** - classify intent, urgency, route, and handoff in one model call.
- **Single- and multi-label classification** - select one category or every applicable tag.
- **Operational gates** - decide whether an agent finished, a human should take over, or content violates a policy.
- **Ordinal labels** - score severity, urgency, or ratings using an ordered label set.
- **Custom taxonomies** - define labels and short descriptions at request time instead of retraining for every category change.

The hosted model retains entity, relation, and structured-extraction support, but classification is the reason to choose it. Use [GLiNER2.5](/concepts/gliner) when extraction is primary, you need span attributes or joint entity-relation decoding, or the input is multilingual.

## How to use GLiNER-2.5-Decide

Call it through Fastino's OpenAI-compatible inference endpoint with a `classifications` schema. Add multiple tasks to classify several aspects of the same text in one call:

```bash
curl -X POST "https://api.fastino.ai/v1/chat/completions" \
  -H "Authorization: Bearer $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "fastino/GLiNER-2.5-Decide",
    "messages": [
      { "role": "user", "content": "My subscription renewed on April 15 after the service was already down. Can I get that refunded?" }
    ],
    "schema": {
      "classifications": [
        {
          "task": "intent",
          "labels": ["refund_request", "cancel_subscription", "login_problem", "speak_to_human"],
          "multi_label": false
        },
        {
          "task": "urgency",
          "labels": ["low", "normal", "high", "critical"],
          "multi_label": false
        }
      ]
    }
  }'
```

`intent` and `urgency` are scored together, so a router gets both judgments from one request. See the [Chat Completions API](/inference/chat-completions) for the response contract, multi-label classification, and confidence thresholds.
