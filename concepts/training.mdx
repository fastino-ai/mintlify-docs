 Training jobs are the core of Fastino's fine-tuning platform. Submit a job with a supported base model and one or more ready  datasets, and Fastino handles compute provisioning, training, checkpoint creation, and artifact preparation. The whole process is asynchronous, you start the job, then poll until it finishes.

Fastino uses supervised fine-tuning (`sft`) for all new training jobs. Fastino supports LoRA and full fine-tuning. 

<Warning>
  `model_name`, `base_model`, and `datasets` are required when creating a training job. Omitting a required field returns `422 Unprocessable Entity`.
</Warning>

## Status lifecycle

Training-job responses include:

- `status`: persisted job status.
  - `normalized_status`: stable status intended for client polling.
  - `is_terminal_status`: whether polling can stop.
  - `error_message`: failure information when available.
  - `is_deployable`: whether the completed artifact passes deployment validation.
  - `deployability_reason`: why the artifact is not deployable.

Prefer `normalized_status` and `is_terminal_status` in polling clients.

| Persisted status | Description |
| --- | --- |
| `requested` | Job was accepted and is awaiting dispatch or provisioning. |
| `running` | Training is actively running. |
| `complete` | Training completed successfully. Artifact preparation may continue. |
| `normalizing` | Fastino is preparing the trained artifact. |
| `artifact_ready` | The trained artifact is ready. |
| `deployed` | The artifact has been deployed. |
| `paused` | The job or its pipeline is paused. |
| `errored` | Training, dispatch, or artifact preparation failed. |
| `stopped` | The job was stopped while preserving existing checkpoints. |
| `terminated` | The job was terminated and its checkpoints were deleted. |

## Create a training job

`POST /felix/training-jobs` Creates a training job and returns immediately. Use the returned job ID to monitor and manage the job.

<Note>
  The default rate limit is **20 training-job creation requests per minute per user**.
</Note>

### Request body

<ParamField body="model_name" type="string" required>
  Human-readable name for the trained model. Maximum length: 100 characters.
</ParamField>

<ParamField body="base_model" type="string" required>
  Supported model ID or compatible checkpoint UUID.
</ParamField>

<ParamField body="datasets" type="object[]" required>
  One or more ready dataset references. Each reference requires `name` and may include `version`.
</ParamField>

<ParamField body="training_type" type="string">
  Fine-tuning method: `lora` or `full`. Defaults to `lora`.
</ParamField>

<ParamField body="validation_data_percentage" type="number">
  Fraction of data reserved for validation. Accepts values from `0` to `1` and defaults to `0.2`.
</ParamField>

<ParamField body="nr_epochs" type="number">
  Maximum number of training epochs. Must be at least `1`.
</ParamField>

<ParamField body="learning_rate" type="number">
  Peak optimizer learning rate. When omitted, the trainer default applies.
</ParamField>

<ParamField body="batch_size" type="number">
  Training batch size. Prefer omitting this field unless an explicit override is required.
</ParamField>

<ParamField body="early_stopping_patience" type="number">
  Number of validation epochs without improvement before stopping. Set to `0` to disable early stopping.
</ParamField>

<ParamField body="warmup_ratio" type="number">
  Fraction of training steps used for learning-rate warmup.
</ParamField>

<ParamField body="project_id" type="string">
  Project associated with the training job. When omitted, the default project is used.
</ParamField>

### Example

```bash
curl -X POST https://api.pioneer.ai/felix/training-jobs \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model_name": "my-ner-model",
    "base_model": "fastino/gliner2-base-v1",
    "datasets": [
      {
        "name": "my-dataset",
        "version": "1"
      }
    ],
    "training_type": "lora",
    "nr_epochs": 5,
    "learning_rate": 5e-5,
    "validation_data_percentage": 0.2
  }'
```

### Response

<ResponseField name="id" type="string">
  Training-job UUID. Use this ID in subsequent requests.
</ResponseField>

<ResponseField name="status" type="string">
  Initial persisted status, normally `requested`.
</ResponseField>

<ResponseField name="normalized_status" type="string">
  Stable status intended for polling.
</ResponseField>

<ResponseField name="is_terminal_status" type="boolean">
  Whether the job has reached a terminal state.
</ResponseField>

## List training jobs

`GET /felix/training-jobs` Returns training jobs visible to the authenticated account or team.

### Query parameters

<ParamField query="status" type="string">
  Filter by persisted job status.
</ParamField>

<ParamField query="project_id" type="string">
  Return only jobs associated with the specified project.
</ParamField>

<ParamField query="limit" type="number">
  Maximum jobs returned. Accepts `1`–`200` and defaults to `200`.
</ParamField>

<ParamField query="offset" type="number">
  Number of matching jobs to skip. Defaults to `0`.
</ParamField>

```bash
curl "https://api.pioneer.ai/felix/training-jobs?status=complete&limit=50&offset=0" \
  -H "X-API-Key: YOUR_API_KEY"
```

### Response

<ResponseField name="training_jobs" type="object[]">
  Training jobs in the current page.
</ResponseField>

<ResponseField name="count" type="number">
  Number of jobs returned in the current page.
</ResponseField>

<ResponseField name="total" type="number">
  Total matching jobs before pagination.
</ResponseField>

<ResponseField name="has_more" type="boolean">
  Whether more matching jobs exist.
</ResponseField>

`GET /felix/training-jobs/{job_id}` Returns the current configuration, status, progress, artifact readiness, and available training metrics.

```bash

```

<ResponseField name="status" type="string">

</ResponseField>

<ResponseField name="normalized_status" type="string">

## Assign or unassign a project

`PATCH /felix/training-jobs/{job_id}` Updates the training job's `project_id`. This operation changes only the training job's project label. It does not automatically move related deployments, inferences, or evaluation runs. Send `project_id: null` to unassign the job.

```bash
curl -X PATCH https://api.pioneer.ai/felix/training-jobs/YOUR_TRAINING_JOB_ID \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "project_id": "YOUR_PROJECT_ID"
  }'
```

## Download the trained artifact

`GET /felix/training-jobs/{job_id}/download` Returns a temporary presigned URL for the completed trained-model artifact. The job must resolve to a completed state and have an available downloadable artifact.

```bash
curl https://api.pioneer.ai/felix/training-jobs/YOUR_TRAINING_JOB_ID/download \
  -H "X-API-Key: YOUR_API_KEY"
```

### Response

<ResponseField name="download_url" type="string">
  Temporary artifact download URL.
</ResponseField>

<ResponseField name="expires_in_seconds" type="number">
  Number of seconds before the URL expires. Defaults to `3600`.
</ResponseField>

<ResponseField name="file_name" type="string">
  Suggested downloaded filename.
</ResponseField>

<Note>
  This downloads the trained job artifact. There is no separate individual-checkpoint download endpoint.
</Note>

## Stop a training job

`POST /felix/training-jobs/{job_id}/stop` Stops an active training job while preserving existing checkpoints. The request body is optional.

<ParamField body="reason" type="string">
  Reason for stopping the job.
</ParamField>

<ParamField body="scores" type="object">
  Metrics used to make the stopping decision.
</ParamField>

<ParamField body="checkpoint" type="string">
  Checkpoint associated with the stopping decision.
</ParamField>

```bash
curl -X POST https://api.pioneer.ai/felix/training-jobs/YOUR_TRAINING_JOB_ID/stop \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "reason": "Validation loss stopped improving",
    "scores": {
      "validation_loss": 0.31
    },
    "checkpoint": "step-500"
  }'
```

## The response reports `status: "stopped"`.

## Synchronize job status

`POST /felix/training-jobs/{job_id}/sync` Refreshes the stored training-job status from the active training provider.

```bash
curl -X POST https://api.pioneer.ai/felix/training-jobs/YOUR_TRAINING_JOB_ID/sync \
  -H "X-API-Key: YOUR_API_KEY"
```

## Returns the refreshed training-job response.

## Terminate a training job

`POST /felix/training-jobs/{job_id}/terminate` Irreversibly stops the provider job, deletes all checkpoints, and marks the job as terminated.

<Warning>
  Termination is destructive. Use the stop endpoint when existing checkpoints should be preserved.
</Warning>

```bash
curl -X POST https://api.pioneer.ai/felix/training-jobs/YOUR_TRAINING_JOB_ID/terminate \
  -H "X-API-Key: YOUR_API_KEY"
```

### Response

<ResponseField name="deleted_checkpoints" type="number">
  Number of checkpoints deleted during termination.
</ResponseField>

## Push a trained model to Hugging Face

`POST /felix/training-jobs/{job_id}/push-to-hub` Pushes a completed training job's artifact to a Hugging Face repository.

<Warning>
  Treat the Hugging Face token as a secret. Never place it in logs, source control, or shared documentation.
</Warning>

### Request body

<ParamField body="repo_id" type="string" required>
  Target Hugging Face repository, such as `username/model-name`.
</ParamField>

<ParamField body="hf_token" type="string" required>
  Hugging Face token with write access to the target repository.
</ParamField>

<ParamField body="private" type="boolean">
  Whether the repository should be private. Defaults to `true`.
</ParamField>

<ParamField body="commit_message" type="string">
  Optional commit message.
</ParamField>

```bash
curl -X POST https://api.pioneer.ai/felix/training-jobs/YOUR_TRAINING_JOB_ID/push-to-hub \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "repo_id": "username/model-name",
    "hf_token": "YOUR_HUGGING_FACE_TOKEN",
    "private": true,
    "commit_message": "Upload trained model"
  }'
```

## Delete a training job

`DELETE /felix/training-jobs/{job_id}` Permanently deletes a training job and its associated checkpoints and stored artifacts.

<Warning>
  Deletion is permanent. Download or export any artifact you need before deleting the job.
</Warning>

```bash
curl -X DELETE https://api.pioneer.ai/felix/training-jobs/YOUR_TRAINING_JOB_ID \
  -H "X-API-Key: YOUR_API_KEY"
```

### Response

```json
{
  "success": true,
  "message": "Training job deleted successfully"
}
```

## Key parameters

| Parameter | Required | Description |
|---|---|---|
| `model_name` | Yes | A name for your trained model, used to identify it in your account. |
| `base_model` | Yes | The model ID to fine-tune. Use a value from `GET /base-models` or a checkpoint UUID from a previous job. |
| `datasets` | Yes | An array of dataset objects: `[{"name": "your-dataset-name"}]`. |
| `training_type` | No | `"lora"` (default, parameter-efficient) or `"full"` (all weights). Decoder LLM training is LoRA-only. |
| `nr_epochs` | No | Number of training epochs. Defaults to 100, except decoder base models default to 10 when omitted. |
| `learning_rate` | No | Learning rate. Omit to use the default for the chosen base model. |

<Note>
  `base_model` is required and must match a model-ID or UUID shape — not a free-form string. Omitting it, or sending a malformed value, returns `422`. A well-formed value that doesn't match any model available for training returns `400` instead.
</Note>

## Supported training targets

New training jobs support only the following target families:

| Family | Supported targets |
| --- | --- |
| GLiNER encoders | GLiNER2.5 Multi |

Use `GET /base-models?supports_training=true` immediately before creating a
job. It is the live source of truth for target availability.

## Starting a training job

```bash
curl -X POST https://api.pioneer.ai/felix/training-jobs \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model_name": "my-ner-model",
    "base_model": "fastino/gliner2-base-v1",
    "datasets": [{"name": "my-ner-dataset"}],
    "training_type": "lora",
    "nr_epochs": 5,
    "learning_rate": 5e-5
  }'
```

The response returns the full job record immediately, including a UUID `id` and initial status:

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "model_name": "my-gliner-model",
  "base_model": "fastino/gliner2-base-v1",
  "status": "requested",
  "nr_epochs": 5,
  "learning_rate": 5e-5
}
```

Save the `id` — you'll use it to poll status, retrieve metrics, and run inference against your trained model.

## Polling status and reading metrics

Poll the job endpoint until `status` reaches a terminal value — `complete`, `deployed`, `errored`, `stopped`, or `terminated`:

```bash
curl https://api.pioneer.ai/felix/training-jobs/3fa85f64-5717-4562-b3fc-2c963f66afa6 \
  -H "X-API-Key: YOUR_API_KEY"
```

The `metrics` field always includes loss values once training starts, plus F1/precision/recall/accuracy if a separate evaluation has been run against the resulting model:

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "status": "complete",
  "metrics": {
    "final_training_loss": 0.12,
    "final_validation_loss": 0.18,
    "best_validation_loss": 0.15,
    "eval_f1_score": 0.94,
    "eval_precision": 0.96,
    "eval_recall": 0.92,
    "eval_accuracy": 0.95
  }
}
```

To retrieve structured stdout/stderr log lines for the job:

```bash
curl https://api.pioneer.ai/felix/training-jobs/3fa85f64-5717-4562-b3fc-2c963f66afa6/logs \
  -H "X-API-Key: YOUR_API_KEY"
```

This returns a JSON list of log entries (`{id, timestamp, level, message, source}`) — it's a point-in-time fetch, not a live stream. Poll it periodically while the job is `running` to follow progress.

## Stopping or terminating a job

To gracefully halt a running job while preserving its checkpoints:

```bash
curl -X POST https://api.pioneer.ai/felix/training-jobs/3fa85f64-5717-4562-b3fc-2c963f66afa6/stop \
  -H "X-API-Key: YOUR_API_KEY"
```

The job status changes to `stopped`. Checkpoints saved before the stop remain available for deployment or download.

To permanently end a job and delete its checkpoints instead, use `/terminate`:

```bash
curl -X POST https://api.pioneer.ai/felix/training-jobs/3fa85f64-5717-4562-b3fc-2c963f66afa6/terminate \
  -H "X-API-Key: YOUR_API_KEY"
```

<Warning>
  `/terminate` stops the provider job if it's still running and permanently deletes all of its checkpoints. This is irreversible — use `/stop` instead if you want to keep the checkpoints trained so far.
</Warning>

## Checkpoints and downloading weights

Fastino saves checkpoints during training. You can list them at any point after the job starts:

```bash
curl https://api.pioneer.ai/felix/training-jobs/3fa85f64-5717-4562-b3fc-2c963f66afa6/checkpoints \
  -H "X-API-Key: YOUR_API_KEY"
```

Each checkpoint carries `is_best`, `is_final`, and `is_deployable` flags. You can deploy any deployable checkpoint — not just the final one — to a live inference endpoint:

```bash
curl -X POST https://api.pioneer.ai/felix/training-jobs/3fa85f64-5717-4562-b3fc-2c963f66afa6/checkpoints/CHECKPOINT_ID/deploy \
  -H "X-API-Key: YOUR_API_KEY"
```

```bash
curl https://api.pioneer.ai/felix/training-jobs/3fa85f64-5717-4562-b3fc-2c963f66afa6/download \
  -H "X-API-Key: YOUR_API_KEY"
```

The response is JSON with a `download_url` that expires in 1 hour — fetch that URL separately to get the actual file:

```json
{
  "success": true,
  "download_url": "https://...",
  "expires_in_seconds": 3600,
  "file_name": "my-ner-model-weights.zip"
}
```

You can also use a checkpoint UUID as the `base_model` value in a new training job to continue training from that checkpoint.

## Training endpoints summary

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/felix/training-jobs` | Start a new training job |
| `GET` | `/felix/training-jobs` | List training jobs (filter by `project_id`, `status`; paginate with `limit`/`offset`) |
| `GET` | `/felix/training-jobs/:id` | Get job status and metrics |
| `GET` | `/felix/training-jobs/:id/logs` | Get structured training log entries |
| `GET` | `/felix/training-jobs/:id/checkpoints` | List saved checkpoints |
| `POST` | `/felix/training-jobs/:id/checkpoints/:checkpoint_id/deploy` | Deploy a specific checkpoint for inference |
| `GET` | `/felix/training-jobs/:id/download` | Get a presigned URL to download trained weights (Pro plan+) |
| `POST` | `/felix/training-jobs/:id/stop` | Gracefully stop a running job, preserving checkpoints |
| `POST` | `/felix/training-jobs/:id/terminate` | Stop the job and permanently delete its checkpoints (irreversible) |
| `DELETE` | `/felix/training-jobs/:id` | Delete the job record — also stops it if active and deletes its checkpoints |
