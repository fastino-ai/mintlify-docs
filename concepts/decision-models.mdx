A **decision model** evaluates text or structured application state against caller-defined outcomes and returns structured decisions—labels, probabilities, scores, and confidence—instead of generated prose.

Use decision models when application code must classify an input, select a route, score against a rubric, moderate content, or decide whether an action should proceed.

## Decision models vs. generative models

|  | Decision model | Generative model |
| --- | --- | --- |
| Best for | Classification, routing, scoring, moderation, and gates | Open-ended generation, conversation, summarization, and coding |
| Output | Structured answers over caller-defined outcomes | Generated text or tool calls |
| Uncertainty | Explicit probabilities and confidence | Usually requires additional calibration or validation |
| Application pattern | Act, route, or escalate from a bounded result | Generate, explain, plan, or transform content |

The two model types can work together. A decision model can classify a request, select an agent or model, or gate an action before a generative model produces an open-ended result.

## Why use a decision model

- **Structured by construction** — downstream code receives a bounded answer instead of prose that must be parsed.
- **Caller-defined outcomes** — your application controls the permitted labels, routes, or levels.
- **Explicit uncertainty** — probabilities and confidence let you automate clear cases and send ambiguous cases to a fallback or review path.
