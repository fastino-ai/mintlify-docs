The [Fastino GLiDE agent skill](https://api.fastino.ai/.well-known/agent-skills/fastino-glide/SKILL.md) helps Cursor, Claude Code, and Codex use Fastino's hosted GLiDE decision model to classify, route, and score structured decisions, and integrate GLiDE inference into a project.

## Install

Run this command from your project:

```bash
npx skills add https://api.fastino.ai --skill fastino-glide
```

The installer lets you choose which supported agents receive the skill.

Before using the skill, expose your Fastino API key to the agent's environment:

```bash
export FASTINO_API_KEY="..."
```

Then invoke it explicitly with `/fastino-glide`, or ask your agent for a classification, routing, or scoring decision built on GLiDE.

## Non-interactive installation

Use the command for your agent to install the skill into the current project without prompts:

<CodeGroup initialSelectedTab={0}>

```bash Cursor
npx skills add https://api.fastino.ai --skill fastino-glide -a cursor -y
```

```bash Claude Code
npx skills add https://api.fastino.ai --skill fastino-glide -a claude-code -y
```

```bash Codex
npx skills add https://api.fastino.ai --skill fastino-glide -a codex -y
```

```text Any agent
"Install the Fastino GLiDE agent skill. Follow the installation
instructions in Fastino's documentation at
https://docs.fastino.ai/concepts/glide-agent-skill. Use one
installation method appropriate for your agent environment. Then use
the Fastino GLiDE skill when working on this project, especially for
classification, routing, and scoring decisions with calibrated
probabilities instead of generated text."
```

</CodeGroup>

For Cursor, Claude Code, and Codex, the `-a` option selects the target agent and `-y` accepts the installation prompts, making those commands suitable for scripts and CI.

## Migrate a TypeSafe or Jev project

After installing the skill, give your coding agent this prompt:

```text
Use the Fastino GLiDE skill to migrate this project from TypeSafe/Jev to
Fastino GLiDE. Find every TypeSafe API and SDK integration, then:

1. Change the endpoint to https://api.fastino.ai/v1/systemone.
2. Replace TYPESAFE_API_KEY with FASTINO_API_KEY and send it as X-API-Key.
3. Replace jev-latest with fastino/glide.
4. Preserve state, question names, primitive types, and compatible criteria.
5. Convert structured instructions to strings.
6. Replace TypeSafe SDK calls with direct HTTP requests.
7. Where code uses TypeSafe's floating-point score, read GLiDE's
   expected_level. Use GLiDE's score only for the integer winning level.
8. Handle Score probabilities and legend as string-keyed maps.
9. Replace 529 retry handling with bounded retries for 425 and 503, and keep
   bounded backoff for 429.
10. Update tests and revalidate all decision thresholds on representative data.

Do not change unrelated business logic. Show me every changed integration point
and any behavior that could not be migrated mechanically. Follow
https://docs.fastino.ai/inference/systemone for the canonical contract.
```

The request structure is similar, but Score semantics are different. See
[Migrate from TypeSafe or Jev](/inference/systemone#migrate-from-typesafe-or-jev)
before shipping the migration.
