Usa GLiDE cuando tu aplicación deba evaluar una situación y devolver decisiones
estructuradas y probabilísticas en lugar de texto generado. Envía un `state` y una
o más `questions` tipadas a [`POST /v1/systemone`](/es/inference/systemone).

## Elige una primitiva

| Tipo de decisión | Primitiva | Resultado |
| --- | --- | --- |
| Sí o no, con una probabilidad | [Noul](/es/concepts/glide-noul) | `noul`, la probabilidad de que la respuesta sea sí |
| Exactamente una opción con nombre | [Choice](/es/concepts/glide-choice) | Etiqueta ganadora y probabilidades de cada opción |
| Un nivel en una escala ordenada | [Score](/es/concepts/glide-score) | Nivel ganador, nivel esperado y probabilidades |

GLiDE responde cada pregunta de forma independiente a partir del mismo estado. No
existe una primitiva multietiqueta. Formula varias preguntas Noul cuando puedan
aplicarse varias etiquetas a la vez.

## Clasificación inicial en una sola llamada

Una solicitud de soporte se puede enrutar, puntuar y comprobar para determinar si
cumple los requisitos para un reembolso en una sola solicitud. Cada respuesta
permanece separada, por lo que tu aplicación puede aplicar un umbral o una acción
diferentes a cada una.

```json
{
  "model": "fastino/glide",
  "state": {
    "message": "I was charged twice for order A-104. Please refund the duplicate.",
    "account_tier": "business",
    "refund_policy": "Duplicate charges qualify for an immediate refund."
  },
  "questions": {
    "team": {
      "type": "choice",
      "instructions": "Which team should handle this request?",
      "criteria": {
        "billing": "Payments, invoices, or duplicate charges",
        "returns": "Product returns or replacements",
        "technical": "Product defects or technical support"
      }
    },
    "urgency": {
      "type": "score",
      "instructions": "How urgently should the team respond?",
      "criteria": [
        "low: can wait for the normal queue",
        "medium: should be handled soon",
        "high: requires immediate attention"
      ]
    },
    "refund_allowed": {
      "type": "noul",
      "instructions": "Does the request qualify for a refund under the supplied policy?",
      "criteria": {
        "true": "The policy allows the refund",
        "false": "The policy does not allow the refund"
      }
    }
  }
}
```

Interpreta los resultados según su primitiva:

- `answers.team.choice` es la ruta seleccionada. Usa `probabilities` para examinar las alternativas.
- `answers.urgency.score` es el índice del nivel ganador. Usa `expected_level` para aplicar un umbral más gradual.
- `answers.refund_allowed.noul` es la probabilidad de que la respuesta sea sí. Elige y valida tu propio umbral de acción.

## Patrones comunes

| Caso de uso | Estado | Preguntas |
| --- | --- | --- |
| Revisión de acciones de agentes | Llamada a herramienta propuesta, contexto visible y política | Noul: ¿se puede ejecutar la acción? Choice: ejecutar, revisar o escalar |
| Moderación de contenido | Contenido y política aplicable | Choice: categoría de la política. Score: gravedad. Noul: ¿enviar a revisión humana? |
| Enrutamiento de modelos o flujos de trabajo | Solicitud, objetivo de latencia y rutas disponibles | Choice: ruta. Score: complejidad. Noul: ¿usar la alternativa más costosa? |
| Control de calidad | Resultado y requisitos explícitos o rúbrica | Una pregunta Noul por requisito. Score: calidad o riesgo generales |
| Clasificación inicial de operaciones | Ticket, contexto de la cuenta y política operativa | Choice: responsable. Score: urgencia. Noul: ¿cumple los requisitos para una acción automatizada? |

Para supervisar agentes, evalúa solo los artefactos que tu sistema tiene permitido
recopilar, como las llamadas a herramientas y los registros visibles para el usuario.
No uses la cadena de pensamiento oculta como superficie de supervisión operativa.

## Diseña preguntas fiables

- Incluye en `state` la evidencia y la política necesarias para tomar la decisión.
- Haz que las opciones de Choice sean mutuamente excluyentes. Añade `other` o `none`
  cuando las opciones enumeradas no sean exhaustivas.
- Escribe los criterios de Score de menor a mayor y describe cada nivel con claridad.
- Usa preguntas Noul independientes para comprobaciones multietiqueta.
- Evalúa las probabilidades y la confianza con datos representativos antes de fijar
  umbrales de automatización.
- Deriva los resultados inciertos o de gran impacto hacia una alternativa más segura.

<Warning>
  GLiDE es probabilístico. No lo uses como única autoridad para decisiones irreversibles,
  críticas para la seguridad, legales, médicas, laborales, crediticias o de control de acceso.
</Warning>

## Cuándo GLiDE no es la herramienta adecuada

| Necesidad | Usa en su lugar |
| --- | --- |
| Extraer nombres, fragmentos, entidades o relaciones de texto | [GLiNER](/es/concepts/gliner) |
| Generar, resumir o reescribir texto libre | Un modelo de lenguaje generativo |
| Aplicar una regla determinista exacta | Código de la aplicación o un motor de políticas |
| Devolver varias etiquetas a partir de una pregunta | Preguntas Noul separadas, una por etiqueta |

Empieza con el [inicio rápido](/es/quickstart) y luego usa la
[Referencia de GLiDE](/es/concepts/decision-models) para definir el esquema de
preguntas de producción.
