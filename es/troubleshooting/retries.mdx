## Reintentar solo fallos transitorios

Usa espera exponencial acotada, respeta `Retry-After` y establece un límite de intentos o tiempo.

## Condiciones de reintento

| Estado | Significado | Acción |
| --- | --- | --- |
| `425` | El modelo seleccionado se está calentando | Reintentar después del retraso indicado por el servidor |
| `429` | Límite de solicitudes alcanzado | Respetar `Retry-After` y reintentar |
| `503` | Servicio temporalmente no disponible | Reintentar con espera acotada |
| `529` | Endpoint compatible con Anthropic sobrecargado | Reintentar manualmente; el SDK de Anthropic no reintenta automáticamente esta respuesta |

No reintentes errores de autenticación, facturación, validación, modelo inexistente o solicitud incorrecta hasta corregirla.

## Lista para reintentos seguros

- Usa una clave de idempotencia al crear trabajos de entrenamiento y otras mutaciones compatibles.
- Mantén el mismo cuerpo al repetir una solicitud idempotente.
- Aplica variación y un retraso máximo.
- Registra el estado final y el ID de solicitud, nunca la clave API.

Consulta los formatos completos y soluciones en [Errores](/es/troubleshooting/errors).
