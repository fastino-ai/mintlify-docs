Fastino ofrece dos interfaces síncronas de inferencia. Elige la que se ajuste a lo que
necesitas:

| Capacidad | [`/v1/chat/completions`](/es/inference/chat-completions) | [`/v1/systemone`](/es/inference/systemone) |
| --- | --- | --- |
| Modelo | Selecciona un modelo base con capacidad de inferencia o el UUID de un trabajo de entrenamiento completado | Siempre usa `fastino/glide` |
| Solicitud | `model` y `messages` compatibles con OpenAI, más el `schema` de nivel superior de Fastino | `state` nativo más una o varias `questions` tipadas |
| Respuesta | Envoltorio de chat-completion de OpenAI; analiza `choices[0].message.content` como JSON | Cuerpo nativo `{ "answers": ..., "usage": ... }` |
| Entrada por lotes | Una conversación por solicitud | Un `state` por solicitud, con varias `questions` evaluadas a la vez |
| Ideal para | Extracción, clasificación, extracción estructurada y relaciones, en modelos base y ajustados | Decisiones de clasificación, enrutamiento y puntuación con probabilidades calibradas |

<Tip>
  Usa [`/v1/chat/completions`](/es/inference/chat-completions) para extracción, clasificación,
  extracción estructurada o relaciones. Usa [`/v1/systemone`](/es/inference/systemone) para
  decisiones estructuradas (clasificación, enrutamiento, puntuación) en lugar de extracción.
</Tip>

Esta página cubre lo que comparten ambas interfaces. Consulta
[`/v1/chat/completions`](/es/inference/chat-completions) para ver el contrato de solicitud y
respuesta de GLiNER y la guía de migración heredada, o [`/v1/systemone`](/es/inference/systemone)
para ver el contrato HTTP de GLiDE; las formas completas de solicitud y respuesta de
Noul/Choice/Score se encuentran en [Modelos de decisión](/es/concepts/decision-models). El uso
del SDK, el entrenamiento de modelos, la evaluación, el historial de inferencia y el feedback
quedan fuera del alcance de esta página.

## Autenticación

Envía una clave de API de Fastino en cada solicitud, sea cual sea la interfaz:

```bash
export FASTINO_API_KEY="fast_sk_..."
```

```http
Authorization: Bearer $FASTINO_API_KEY
Content-Type: application/json
```

## Arranques en frío y reintentos

Un modelo inactivo o recién desplegado puede tener un arranque en frío, en cualquiera de las dos
interfaces. Usa un tiempo de espera de lectura de al menos 300 segundos y reintenta las
respuestas `425`, `429` y `503`. Respeta la cabecera de respuesta `Retry-After` cuando esté
presente.

Una solicitud que agota el tiempo aún puede calentar el despliegue, lo que permite que la
siguiente solicitud tenga éxito. No reintentes errores de autenticación, facturación, validación
ni de modelo desconocido sin corregir el problema subyacente.

```bash
curl --max-time 300 -X POST "https://api.fastino.ai/v1/chat/completions" \
  -H "Authorization: Bearer $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d @request.json
```

El mismo patrón de tiempo de espera y reintentos se aplica a `/v1/systemone`.

## Errores

Ambas interfaces comparten los mismos códigos de estado para autenticación, facturación,
validación, limitación de tasa y arranques en frío. Algunos códigos difieren ligeramente según
la interfaz; por ejemplo, `/v1/systemone` no tiene despliegues ajustados por ahora, así que su
caso `409` no se aplica. Consulta la tabla exacta en la página de cada endpoint: [errores de
`/v1/chat/completions`](/es/inference/chat-completions#errores) o [errores de
`/v1/systemone`](/es/inference/systemone#errores).
