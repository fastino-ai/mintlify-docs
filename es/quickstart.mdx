Esta guía te lleva por el camino más rápido hasta una integración funcional con Fastino. Al terminar, habrás realizado con éxito una llamada de decisión con GLiDE y entenderás la forma de la API. Solo necesitas una cuenta de Fastino y una terminal.

<Steps>
  <Step title="Regístrate y obtén tu API key">
    Crea una cuenta en [Fastino](https://agent.fastino.ai/).

    Una vez que hayas iniciado sesión, ve a **Settings → API Keys** y genera una nueva clave. Cópiala en un lugar seguro, ya que no podrás volver a verla después de cerrar el diálogo.

    <Warning>
      Mantén tu API key fuera del control de versiones. Usa una variable de entorno o un gestor de secretos en lugar de escribirla directamente en tus archivos fuente.
    </Warning>

    Establece tu clave como una variable de entorno para que los ejemplos siguientes funcionen tal cual:

    ```bash
    export FASTINO_API_KEY="your_api_key_here"
    ```
  </Step>
  <Step title="Lista los modelos base disponibles (opcional)">
    Puedes explorar los modelos que Fastino tiene disponibles. Usa `GET /v1/base-models` para ver el catálogo completo.

    <CodeGroup>

    ```bash curl
    curl https://api.fastino.ai/v1/base-models \
      -H "X-API-Key: $FASTINO_API_KEY"
    ```

    ```python Python
    import os
    import requests
    
    response = requests.get(
        "https://api.fastino.ai/v1/base-models",
        headers={"X-API-Key": os.environ["FASTINO_API_KEY"]}
    )
    print(response.json())
    ```

    ```javascript JavaScript
    const response = await fetch(
      "https://api.fastino.ai/v1/base-models",
      {
        headers: {
          "X-API-Key": process.env.FASTINO_API_KEY
        }
      }
    );
    const data = await response.json();
    console.log(data);
    ```

    </CodeGroup>

    La respuesta lista los IDs de modelo que puedes pasar a `/v1/chat/completions`. Por ejemplo, `fastino/gliner2-base-v1` es el modelo base de GLiNER para tareas de NER.
  </Step>
  <Step title="Ejecuta tu primera llamada de inferencia">
    Llama a `POST /v1/systemone` con un `model`, un `state` que describa la situación y una o más `questions` tipadas. GLiDE devuelve directamente probabilidades calibradas y etiquetas. No hay texto generado que analizar. El ejemplo siguiente hace una sola pregunta de sí/no (`noul`).

    <CodeGroup>

    ```bash curl
    curl -X POST "https://api.fastino.ai/v1/systemone" \
      -H "X-API-Key: $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "fastino/glide",
        "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
        "questions": {
          "refund_allowed": {
            "type": "noul",
            "instructions": "Does this request qualify for a refund?",
            "criteria": { "true": "Qualifies", "false": "Does not qualify" }
          }
        }
      }'
    ```

    ```python Python
    import os
    import requests

    response = requests.post(
        "https://api.fastino.ai/v1/systemone",
        headers={
            "X-API-Key": os.environ["FASTINO_API_KEY"],
            "Content-Type": "application/json",
        },
        json={
            "model": "fastino/glide",
            "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
            "questions": {
                "refund_allowed": {
                    "type": "noul",
                    "instructions": "Does this request qualify for a refund?",
                    "criteria": {"true": "Qualifies", "false": "Does not qualify"},
                }
            },
        },
    )

    response.raise_for_status()
    print(response.json())
    ```

    ```javascript JavaScript
    const response = await fetch(
      "https://api.fastino.ai/v1/systemone",
      {
        method: "POST",
        headers: {
          "X-API-Key": process.env.FASTINO_API_KEY,
          "Content-Type": "application/json",
        },
        body: JSON.stringify({
          model: "fastino/glide",
          state: "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
          questions: {
            refund_allowed: {
              type: "noul",
              instructions: "Does this request qualify for a refund?",
              criteria: { true: "Qualifies", false: "Does not qualify" },
            },
          },
        }),
      }
    );

    if (!response.ok) {
      throw new Error(`Inference failed: ${response.status} ${await response.text()}`);
    }

    const result = await response.json();
    console.log(JSON.stringify(result, null, 2));
    ```

    </CodeGroup>

    Respuesta:

    ```json
    {
      "model": "glide",
      "answers": {
        "refund_allowed": {
          "type": "noul",
          "noul": 0.9989566626894673,
          "confidence": 0.9979133253789345
        }
      },
      "usage": { "input_tokens": 443, "output_tokens": 62 },
      "token_usage": 505
    }
    ```

    `answers.refund_allowed.noul` es la probabilidad de que la respuesta sea "sí". Un valor de `0.999` es una señal clara de que la solicitud cumple los requisitos. Consulta [Modelos de decisión](/es/concepts/decision-models) para ver los tipos de pregunta `choice` y `score`, el enrutamiento condicionado por la confianza y la referencia completa de primitivas.

    <Accordion title="¿Quieres extraer entidades? Usa GLiNER a través de /v1/chat/completions">
      Si necesitas extracción a nivel de fragmento (NER, clasificación, registros estructurados) en lugar de una decisión, llama a `POST /v1/chat/completions` con un modelo, un mensaje y un esquema que defina qué quieres extraer:

      ```bash curl
      curl -X POST "https://api.fastino.ai/v1/chat/completions" \
        -H "Authorization: Bearer $FASTINO_API_KEY" \
        -H "Content-Type: application/json" \
        -d '{
          "model": "fastino/gliner2.5-multi-v1",
          "messages": [
            {
              "role": "user",
              "content": "Apple announced the MacBook Pro at WWDC in Cupertino."
            }
          ],
          "schema": {
            "entities": [
              { "name": "organization", "description": "business or institution name" },
              { "name": "product", "description": "named commercial product" },
              { "name": "event", "description": "named conference or event" },
              { "name": "location", "description": "city, region, or place" }
            ]
          },
          "threshold": 0.5
        }'
      ```

      Para modelos encoder (GLiNER), el objeto `schema` define la tarea y puede incluir `entities`, `classifications`, `structures` y `relations`. Para modelos decoder (LLM), omite `schema` y envía un mensaje de chat normal. Consulta la [API de inferencia](/es/inference) para ver el contrato completo, ejemplos en Python/JavaScript y los códigos de error.

      <Note>
        `model` debe ser el ID de un modelo base con capacidad de inferencia o el UUID de un trabajo de entrenamiento completado y desplegable. Tras el entrenamiento, despliega el artefacto seleccionado antes de usar el UUID del trabajo para inferencia.
      </Note>
    </Accordion>
  </Step>
  <Step title="Inicia un trabajo de entrenamiento (opcional)">
    Cuando estés listo para ajustar el modelo con tus propios datos, inicia un trabajo de entrenamiento.

    <CodeGroup>

    ```bash curl
    curl -X POST https://api.fastino.ai/v1/training-jobs \
      -H "X-API-Key: $FASTINO_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model_name": "my-ner-model",
        "base_model": "fastino/gliner2-base-v1",
        "datasets": [{"name": "my-dataset"}],
        "training_type": "lora",
        "nr_epochs": 5,
        "learning_rate": 5e-5
      }'
    ```

    ```python Python
    import os
    import requests
    
    response = requests.post(
        "https://api.fastino.ai/v1/training-jobs",
        headers={
            "X-API-Key": os.environ["FASTINO_API_KEY"],
            "Content-Type": "application/json"
        },
        json={
            "model_name": "my-ner-model",
            "base_model": "fastino/gliner2-base-v1",
            "datasets": [{"name": "my-dataset"}],
            "training_type": "lora",
            "nr_epochs": 5,
            "learning_rate": 5e-5
        }
    )
    print(response.json())
    # {"id": "uuid-of-training-job", "status": "requested"}
    ```

    </CodeGroup>

    La respuesta incluye un `id` de trabajo. Consulta `GET /v1/training-jobs/{id}` para comprobar el estado. Cuando el trabajo llegue a `complete`, usa el ID del trabajo como `model` en las llamadas a `/v1/chat/completions`.

    Valores de estado del trabajo: `requested` → `running` → `complete` (o `failed` / `stopped`).
  </Step>
</Steps>
