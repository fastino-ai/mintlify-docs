`GET /v1/training/jobs`

Devuelve los trabajos de entrenamiento de configuración e interactivos visibles
para la cuenta autenticada.

Sin `type`, los trabajos de configuración e interactivos se intercalan por
`created_at`, del más reciente al más antiguo. Si dos trabajos tienen la misma
marca de tiempo, el trabajo de configuración aparece primero. Pasa
`type=interactive` para listar solo los trabajos interactivos.

## Solicitud

<ParamField header="X-API-Key" type="string" required>
  Tu clave de API de Fastino.
</ParamField>

<ParamField query="status" type="string">
  Filtra ambos tipos de trabajo por estado. Los trabajos interactivos admiten `creating`, `active`, `stopping`, `stopped` y `failed`; `running` también coincide con `active`, mientras que `errored` y `error` coinciden con `failed`. `running`, `errored`, `error`, `stopped` y `failed` pueden coincidir con ambos tipos. `creating`, `active` y `stopping` solo coinciden con trabajos interactivos; los demás estados config solo con trabajos config. Para los trabajos config, `status=complete` devuelve trabajos persistidos como `complete`, `artifact_ready` o `deployed`.
</ParamField>

<ParamField query="type" type="string">
  Filtra por `config` o `interactive`.
</ParamField>

<ParamField query="project_id" type="string">
  Filtra por ID de proyecto.
</ParamField>

<ParamField query="limit" type="integer" default="200">
  Tamaño de página, de `1` a `200`.
</ParamField>

<ParamField query="offset" type="integer" default="0">
  Número de trabajos coincidentes que se omiten.
</ParamField>

<RequestExample>

```bash cURL
curl "https://api.fastino.ai/v1/training/jobs?type=config&status=complete&limit=50&offset=0" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

</RequestExample>

## Respuesta

<ResponseField name="success" type="boolean">
  Indica si la solicitud se completó correctamente.
</ResponseField>

<ResponseField name="training_jobs" type="object[]">
  Registros de trabajos de entrenamiento de esta página.
</ResponseField>

Todos los registros incluyen `id` y `created_at`. Los registros interactivos
también repiten `id` en `job_id` y `training_run_id` por compatibilidad con la
API y el SDK, e incluyen `status`, `stop_reason`, `error_message` e
`is_terminal_status`. Consulta un trabajo interactivo por `id` hasta que el
indicador terminal sea true.

Un registro con `type: "config"` y `source: "interactive_checkpoint"` es el modelo servido creado a partir de un checkpoint sampler interactivo. Sus campos de entrenamiento config, incluidos épocas, tamaño de lote, tasa de aprendizaje y porcentaje de validación, son `null`.

<ResponseField name="count" type="integer">
  Número de trabajos de esta página.
</ResponseField>

<ResponseField name="total" type="integer">
  Número total de trabajos coincidentes antes de la paginación.
</ResponseField>

<ResponseField name="has_more" type="boolean">
  Indica si existe otra página después de esta.
</ResponseField>

<ResponseExample>

```json Response
{
  "success": true,
  "training_jobs": [],
  "count": 0,
  "total": 0,
  "has_more": false
}
```

</ResponseExample>

Los valores de paginación no válidos devuelven `422`.

Consulta la [descripción general de la API de entrenamiento](/es/training) para ver el conjunto completo de estados persistidos.
