`POST /v1/training/jobs/{job_id}/save-weights`

Guarda los pesos LoRA y el estado del optimizador del trabajo como
`weights/<name>`. Puedes
[cargarlo](/es/api-reference/training-jobs/interactive/load-weights) de nuevo en
el mismo trabajo o [iniciar un trabajo nuevo](/es/api-reference/training-jobs/interactive/create-model)
a partir de él. Para muestrear o descargar pesos, guárdalos en su lugar con
[`POST /v1/training/jobs/{job_id}/save-weights-for-sampler`](/es/api-reference/training-jobs/interactive/save-weights-for-sampler).

El guardado se ejecuta en orden con las demás llamadas del trabajo.

## Solicitud

<ParamField header="X-API-Key" type="string" required>
  Tu clave de API de Fastino.
</ParamField>

<ParamField path="job_id" type="string" required>
  ID del trabajo interactivo.
</ParamField>

<ParamField body="name" type="string" required>
  De 1 a 128 caracteres entre `A-Z`, `a-z`, `0-9`, `.`, `_` y `-`.
</ParamField>

<ParamField body="ttl_seconds" type="integer | null">
  Elimina el checkpoint automáticamente tras este número de segundos, de `3600`
  (1 hora) a `315360000` (10 años). Omítelo o envía `null` para conservar el checkpoint hasta que lo elimines. Los checkpoints activos cuentan para el [uso de almacenamiento](/es/api-reference/training-jobs/interactive/storage-usage).
</ParamField>

<ParamField body="overwrite" type="boolean" default="false">
  Reemplaza un checkpoint de estado que tenga el mismo nombre.
</ParamField>

<ParamField body="user_metadata" type="object">
  Metadatos de pares clave-valor de tipo cadena que se guardan con el checkpoint.
</ParamField>

<RequestExample>

```bash cURL
curl -X POST "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/save-weights" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "step-000100"}'
```

</RequestExample>

## Respuesta

<ResponseField name="future_id" type="string">
  El future `save`.
</ResponseField>

<ResponseField name="checkpoint_id" type="string">
  `weights/<name>`.
</ResponseField>

<ResponseField name="path" type="string">
  Ruta completa del checkpoint. Pásala como `from_checkpoint` cuando crees un trabajo.
</ResponseField>

<ResponseExample>

```json Response
{
  "future_id": "FUTURE_ID",
  "job_id": "SESSION_ID:train:0",
  "type": "save",
  "checkpoint_id": "weights/step-000100",
  "path": "tinker://SESSION_ID:train:0/weights/step-000100"
}
```

</ResponseExample>

| Estado | Significado |
| --- | --- |
| `400` | El nombre tiene caracteres o una longitud no válidos, el TTL está fuera de rango o el trabajo se detuvo. |
| `404` | El trabajo no existe o pertenece a otro equipo. |
| `422` | Al cuerpo le falta `name` o tiene un campo desconocido. |
