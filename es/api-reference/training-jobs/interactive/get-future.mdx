`GET /v1/training/jobs/{job_id}/futures/{future_id}`

Toda llamada de un trabajo interactivo que ejecuta una operación devuelve un
`future_id`. Consulta el future hasta que su `status` sea `completed`, `failed`
o `cancelled`. Usa `wait=true` para esperar como máximo 25 segundos por
solicitud; si se agota el tiempo, la respuesta puede seguir devolviendo un
future no terminal. Los resultados se conservan durante una hora.

## Solicitud

<ParamField header="X-API-Key" type="string" required>
  Tu clave de API de Fastino.
</ParamField>

<ParamField path="job_id" type="string" required>
  ID del trabajo interactivo.
</ParamField>

<ParamField path="future_id" type="string" required>
  ID del future devuelto cuando se encoló el trabajo.
</ParamField>

<ParamField query="wait" type="boolean" default="false">
  Espera hasta 25 segundos a que termine un future antes de responder. Repite la
  solicitud hasta que finalice.
</ParamField>

<RequestExample>

```bash cURL
curl "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/futures/$FUTURE_ID?wait=true" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

</RequestExample>

## Respuesta

<ResponseField name="future_id" type="string">
  El future.
</ResponseField>

<ResponseField name="job_id" type="string">
  El trabajo.
</ResponseField>

<ResponseField name="type" type="string">
  `create`, `load`, `forward`, `forward_backward`, `optim_step`, `save` o `sample`.
</ResponseField>

<ResponseField name="status" type="string">
  `pending`, `running`, `completed`, `failed` o `cancelled`.
</ResponseField>

<ResponseField name="queue_state" type="string | null">
  Mientras no ha terminado: `active`, o `paused_capacity` mientras se prepara la capacidad de GPU.
</ResponseField>

<ResponseField name="queue_state_reason" type="string | null">
  Explicación legible sobre la capacidad mientras `queue_state` es
  `paused_capacity`; en caso contrario, `null`.
</ResponseField>

<ResponseField name="result" type="any">
  Una vez `completed`:

  - `forward` y `forward_backward`: `loss_fn_outputs` (una entrada de tensores
    por dato, como `logprobs`) y `metrics`.
  - `sample`: `sequences`, cada una con `tokens`, `logprobs` y `stop_reason`,
    además de `prompt_logprobs` cuando se solicita.
  - `save`: la ruta del checkpoint.
  - Otros tipos: una confirmación.
</ResponseField>

<ResponseField name="error" type="object | null">
  Cuando es `failed` o `cancelled`: `message` y `category` (`user` si el
  problema está en la solicitud, `server` si es un problema de Fastino).
</ResponseField>

<ResponseExample>

```json Pending
{
  "future_id": "FUTURE_ID",
  "job_id": "SESSION_ID:train:0",
  "type": "forward_backward",
  "status": "pending",
  "queue_state": "paused_capacity",
  "queue_state_reason": null,
  "result": null,
  "error": null
}
```

```json Completed sample
{
  "future_id": "FUTURE_ID",
  "job_id": "SESSION_ID:train:0",
  "type": "sample",
  "status": "completed",
  "queue_state": null,
  "queue_state_reason": null,
  "result": {
    "sequences": [
      {"tokens": [59604, 13, 151645], "logprobs": [-0.21, -0.05, -0.01], "stop_reason": "stop", "topk_logprobs": null}
    ],
    "prompt_logprobs": null,
    "topk_prompt_logprobs": null,
    "prompt_cache_hit_tokens": 0
  },
  "error": null
}
```

</ResponseExample>

| Estado | Significado |
| --- | --- |
| `404` | El trabajo o el future no existe, pertenece a otro equipo, está asociado a otro trabajo o su registro se eliminó después de unos siete días. |
| `410` | Revisa `error.message`. Una operación perdida se puede volver a enviar. Si el resultado caducó tras una hora de retención, la operación puede haberse ejecutado; no repitas una operación mutante hasta conciliar los checkpoints y el registro duradero del bucle. Consulta [Bucle de entrenamiento](/es/training/training-loop) y [Checkpoints](/es/training/checkpoints). |
