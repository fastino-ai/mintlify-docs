`POST /v1/training/jobs/create-model`

Crea un trabajo de entrenamiento LoRA `interactive` sobre un modelo base decodificador o un trabajo nuevo a partir de un estado de entrenamiento guardado. Después, tu aplicación envía cada pasada forward-backward, paso del optimizador, checkpoint y solicitud de muestreo. Los clientes JSON nativos no envían valores `seq_id` ni heartbeats. Para el entrenamiento gestionado con un dataset subido, usa [`POST /v1/training/jobs`](/es/api-reference/training-jobs/create).

El trabajo está listo cuando termina su future `create`. Léelo con [`GET /v1/training/jobs/{job_id}/futures/{future_id}`](/es/api-reference/training-jobs/interactive/get-future).

Cada equipo puede tener como máximo `16` trabajos interactivos activos. Cada trabajo puede tener hasta `512` operaciones en cola al mismo tiempo. Superar cualquiera de los límites devuelve `429`.

## Solicitud

<ParamField header="X-API-Key" type="string" required>
  Su clave API de Fastino.
</ParamField>

Envíe exactamente uno de `base_model` y `from_checkpoint`.

<ParamField body="base_model" type="string">
  `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16`,
  `nvidia/NVIDIA-Nemotron-3.5-Super-VL-120B-A12B-NVFP4` o `Qwen/Qwen3.6-35B-A3B`.
</ParamField>

<ParamField body="from_checkpoint" type="string">
  El `path` devuelto por [`save-weights`](/es/api-reference/training-jobs/interactive/save-weights) para uno de tus trabajos, como `tinker://<job_id>/weights/<name>`. El trabajo nuevo usa el modelo base y la configuración LoRA de ese checkpoint, por lo que debes omitir `lora_config`. Los checkpoints sampler se rechazan.
</ParamField>

<ParamField body="load_optimizer" type="boolean" default="false">
  Configure `load_optimizer` con `from_checkpoint` para restaurar el estado del optimizador.
</ParamField>

<ParamField body="lora_config" type="object">
  Configuración de LoRA para un nuevo trabajo.

  <Expandable title="properties">
    <ParamField body="rank" type="integer" default="32">
      Rango LoRA, del 1 al 32.
    </ParamField>
    <ParamField body="seed" type="integer">
      Semilla de inicialización del adaptador.
    </ParamField>
    <ParamField body="train_attn" type="boolean" default="true">
      Entrenar capas de atención.
    </ParamField>
    <ParamField body="train_mlp" type="boolean" default="true">
      Entrene capas MLP.
    </ParamField>
    <ParamField body="train_unembed" type="boolean" default="true">
      Entrene la capa de desincrustación.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="optimizer_config" type="object">
  Familia de optimizadores. Solo se sirve `{"type": "adamw"}`, que es el valor predeterminado.
</ParamField>

<ParamField body="project_id" type="string">
  Proyecto al que pertenece el trabajo y su uso. El valor predeterminado es su proyecto predeterminado.
</ParamField>

<ParamField body="user_metadata" type="object">
  Tus propios metadatos JSON para el trabajo.
</ParamField>

<RequestExample>

```bash cURL
curl -X POST "https://api.fastino.ai/v1/training/jobs/create-model" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "base_model": "Qwen/Qwen3.6-35B-A3B",
    "lora_config": {"rank": 32}
  }'
```

</RequestExample>

## Respuesta

<ResponseField name="job_id" type="string">
  ID del trabajo interactivo. Úsalo con todas las rutas `/v1/training/jobs/{job_id}`.
</ResponseField>

<ResponseField name="type" type="string">
  Siempre `interactive`.
</ResponseField>

<ResponseField name="base_model" type="string">
  Modelo base del trabajo.
</ResponseField>

<ResponseField name="future_id" type="string">
  El future `create` del trabajo.
</ResponseField>

<ResponseField name="load_future_id" type="string | null">
  Con `from_checkpoint`, el future que carga el checkpoint.
</ResponseField>

<ResponseExample>

```json Response
{
  "job_id": "SESSION_ID:train:0",
  "type": "interactive",
  "base_model": "Qwen/Qwen3.6-35B-A3B",
  "future_id": "FUTURE_ID",
  "load_future_id": null
}
```

</ResponseExample>

## Errores

| Estado | Significado |
| --- | --- |
| `400` | El modelo no está disponible, el rango está fuera del intervalo permitido, `from_checkpoint` es un checkpoint sampler o se envió `lora_config` con `from_checkpoint`. |
| `402` | El equipo no tiene créditos o no tiene una configuración de pago válida. |
| `404` | El entrenamiento interactivo no está disponible para el equipo o el checkpoint no existe. |
| `429` | El equipo ya tiene `16` trabajos interactivos activos. Detén un trabajo inactivo antes de reintentar. |
| `422` | Se enviaron ambos o ninguno de `base_model` y `from_checkpoint`, o el cuerpo tiene un campo desconocido. |
