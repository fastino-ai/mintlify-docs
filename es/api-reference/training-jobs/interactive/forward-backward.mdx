`POST /v1/training/jobs/{job_id}/forward-backward`

Calcula la pérdida de un lote de datos a nivel de token y acumula sus
gradientes. El siguiente [paso del optimizador](/es/api-reference/training-jobs/interactive/optim-step)
los aplica. La respuesta es un futuro; leer el registro de pérdidas y por token
probabilidades de
[`GET /v1/training/jobs/{job_id}/futures/{future_id}`](/es/api-reference/training-jobs/interactive/get-future).

[`POST /v1/training/jobs/{job_id}/forward`](/es/api-reference/training-jobs/interactive/forward)
toma el mismo cuerpo y calcula la pérdida sin gradientes.

## Solicitud

<ParamField header="X-API-Key" type="string" required>
  Su clave API de Fastino.
</ParamField>

<ParamField path="job_id" type="string" required>
  Identificación de trabajo interactiva.
</ParamField>

<ParamField body="datums" type="object[]" required>
  Uno o más ejemplos de entrenamiento. Tokenízalos tú mismo con los del modelo base.
  tokenizador.

  <Expandable title="properties">
    <ParamField body="model_input" type="object" required>
      `{"chunks": [{"type": "encoded_text", "tokens": [...]}]}`. El token de entrada
      ID, N tokens en total.
    </ParamField>
    <ParamField body="loss_fn_inputs" type="object" required>
      Tensores por posición, cada uno `{"data": [...], "dtype": "int64" | "float32"}`
      con un `shape` opcional. Cada tensor tiene N valores.

      - `target_tokens` (`int64`, requerido): el token esperado en cada posición,
        Por lo general, la entrada se desplazó uno hacia la izquierda.
      - `weights` (`float32`): pérdida de peso por posición. Utilice `0` para recibir aviso
        posiciones y `1` para posiciones de finalización.
      - `logprobs` y `advantages` (`float32`): requerido por toda pérdida excepto
        `cross_entropy`. `logprobs` son las probabilidades logarítmicas del muestreador del
        objetivos.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="loss_fn" type="string" default="cross_entropy">
  `cross_entropy`, `importance_sampling`, `ppo`, `cispo` o `dro`.
</ParamField>

<ParamField body="loss_fn_config" type="object">
  Configuración de pérdidas. `ppo` y `cispo` toman `clip_low_threshold` y
  `clip_high_threshold`; `dro` toma `beta`. Se rechazan las claves desconocidas.
</ParamField>

<RequestExample>

```bash cURL
curl -X POST "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/forward-backward" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "loss_fn": "cross_entropy",
    "datums": [
      {
        "model_input": {"chunks": [{"type": "encoded_text", "tokens": [151644, 872, 198, 3838]}]},
        "loss_fn_inputs": {
          "target_tokens": {"data": [872, 198, 3838, 30], "dtype": "int64"},
          "weights": {"data": [0, 0, 1, 1], "dtype": "float32"}
        }
      }
    ]
  }'
```

</RequestExample>

## Errores

| Estado | Significado |
| --- | --- |
| `400` | `loss_fn` desconocido, un tensor `target_tokens` no entero, ID de tokens fuera de vocabulario o el trabajo se detuvo. |
| `402` | El equipo no tiene créditos o no tiene una configuración de pago válida. |
| `404` | El trabajo no existe o pertenece a otro equipo. |
| `422` | `datums` está vacío o el cuerpo tiene un campo desconocido. |

Problemas encontrados mientras se ejecuta el lote, como una entrada de pérdida faltante o no coincidente
longitudes de tensor, una clave `loss_fn_config` desconocida o un dato más largo que el
El límite del modelo, falla el futuro. Su `error.category` es `user`.
