Los clientes nativos crean un trabajo `interactive` con [`POST /v1/training/jobs/interactive`](/es/api-reference/training-jobs/interactive/create). Los clientes Tinker crean el mismo tipo mediante el SDK compatible.

`GET /v1/training/jobs/{job_id}/checkpoints`

Devuelve los checkpoints visibles para un trabajo de entrenamiento.

## Solicitud

<ParamField header="X-API-Key" type="string" required>
  Tu clave de API de Fastino.
</ParamField>

<ParamField path="job_id" type="string" required>
  UUID de un trabajo config o ID de trabajo interactive devuelto por el SDK compatible.
</ParamField>

<RequestExample>

```bash cURL
curl https://api.fastino.ai/v1/training/jobs/YOUR_TRAINING_JOB_ID/checkpoints \
  -H "X-API-Key: $FASTINO_API_KEY"
```

</RequestExample>

## Respuesta

<ResponseField name="success" type="boolean">
  Si la solicitud tuvo éxito.
</ResponseField>

<ResponseField name="checkpoints" type="object[]">
  Checkpoints guardados. La forma de cada elemento depende del tipo de trabajo.
</ResponseField>

<ResponseField name="count" type="integer">
  Número de checkpoints devueltos.
</ResponseField>

### Trabajo config

Los checkpoints config incluyen `id`, `job_id`, epoch, step, pérdidas,
métricas, despliegue y marcas de tiempo. Su `id` no se acepta en el endpoint de
descarga de checkpoints interactivos.

<ResponseExample>

```json Response
{
  "success": true,
  "checkpoints": [
    {
      "id": "CHECKPOINT_ID",
      "job_id": "YOUR_TRAINING_JOB_ID",
      "epoch": 5,
      "step": 500,
      "training_loss": 0.12,
      "validation_loss": 0.18,
      "is_deployable": true,
      "is_best": true,
      "is_final": true,
      "created_at": "2026-09-22T20:30:00Z",
      "updated_at": "2026-09-22T20:30:00Z"
    }
  ],
  "count": 1
}
```

</ResponseExample>

### Trabajo interactive

Los trabajos interactive también devuelven `run_id`. Sus checkpoints se
ordenan del más reciente al más antiguo. Usa `checkpoint_id`, como
`sampler_weights/checkpoint-1`, con el
[endpoint de descarga interactiva](/es/api-reference/training-jobs/download-checkpoint).
No envíes el `id` del checkpoint config ni `tinker_path`.

<ResponseExample>

```json Response
{
  "success": true,
  "run_id": "session-1:train:0",
  "checkpoints": [
    {
      "checkpoint_id": "sampler_weights/checkpoint-1",
      "checkpoint_type": "sampler",
      "time": "2026-09-22T20:30:00Z",
      "tinker_path": "tinker://session-1:train:0/sampler_weights/checkpoint-1",
      "size_bytes": 12345,
      "public": false,
      "user_metadata": null,
      "expires_at": null
    }
  ],
  "count": 1
}
```

</ResponseExample>

Un trabajo desconocido o inaccesible devuelve `404`.
