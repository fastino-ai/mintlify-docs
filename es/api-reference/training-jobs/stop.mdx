`POST /v1/training/jobs/{job_id}/stop`

Detiene un trabajo en ejecución y conserva los checkpoints creados antes de detenerlo. En un trabajo interactivo, la solicitud responde de inmediato y rechaza llamadas nuevas. Las operaciones ya encoladas pueden terminar antes de liberar los recursos. El uso puede continuar hasta esa liberación.

## Solicitud

<ParamField header="X-API-Key" type="string" required>
  Tu clave de API de Fastino.
</ParamField>

<ParamField path="job_id" type="string" required>
  UUID del trabajo config o ID del trabajo interactivo.
</ParamField>

### Trabajo config

El cuerpo JSON es opcional para un trabajo config.

<ParamField body="reason" type="string">
  Por qué se detuvo el trabajo.
</ParamField>

<ParamField body="scores" type="object">
  Métricas numéricas usadas para tomar la decisión de detención.
</ParamField>

<ParamField body="checkpoint" type="string">
  Ruta o paso del checkpoint asociado con la detención.
</ParamField>

### Trabajo interactivo

No envíes un cuerpo de solicitud. La respuesta incluye los campos comunes
verificados `success`, `job_id` y `status`.

### Ejemplo de solicitud para un trabajo config

<RequestExample>

```bash cURL
curl -X POST https://api.fastino.ai/v1/training/jobs/YOUR_TRAINING_JOB_ID/stop \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"reason": "Validation loss stopped improving"}'
```

</RequestExample>

### Ejemplo de solicitud para un trabajo interactivo


<RequestExample>

```bash cURL
curl -X POST https://api.fastino.ai/v1/training/jobs/YOUR_INTERACTIVE_JOB_ID/stop \
  -H "X-API-Key: $FASTINO_API_KEY"
```

</RequestExample>

## Respuesta de un trabajo config

<ResponseExample>

```json Response
{
  "success": true,
  "message": "Training job stopped",
  "job_id": "YOUR_TRAINING_JOB_ID",
  "status": "stopped"
}
```

```json 202 — cancelación pendiente
{
  "success": true,
  "message": "Training job cancellation is still being confirmed.",
  "job_id": "YOUR_TRAINING_JOB_ID",
  "status": "stopping"
}
```

</ResponseExample>

El campo `message`, la respuesta `202` y la regla de consulta se aplican solo a
los trabajos config. Después de un `202` de un trabajo config, consulta
`GET /v1/training/jobs/{job_id}`. No repitas la solicitud de detención mientras
la cancelación esté pendiente.

## Respuesta de un trabajo interactivo

Un trabajo interactivo usa la misma operación sin cuerpo. La respuesta incluye
los campos comunes `success`, `job_id` y `status`. No exijas el campo `message`,
que es exclusivo de los trabajos config.

```json Response
{
  "success": true,
  "job_id": "YOUR_INTERACTIVE_JOB_ID",
  "status": "stopped"
}
```

## Estados de trabajos config

Los siguientes estados y detalles de error solo se aplican a trabajos config.

| Estado | Significado |
| --- | --- |
| `200` | El trabajo está detenido y los checkpoints existentes siguen disponibles. |
| `202` | La cancelación del proveedor todavía se está confirmando. |
| `400` | El ID del trabajo config o la solicitud no son válidos. |
| `409 training_job_already_finished` | El trabajo alcanzó un estado terminal antes de la detención. |
| `422` | El cuerpo JSON de la solicitud del trabajo config no es válido. |
