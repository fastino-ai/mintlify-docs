La API de RL de Fastino ejecuta cargas de trabajo de aprendizaje por refuerzo y
postentrenamiento personalizado como **trabajos de entrenamiento interactivos**.
Los trabajos interactivos usan el mismo recurso de trabajo de entrenamiento y
los mismos IDs que las demás cargas de entrenamiento de Fastino:
`/v1/training/jobs`.

Tu aplicación controla el bucle: prompts, datasets, recompensas, ventajas,
evaluación y criterios de parada. Fastino controla las operaciones del modelo
solicitadas por ese bucle, incluidos el muestreo, las pasadas hacia delante y
hacia atrás, los pasos del optimizador y los checkpoints.

<Note>
  La API de RL tiene acceso limitado. Confirma que Fastino haya habilitado el
  entrenamiento interactivo para tu equipo antes de planificar una carga de
  trabajo de producción.
</Note>

## Un trabajo, dos vistas

Un cliente de entrenamiento creado mediante el SDK compatible representa un
trabajo interactivo de Fastino. El valor devuelto por
`training_client.get_info().model_data.model_id` es el ID canónico del trabajo
de entrenamiento. Usa ese mismo ID con `GET /v1/training/jobs/{job_id}` y otras
rutas documentadas de administración de trabajos o checkpoints.

No hay una ejecución de Tinker independiente detrás del trabajo ni enrutamiento
saliente hacia otro servicio de entrenamiento. El paquete de Python `tinker` es
una capa de compatibilidad del cliente para aplicaciones que ya usan sus formas
de objetos y métodos.

## Cliente compatible

Fastino prueba `tinker==0.33.1`. Configúralo con:

- URL base: `https://api.fastino.ai/v1/training/compat/tinker`
- Origen de credenciales: `TINKER_CREDENTIAL_CMD`
- Credencial: una clave de API normal de Fastino que comience por `fast_sk_`

El SDK añade `/api/v1/{operation}` a la URL base configurada. Las rutas del
adaptador se omiten intencionadamente del OpenAPI y de la referencia de la API
de Fastino. No construyas solicitudes HTTP al adaptador; usa el SDK para las
operaciones interactivas y las rutas canónicas de Fastino para administrar
trabajos y checkpoints.

## Cómo funciona el bucle

1. Crea un cliente de entrenamiento interactivo.
2. Captura sus pesos para el muestreo.
3. Genera y puntúa respuestas candidatas en tu aplicación.
4. Convierte las recompensas en datos de entrenamiento.
5. Pide al SDK que ejecute operaciones hacia delante/hacia atrás y del optimizador en el mismo trabajo.
6. Guarda checkpoints de estado o de muestreador y continúa.

Consulta `ServiceClient.get_server_capabilities()` antes de elegir un modelo o
depender de una función opcional del SDK. La respuesta de capacidades es la
fuente de verdad del entorno que puede usar tu equipo.
