Un **modelo de decisión** evalúa texto o el estado estructurado de una aplicación frente a resultados definidos por quien llama y devuelve decisiones estructuradas (etiquetas, distribuciones de probabilidad, puntuaciones y confianza) en lugar de prosa generada. Usa modelos de decisión para clasificación, enrutamiento de agentes y modelos, puntuación, moderación, barreras de protección y compuertas de sí o no en las que el código de la aplicación debe actuar sobre una respuesta acotada.

El [modelo de decisión GLiDE](/es/concepts/glide) de Fastino acepta un `state` compartido y una o más `questions` tipadas a través de la API de System One. Quien llama define los resultados permitidos, y GLiDE devuelve probabilidades calibradas que el código puede comparar con un umbral, enrutar o escalar para revisión.

## Modelos de decisión frente a LLM generativos

|  | Modelo de decisión | LLM generativo |
| --- | --- | --- |
| Ideal para | Clasificación, enrutamiento, puntuación, moderación y compuertas | Generación abierta, conversación, resumen y programación |
| Salida | Respuestas tipadas sobre resultados definidos por quien llama | Texto generado o llamadas a herramientas |
| Incertidumbre | Probabilidades y confianza explícitas | Normalmente requiere calibración o validación adicional |
| Patrón de aplicación | Actuar, enrutar o escalar a partir de un resultado acotado | Generar, explicar, planificar o transformar contenido |

Los dos tipos de modelo pueden trabajar juntos: usa un modelo de decisión para clasificar una solicitud, seleccionar un agente o modelo, o controlar una acción, y luego llama a un LLM generativo solo cuando el flujo de trabajo necesite una salida abierta.

## Primitivas de los modelos de decisión

Cada pregunta que le haces a [GLiDE](/es/concepts/glide) usa uno de tres tipos y se envía a `POST /v1/systemone` sobre un `state` compartido:

- **[Noul](/es/concepts/glide-noul)**: una pregunta de sí o no que devuelve una probabilidad entre 0 y 1. Piensa en ella como un booleano en una escala continua. "¿Esta solicitud cumple los requisitos para un reembolso?" podría devolver `0.999`, es decir, un 99,9 % de probabilidad de que la respuesta sea sí.
- **[Choice](/es/concepts/glide-choice)**: una pregunta de elegir una entre varias opciones que devuelve una distribución de probabilidad sobre hasta 255 opciones con nombre. "¿Qué equipo debería encargarse de esto?" podría devolver `{"billing": 0.0006, "returns": 0.999, "shipping": 0.0005}`.
- **[Score](/es/concepts/glide-score)**: una pregunta de calificar en una escala según una rúbrica ordenada que tú defines. "¿Qué tan urgente es esta solicitud?" con tres niveles podría devolver `score: 0` (baja) y `expected_level: 0.276`, un resultado ponderado por probabilidad entre baja y media, más cercano a baja.

Elige el tipo que coincida con la forma de la respuesta que necesita tu código.

<Tip>
  Noul frente a Score: un Noul en `0.5` significa la máxima incertidumbre entre sí y no; no expresa grado. Si necesitas medir un grado (urgencia, gravedad, frustración), usa un Score con niveles definidos. Si necesitas una compuerta binaria, usa un Noul.
</Tip>

No existe una primitiva multietiqueta: cada pregunta es de una sola etiqueta. Si necesitas varios juicios simultáneos, haz varias preguntas independientes en una misma llamada; consulta [Combinar varias preguntas](#combinar-varias-preguntas).

## Límites

- Cada prompt de pregunta renderizado (`state` más esa pregunta) debe caber en **40,000
  tokens**.
- Choice y Score aceptan hasta **255 opciones o niveles**.
- Una solicitud evalúa un único `state` compartido. Pon varias preguntas con nombre bajo `questions`;
  `/v1/systemone` no acepta un lote de estados independientes.
- `usage.input_tokens` suma las pasadas internas de todas las preguntas, por lo que puede superar 40,000
  aunque cada prompt renderizado individual quepa.

## Parámetros de la solicitud

<ParamField body="state" type="string | object | array" required>
  El contexto que se va a evaluar: una cadena de texto simple, un objeto JSON o un array JSON. Consulta [Formas de state](#formas-de-state) más abajo para saber cuál usar.
</ParamField>

<ParamField body="questions" type="object" required>
  Una o más preguntas tipadas y con nombre que se evalúan frente a `state`. Cada clave es el nombre que elijas para la pregunta; cada valor es un objeto de pregunta con `type`, `instructions` y (para `choice`/`score`) `criteria`. Consulta [Noul](/es/concepts/glide-noul), [Choice](/es/concepts/glide-choice) y [Score](/es/concepts/glide-score) para ver la forma completa de la solicitud y la respuesta de cada tipo.
</ParamField>

<ParamField body="model" type="string" required>
  El modelo de decisión que se va a usar, por ejemplo `fastino/GLiDE`. Si lo omites, se devuelve `422 'model' must be provided`. La respuesta lo devuelve sin el prefijo del proveedor (`fastino/GLiDE` → `glide`).
</ParamField>


### Formas de state

`state` es el material frente al que se evalúa cada pregunta. Piensa en ello como lo que le entregarías a un panel de expertos antes de pedirles que emitan un juicio.

| Forma | Útil para | Ejemplo |
| --- | --- | --- |
| String | Un solo mensaje, artículo o pasaje | `"My card was charged twice."` |
| Object | Campos con nombre, registros relacionados o estado de la aplicación | `{"message": "My card was charged twice.", "order_id": "A-104"}` |
| Array | Una secuencia de mensajes o registros | `["Hi", "My order number is A-104.", "My card was charged twice."]` |

Usa un objeto cuando la decisión dependa de comparar varias partes con nombre (por ejemplo, un ticket y la política con la que se evalúa): así cada parte queda etiquetada y sus relaciones quedan claras. Una cadena simple basta cuando el caso es un único pasaje autocontenido. Todas las preguntas de una solicitud ven el mismo `state` y se evalúan de forma independiente frente a él.

## Confianza

Cada respuesta incluye un valor `confidence`. La respuesta te dice *qué* concluyó GLiDE; la confianza te dice *si debes actuar en consecuencia*. Trátalos como dos ejes separados, no como uno solo.

| Tipo de pregunta | Fórmula | Rango |
| --- | --- | --- |
| Noul | `\|2 × noul − 1\|` | De `0` (máxima incertidumbre, `noul = 0.5`) a `1` (certeza total, `noul = 0` o `1`) |
| Choice / Score | `top1 − top2` (margen de probabilidad entre la mejor y la segunda mejor opción o nivel) | De `0` (dos opciones empatadas) a `1` (una opción concentra ~toda la masa de probabilidad) |

Una respuesta con baja confianza no es incorrecta: significa que la masa de probabilidad está repartida entre dos o más resultados en lugar de concentrarse en uno, lo cual ya es una señal útil. Un patrón habitual es el **enrutamiento condicionado por la confianza**: actúa automáticamente sobre las respuestas con alta confianza y deriva las de baja confianza a una alternativa (revisión humana, una categoría más amplia, una comprobación secundaria):

```python
answer = response["answers"]["department"]

if answer["confidence"] >= 0.6:
    route_to(answer["choice"])
else:
    route_to("triage-queue")  # ambiguous - let a human or a broader handler decide
```

Ajusta el umbral con datos reales de tu caso de uso en lugar de dar por hecho que `0.5` es el valor correcto: la confianza está calibrada por modelo y no se garantiza que se corresponda con ninguna tolerancia concreta a la ambigüedad de tu negocio.

Cada página de primitiva incluye un ejemplo práctico y más información sobre cómo usar su resultado: [Noul](/es/concepts/glide-noul), [Choice](/es/concepts/glide-choice), [Score](/es/concepts/glide-score).

## Combinar varias preguntas

Haz varias preguntas de distintos tipos sobre el mismo `state` en una sola llamada. Todas las preguntas se evalúan juntas en un único viaje de ida y vuelta.

<CodeGroup>

```bash cURL
curl -s https://api.fastino.ai/v1/systemone \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "fastino/GLiDE",
    "state": "Refund request: the receipt is attached, the purchase was 10 days ago, and refunds are allowed within 30 days.",
    "questions": {
      "department": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "billing": "Payment or charge disputes",
          "returns": "Refund or return requests",
          "shipping": "Delivery or shipping issues"
        }
      },
      "urgency": {
        "type": "score",
        "instructions": "How urgent is this request?",
        "criteria": [
          "low urgency, can wait",
          "medium urgency, handle soon",
          "high urgency, handle immediately"
        ]
      }
    }
  }'
```

</CodeGroup>
