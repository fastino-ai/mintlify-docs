Evalúa GLiNER 2.5 Decide con ejemplos etiquetados de tu aplicación antes de usar sus clasificaciones para activar acciones en producción.

## Comprende el comportamiento del umbral

`cls_threshold` solo se aplica a tareas con `multi_label: true`:

```json
{
  "task": "topics",
  "labels": ["billing", "technical", "account", "security"],
  "multi_label": true,
  "cls_threshold": 0.5
}
```

- Aumenta el umbral para devolver menos etiquetas y favorecer en general la precisión.
- Reduce el umbral para devolver más etiquetas y favorecer en general la exhaustividad.
- Las tareas de una sola etiqueta siempre devuelven la etiqueta con mayor puntuación; `cls_threshold` no cambia su selección.
- `cls_threshold` es una opción de inferencia. No afecta al entrenamiento.

## Crea un conjunto de evaluación

Usa ejemplos que representen el tráfico de producción, incluidos:

- Entradas frecuentes para cada etiqueta
- Etiquetas poco frecuentes pero importantes
- Entradas ambiguas cerca de los límites entre categorías
- Entradas que deban recibir varias etiquetas
- Entradas que no deban producir ningún resultado multietiqueta con el umbral seleccionado
- Entradas fuera del dominio o mal formadas que pueda encontrar tu aplicación

Mantén los datos de evaluación separados de los datos de ajuste fino.

## Mide el comportamiento que necesita tu aplicación

Para tareas de una sola etiqueta, revisa la exactitud general y los errores por etiqueta. Una matriz de confusión ayuda a detectar las etiquetas que el modelo intercambia con frecuencia.

Para tareas multietiqueta, mide precisión, exhaustividad y F1 tanto en general como por etiqueta. Revisa también:

- Falsos positivos que activan acciones incorrectas
- Falsos negativos que omiten acciones necesarias
- Número de etiquetas seleccionadas por entrada
- Frecuencia de selecciones vacías
- Resultados próximos al umbral

## Selecciona un umbral

1. Ejecuta el conjunto de evaluación y conserva cada etiqueta seleccionada y su confianza.
2. Prueba varios umbrales candidatos.
3. Compara precisión, exhaustividad e impacto empresarial.
4. Elige un umbral por tarea cuando las tareas tengan costes de error diferentes.
5. Repite la evaluación después de cambiar las etiquetas, los datos o el modelo.

No asumas que `0.5` es adecuado en todos los casos. Para acciones de alto impacto, usa umbrales de automatización conservadores y conserva una ruta de revisión o alternativa.

## Ajusta el modelo para tu dominio

Empieza con etiquetas definidas en tiempo de ejecución y evalúa primero el modelo base. Realiza un ajuste fino cuando una evaluación representativa demuestre que los cambios de esquema y el ajuste de umbrales no alcanzan la calidad que requiere tu dominio.

### 1. Confirma el objetivo de entrenamiento

Consulta el [catálogo de modelos base](/es/api-reference/training/base-models) y confirma que el modelo de clasificación seleccionado admite el tipo de entrenamiento que quieres usar.

### 2. Prepara los datos de clasificación

Guarda un objeto JSON por línea. Usa `label` para ejemplos de una sola etiqueta:

```jsonl
{"text":"The setup was straightforward.","label":"positive"}
{"text":"The application crashes during sign in.","label":"negative"}
```

Usa `labels` para ejemplos multietiqueta:

```jsonl
{"text":"The app crashes on login and I need help urgently.","labels":["technical_issue","login_problem","urgent"]}
```

Usa nombres de etiquetas estables que coincidan con la taxonomía del esquema de inferencia. Incluye ejemplos representativos para cada etiqueta y conserva una partición de evaluación separada.

### 3. Inicia y supervisa el entrenamiento

Crea un trabajo de entrenamiento con el dataset preparado y un modelo base de clasificación entrenable. Elige únicamente parámetros de entrenamiento admitidos por la receta del modelo.

<Card title="Trabajos de entrenamiento" icon="activity" href="/es/training">
  Envía un trabajo, supervisa su estado, consulta métricas y checkpoints, y recupera el artefacto resultante.
</Card>

### 4. Evalúa el resultado entrenado

Compara el modelo entrenado con el modelo base usando el mismo conjunto reservado:

- Exactitud general y por etiqueta para tareas de una sola etiqueta
- Precisión, exhaustividad y F1 para tareas multietiqueta
- Errores en etiquetas poco frecuentes y de alto impacto
- Comportamiento cerca de los umbrales de producción
- Latencia y requisitos operativos

No selecciones un checkpoint basándote únicamente en la pérdida de entrenamiento. Evalúa el comportamiento de clasificación que usará tu aplicación.

### 5. Usa el modelo entrenado

Cuando el checkpoint seleccionado pueda desplegarse, usa su identificador de modelo con el endpoint de inferencia admitido y conserva el mismo esquema de clasificación que espera tu aplicación. Vuelve a validar los umbrales, porque el comportamiento de la confianza puede cambiar después del ajuste fino.
