Los trabajos de entrenamiento hacen referencia a datasets listos por su nombre. Prepara un archivo JSONL, súbelo mediante la
API de datasets en dos pasos y confirma que la versión procesada existe antes de llamar a
`POST /v1/training/jobs`.

## Elegir un formato de dataset

Cada línea del archivo debe ser un objeto JSON. Usa una misma estructura en todo el
dataset.

### Reconocimiento de entidades nombradas

Usa `text` junto con una lista `entities` de pares `[span, label]`. Cada span debe aparecer literalmente
en el texto. Incluye ejemplos negativos con una lista vacía.

```jsonl
{"text":"Ada Lovelace worked in London.","entities":[["Ada Lovelace","PERSON"],["London","LOCATION"]]}
{"text":"No tagged entities here.","entities":[]}
```

### Clasificación

Usa `label` para datos de una sola etiqueta o `labels` para datos multietiqueta.

```jsonl
{"text":"The setup was straightforward.","label":"positive"}
{"text":"The request needs billing and technical help.","labels":["billing","technical"]}
```

### Decodificador

Establece `dataset_type` en `decoder` y da a cada fila un array `messages` con
roles y contenido de chat.

```jsonl
{"messages":[{"role":"user","content":"What is 2+2?"},{"role":"assistant","content":"4"}]}
```

<Note>
  Los trabajos de configuración no aceptan modelos base decodificadores, así que
  un dataset de decodificador no puede iniciar un
  [trabajo de configuración](/es/api-reference/training-jobs/create). Para
  entrenar un decodificador, tokeniza tus ejemplos y procésalos en un
  [trabajo interactivo](/es/training/quickstart#custom-training-loop).
</Note>

## Subir un dataset

### 1. Reservar una URL de subida

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/upload/url \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "dataset_name": "docs-example-ner",
    "filename": "training.jsonl",
    "dataset_type": "ner"
  }' | tee dataset-upload.json

export PRESIGNED_URL="$(jq -r '.presigned_url' dataset-upload.json)"
export DATASET_ID="$(jq -r '.dataset_id' dataset-upload.json)"
export DATASET_VERSION="$(jq -r '.version_number' dataset-upload.json)"
```

La respuesta contiene una `presigned_url` de corta duración, un `dataset_id` y un
`version_number`. Los comandos anteriores conservan los tres valores. Sube los
bytes exactos del archivo a la URL prefirmada:

```bash
curl --fail-with-body -X PUT --upload-file training.jsonl "$PRESIGNED_URL"
```

### 2. Procesar el archivo subido

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/upload/process \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d "$(jq -n --arg dataset_id "$DATASET_ID" '{dataset_id: $dataset_id}')"
```

El procesamiento devuelve `202`. Consulta el dataset por su nombre y selecciona
la entrada cuyo `version_number` coincida exactamente con la respuesta de la
subida. Continúa hasta que el `status` de esa versión sea `ready` o `failed`.
Si es `failed`, detente y muestra su `processing_error`; no uses esa versión
para entrenar.

```bash
curl --fail-with-body -sS https://api.fastino.ai/v1/datasets/docs-example-ner \
  -H "X-API-Key: $FASTINO_API_KEY"
```

## Iniciar el entrenamiento

Pasa el nombre exacto del dataset al [endpoint de creación de trabajos
de entrenamiento](/es/api-reference/training-jobs/create):

```json
{
  "model_name": "my-ner-model",
  "base_model": "fastino/gliner2-multi-v1",
  "datasets": [
    {"name": "docs-example-ner", "version": "VERSION_NUMBER_FROM_UPLOAD"}
  ],
  "training_type": "lora"
}
```

Usa `GET /v1/base-models?supports_training=true` justo antes del envío para seleccionar un
modelo base que se pueda entrenar actualmente.

## Bloqueos comunes

| Estado | Causa | Acción |
| --- | --- | --- |
| `401` | API key ausente o no válida | Envía `X-API-Key: $FASTINO_API_KEY` |
| `404` | El nombre del dataset no existe | Confirma el nombre exacto y espera a que termine el procesamiento |
| `failed` | Falló la validación asíncrona del contenido | Lee `processing_error`, corrige el JSONL y sube una versión nueva |
| `422` | La estructura de la solicitud se rechazó antes del procesamiento | Corrige los campos de la solicitud antes de reintentar |

No subas la estructura interna `{"input": ..., "output": ...}` del entrenador de GLiNER. Conviértela
primero al formato público de `text` más `entities`.
