title: "Compatibilidad del SDK"
description: "Versiones del SDK de Tinker, modelos, operaciones de entrenamiento, operaciones de muestreo y funciones de pérdida compatibles."
---

Usa esta referencia para comprobar si una aplicación de Tinker existente puede
ejecutarse en Fastino sin cambios en el algoritmo.

## Contrato del cliente

| Elemento | Valor |
| --- | --- |
| Paquete de Python | `tinker` |
| Versión probada | `0.32.0` |
| Versión mínima compatible | `0.25.0` |
| URL base | `https://api.fastino.ai/tinker` |
| Credencial | `tml-` seguido de una clave de Fastino `fast_sk_...` |
| Acceso del equipo | Acceso limitado para el equipo de Fastino autenticado |

Fija `tinker==0.32.0` cuando desarrolles con esta versión preliminar.

## Modelos

| Modelo base | Ventana de contexto | Rango máximo de LoRA |
| --- | ---: | ---: |
| `Qwen/Qwen3.6-35B-A3B` | 32,768 | 32 |
| `nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-BF16` | 32,768 | 32 |
| `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16` | 65,536 | 32 |

Llama a `get_server_capabilities()` antes de elegir un modelo. La respuesta de
capacidades es la fuente de verdad para la disponibilidad y las ventanas de
contexto actuales.

## Operaciones de entrenamiento

| Capacidad | Compatibilidad |
| --- | --- |
| Crear un cliente de entrenamiento LoRA | Compatible |
| `forward` | Compatible |
| `forward_backward` | Compatible |
| `optim_step` | Compatible |
| Guardar o cargar el estado de entrenamiento | Compatible |
| Crear un cliente nuevo desde un estado guardado | Compatible |
| Guardar pesos del muestreador | Compatible |
| Crear un cliente de muestreo desde los pesos de entrenamiento | Compatible |
| Descargar o liberar una ejecución | Compatible |
| Configuraciones de entrenamiento distintas de LoRA | No compatibles |

La familia de optimizadores compatible es AdamW mediante `AdamParams` del SDK.

### Funciones de pérdida

- `cross_entropy`
- `importance_sampling`
- `ppo`
- `cispo`
- `dro`

Usa `importance_sampling` para el bucle on-policy de [Entrenar con recompensas
verificables](/es/rl-api/verifiable-rewards).

## Operaciones de muestreo

| Capacidad | Compatibilidad |
| --- | --- |
| Muestrear desde un modelo base | Compatible |
| Muestrear desde pesos del muestreador con nombre | Compatible |
| Muestrear desde los pesos de entrenamiento actuales | Compatible |
| Solicitar varias muestras | Compatible |
| Calcular probabilidades logarítmicas de tokens | Compatible |
| Cancelar un future de muestreo en cola | Compatible |
| Fragmentos de prompts de imagen o multimodales | No compatibles |
| `target_prompt_logprobs` | No compatible |
| `prompt_alt_tokens_k` | No compatible |

Los modelos actuales aceptan fragmentos codificados de tokens de texto. El
muestreo requiere un `SamplingClient`.

## Otras diferencias

| Capacidad | Comportamiento |
| --- | --- |
| Exportación de trazas de sesión | No compatible |
| Endpoint de auditoría del SDK | No devuelve entradas |
| Carga de puntos de control entre equipos | No compatible |
| Descubrimiento mediante OpenAPI | Las rutas de RL se omiten intencionadamente |

Usa los registros de tu aplicación y los registros de uso de proyectos de
Fastino para la atribución operativa.

Para consultar los futures, los puntos de control, los reintentos, la
facturación, los límites y los errores, consulta [Comportamiento en tiempo de
ejecución y errores](/es/rl-api/runtime).
