---
title: "Compatibilidad del SDK"
description: "Compatibilidad y asignaciones exactas del SDK de Tinker para los trabajos de entrenamiento interactivos de Fastino."
---

Fastino prueba el contrato de compatibilidad con `tinker==0.33.1`. El paquete
define las firmas del SDK; esta página define qué métodos admite Fastino y cómo
se asignan al dominio de entrenamiento de Fastino.

| Elemento | Valor compatible |
| --- | --- |
| Paquete | `tinker==0.33.1` |
| URL base | `https://api.fastino.ai/v1/training/compat/tinker` |
| Autenticación | Una clave `fast_sk_` impresa por `TINKER_CREDENTIAL_CMD` |
| Identidad del recurso | Un cliente de entrenamiento es un trabajo interactivo de Fastino con el mismo ID |

El SDK añade `/api/v1/<operation>` a la URL base. Las rutas del adaptador se
ocultan del OpenAPI y de la referencia de la API. Los usuarios no deben
construir solicitudes al adaptador.

## Entrenamiento y muestreo

| Método u operación del SDK | Asignación de Fastino | Compatibilidad |
| --- | --- | --- |
| `create_lora_training_client` | `POST /v1/training/jobs` con tipo de trabajo interactivo | Compatible |
| `copy_weights` | Crear un trabajo interactivo desde el checkpoint | Compatible |
| `TrainingClient.get_info` | `GET` del trabajo canónico de Fastino | Compatible |
| `forward` | `/forward` en el trabajo interactivo | Compatible |
| `forward_backward` | `/forward-backward` en el trabajo interactivo | Compatible |
| Operación personalizada hacia delante/hacia atrás | `/forward-backward` en el trabajo interactivo | Compatible |
| `optim_step` | `/optim-step` en el trabajo interactivo | Compatible |
| `save_state` | `POST` de un checkpoint de tipo `state` | Compatible |
| `save_weights_for_sampler` | `POST` de un checkpoint de tipo `sampler` | Compatible |
| Cargar el estado de entrenamiento | Carga del checkpoint en el trabajo interactivo | Compatible |
| Crear u obtener un cliente de muestreo | Resolver el checkpoint seleccionado | Compatible |
| `SamplingClient.sample` | Muestreo del checkpoint | Compatible |

Conserva sin cambios el parámetro `base_model` del método del SDK. Consulta
`ServiceClient.get_server_capabilities()` antes de seleccionar un modelo base o
depender de una operación opcional. Las capacidades son la fuente de verdad;
esta referencia no establece un catálogo fijo de modelos, pérdidas, rangos,
ventanas de contexto ni límites por llamada.

## Futures

| Método u operación del SDK | Asignación de Fastino | Compatibilidad |
| --- | --- | --- |
| Resultado/obtención de future | Obtener operaciones | Compatible |
| Cancelación de future | Cancelar operaciones | Compatible |
| Recuperación por lotes con `retrieve_futures` | Ninguna | No compatible |

## Administración

| Método u operación del SDK | Asignación de Fastino | Compatibilidad |
| --- | --- | --- |
| Listar ejecuciones de entrenamiento con `RestClient` | Listar trabajos canónicos de Fastino | Compatible |
| Obtener una ejecución de entrenamiento con `RestClient` | Obtener un trabajo canónico de Fastino | Compatible |
| Listar u obtener checkpoints | Rutas canónicas de trabajos/checkpoints | Compatible |
| Descargar o eliminar un checkpoint | Rutas canónicas de trabajos/checkpoints | Compatible |
| Publicar o retirar la publicación de un checkpoint | Rutas canónicas de trabajos/checkpoints | Compatible |
| Establecer o borrar el TTL de un checkpoint | Rutas canónicas de trabajos/checkpoints | Compatible |
| Obtener el uso de almacenamiento de checkpoints | Rutas canónicas de trabajos/checkpoints | Compatible |

## Infraestructura exclusiva del adaptador

El SDK puede usar la infraestructura del adaptador para capacidades, sesiones,
heartbeat, telemetría, autenticación e integración de auditoría. Son detalles
de implementación y no tienen una ruta pública de Fastino. No los trates como
API HTTP orientadas al cliente.

## Explícitamente no compatible

- Recuperación de futures por lotes mediante `retrieve_futures`
- `save_weights_external`
- `external_weights_urls`
- Operaciones de autenticación o tokens del SDK
- Operaciones de facturación, uso o eventos del SDK

La autenticación solo se proporciona mediante una clave normal de Fastino
`fast_sk_` a través de `TINKER_CREDENTIAL_CMD`. Las credenciales que comienzan
por `tml-` se rechazan y los ejemplos activos no deben establecer
`TINKER_API_KEY`.

Para obtener orientación sobre el ciclo de vida y la recuperación, consulta
[Comportamiento en tiempo de ejecución y errores](/es/rl-api/runtime).
