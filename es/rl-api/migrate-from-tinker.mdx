---
title: "Migrar desde Tinker"
description: "Migra una carga de trabajo existente del SDK de Tinker a la API de RL de Fastino."
---

La API de RL de Fastino implementa un subconjunto documentado del contrato del
SDK de Tinker. Las formas de las llamadas del SDK pueden permanecer sin cambios
cuando se cumplen todos los puntos de la lista de comprobación de
compatibilidad. Una migración sustituye cuatro puntos de integración:

1. Endpoint
2. Credencial
3. Nombre del modelo
4. Supuestos operativos

Esta guía trata el programa existente como prueba de aceptación. Cambia primero
la conexión, ejecuta un trabajo corto y solo entonces ajusta el algoritmo.

## 1. Fija una versión probada del SDK

Fastino prueba actualmente el contrato con:

```text
tinker==0.32.0
```

El cliente mínimo compatible es `0.25.0`. Fija `0.32.0` durante la migración
para evitar que una actualización no relacionada del SDK oculte un problema de
conexión o compatibilidad.

<CodeGroup>

```bash uv
uv add "tinker==0.32.0"
```

```bash pip
pip install "tinker==0.32.0"
```

</CodeGroup>

## 2. Sustituye el endpoint y la clave

El código existente que construye `tinker.ServiceClient()` sin argumentos
explícitos puede migrarse únicamente mediante variables de entorno:

```bash
export FASTINO_API_KEY="fast_sk_..."
export TINKER_API_KEY="tml-${FASTINO_API_KEY}"
export TINKER_BASE_URL="https://api.fastino.ai/tinker"
```

La parte `tml-` es un prefijo de compatibilidad que consume el SDK de Tinker.
Fastino autentica la clave `fast_sk_...` que contiene.

Si tu aplicación pasa los valores explícitamente, realiza el cambio
equivalente:

```python
import os

import tinker


service_client = tinker.ServiceClient(
    base_url="https://api.fastino.ai/tinker",
    api_key=f"tml-{os.environ['FASTINO_API_KEY']}",
)
```

No añadas `/api/v1`. El SDK añade su propia ruta.

## 3. Selecciona un modelo compatible con Fastino

No des por hecho que un modelo disponible en otro entorno de Tinker lo estará
en Fastino. Consulta las capacidades durante la migración:

```python
capabilities = service_client.get_server_capabilities()
for model in capabilities.supported_models:
    print(model.model_name)
```

Usa la respuesta de capacidades activa para tomar decisiones de producción.
Compara el resultado con [Compatibilidad del cliente](/es/rl-api/compatibility)
cuando necesites consultar las ventanas de contexto o los límites de LoRA.

## 4. Compara el bucle de aprendizaje

Estas llamadas principales mantienen sus formas del SDK de Tinker:

```python
training_client = service_client.create_lora_training_client(
    base_model=model_name,
    rank=32,
)

sampler_path = training_client.save_weights_for_sampler(
    "migration-smoke"
).result().path
sampling_client = service_client.create_sampling_client(
    model_path=sampler_path
)
sample_future = sampling_client.sample(prompt, num_samples, sampling_params)
sample_result = sample_future.result()

train_future = training_client.forward_backward(
    datums,
    loss_fn="importance_sampling",
)
optim_future = training_client.optim_step(adam_params)
train_result = train_future.result()
optim_result = optim_future.result()
```

Las formas de las llamadas anteriores son compatibles. Antes de reutilizar el
bucle que las rodea, confirma que su modelo, rango de LoRA, nombre de función de
pérdida, campos de datum, parámetros de muestreo, comportamiento de puntos de
control y dependencias operativas figuren como compatibles en la [referencia de
compatibilidad](/es/rl-api/compatibility).

El renderizador, la construcción de prompts, las funciones de recompensa, los
cálculos de ventajas, el procesamiento por lotes y los criterios de parada se
ejecutan en tu aplicación. Consérvalos para la primera prueba de migración solo
después de superar esa lista de comprobación.

## 5. Verifica una ejecución pequeña

Usa una ejecución de aceptación de bajo coste antes de restaurar los tamaños de
lote de producción:

- Obtén las capacidades.
- Crea un cliente de entrenamiento LoRA.
- Muestrea un grupo pequeño.
- Envía una operación hacia delante-atrás.
- Aplica un paso del optimizador.
- Guarda un punto de control de estado.
- Crea un cliente de entrenamiento nuevo a partir de ese punto de control.
- Cierra el cliente de servicio.

Compara los resultados semánticos, no valores de coma flotante exactos. Los
distintos modelos e infraestructuras compatibles pueden producir muestras y
métricas diferentes.

## 6. Revisa las diferencias operativas

| Área | Acción de migración |
| --- | --- |
| Acceso | El acceso a la API de RL se habilita por equipo de Fastino. Un equipo sin acceso recibe `404 Not Found`. |
| Autenticación | Usa una clave de API de Fastino encapsulada con el prefijo de compatibilidad `tml-`. |
| Modelos | Elige entre los modelos de la respuesta de capacidades. No conserves un modelo de origen no compatible. |
| Ciclo de vida de la sesión | Cierra `ServiceClient` para liberar las ejecuciones activas. |
| Recuperación | Mantén puntos de control explícitos como límite de recuperación controlado por tu aplicación. |
| Resultados de futures | Resuelve y conserva los resultados completados en el plazo de una hora. |
| Cancelación | La cancelación se aplica al muestreo, no a las operaciones de entrenamiento individuales. |
| Puntos de control publicados | La publicación no permite que otro equipo de Fastino cargue un punto de control. |
| Exportación de trazas | Elimina el código que requiera la exportación de trazas de Tinker. No es compatible. |
| Entradas de auditoría | No dependas del historial de auditoría. Las llamadas de auditoría no devuelven entradas. |

Consulta [Compatibilidad del cliente](/es/rl-api/compatibility) para conocer las
funciones de pérdida y los métodos compatibles. Consulta [Comportamiento en
tiempo de ejecución y errores](/es/rl-api/runtime) para conocer los reintentos,
la facturación, los puntos de control y los errores.

## Lista de comprobación de la migración

- [ ] Fija `tinker==0.32.0`.
- [ ] Configura `TINKER_BASE_URL` como `https://api.fastino.ai/tinker`.
- [ ] Encapsula la clave de Fastino como `tml-fast_sk_...`.
- [ ] Confirma que el equipo tenga acceso a la API de RL.
- [ ] Sustituye los nombres de modelo no compatibles.
- [ ] Ejecuta un paso de muestreo y entrenamiento.
- [ ] Guarda y restaura un punto de control de estado.
- [ ] Elimina las dependencias de datos de trazas o auditoría no compatibles.
- [ ] Cierra el cliente de servicio.
- [ ] Aumenta el tamaño de la carga de trabajo solo después de superar la ejecución de aceptación.
