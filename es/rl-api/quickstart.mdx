Este tutorial conecta el SDK de Tinker con Fastino, verifica el acceso de tu
equipo y muestrea un modelo compatible. Así se comprueba la conexión antes de
crear un bucle de entrenamiento.

<Warning>
  La comprobación de capacidad es de solo lectura. La solicitud de muestreo es
  inferencia facturable. Esta guía rápida no entrena un modelo ni crea un punto
  de control.
</Warning>

## 1. Configura tu clave de API

1. **Crea una cuenta de [Fastino](https://agent.fastino.ai/)**
2. **Obtén tu clave de API** en [Configuración](https://agent.fastino.ai/api-keys)

Configura la clave como variable de entorno para poder ejecutar los ejemplos
sin modificarlos:

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="your_api_key_here"
```

```powershell Windows
$env:FASTINO_API_KEY = "your_api_key_here"
```

</CodeGroup>

Las claves de Fastino comienzan por `fast_sk_`. Tu equipo también debe tener
habilitado el acceso a la API de RL. Instalar el SDK de Tinker no concede
acceso.

## 2. Crea un entorno de Python

Necesitas Python 3.11 o posterior.

<CodeGroup>

```bash uv · macOS/Linux
uv init fastino-rl
cd fastino-rl
uv add "tinker==0.32.0"
source .venv/bin/activate
```

```powershell uv · Windows
uv init fastino-rl
cd fastino-rl
uv add "tinker==0.32.0"
.\.venv\Scripts\Activate.ps1
```

```bash pip · macOS/Linux
mkdir fastino-rl && cd fastino-rl
python -m venv .venv
source .venv/bin/activate
pip install "tinker==0.32.0"
```

```powershell pip · Windows
mkdir fastino-rl
cd fastino-rl
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install "tinker==0.32.0"
```

</CodeGroup>

## 3. Configura el cliente de Tinker

Conecta el SDK de Tinker con Fastino y deriva la variable de entorno que el SDK
espera:

<CodeGroup>

```bash macOS/Linux
export TINKER_API_KEY="tml-${FASTINO_API_KEY}"
export TINKER_BASE_URL="https://api.fastino.ai/tinker"
```

```powershell Windows
$env:TINKER_API_KEY = "tml-$env:FASTINO_API_KEY"
$env:TINKER_BASE_URL = "https://api.fastino.ai/tinker"
```

</CodeGroup>

No crees una segunda clave. `TINKER_API_KEY` es el nombre de la variable de
entorno del SDK de Tinker y `tml-` es el prefijo de compatibilidad que espera.
Tu clave de Fastino sigue siendo la credencial que autentica la solicitud. No la
incluyas en el control de versiones.

## 4. Verifica el acceso

Crea `check_rl_api.py`:

```python
import tinker


TUTORIAL_MODEL = "Qwen/Qwen3.6-35B-A3B"
client = tinker.ServiceClient()
try:
    capabilities = client.get_server_capabilities()
    model_names = {model.model_name for model in capabilities.supported_models}
    if TUTORIAL_MODEL not in model_names:
        available = ", ".join(sorted(model_names)) or "none"
        raise RuntimeError(
            f"{TUTORIAL_MODEL} is not available; available models: {available}. "
            "Stop before billable work and ask Fastino about tutorial-model access."
        )
    print(f"Ready to use {TUTORIAL_MODEL}")
except KeyboardInterrupt:
    client.close("interrupted").result()
    raise
except Exception:
    client.close("errored").result()
    raise
else:
    client.close("success").result()
```

Ejecútalo:

```bash
python check_rl_api.py
```

Una respuesta correcta confirma que el modelo utilizado a continuación está
disponible para tu equipo. Usa la respuesta de capacidades como fuente de
verdad al elegir un modelo.

Si la llamada devuelve `404 Not Found`, confirma que la URL base termina en
`/tinker`. Si es así, solicita a Fastino que habilite el acceso a la API de RL
para tu equipo.

## 5. Ejecuta tu primer muestreo

Crea `sample_rl_api.py`:

```python
import tinker


TUTORIAL_MODEL = "Qwen/Qwen3.6-35B-A3B"
service_client = tinker.ServiceClient()
try:
    sampling_client = service_client.create_sampling_client(
        base_model=TUTORIAL_MODEL
    )
    tokenizer = sampling_client.get_tokenizer()
    prompt_tokens = tokenizer.apply_chat_template(
        conversation=[
            {"role": "user", "content": "Explain what a reward function does in RL."}
        ],
        add_generation_prompt=True,
        return_dict=False,
    )
    result = sampling_client.sample(
        prompt=tinker.types.ModelInput.from_ints(prompt_tokens),
        num_samples=1,
        sampling_params=tinker.types.SamplingParams(
            max_tokens=128,
            temperature=0.7,
        ),
    ).result()
    print(tokenizer.decode(result.sequences[0].tokens))
except KeyboardInterrupt:
    service_client.close("interrupted").result()
    raise
except Exception:
    service_client.close("errored").result()
    raise
else:
    service_client.close("success").result()
```

Ejecútalo:

```bash
python sample_rl_api.py
```

Una ejecución correcta imprime una respuesta del modelo. Tu aplicación envió
un prompt de texto mediante el SDK, Fastino realizó la inferencia y el cliente
decodificó los tokens devueltos.

<Note>
  Aquí se usa `Qwen/Qwen3.6-35B-A3B` porque es compatible con el contrato actual
  de la API de RL. No copies el nombre de un modelo de otro entorno de Tinker
  sin comprobar primero la respuesta de capacidades.
</Note>

## 6. Cierra los clientes en tu propio código

El ejemplo cierra su `ServiceClient` en caso de éxito, interrupción o error. Usa
el mismo patrón en aplicaciones de larga duración.

Cerrar el cliente finaliza su sesión y libera las ejecuciones de entrenamiento
activas. Los puntos de control guardados siguen disponibles de acuerdo con su
configuración de retención.

Usa `success` solo después de una ejecución completada. Cierra con `errored`
cuando una excepción se propague y con `interrupted` después de una cancelación
o un cierre.
