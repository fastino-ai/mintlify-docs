title: "Checkpoints y recuperación"
description: "Guarda el estado del trabajo interactivo y el progreso de la aplicación y recupéralos sin repetir el trabajo completado."
---

Un checkpoint de estado protege el estado de entrenamiento del servidor. Un
registro de recuperación completo también protege el estado controlado por el
usuario que indica al controlador qué debe hacer después.

## Qué guardar

| Registro | Contiene | Almacenado por |
| --- | --- | --- |
| Checkpoint de estado | Pesos de entrenamiento y estado del optimizador representados por el checkpoint del SDK | Fastino |
| Registro del bucle | ID del trabajo de origen, ruta del checkpoint, paso, cursor del dataset, configuración y linaje de reanudación | Tu aplicación |

El cliente de entrenamiento del SDK representa un trabajo interactivo de
Fastino. Lee su ID canónico de
`training_client.get_info().model_id`.

## 1. Guarda el estado y el progreso del bucle

Guarda el estado mediante el SDK y conserva después el checkpoint devuelto con
los campos del cliente necesarios para continuar:

```python
import json
from pathlib import Path


source_job_id = training_client.get_info().model_id
state = training_client.save_state(f"step-{step:06d}").result()
record = {
    "source_job_id": source_job_id,
    "state_path": state.path,
    "model": model_name,
    "dataset_revision": dataset_revision,
    "optimizer": optimizer_config,
    "step": step,
    "dataset_cursor": dataset_cursor,
    "reward_version": reward_version,
}

with Path(log_path).open("a", encoding="utf-8") as checkpoint_log:
    checkpoint_log.write(json.dumps(record, sort_keys=True) + "\n")
```

Usa nombres de checkpoint únicos para que cada registro identifique un límite
de recuperación inequívoco. No supongas una duración no documentada.

## 2. Lee el registro completo más reciente

Un proceso puede detenerse mientras escribe la última línea. Recorre el archivo
hacia atrás y omite una cola con formato incorrecto:

```python
def get_last_checkpoint(log_path: str) -> dict[str, object] | None:
    path = Path(log_path)
    if not path.exists():
        return None

    for line in reversed(path.read_text(encoding="utf-8").splitlines()):
        try:
            record = json.loads(line)
        except json.JSONDecodeError:
            continue
        if isinstance(record, dict) and isinstance(record.get("state_path"), str):
            return record
    return None
```

## 3. Valida antes de cargar

Compara el registro con el checkpoint de origen y la continuación solicitada:

- ID del trabajo de origen codificado en la ruta del checkpoint
- Modelo base y configuración entrenable
- Revisión y cursor del dataset
- Revisión de la implementación de recompensas
- Configuración del optimizador
- Supuestos del renderizador y del tokenizador

Detente para solicitar una decisión explícita si estos campos entran en
conflicto. No combines silenciosamente un checkpoint con otro experimento.

Los clientes nativos crean un trabajo nuevo con `from_checkpoint` o llaman a
[`load checkpoint`](/es/api-reference/training-jobs/interactive/load-checkpoint)
en un trabajo compatible. Los clientes Tinker usan el flujo compatible para
cargar el estado:

```python
training_client = (
    service_client.create_training_client_from_state_with_optimizer(
        str(resume["state_path"])
    )
)
resumed_job_id = training_client.get_info().model_id
```

Esta fábrica crea un nuevo trabajo interactive y después carga los pesos y el
estado del optimizador del checkpoint de origen. El ID reanudado normalmente
difiere del ID de origen. Guarda `source_job_id`, `state_path` y
`resumed_job_id` como linaje de la aplicación. No rechaces la continuación
porque los IDs difieran. No construyas rutas hijas privadas de compatibilidad.

## 4. Haz recuperable el límite

Usa este orden:

1. Resuelve los futures hacia delante/hacia atrás y del optimizador.
2. Guarda el checkpoint de estado.
3. Conserva el registro del bucle que contiene su identificador.
4. Marca como completado el paso de la aplicación.
5. Inicia el siguiente paso.

Si el proceso termina después de guardar el checkpoint, pero antes de conservar
el registro, mantén el registro completo anterior como punto de recuperación de
confianza. No marques un paso como completado antes de que su registro sea duradero.

## 5. Mantén separados los tipos de checkpoint

```python
state = training_client.save_state("step-000100").result()
sampler = training_client.save_weights_for_sampler(
    "step-000100",
    ttl_seconds=24 * 60 * 60,
).result()
```

Usa un checkpoint de estado para recuperar el entrenamiento y uno de muestreador
para rollouts o evaluación. No uses un checkpoint de muestreador como punto de
recuperación del estado del optimizador.

`ttl_seconds` tiene el valor predeterminado `None`; sin TTL, el checkpoint no
caduca automáticamente. Los checkpoints activos cuentan para el almacenamiento.
Para la limpieza automática, usa un valor inclusivo entre `3_600` y
`315_360_000` segundos.

La API pública de entrenamiento permite guardar, cargar, muestrear, inspeccionar,
eliminar, publicar, retirar la publicación y establecer la retención de
checkpoints interactivos. El tipo de guardado `save-weights` corresponde a `weights`.
El tipo `save-weights-for-sampler` corresponde a `sampler_weights`. El muestreo desde un
checkpoint del sampler guardado sigue disponible después de detener el trabajo.
Las rutas compartidas de lista y descarga cubren los checkpoints interactivos.
La descarga sigue requiriendo el permiso para descargar pesos. Tinker ofrece
métodos equivalentes del SDK. No construyas rutas hijas privadas de compatibilidad
ni supongas un periodo de retención no documentado.

## 6. Verifica la continuación

Antes de aumentar la carga reanudada:

1. Carga el checkpoint de estado seleccionado.
2. Lee el ID nuevo de `training_client.get_info().model_id`, guárdalo como
   `resumed_job_id` y confírmalo mediante
   `GET /v1/training/jobs/{resumed_job_id}`.
3. Ejecuta una pequeña evaluación con datos reservados.
4. Envía una actualización de entrenamiento compatible.
5. Guarda un checkpoint de estado nuevo con otro nombre.
6. Conserva el siguiente registro del bucle.

Usa las rutas JSON nativas o el SDK de Tinker compatible para las operaciones interactivas del modelo.

## Diagnostica errores de recuperación

| Síntoma | Comprobación |
| --- | --- |
| Falla un future | Registra el ID del trabajo y el resultado de la operación. No avances el estado dependiente de la aplicación |
| No se puede cargar un checkpoint | Verifica su trabajo, su tipo de checkpoint y el registro de recuperación controlado por el cliente |
| Se rechaza el checkpoint de origen | Comprueba el trabajo de origen, el tipo de checkpoint y `state_path`; no exijas que el ID nuevo coincida con el de origen |
| Falla la consulta del trabajo reanudado | Confirma que el ID proceda de `get_info().model_id` del cliente reanudado y que esté autenticado el mismo equipo de Fastino |
