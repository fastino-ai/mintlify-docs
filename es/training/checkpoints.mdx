---
title: "Checkpoints y recuperación"
description: "Guarda el estado del trabajo interactivo y el progreso de la aplicación y recupéralos sin repetir el trabajo completado."
---

Un checkpoint de estado protege el estado de entrenamiento del servidor. Un
registro de recuperación completo protege también el estado propio del usuario
que indica a tu controlador qué hacer a continuación.

Los ejemplos usan los helpers `call` y `wait` del
[script de la guía rápida](/es/training/decoder-quickstart).

## Qué guardar

| Registro | Contiene | Lo guarda |
| --- | --- | --- |
| Checkpoint de estado | Pesos LoRA y estado del optimizador | Fastino |
| Registro del bucle | ID del trabajo de origen, ruta del checkpoint, paso, cursor del dataset, configuración y linaje de reanudación | Tu aplicación |

## 1. Guarda el estado y el progreso del bucle

Guarda el estado con `save-weights`, espera a que termine y persiste su ruta junto con
los campos propios del cliente necesarios para continuar:

```python
import json
from pathlib import Path


state = call(
    "POST",
    f"/v1/training/jobs/{job_id}/save-weights",
    {"name": f"step-{step:06d}"},
)
state_path = wait(job_id, state["future_id"])
record = {
    "source_job_id": job_id,
    "state_path": state_path,
    "model": model_name,
    "dataset_revision": dataset_revision,
    "optimizer": adam_params,
    "step": step,
    "dataset_cursor": dataset_cursor,
    "reward_version": reward_version,
}

with Path(log_path).open("a", encoding="utf-8") as checkpoint_log:
    checkpoint_log.write(json.dumps(record, sort_keys=True) + "\n")
```

La ruta de la respuesta inicial de guardado es provisional. El checkpoint solo
pasa a ser duradero cuando se completa el future de guardado; si el future falla
o se cancela, no persistas ni uses esa ruta.

Usa nombres de checkpoint únicos para que cada registro identifique un punto de
recuperación inequívoco. Los nombres usan de 1 a 128 caracteres de `A-Z`, `a-z`,
`0-9`, `.`, `_` y `-`. Los prefijos `__park-` y `__snap-` están reservados.

## 2. Lee el registro completo más reciente

Un proceso puede detenerse mientras escribe la última línea. Recorre el archivo
hacia atrás y omite una cola mal formada:

```python
def get_last_checkpoint(log_path: str) -> dict[str, object] | None:
    path = Path(log_path)
    if not path.exists():
        return None

    for line in reversed(path.read_text(encoding="utf-8").splitlines()):
        try:
            record = json.loads(line)
        except json.JSONDecodeError:
            continue
        if isinstance(record, dict) and isinstance(record.get("state_path"), str):
            return record
    return None
```

## 3. Valida antes de cargar

Compara el registro con el checkpoint de origen y la continuación solicitada:

- ID del trabajo de origen en la ruta del checkpoint
- Modelo base y configuración LoRA
- Revisión y cursor del dataset
- Revisión de la implementación de recompensas
- Ajustes del optimizador
- Supuestos sobre el tokenizador y la plantilla de chat

Detente para tomar una decisión explícita si estos campos entran en conflicto.
No combines en silencio un checkpoint con otro experimento.

Después, elige cómo continuar:

| Situación | Llamada |
| --- | --- |
| El trabajo de origen sigue activo y quieres revertir | `POST /v1/training/jobs/{job_id}/load-weights` con `{"path": "<name>", "optimizer": true}` |
| El trabajo de origen se detuvo o se liberó | `POST /v1/training/jobs/create-model` con `from_checkpoint` y `load_optimizer` |

Para continuar en un trabajo nuevo:

```python
resumed = call(
    "POST",
    "/v1/training/jobs/create-model",
    {"from_checkpoint": resume["state_path"], "load_optimizer": True},
)
wait(resumed["job_id"], resumed["future_id"])
wait(resumed["job_id"], resumed["load_future_id"])
resumed_job_id = resumed["job_id"]
```

El trabajo nuevo toma el modelo base y la configuración LoRA del checkpoint, así
que no envíes `lora_config`. Su ID es distinto del ID de origen. Registra
`source_job_id`, `state_path` y `resumed_job_id` como linaje propio de la
aplicación.

## 4. Haz recuperable el límite

Usa este orden:

1. Espera a que terminen los futures de forward-backward y del optimizador.
2. Guarda el checkpoint de estado y espera el future de guardado.
3. Persiste el registro del bucle con su ruta.
4. Marca como completado el paso de la aplicación.
5. Empieza el paso siguiente.

Si el proceso termina después de guardar el checkpoint pero antes de persistir
el registro, conserva el registro completo anterior como punto de recuperación
fiable. No marques un paso como completado antes de que su registro sea duradero.

Los resultados de los futures se pueden recuperar durante una hora. En ese
plazo, consulta el `future_id` de guardado conocido antes de decidir qué
ocurrió. Si devuelve `410`, no repitas el guardado a ciegas: concilia los
checkpoints del trabajo con tu registro duradero del bucle. El límite de
confirmación a largo plazo es un checkpoint completado junto con su registro
duradero en la aplicación, no el future en sí.

## 5. Mantén separados los tipos de checkpoint

```python
name = f"step-{step:06d}"
state = call(
    "POST",
    f"/v1/training/jobs/{job_id}/save-weights",
    {"name": name},
)
sampler = call(
    "POST",
    f"/v1/training/jobs/{job_id}/save-weights-for-sampler",
    {"name": name, "ttl_seconds": 24 * 60 * 60},
)
```

| Se guarda con | Sufijo del ID del checkpoint | Ruta completa | Úsalo para |
| --- | --- | --- | --- |
| `save-weights` | `weights/<name>` | `tinker://<job_id>/weights/<name>` | Recuperar el entrenamiento: cargarlo o iniciar un trabajo nuevo desde él |
| `save-weights-for-sampler` | `sampler_weights/<name>` | `tinker://<job_id>/sampler_weights/<name>` | Rollouts, evaluación y descarga como archivos PEFT LoRA |

No uses un checkpoint sampler como punto de recuperación: no tiene estado del
optimizador y no se puede iniciar un trabajo nuevo desde él. Pasa la ruta
completa `tinker://.../weights/<name>`, no el sufijo del ID del checkpoint, como
`from_checkpoint`.

`ttl_seconds` vale `null` por defecto, así que si lo omites el checkpoint se
conserva hasta que lo elimines. Los checkpoints vivos cuentan para el
almacenamiento de checkpoints. Para activar la limpieza automática, pasa un
valor de `3600` a `315360000` segundos (de 1 hora a 10 años).

Gestiona los checkpoints con estas rutas:

| Tarea | Ruta |
| --- | --- |
| Listar los checkpoints de un trabajo | [`GET /v1/training/jobs/{job_id}/checkpoints`](/es/api-reference/training-jobs/checkpoints) |
| Obtener un checkpoint | [`GET /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}`](/es/api-reference/training-jobs/interactive/get-checkpoint) |
| Descargar como archivo `.tar` | [`GET /v1/training/jobs/{job_id}/checkpoints/{checkpoint_id}/download`](/es/api-reference/training-jobs/download-checkpoint) |
| Cambiar su TTL | [`PUT /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}/ttl`](/es/api-reference/training-jobs/interactive/set-checkpoint-ttl) |
| Publicar o despublicar | [`POST /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}/publish`](/es/api-reference/training-jobs/interactive/publish-checkpoint) |
| Eliminar | [`DELETE /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}`](/es/api-reference/training-jobs/interactive/delete-checkpoint) |
| Leer el uso de almacenamiento | [`GET /v1/training/usage`](/es/api-reference/training-jobs/interactive/storage-usage) |

Descargar requiere el acceso de descarga de pesos del equipo.

Después de detener un trabajo, se rechazan las operaciones de entrenamiento que
lo modifican, pero aún puedes listar, inspeccionar, descargar, publicar, cambiar
el TTL y eliminar sus checkpoints. También puedes muestrear desde sus
checkpoints sampler.

## 6. Verifica la continuación

Antes de escalar la carga reanudada:

1. Inicia el trabajo nuevo desde el checkpoint de estado elegido.
2. Persiste su ID como `resumed_job_id` y confírmalo con
   `GET /v1/training/jobs/{resumed_job_id}`.
3. Ejecuta una pequeña evaluación con datos reservados.
4. Envía una actualización de entrenamiento.
5. Guarda un checkpoint de estado nuevo con otro nombre.
6. Persiste el siguiente registro del bucle.

## Despliega tu modelo entrenado

Despliega un checkpoint sampler para servirlo como modelo. El despliegue está
disponible para los modelos base compatibles; las demás bases devuelven `400`.

```bash
curl -X POST "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/checkpoints/sampler_weights/step-000100/deploy" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model_name": "support-replies-v1"}'
```

La respuesta contiene el `model_id` del modelo y un `status` `deploying`. Repite
la misma llamada para ver el progreso: devuelve el mismo modelo, y `status` pasa
a `deployed` cuando el modelo está listo. Después llámalo por su ID:

```bash
curl -X POST "https://api.fastino.ai/v1/chat/completions" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "Summarize this ticket in one sentence."}]
  }'
```

Sustituye `MODEL_ID` por el `model_id` devuelto. Consulta
[Desplegar checkpoint](/es/api-reference/training-jobs/interactive/deploy-checkpoint)
para ver los campos y errores.

## Diagnostica errores de recuperación

| Síntoma | Comprobación |
| --- | --- |
| Un future falla | Registra el ID del trabajo y el `error` del future. No avances el estado dependiente de la aplicación |
| Una llamada de entrenamiento devuelve `400` tras una pausa | El trabajo se detuvo o se liberó tras 30 minutos inactivo. Las operaciones de entrenamiento que modifican el trabajo no están disponibles; la gestión de checkpoints y el muestreo desde checkpoints sampler siguen disponibles. Para continuar entrenando, inicia un trabajo nuevo desde el último checkpoint de estado |
| Un checkpoint no se puede cargar | Verifica su trabajo, su tipo y el registro de recuperación del cliente |
| Se rechaza `from_checkpoint` | Confirma que es una ruta completa `tinker://<job_id>/weights/<name>` de tu equipo; los checkpoints sampler no pueden iniciar un trabajo |
| Falla la consulta del trabajo reanudado | Confirma que el ID vino de la respuesta de creación del trabajo nuevo y que estás autenticado en el mismo equipo de Fastino |
