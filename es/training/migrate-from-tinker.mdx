---
title: "Migrar desde Tinker"
description: "Traslada una carga de trabajo compatible del SDK de Tinker a los trabajos de entrenamiento interactivos de Fastino."
---

La API de entrenamiento admite el SDK de Python `tinker==0.32.0` sin
modificaciones para las operaciones que se indican abajo. Cambia solo la URL
base y la credencial. Un cliente de entrenamiento migrado es un trabajo de
Fastino en `/v1/training/jobs`; su ID de modelo del SDK y su ID canónico de
trabajo de Fastino son idénticos.

Trata tu programa existente como prueba de aceptación. Cambia la conexión,
comprueba cada operación y ejecuta una pequeña prueba de humo antes de
restablecer los tamaños de las cargas de producción.

## 1. Fija el paquete probado

<CodeGroup>

```bash uv
uv add "tinker==0.32.0"
```

```bash pip
pip install "tinker==0.32.0"
```

</CodeGroup>

## 2. Sustituye el endpoint y la autenticación

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="fast_sk_..."
export TINKER_BASE_URL="https://api.fastino.ai/v1/training/compat/tinker"
export TINKER_CREDENTIAL_CMD='printf "%s\n" "$FASTINO_API_KEY"'
```

```powershell Windows
$env:FASTINO_API_KEY = "fast_sk_..."
$env:TINKER_BASE_URL = "https://api.fastino.ai/v1/training/compat/tinker"
$env:TINKER_CREDENTIAL_CMD = 'powershell -NoProfile -Command "[Console]::Out.WriteLine($env:FASTINO_API_KEY)"'
```

</CodeGroup>

`TINKER_CREDENTIAL_CMD` se ejecuta con cada solicitud de token y debe imprimir
una credencial no vacía. Usa una clave normal `fast_sk_` de Fastino; las
credenciales `tml-` se rechazan. No establezcas `TINKER_API_KEY`.

## 3. Comprueba la carga de trabajo

1. Consulta `ServiceClient.get_server_capabilities()` y elige un modelo base disponible. Conserva el nombre de parámetro `base_model` del SDK.
2. Compara cada método de tu código con el [comportamiento compatible del cliente](#supported-client-behavior).
3. Elimina dependencias de la recuperación de futures por lotes no compatible,
   la exportación de pesos externos o las URL de pesos externos.
4. Mantén en tu aplicación el renderizado de prompts, la lógica de recompensas, el procesamiento por lotes, la evaluación y los criterios de parada.

Capabilities solo lista modelos habilitados y sus longitudes de contexto. No
incluye rangos LoRA, optimizadores, pérdidas, métodos opcionales ni límites de
operación. Fastino acepta actualmente rangos LoRA de 1 a 32, usa `adamw` al
crear el cliente y admite `cross_entropy`, `importance_sampling`, `ppo`,
`cispo` y `dro`. El servicio activo valida estos ajustes al enviarlos.

## 4. Ejecuta una prueba de humo

Usa los datums válidos más pequeños y los ajustes del optimizador de tu carga de
trabajo existente para realizar una prueba de bajo coste que:

- Cree un cliente con `create_lora_training_client(base_model=...)`
- Lea `training_client.get_info().model_id`
- Guarde los pesos del muestreador y realice un muestreo
- Ejecute una operación compatible hacia delante/hacia atrás y un paso del optimizador
- Guarde y vuelva a cargar un checkpoint de estado
- Obtenga el ID de cada cliente de `GET /v1/training/jobs/{job_id}`; una
  reanudación mediante la fábrica crea un ID nuevo a partir del checkpoint de origen

Accede a la API de entrenamiento mediante el SDK de Tinker compatible para las
operaciones interactivas. La interfaz HTTP del SDK se omite intencionadamente
del OpenAPI y de la referencia de la API de Fastino; no construyas llamadas
HTTP equivalentes.

## Comportamiento compatible del cliente

La API de entrenamiento admite las siguientes llamadas de `tinker==0.32.0`
sobre un trabajo interactivo de Fastino.

### Entrenamiento y muestreo

| Método u operación del SDK | Comportamiento de Fastino |
| --- | --- |
| `create_lora_training_client` | Crea un trabajo interactivo |
| `copy_weights` | Inicia un trabajo interactivo desde un checkpoint |
| `TrainingClient.get_info` | Devuelve el trabajo interactivo |
| `forward` | Ejecuta una operación solo hacia delante |
| `forward_backward` | Ejecuta una operación hacia delante y hacia atrás |
| Operación personalizada hacia delante/hacia atrás | Ejecuta una operación compatible con pérdida personalizada |
| `optim_step` | Aplica una actualización del optimizador |
| `save_state` | Guarda el estado del entrenamiento |
| `save_weights_for_sampler` | Guarda los pesos del muestreador |
| Cargar el estado de entrenamiento | Restaura un checkpoint de estado |
| Crear u obtener un cliente de muestreo | Resuelve los pesos del muestreador |
| `SamplingClient.sample` | Muestrea mediante el checkpoint seleccionado |

Conserva sin cambios el parámetro `base_model` del SDK. Elige el modelo mediante
capabilities; usa los límites documentados para rango y pérdida y gestiona los
errores de validación del servicio activo.

### Futures y administración

| Método u operación del SDK | Comportamiento de Fastino |
| --- | --- |
| Resultado/obtención de future | Obtiene un resultado asíncrono |
| Cancelación de future | Cancela solo un future de muestreo no terminado de `sample`. Los futures de operaciones de entrenamiento no se cancelan |
| `list_training_runs` o `get_training_run` | Lee solo ejecuciones interactivas. `/v1/training/jobs` lee trabajos de configuración e interactivos |
| `list_checkpoints` o `list_user_checkpoints` | Lee los checkpoints que pertenecen al trabajo o al equipo |
| `get_weights_info_by_tinker_path` | Lee los metadatos de pesos de un checkpoint, incluido el rango LoRA |
| `get_checkpoint_archive_url` | Devuelve un enlace de archivo firmado para un checkpoint interactivo. Requiere permiso de descarga de pesos |
| `delete_checkpoint_from_tinker_path` | Elimina un checkpoint |
| `publish_checkpoint_from_tinker_path` o `unpublish_checkpoint_from_tinker_path` | Cambia la publicación dentro del equipo propietario. No permite que otro equipo cargue la ruta |
| `set_checkpoint_ttl_from_tinker_path` | Establece o borra la retención del checkpoint |
| `get_current_checkpoint_storage_usage` | Lee el almacenamiento actual de checkpoints, opcionalmente para un proyecto |
| `get_billing_usage` | Lee eventos de uso por hora en una ventana alineada a la hora |

Las dos rutas de descarga de checkpoints requieren el permiso del equipo para descargar pesos. Una es el método del SDK `get_checkpoint_archive_url`. La otra es la ruta pública [`GET /v1/training/jobs/{job_id}/checkpoints/{checkpoint_id}/download`](/es/api-reference/training-jobs/download-checkpoint). Sin ese permiso, ambas devuelven `403` con `For downloading models, please contact sales@fastino.ai`. El SDK gestiona automáticamente el intercambio de tokens con la clave que imprime `TINKER_CREDENTIAL_CMD`. No construyas solicitudes HTTP equivalentes.

### Llamadas no compatibles

Fastino no admite:

- Recuperación de futures por lotes mediante `retrieve_futures`
- `save_weights_external`
- `external_weights_urls`
- Exportación de trazas de sesión
- Entradas del registro de auditoría
- Muestreo sin un `SamplingClient` y su sesión de muestreo
- `target_prompt_logprobs` o un `prompt_alt_tokens_k` positivo
- Fragmentos de prompt distintos de `encoded_text`
- Optimizadores distintos de AdamW
- Rangos LoRA fuera del intervalo de 1 a 32

Estas restricciones describen el comportamiento con claves de API normales de
Fastino. Una clave de ejecución de sandbox tiene un ámbito de escritura más
reducido: tampoco puede eliminar o publicar checkpoints, cambiar su TTL ni
reasignar el proyecto de una sesión. Las operaciones
correspondientes siguen siendo compatibles con claves de API normales.

No deduzcas la compatibilidad porque un método exista en el paquete instalado.
La tabla define el subconjunto compatible; capabilities solo informa modelos
habilitados y longitudes de contexto.

## Soluciona problemas de conexión

| Síntoma | Comprobación |
| --- | --- |
| La autenticación falla | Confirma que `TINKER_CREDENTIAL_CMD` imprima una única clave `fast_sk_` actual y ninguna salida adicional |
| El cliente no puede conectarse | Confirma que `TINKER_BASE_URL` sea exactamente `https://api.fastino.ai/v1/training/compat/tinker` |
| Una llamada del SDK o descarga de checkpoint devuelve `403` con un mensaje sobre el borrado de datos del equipo | El equipo se está eliminando. No reintentes la operación; contacta con el administrador de la cuenta o con el soporte de Fastino si la eliminación es inesperada |
| Una descarga de checkpoint devuelve `403` y pide contactar con ventas | Al equipo le falta el permiso de descarga de pesos. Contacta con sales@fastino.ai |
| Se rechaza un modelo | Vuelve a consultar capabilities y elige un modelo habilitado |
| Se rechaza un rango, pérdida u operación | Compara la llamada con los límites documentados y la tabla de compatibilidad |
| Falla la consulta del trabajo canónico | Confirma que el ID proceda de `get_info().model_id` y que esté autenticado el mismo equipo de Fastino |

## Lista de comprobación de la migración

- [ ] Fija `tinker==0.32.0`.
- [ ] Establece la URL base de la API de entrenamiento para el SDK de Tinker.
- [ ] Proporciona una clave `fast_sk_` mediante `TINKER_CREDENTIAL_CMD`.
- [ ] Comprueba cada método del SDK con el comportamiento compatible del cliente.
- [ ] Elige un modelo habilitado mediante capabilities y valida rango, pérdida
      y operaciones opcionales con esta guía.
- [ ] Completa una actualización de muestreo y entrenamiento.
- [ ] Guarda y vuelve a cargar un checkpoint de estado.
- [ ] Verifica el ID de modelo del SDK mediante el endpoint canónico del trabajo.
- [ ] Aumenta el tamaño de la carga solo después de superar la prueba de humo.
