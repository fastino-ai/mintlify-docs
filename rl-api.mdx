The RL API is Fastino's programmable interface for reinforcement learning and
custom post-training. It implements the Tinker SDK contract, so you can bring an
existing Tinker training loop or start from the open-source Tinker cookbook.

<Note>
  The RL API is in limited access. Confirm that Fastino has enabled it for your
  team before planning a production migration.
</Note>

You control the loop:

1. Sample responses from the current policy.
2. Score each response with your reward function.
3. Turn rewards into advantages.
4. Send the training batch to the RL API.
5. Apply an optimizer step and checkpoint the result.

Fastino manages the training and sampling infrastructure behind that loop. Your
code keeps ownership of the dataset, reward function, rollout strategy, and
stopping criteria.

<Tip>
  Already using Tinker? Keep your SDK calls and set the Fastino endpoint and API
  key. Start with [Migrate from Tinker](/rl-api/migrate-from-tinker).
</Tip>

## Why use the RL API

- **Bring existing code.** The official `tinker` Python package is the client.
- **Define any programmatic reward.** Grade math, code, tool use, structured
  output, or your own environment.
- **Separate orchestration from compute.** Keep the learning algorithm in your
  application while Fastino runs model operations.
- **Resume from durable checkpoints.** Save weights or optimizer state and
  restore a run later.
- **Track usage with Fastino.** Training, sampling, and checkpoint storage use
  the same account and project billing boundary as your other Fastino
  workloads.

## Before you start

You need:

- A Fastino API key beginning with `fast_sk_`
- RL API access enabled for your Fastino team
- Python 3.11 or later
- `tinker==0.32.0` for the tested client contract

The RL API is intentionally documented separately from Fastino's OpenAPI
reference. Use these pages and the Tinker SDK types for RL operations. Use the
[API reference](/api-reference/inference/overview) for native Fastino HTTP
APIs.
