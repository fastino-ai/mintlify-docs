This quickstart covers both Training API paths. Use managed training when you
want Fastino to run the loop. Use a custom training loop when your application
must control sampling, rewards, and model updates.

## 1. Authenticate

1. Create a [Fastino account](https://agent.fastino.ai/).
2. Open [API keys](https://agent.fastino.ai/api-keys).
3. Create a key and copy it when shown.

Store the key in an environment variable:

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="fast_sk_..."
```

```powershell Windows
$env:FASTINO_API_KEY = "fast_sk_..."
```

</CodeGroup>

Send this key as `X-API-Key: $FASTINO_API_KEY`. See
[Authentication](/authentication) for the complete authentication contract.

## 2. Choose a path

| Goal | Path |
| --- | --- |
| Provide data and configuration, then let Fastino run training | [Managed training](#managed-training) |
| Control sampling, rewards, and updates in your application | [Custom training loop](#custom-training-loop) |

## Managed training

### 3. Prepare a dataset

[Upload and process a training dataset](/concepts/datasets), then wait until its
version is `ready`.

### 4. Choose a model

Query the live catalog before submission:

```bash
curl "https://api.fastino.ai/v1/base-models?supports_training=true" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

Save the selected model ID.

### 5. Create the job

```bash
curl -X POST "https://api.fastino.ai/v1/training/jobs" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "model_name": "my-trained-model",
    "base_model": "MODEL_ID_FROM_CATALOG",
    "datasets": [
      {"name": "my-ready-dataset", "version": "VERSION_NUMBER"}
    ],
    "training_type": "lora"
  }'
```

Save the returned `id`. It is the `job_id` used by every job-specific route.
Reuse the same `Idempotency-Key` only when retrying this exact create request.

### 6. Poll the job

```bash
curl "https://api.fastino.ai/v1/training/jobs/JOB_ID" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

For config jobs:

- `status` is the persisted lifecycle value, such as `errored`.
- `normalized_status` is the stable polling value, such as `failed`.
- `is_terminal_status` tells your client when to stop polling.
- `error_message` describes a failure when available.

Continue until `is_terminal_status` is `true`, then inspect the final status,
checkpoints, logs, and deployment eligibility.

## Custom training loop

Choose one supported interface:

- Native JSON clients call
  [`POST /v1/training/jobs/create-model`](/api-reference/training-jobs/interactive/create-model),
  queue model operations under `/v1/training/jobs/{job_id}`, and poll each
  returned `future_id` until `completed`, `failed`, or `cancelled`.
- Existing Tinker programs keep `tinker==0.32.0` and use the setup below.

Native clients send no `seq_id` and no heartbeat. The server assigns operation
ordering and keeps the internal session alive. A request with `wait=true` waits
for at most 25 seconds, so a client must continue polling a nonterminal
future. Follow [Build a custom training loop](/training/training-loop) for
the native route sequence.

### Native JSON path

1. Call
   [`POST /v1/training/jobs/create-model`](/api-reference/training-jobs/interactive/create-model)
   with `base_model`, or with `from_checkpoint` and `load_optimizer`.
2. Poll the returned create `future_id` through
   [Get a future](/api-reference/training-jobs/interactive/get-future)
   until `completed`, `failed`, or `cancelled`.
3. Queue
   [forward-backward](/api-reference/training-jobs/interactive/forward-backward)
   and [an optimizer step](/api-reference/training-jobs/interactive/optim-step).
   Poll each `future_id` to a terminal status before the next dependent step.
4. [Save sampler weights](/api-reference/training-jobs/interactive/save-sampler-weights)
   and poll the save future to a terminal status.
5. Stop the job through the shared
   [stop operation](/api-reference/training-jobs/stop).
6. [Sample from the saved checkpoint](/api-reference/training-jobs/interactive/sample)
   after stop, then poll the sample future to a terminal status.

Only a queued or running sample future can be cancelled. An HTTP rejection
means that the server did not queue the call. A queued future can
instead finish with `status: "failed"`.

### Tinker SDK path

The Tinker path requires Python 3.11 or later. Do not construct private
compatibility child routes.

### 3. Install the tested client

<CodeGroup>

```bash uv
uv init fastino-training
cd fastino-training
uv add "tinker==0.32.0"
```

```bash pip
mkdir fastino-training && cd fastino-training
python -m venv .venv
source .venv/bin/activate
pip install "tinker==0.32.0"
```

```powershell pip · Windows
mkdir fastino-training
cd fastino-training
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install "tinker==0.32.0"
```

</CodeGroup>

### 4. Configure the client

`TINKER_CREDENTIAL_CMD` runs for every token request and must print one
nonempty credential.

<CodeGroup>

```bash macOS/Linux
export TINKER_BASE_URL="https://api.fastino.ai/v1/training/compat/tinker"
export TINKER_CREDENTIAL_CMD='printf "%s\n" "$FASTINO_API_KEY"'
```

```powershell Windows
$env:TINKER_BASE_URL = "https://api.fastino.ai/v1/training/compat/tinker"
$env:TINKER_CREDENTIAL_CMD = 'powershell -NoProfile -Command "[Console]::Out.WriteLine($env:FASTINO_API_KEY)"'
```

</CodeGroup>

Use a normal Fastino key beginning with `fast_sk_`. Credentials beginning with
`tml-` are rejected. Do not set `TINKER_API_KEY`.

### 5. Choose an enabled model

Call `ServiceClient.get_server_capabilities()` and select an enabled model.
Capabilities report model names and advertised context lengths, but not LoRA
ranks, optimizers, losses, optional methods, or per-operation limits. Fastino
currently accepts LoRA ranks from 1 through 32 and defaults to 32.

<CodeGroup>

```bash macOS/Linux
export FASTINO_TRAINING_MODEL="<model from capabilities>"
export FASTINO_TRAINING_LORA_RANK="32"
```

```powershell Windows
$env:FASTINO_TRAINING_MODEL = "<model from capabilities>"
$env:FASTINO_TRAINING_LORA_RANK = "32"
```

</CodeGroup>

### 6. Create the job and sample

Create `quickstart.py`:

```python
import os

import tinker


service_client = tinker.ServiceClient()
outcome = "errored"
try:
    capabilities = service_client.get_server_capabilities()
    print(capabilities)

    training_client = service_client.create_lora_training_client(
        base_model=os.environ["FASTINO_TRAINING_MODEL"],
        rank=int(os.environ["FASTINO_TRAINING_LORA_RANK"]),
    )

    job_id = training_client.get_info().model_id
    print(f"TRAINING_JOB_ID={job_id}")

    checkpoint = training_client.save_weights_for_sampler(
        "quickstart-sampler",
        ttl_seconds=24 * 60 * 60,
    ).result()
    sampling_client = service_client.create_sampling_client(
        model_path=checkpoint.path
    )

    tokenizer = sampling_client.get_tokenizer()
    prompt_tokens = tokenizer.apply_chat_template(
        conversation=[
            {
                "role": "user",
                "content": "Explain the purpose of a reward function in one sentence.",
            }
        ],
        add_generation_prompt=True,
        return_dict=False,
    )
    result = sampling_client.sample(
        prompt=tinker.types.ModelInput.from_ints(prompt_tokens),
        num_samples=1,
        sampling_params=tinker.types.SamplingParams(max_tokens=64),
    ).result()

    print(tokenizer.decode(result.sequences[0].tokens))
except KeyboardInterrupt:
    outcome = "interrupted"
    raise
else:
    outcome = "success"
finally:
    service_client.close(outcome).result()
```

Run the script:

```bash
python quickstart.py
```

Copy the value printed after `TRAINING_JOB_ID=`.

### 7. Verify the canonical job

<CodeGroup>

```bash macOS/Linux
export TRAINING_JOB_ID="<ID printed by quickstart.py>"
curl --fail-with-body \
  -H "X-API-Key: $FASTINO_API_KEY" \
  "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID"
```

```powershell Windows
$env:TRAINING_JOB_ID = "<ID printed by quickstart.py>"
Invoke-RestMethod `
  -Headers @{ "X-API-Key" = "$env:FASTINO_API_KEY" } `
  -Uri "https://api.fastino.ai/v1/training/jobs/$env:TRAINING_JOB_ID"
```

</CodeGroup>

The response describes the same job created by
`create_lora_training_client(...)`. Continue with the SDK client for model
operations and use the canonical jobs API for documented job reads. Native
JSON clients use the public interactive operation pages instead.
