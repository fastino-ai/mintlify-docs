This quickstart covers both Training API paths. Use managed training to
fine-tune a GLiNER encoder while Fastino runs the loop. Use a custom training
loop to train a decoder LLM when your application must control sampling,
rewards, and model updates.

## 1. Authenticate

1. Create a [Fastino account](https://agent.fastino.ai/).
2. Open [API keys](https://agent.fastino.ai/api-keys).
3. Create a key and copy it when shown.

Store the key in an environment variable:

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="fast_sk_..."
```

```powershell Windows
$env:FASTINO_API_KEY = "fast_sk_..."
```

</CodeGroup>

Send this key as `X-API-Key: $FASTINO_API_KEY`. See
[Authentication](/authentication) for the complete authentication contract.

## 2. Choose a path

| Goal | Path |
| --- | --- |
| Fine-tune a GLiNER encoder from a dataset and let Fastino run training | [Managed training](#managed-training) |
| Train a decoder LLM and control sampling, rewards, and updates in your application | [Custom training loop](#custom-training-loop) |

## Managed training

### 3. Prepare a dataset

[Upload and process a training dataset](/concepts/datasets), then wait until its
version is `ready`.

### 4. Choose a model

Managed training supports `fastino/gliner2-multi-v1` and
`fastino/GLiNER-2.5-Decide`. Query the live catalog before submission:

```bash
curl "https://api.fastino.ai/v1/base-models?supports_training=true" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

Save the selected model ID.

### 5. Create the job

```bash
curl -X POST "https://api.fastino.ai/v1/training/jobs" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{
    "model_name": "my-trained-model",
    "base_model": "MODEL_ID_FROM_CATALOG",
    "datasets": [
      {"name": "my-ready-dataset", "version": "VERSION_NUMBER"}
    ],
    "training_type": "lora"
  }'
```

Save the returned `id`. It is the `job_id` used by every job-specific route.
Reuse the same `Idempotency-Key` only when retrying this exact create request.

### 6. Poll the job

```bash
curl "https://api.fastino.ai/v1/training/jobs/JOB_ID" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

For config jobs:

- `status` is the persisted lifecycle value, such as `errored`.
- `normalized_status` is the stable polling value, such as `failed`.
- `is_terminal_status` tells your client when to stop polling.
- `error_message` describes a failure when available.

Continue until `is_terminal_status` is `true`, then inspect the final status,
checkpoints, logs, and deployment eligibility.

## Custom training loop

Choose one supported interface:

- Native JSON clients call
  [`POST /v1/training/jobs/create-model`](/api-reference/training-jobs/interactive/create-model),
  queue model operations under `/v1/training/jobs/{job_id}`, and poll each
  returned `future_id` until `completed`, `failed`, or `cancelled`.
- Existing Tinker programs keep `tinker==0.32.0` and use the setup below.

Native clients send no `seq_id` and no heartbeat. The server assigns operation
ordering and keeps the internal session alive. A request with `wait=true` waits
for at most 25 seconds, so a client must continue polling a nonterminal
future. Follow [Build a custom training loop](/training/training-loop) for
the native route sequence.

### Native JSON path

1. Call
   [`POST /v1/training/jobs/create-model`](/api-reference/training-jobs/interactive/create-model)
   with `base_model`, or with `from_checkpoint` and `load_optimizer`.
2. Poll the returned create `future_id` through
   [Get a future](/api-reference/training-jobs/interactive/get-future)
   until `completed`, `failed`, or `cancelled`.
3. Queue
   [forward-backward](/api-reference/training-jobs/interactive/forward-backward)
   and [an optimizer step](/api-reference/training-jobs/interactive/optim-step).
   Poll each `future_id` to a terminal status before the next dependent step.
4. [Save sampler weights](/api-reference/training-jobs/interactive/save-weights-for-sampler)
   and poll the save future to a terminal status.
5. Stop the job through the shared
   [stop operation](/api-reference/training-jobs/stop).
6. [Sample from the saved checkpoint](/api-reference/training-jobs/interactive/sample)
   after stop, then poll the sample future to a terminal status.

Only a queued or running sample future can be cancelled. An HTTP rejection
means that the server did not queue the call. A queued future can
instead finish with `status: "failed"`.

### Tinker SDK path

The Tinker path requires Python 3.11 or later.

### 3. Install the client libraries

You need Python 3.11 or later. `transformers` provides the model's tokenizer;
the training itself runs on Fastino.

<CodeGroup>

```bash uv
uv init fastino-training
cd fastino-training
uv add "tinker==0.32.0"
```

```bash pip
mkdir fastino-training && cd fastino-training
python -m venv .venv
source .venv/bin/activate
pip install "tinker==0.32.0"
```

```powershell pip · Windows
mkdir fastino-training
cd fastino-training
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install "tinker==0.32.0"
```

</CodeGroup>

### 4. Choose a model

| Model ID | Context length |
| --- | --- |
| `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16` | 65,536 tokens |
| `nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-BF16` | 32,768 tokens |
| `Qwen/Qwen3.6-35B-A3B` | 32,768 tokens |

LoRA ranks from 1 through 32 are supported; the default is 32.

<CodeGroup>

```bash macOS/Linux
export FASTINO_TRAINING_MODEL="Qwen/Qwen3.6-35B-A3B"
```

```powershell Windows
$env:FASTINO_TRAINING_MODEL = "Qwen/Qwen3.6-35B-A3B"
```

</CodeGroup>

### 5. Create the job

```bash
curl -X POST "https://api.fastino.ai/v1/training/jobs/create-model" \
  -H "X-API-Key: $FASTINO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"base_model": "Qwen/Qwen3.6-35B-A3B", "lora_config": {"rank": 32}}'
```

The response has a `job_id` and the `future_id` of the job's `create`
future:

```json
{
  "job_id": "SESSION_ID:train:0",
  "type": "interactive",
  "base_model": "Qwen/Qwen3.6-35B-A3B",
  "future_id": "FUTURE_ID",
  "load_future_id": null
}
```

Every call that does work returns a future. Read it until `status` is
`completed`. With `wait=true`, the request waits up to 25 seconds:

```bash
curl "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID/futures/$FUTURE_ID?wait=true" \
  -H "X-API-Key: $FASTINO_API_KEY"
```

### 6. Train, save, and sample

The script below runs the whole loop: create a job, run three
forward-backward passes and optimizer steps, save a sampler checkpoint, sample
from it, and stop the job.

Create `quickstart.py`:

```python
import os

import requests
from transformers import AutoTokenizer

API = "https://api.fastino.ai"
MODEL = os.environ["FASTINO_TRAINING_MODEL"]

session = requests.Session()
session.headers["X-API-Key"] = os.environ["FASTINO_API_KEY"]


def call(method, path, body=None):
    response = session.request(method, API + path, json=body, timeout=60)
    response.raise_for_status()
    return response.json() if response.content else None


def wait(job_id, future_id):
    path = f"/v1/training/jobs/{job_id}/futures/{future_id}?wait=true"
    while True:
        future = call("GET", path)
        if future["status"] == "completed":
            return future["result"]
        if future["status"] in ("failed", "cancelled"):
            raise RuntimeError(future["error"])


def datum(prompt_tokens, completion_tokens):
    tokens = prompt_tokens + completion_tokens
    weights = [0.0] * (len(prompt_tokens) - 1) + [1.0] * len(completion_tokens)
    return {
        "model_input": {"chunks": [{"type": "encoded_text", "tokens": tokens[:-1]}]},
        "loss_fn_inputs": {
            "target_tokens": {"data": tokens[1:], "dtype": "int64"},
            "weights": {"data": weights, "dtype": "float32"},
        },
    }


tokenizer = AutoTokenizer.from_pretrained(MODEL)
prompt = tokenizer.apply_chat_template(
    [{"role": "user", "content": "What is the capital of France?"}],
    add_generation_prompt=True,
    return_dict=False,
)
completion = tokenizer.encode("Paris.", add_special_tokens=False)
completion.append(tokenizer.eos_token_id)
batch = {"datums": [datum(prompt, completion)], "loss_fn": "cross_entropy"}

created = call(
    "POST",
    "/v1/training/jobs/create-model",
    {"base_model": MODEL, "lora_config": {"rank": 32}},
)
job_id = created["job_id"]
jobs = f"/v1/training/jobs/{job_id}"
print(f"TRAINING_JOB_ID={job_id}")

try:
    wait(job_id, created["future_id"])

    for step in range(3):
        backward = call("POST", f"{jobs}/forward-backward", batch)
        update = call(
            "POST",
            f"{jobs}/optim-step",
            {"adam_params": {"learning_rate": 1e-4}},
        )
        result = wait(job_id, backward["future_id"])
        wait(job_id, update["future_id"])
        print(f"step {step}: loss {result['metrics']['loss:sum']:.4f}")

    saved = call(
        "POST",
        f"{jobs}/save-weights-for-sampler",
        {"name": "quickstart", "ttl_seconds": 24 * 60 * 60},
    )
    wait(job_id, saved["future_id"])

    sample = call(
        "POST",
        f"{jobs}/sample",
        {
            "checkpoint": "quickstart",
            "prompt_tokens": prompt,
            "sampling_params": {"max_tokens": 32},
        },
    )
    sequence = wait(job_id, sample["future_id"])["sequences"][0]
    print(tokenizer.decode(sequence["tokens"]))
finally:
    call("POST", f"{jobs}/stop")
```

The optimizer step is queued right after the forward-backward pass, without
waiting. The job runs calls in the order it receives them.

Run the script:

```bash
python quickstart.py
```

Copy the value printed after `TRAINING_JOB_ID=`.

<Note>
  An interactive job with no calls for 30 minutes is released. Its checkpoints
  are kept. Stopping returns immediately and prevents new calls, but already
  queued operations may finish before resources are released. Usage may
  continue until that release. You can still sample and download its sampler
  checkpoints.
</Note>

### 7. Verify the canonical job

<CodeGroup>

```bash macOS/Linux
export TRAINING_JOB_ID="<ID printed by quickstart.py>"
curl --fail-with-body \
  -H "X-API-Key: $FASTINO_API_KEY" \
  "https://api.fastino.ai/v1/training/jobs/$TRAINING_JOB_ID"
```

```powershell Windows
$env:TRAINING_JOB_ID = "<ID printed by quickstart.py>"
Invoke-RestMethod `
  -Headers @{ "X-API-Key" = "$env:FASTINO_API_KEY" } `
  -Uri "https://api.fastino.ai/v1/training/jobs/$env:TRAINING_JOB_ID"
```

</CodeGroup>

The response describes the same job created by
`create_lora_training_client(...)`. Continue with the SDK client for model
operations and use the canonical jobs API for documented job reads. Native
JSON clients use the public interactive operation pages instead.
