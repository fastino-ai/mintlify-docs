---
title: "Migrate from Tinker"
description: "Run your existing Tinker Python SDK workload on Fastino by changing the SDK base URL and credential, then verify the connection and review the limits."
---

You do not need to rewrite your training loop or change how your project manages
the Tinker SDK. Fastino supports `tinker==0.32.0`. Point the SDK's API base URL
and credential at Fastino, then run your existing program.

## 1. Point the SDK to Fastino

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="fast_sk_..."
unset TINKER_API_KEY
export TINKER_BASE_URL="https://api.fastino.ai/v1/training/compat/tinker"
export TINKER_CREDENTIAL_CMD='printf "%s\n" "$FASTINO_API_KEY"'
```

```powershell Windows
$env:FASTINO_API_KEY = "fast_sk_..."
Remove-Item Env:TINKER_API_KEY -ErrorAction SilentlyContinue
$env:TINKER_BASE_URL = "https://api.fastino.ai/v1/training/compat/tinker"
$env:TINKER_CREDENTIAL_CMD = 'powershell -NoProfile -Command "[Console]::Out.WriteLine($env:FASTINO_API_KEY)"'
```

</CodeGroup>

Use a Fastino `fast_sk_` key with `TINKER_CREDENTIAL_CMD`. Before constructing
the service client, unset `TINKER_API_KEY`: `tinker==0.32.0` sends an ambient
value while fetching client configuration, before it switches to credential
command authentication. Fastino rejects Tinker `tml-` keys with `401`.

## 2. Verify the connection

```python
import tinker

service_client = tinker.ServiceClient()
print(service_client.get_server_capabilities())
```

Choose a model returned by `get_server_capabilities()`, then run a small version
of your existing workload. The smoke test should complete one training update,
save and reload state, and save sampler weights with an explicit TTL before
sampling. Increase the workload size after it completes.

## Tinker SDK compatibility

With `tinker==0.32.0`, each Tinker training client is an interactive Fastino
job. The SDK model ID is also its ID under `/v1/training/jobs`.

| Area | Supported behavior |
| --- | --- |
| Training | Create or restore a client; inspect it; run forward, forward/backward, `forward_backward_custom`, and optimizer operations. The custom helper computes the loss in your process and translates it into supported built-in model operations. |
| Checkpoints | Save and load state; save sampler weights; inspect, list, download, delete, publish, unpublish, and set retention |
| Sampling | Create or retrieve a sampling client and call `sample` |
| Futures | Retrieve individual asynchronous results; cancel unfinished sampling futures |
| Usage | List or get interactive runs and read checkpoint storage or hourly billing usage |

<AccordionGroup>
  <Accordion title="Supported administration calls">
    Fastino supports `list_training_runs`, `get_training_run`,
    `list_checkpoints`, `list_user_checkpoints`,
    `get_weights_info_by_tinker_path`, `get_checkpoint_archive_url`,
    `delete_checkpoint_from_tinker_path`,
    `publish_checkpoint_from_tinker_path`,
    `unpublish_checkpoint_from_tinker_path`,
    `set_checkpoint_ttl_from_tinker_path`,
    `get_current_checkpoint_storage_usage`, and `get_billing_usage`.

    Run listing reads interactive runs only. Use `/v1/training/jobs` to list
    both config and interactive jobs.
  </Accordion>
  <Accordion title="Limits">
    - LoRA rank must be between 1 and 32.
    - The optimizer is AdamW.
    - Supported losses are `cross_entropy`, `importance_sampling`, `ppo`, `cispo`, and `dro`.
    - Prompt chunks must use `encoded_text`.
    - Training operations run in order. Training-operation futures cannot be cancelled.
    - The SDK session is released after 5 minutes without its heartbeat. Keep the `ServiceClient` active or finish the session before a laptop sleeps.
    - Checkpoint downloads are enabled by default. Downloaded decoder adapters use Fastino's training-cell layout and are not currently compatible with stock PEFT or standard vLLM; use Fastino for sampling and supported checkpoint deployment.
    - Publishing changes visibility within the owning team. It does not make the path loadable by another team.
  </Accordion>
  <Accordion title="Unsupported calls">
    - Batch future retrieval with `retrieve_futures`
    - `save_weights_external` and `external_weights_urls`
    - Session trace export and Audit-log entries
    - Sampling without a `SamplingClient`
    - `target_prompt_logprobs` and positive `prompt_alt_tokens_k`
  </Accordion>
</AccordionGroup>

If authentication fails, confirm that `TINKER_CREDENTIAL_CMD` prints exactly
one current `fast_sk_` key and that `TINKER_BASE_URL` matches the value above.
