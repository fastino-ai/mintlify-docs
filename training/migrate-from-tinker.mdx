---
title: "Migrate from Tinker"
description: "Move a compatible Tinker SDK workload onto Fastino interactive training jobs."
---

Fastino supports a defined subset of the `tinker` SDK as a client interface for
interactive training jobs. A migrated training client is a Fastino job in
`/v1/training/jobs`; its SDK model ID and canonical Fastino job ID are identical.

You have two options:

- **Keep the SDK.** Point `tinker` at Fastino's compatibility base URL and
  authenticate with a Fastino API key. Follow steps 1–4 below.
- **Switch to the native routes.** Call Fastino's REST routes with JSON and the
  same API key. See [Switch to the native routes](#switch-to-the-native-routes).

Either way, treat your existing program as the acceptance test. Change the
connection, check every operation, and run a small smoke test before restoring
production workload sizes.

## 1. Pin the tested package

<CodeGroup>

```bash uv
uv add "tinker==0.32.0"
```

```bash pip
pip install "tinker==0.32.0"
```

</CodeGroup>

## 2. Replace endpoint and authentication

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="fast_sk_..."
export TINKER_BASE_URL="https://api.fastino.ai/v1/training/compat/tinker"
export TINKER_CREDENTIAL_CMD='printf "%s\n" "$FASTINO_API_KEY"'
```

```powershell Windows
$env:FASTINO_API_KEY = "fast_sk_..."
$env:TINKER_BASE_URL = "https://api.fastino.ai/v1/training/compat/tinker"
$env:TINKER_CREDENTIAL_CMD = 'powershell -NoProfile -Command "[Console]::Out.WriteLine($env:FASTINO_API_KEY)"'
```

</CodeGroup>

`TINKER_CREDENTIAL_CMD` runs on every token request and must print a nonempty
credential. Use a normal `fast_sk_` Fastino key; `tml-` credentials are rejected.
Do not set `TINKER_API_KEY`.

Confirm the connection before you change anything else:

```python
import tinker

service_client = tinker.ServiceClient()
print(service_client.get_server_capabilities())
```

## 3. Check the workload

1. Query `ServiceClient.get_server_capabilities()` and choose an available base
   model. Keep the SDK parameter name `base_model`.
2. Compare every method in your code with the
   [supported client behavior](#supported-client-behavior).
3. Remove dependencies on unsupported batch future retrieval, external weight
   export, or external weight URLs.
4. Keep prompt rendering, reward logic, batching, evaluation, and stopping
   criteria in your application.

Capabilities list enabled models and their advertised context lengths. They do
not enumerate LoRA ranks, optimizers, losses, optional methods, or per-operation
limits. Fastino currently accepts LoRA ranks from 1 through 32,
uses `adamw` when creating the client, and supports `cross_entropy`,
`importance_sampling`, `ppo`, `cispo`, and `dro` losses. The active service
validates these settings when you submit the client or operation.

## 4. Run a smoke test

Use the smallest valid datums and optimizer settings from your existing
workload for a low-cost test that:

- Creates one client with `create_lora_training_client(base_model=...)`
- Reads `training_client.get_info().model_id`
- Saves sampler weights with an explicit TTL and samples once
- Runs one supported forward/backward operation and one optimizer step
- Saves and reloads a state checkpoint
- Fetches each client's ID from `GET /v1/training/jobs/{job_id}`; a factory
  resume creates a new job ID seeded from the source checkpoint

Keep using the Tinker SDK for SDK workloads. For direct HTTP clients, use the
[native routes](#switch-to-the-native-routes).

## Supported client behavior

Fastino supports the following `tinker==0.32.0` calls on one interactive
Fastino job.

### Training and sampling

| SDK method or operation | Fastino behavior |
| --- | --- |
| `create_lora_training_client` | Creates an interactive job |
| `copy_weights` | Starts an interactive job from a checkpoint |
| `TrainingClient.get_info` | Returns the interactive job |
| `forward` | Runs a forward-only operation |
| `forward_backward` | Runs a forward and backward operation |
| Custom forward/backward operation | Runs a supported custom-loss operation |
| `optim_step` | Applies an optimizer update |
| `save_state` | Saves training state |
| `save_weights_for_sampler` | Saves sampler weights |
| Load training state | Restores a state checkpoint |
| Create or get a sampling client | Resolves sampler weights |
| `SamplingClient.sample` | Samples through the selected checkpoint |

Keep the SDK parameter `base_model` unchanged. Query
`ServiceClient.get_server_capabilities()` before selecting a model. Use the
documented limits above for rank and loss, and handle validation errors from
the active service.

### Futures and administration

| SDK method or operation | Fastino behavior |
| --- | --- |
| Future result/get | Retrieves one asynchronous result |
| Future cancel | Cancels an unfinished sampling future from `sample`. Training-operation futures are not cancelled |
| `list_training_runs` or `get_training_run` | Reads interactive runs only |
| List checkpoints | Reads checkpoints that belong to the job |
| Download checkpoint archive | Downloads an interactive checkpoint |
| Delete checkpoint | Deletes a checkpoint through the SDK |
| Publish or unpublish checkpoint | Changes checkpoint publication through the SDK |
| Set or clear checkpoint TTL | Changes checkpoint retention through the SDK |
| Checkpoint storage usage | Reads current checkpoint storage through the SDK |
| Billing usage | Reads hourly usage events through the SDK |

The SDK handles token exchange automatically using the key printed by
`TINKER_CREDENTIAL_CMD`. Each of these methods also has a
[native route](#switch-to-the-native-routes).

### Unsupported calls

Fastino does not support:

- Batch future retrieval through `retrieve_futures`
- `save_weights_external`
- `external_weights_urls`
- Session-trace export
- Audit-log entries

Do not infer support because a method exists in the installed package. The
support table documents Fastino's SDK subset; capabilities only report enabled
models and their context lengths.

## Troubleshoot the connection

| Symptom | Check |
| --- | --- |
| Authentication fails | Confirm that `TINKER_CREDENTIAL_CMD` prints one current `fast_sk_` key and no extra output |
| The client cannot connect | Confirm that `TINKER_BASE_URL` is exactly `https://api.fastino.ai/v1/training/compat/tinker` |
| A model is rejected | Query capabilities again and choose an enabled model |
| A rank, loss, or operation is rejected | Compare the call with the documented limits and support table; capabilities do not list these settings |
| Canonical job lookup fails | Confirm that the ID came from `get_info().model_id` and that the same Fastino team is authenticated |

## Migration checklist

- [ ] Pin `tinker==0.32.0`.
- [ ] Set the Fastino adapter base URL.
- [ ] Deliver a `fast_sk_` key through `TINKER_CREDENTIAL_CMD`.
- [ ] Check every SDK method against the supported client behavior.
- [ ] Select an enabled model from capabilities and validate rank, loss, and
      operations against this guide.
- [ ] Complete one sampling and training update.
- [ ] Save and reload one state checkpoint.
- [ ] Verify the SDK model ID through the canonical job endpoint.
- [ ] Increase workload size only after the smoke test passes.

## Switch to the native routes

Every SDK call above has a native REST route under `/v1/training/jobs`. Send
JSON with the same `fast_sk_` key as `X-API-Key` or
`Authorization: Bearer`. You don't need sessions, request sequence numbers, or
heartbeats: Fastino orders each job's calls as it receives them and keeps
the job alive while you call it. An interactive job with no calls for 30
minutes is released; its checkpoints are kept.

Each route that does work returns an `future_id`. Read its result with
`GET /v1/training/jobs/{job_id}/futures/{future_id}?wait=true`; this
replaces `future.result()`.

| Tinker call | Native route |
| --- | --- |
| `create_lora_training_client(base_model=..., rank=...)` | `POST /v1/training/jobs/create-model` with `base_model` and `lora_config` |
| `create_training_client_from_state(path)` | `POST /v1/training/jobs/create-model` with `from_checkpoint` and `"load_optimizer": true` |
| `TrainingClient.get_info()` | `GET /v1/training/jobs/{job_id}` |
| `forward(datums, loss_fn)` | `POST /v1/training/jobs/{job_id}/forward` |
| `forward_backward(datums, loss_fn)` | `POST /v1/training/jobs/{job_id}/forward-backward` |
| `optim_step(AdamParams(...))` | `POST /v1/training/jobs/{job_id}/optim-step` with `adam_params` |
| `save_state(name)` | `POST /v1/training/jobs/{job_id}/save-weights` |
| `save_weights_for_sampler(name, ttl_seconds=...)` | `POST /v1/training/jobs/{job_id}/save-weights-for-sampler` with `ttl_seconds` |
| `load_state(path)` / `load_state_with_optimizer(path)` | `POST /v1/training/jobs/{job_id}/load-weights` with `path` and `optimizer` for the same job's state; for another job's state, create a job with `from_checkpoint` |
| `SamplingClient.sample(prompt, ...)` | `POST /v1/training/jobs/{job_id}/sample` with `checkpoint` and `prompt_tokens` |
| Future `result()` | `GET /v1/training/jobs/{job_id}/futures/{future_id}` |
| Future `cancel()` on a sample | `POST /v1/training/jobs/{job_id}/futures/{future_id}/cancel` |
| `RestClient` list or get training runs | `GET /v1/training/jobs?type=interactive`, `GET /v1/training/jobs/{job_id}` |
| List checkpoints | `GET /v1/training/jobs/{job_id}/checkpoints` |
| Download checkpoint archive | `GET /v1/training/jobs/{job_id}/checkpoints/{checkpoint_id}/download` |
| Delete checkpoint | `DELETE /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}` |
| Publish or unpublish checkpoint | `POST` or `DELETE /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}/publish` |
| Set or clear checkpoint TTL | `PUT /v1/training/jobs/{job_id}/checkpoints/{kind}/{name}/ttl` |
| Checkpoint storage usage | `GET /v1/training/usage` |
| `ServiceClient.close()` / unload the model | `POST /v1/training/jobs/{job_id}/stop` |

Datums keep the SDK's shape as JSON: `model_input.chunks[].tokens` plus
`loss_fn_inputs` tensors such as `{"data": [...], "dtype": "int64"}`. Tokenize
with the model's Hugging Face tokenizer (`transformers.AutoTokenizer`). The
[Quickstart](/training/quickstart#custom-training-loop) has a complete script.
