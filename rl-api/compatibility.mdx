Use this reference to check which parts of the Tinker client contract Fastino's
RL API supports. The pinned `tinker==0.32.0` package defines method signatures.
This page defines Fastino-specific support boundaries, and an explicitly
unsupported item here overrides its availability in the client package.

## Client contract

| Item | Value |
| --- | --- |
| Python package | `tinker` |
| Tested version | `0.32.0` |
| Minimum supported version | `0.25.0` |
| Base URL | `https://api.fastino.ai/tinker` |
| Credential | `tml-` followed by a Fastino `fast_sk_...` key |
| Team access | Limited access for the authenticated Fastino team |

Pin `tinker==0.32.0` when you build against this preview.

## Models

| Base model | Context window | Maximum LoRA rank |
| --- | ---: | ---: |
| `Qwen/Qwen3.6-35B-A3B` | 32,768 | 32 |
| `nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-BF16` | 32,768 | 32 |
| `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16` | 65,536 | 32 |

Call `get_server_capabilities()` before choosing a model. The capability
response is the source of truth for current availability and context windows.

## Training operations

| Capability | Support |
| --- | --- |
| Create a LoRA training client | Supported |
| `forward` | Supported |
| `forward_backward` | Supported |
| `optim_step` | Supported |
| Save or load training state | Supported |
| Create a new client from saved state | Supported |
| Save sampler weights | Supported |
| Create a sampling client from training weights | Supported |
| Unload or release a run | Supported |
| Training layouts other than LoRA | Not supported |

The supported optimizer family is AdamW through SDK `AdamParams`.

### Loss functions

The gateway accepts these built-in loss names:

- `cross_entropy`
- `importance_sampling`
- `ppo`
- `cispo`
- `dro`

Acceptance confirms the client contract and request shape. It does not certify
that every external recipe has identical numerical behavior on every model.
Qualify the loss, datum fields, and model together with a small held-out run
before increasing workload size.

[Train with verifiable rewards](/rl-api/verifiable-rewards) illustrates the
`importance_sampling` datum shape.

## Sampling operations

| Capability | Support |
| --- | --- |
| Sample from a base model | Supported |
| Sample from named sampler weights | Supported |
| Sample from current training weights | Supported |
| Request multiple samples | Supported |
| Compute token log probabilities | Supported |
| Cancel a queued sampling future | Supported |
| Image or multimodal prompt chunks | Not supported |
| `target_prompt_logprobs` | Not supported |
| `prompt_alt_tokens_k` | Not supported |

Current models accept encoded text-token chunks. Sampling requires a
`SamplingClient`.

## Other differences

| Capability | Behavior |
| --- | --- |
| Session trace export | Not supported |
| SDK audit endpoint | Returns no entries |
| Cross-team checkpoint loading | Not supported |
| OpenAPI discovery | RL routes are intentionally absent |

attribution.
