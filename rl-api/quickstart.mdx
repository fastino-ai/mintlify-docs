This tutorial connects the Tinker SDK to Fastino, verifies your team's access,
and samples from a supported model. It proves the connection before you build a
training loop.

<Warning>
  The capability check is read-only. The sample request is billable inference.
  This quickstart does not train a model or create a checkpoint.
</Warning>

## 1. Set up your API key

1. **Create a [Fastino](https://agent.fastino.ai/) account**
2. **Get your API key** from [Settings](https://agent.fastino.ai/api-keys)

Set your key as an environment variable so the examples below work as-is:

<CodeGroup>

```bash macOS/Linux
export FASTINO_API_KEY="your_api_key_here"
```

```powershell Windows
$env:FASTINO_API_KEY = "your_api_key_here"
```

</CodeGroup>

Fastino keys begin with `fast_sk_`. Your team must also have RL API access
enabled. Installing the Tinker SDK does not grant access.

## 2. Create a Python environment

You need Python 3.11 or later.

<CodeGroup>

```bash uv · macOS/Linux
uv init fastino-rl
cd fastino-rl
uv add "tinker==0.32.0"
source .venv/bin/activate
```

```powershell uv · Windows
uv init fastino-rl
cd fastino-rl
uv add "tinker==0.32.0"
.\.venv\Scripts\Activate.ps1
```

```bash pip · macOS/Linux
mkdir fastino-rl && cd fastino-rl
python -m venv .venv
source .venv/bin/activate
pip install "tinker==0.32.0"
```

```powershell pip · Windows
mkdir fastino-rl
cd fastino-rl
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install "tinker==0.32.0"
```

</CodeGroup>

## 3. Configure the Tinker client

Point the Tinker SDK at Fastino and derive the environment variable it expects:

<CodeGroup>

```bash macOS/Linux
export TINKER_API_KEY="tml-${FASTINO_API_KEY}"
export TINKER_BASE_URL="https://api.fastino.ai/tinker"
```

```powershell Windows
$env:TINKER_API_KEY = "tml-$env:FASTINO_API_KEY"
$env:TINKER_BASE_URL = "https://api.fastino.ai/tinker"
```

</CodeGroup>

Do not create a second key. `TINKER_API_KEY` is the Tinker SDK's
environment-variable name, and `tml-` is the compatibility prefix it expects.
Your Fastino key remains the credential that authenticates the request. Do not
commit it to source control.

## 4. Verify access

Create `check_rl_api.py`:

```python
import tinker


TUTORIAL_MODEL = "Qwen/Qwen3.6-35B-A3B"
client = tinker.ServiceClient()
try:
    capabilities = client.get_server_capabilities()
    model_names = {model.model_name for model in capabilities.supported_models}
    if TUTORIAL_MODEL not in model_names:
        available = ", ".join(sorted(model_names)) or "none"
        raise RuntimeError(
            f"{TUTORIAL_MODEL} is not available; available models: {available}. "
            "Stop before billable work and ask Fastino about tutorial-model access."
        )
    print(f"Ready to use {TUTORIAL_MODEL}")
except KeyboardInterrupt:
    client.close("interrupted").result()
    raise
except Exception:
    client.close("errored").result()
    raise
else:
    client.close("success").result()
```

Run it:

```bash
python check_rl_api.py
```

A successful response confirms that the model used below is currently available
to your team. Use the capability response as the source of truth when choosing
a model.

If the call returns `404 Not Found`, confirm that the base URL ends in
`/tinker`. If it does, ask Fastino to enable RL API access for your team.

## 5. Run your first sample

Create `sample_rl_api.py`:

```python
import tinker


TUTORIAL_MODEL = "Qwen/Qwen3.6-35B-A3B"
service_client = tinker.ServiceClient()
try:
    sampling_client = service_client.create_sampling_client(
        base_model=TUTORIAL_MODEL
    )
    tokenizer = sampling_client.get_tokenizer()
    prompt_tokens = tokenizer.apply_chat_template(
        conversation=[
            {"role": "user", "content": "Explain what a reward function does in RL."}
        ],
        add_generation_prompt=True,
        return_dict=False,
    )
    result = sampling_client.sample(
        prompt=tinker.types.ModelInput.from_ints(prompt_tokens),
        num_samples=1,
        sampling_params=tinker.types.SamplingParams(
            max_tokens=128,
            temperature=0.7,
        ),
    ).result()
    print(tokenizer.decode(result.sequences[0].tokens))
except KeyboardInterrupt:
    service_client.close("interrupted").result()
    raise
except Exception:
    service_client.close("errored").result()
    raise
else:
    service_client.close("success").result()
```

Run it:

```bash
python sample_rl_api.py
```

A successful run prints one model response. Your application sent a text
prompt through the SDK, Fastino performed inference, and the client decoded the
returned tokens.

<Note>
  `Qwen/Qwen3.6-35B-A3B` is used here because it is supported by the current RL
  API contract. Do not copy a model name from a different Tinker environment
  without checking the capability response first.
</Note>

## 6. Close clients in your own code

The example closes its `ServiceClient` on success, interruption, and error. Use
the same pattern in long-running applications.

Closing the client ends its session and releases active training runs. Saved
checkpoints remain available according to their retention settings.

Use `success` only after a completed run. Close with `errored` when an exception
escapes, and with `interrupted` after cancellation or shutdown.
